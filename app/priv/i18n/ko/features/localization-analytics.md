## 데이터로 다음 표적 언어를 결정하세요

대부분의 팀은 직감으로 표적 언어를 선택합니다. 현지화 분석은 이를 신호로 대체합니다. Web SDK 를 추가하면 Glossia 는 방문자의 브라우저에서 요청한 언어, 그들이 온 국가, 그리고 무엇보다 이미 지원하는 언어와의 중첩 부분을 보여줍니다.

주요 지표는 **현지화 격차**: 선호 언어를 지원하지 않는 방문자의 비율입니다. 국가, 리퍼러, 페이지별로 세부 분석하여 지원되지 않는 수요가 어디에 집중되어 있는지, 그리고 어떤 새로운 표적 언어가 변화를 일으킬 수 있는지 정확히 확인하세요.

## 절충 없는 개인정보 보호

Glossia 분석은 필요 없는 것은 수집하지 않으며 식별 가능한 정보는 저장하지 않습니다. 브라우저는 페이지 URL, 리퍼러, 선호 언어, 시간대, 화면 크기를 전송합니다. 서버는 IP 와 User-Agent 의 일일 로테이션 해시로 고유 방문자를 추출한 후 이를 삭제합니다. 쿠키는 설정되지 않으며, 지문 식별되지 않으며, 방문자는 날짜 간이나 사이트 간 추적될 수 없습니다.

그 결과는 동의 배너 없이도 배포 가능한 분석입니다. 이는 귀하의 국제 방문자들이 이미 가지고 있는 개인정보 보호 기대감과 일치합니다.

## 몇 초 만에 설치

사이트에 한 줄을 추가하고 Glossia 가 측정을 시작합니다:

```html
<script defer data-domain="example.com" src="https://cdn.glossia.ai/web.js"></script>
```

npm 을 선호하시나요? 설치 `@glossia/web` 그리고 호출 `init({ domain })`. 어떤 경우든 페이지뷰, 클라이언트 측 내비게이션 및 커스텀 이벤트는 현지화 기회를 우선순위로 정하는 동일한 대시보드에 유입됩니다.
