## 개발자 우선

REST API 는 Glossia 의 핵심입니다. 대시보드, CLI, 그리고 [MCP 서버](/features/mcp-server) 모두 동일한 엔드포인트를 사용합니다. 기능을 추가할 때, API 에 먼저 적용되고 모든 다른 곳에서 볼 수 있습니다.

이는 UI 에 의한 제약에서 자유롭다는 의미입니다. 상상할 수 있는 워크플로우라면, CI/CD 통합부터 커스텀 대시보드까지, 모두 동일한 안정적이고 문서화된 인터페이스 위에 구축될 수 있습니다.

## 인증

Glossia 는 모든 API 인증에 OAuth 2.1 과 PKCE 를 사용합니다. 이 프로세스는 1 차 및 3 차 클라이언트를 모두 지원합니다. 다음 [인증 및 권한 부여 문서](/docs/reference/apis/authentication) 전체 가이드를 보려면.

**동적 클라이언트 등록** -- 클라이언트는 프로그램 방식으로 다음에서 등록됩니다. `/oauth/register` 리디렉션 URI 와 권한 유형을 포함합니다. 수동 승인 단계는 없으며, 통과해야 할 포털도 없습니다.

**PKCE 와 함께 권한 부여 코드** -- 사용자가 브라우저 기반 동의 화면을 통해 클라이언트를 승인합니다. PKCE 확정은 시크릿을 저장할 수 없는 공개 클라이언트에서도 토큰이 안전하게 유지되도록 보장합니다.

**토큰 수명 주기** -- 액세스 토큰은 표준 OAuth 엔드포인트를 통해 교환, 조회 및 취소할 수 있습니다. 토큰 엔드포인트의 속도 제한은 무차별 공격으로부터 보호합니다.

## 인가

접근 제어는 두 가지 레이어를 사용합니다. 다음 [인증 문서](/docs/reference/apis/authentication) 는 범주, 역할 및 전체 권한 행렬을 자세히 다룹니다.

**범위** 는 토큰이 접근 가능한 범주를 정의합니다. 권한이 있는 토큰은 `voice:read` 음성 설정을 읽을 수는 있지만 수정할 수는 없습니다. 범위는 다음 `resource:action` 패턴: `account:read`, `organization:write`, `glossary:admin` 용어 관리 등에 사용됩니다.

**정책** 사용자와 특정 리소스 간의 관계를 확인합니다. 올바른 범위를 지닌 유효한 토큰도 사용자가 속해 있지 않은 조직에는 접근할 수 없습니다. 모든 요청은 두 레이어 모두에 대해 확인됩니다.

## 페이징, 필터링, 및 정렬

모든 목록 엔드포인트는 일관된 메타데이터를 포함한 페이지네이션된 결과를 반환합니다:

각 응답에는 `total_count`, `total_pages`, `current_page`, `page_size`, `has_next_page?`, 그리고 `has_previous_page?` 이므로 클라이언트는 추측 없이 페이지네이션 제어를 구축할 수 있습니다.

인덱싱된 필드를 사용하여 필터링합니다. `filters[field]=value` 쿼리 매개변수. 오름차순 또는 내림차순 으로 `order_by[]` 파라미터. 모든 리소스에서 인터페이스는 동일합니다.

## OpenAPI 및 인터랙티브 문서

전체 OpenAPI 3.1 사양은 다음에서 확인할 수 있습니다 `/api/openapi.json`. 해당 [인터랙티브 API 참조](/docs/reference/apis/rest) Scalar 로 제공되며 브라우저에서 직접 엔드포인트를 탐색하고 스키마를 검토하며 테스트 요청을 작성할 수 있습니다.

언어별 클라이언트 라이브러리는 사양에서 생성할 수 있습니다. 계약서는 버전 관리가 되며 안정적이므로, 새로운 기능을 출시했을 때 통합이 중단되지 않습니다.
