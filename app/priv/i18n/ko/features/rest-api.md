## 개발자 우선

REST API 는 Glossia 의 핵심입니다. 대시보드, CLI, 그리고 [MCP 서버](/features/mcp-server) 모두 동일한 엔드포인트를 사용합니다. 기능을 추가하면 API 에 먼저 적용되고, 그곳에서 다른 모든 곳에 표시됩니다.

이는 UI 에 제한받지 않는다는 뜻입니다. CI/CD 통합부터 맞춤형 대시보드까지 상상할 수 있는 모든 워크플로우를 동일한 안정적이고 문서화된 인터페이스 위에서 구축할 수 있습니다.

## 인증

Glossia 는 모든 API 인증에 PKCE 와 함께 OAuth 2.1 을 사용합니다. 해당 플로우 는 제 1 파티 및 제 3 파티 클라이언트를 모두 지원합니다. 다음 [인증 및 권한 부여 문서](/docs/reference/apis/authentication) 전체 가이드를 위한.

**동적 클라이언트 등록** -- 클라이언트는 프로그램 방식으로 등록됩니다. `/oauth/register` 리디렉션 URI 와 인가 유형을 통해. 수동 승인 단계는 없으며, 포털을 클릭할 필요가 없습니다.

**PKCE 와 인가 코드** -- 사용자는 브라우저 기반 동의 화면을 통해 클라이언트를 승인합니다. PKCE 확장은 공개 클라이언트가 비밀을 저장할 수 없는 경우에도 토큰이 안전하게 유지되도록 보장합니다.

**토큰 라이프사이클** -- 액세스 토큰은 표준 OAuth 엔드포인트를 통해 교환, 확인 및 취소할 수 있습니다. 토큰 엔드포인트의 속도 제한은 무차별 대입 공격으로부터 보호합니다.

## 권한

접근 제어는 두 가지 레이어를 사용합니다. 는 [인증 문서](/docs/reference/apis/authentication) 범위, 역할 및 전체 권한 매트릭스를 자세히 다룹니다.

**범위** 토큰이 접근할 수 있는 리소스 범주를 정의합니다. 권한을 가진 토큰은 `voice:read` 음성 설정만 읽을 수 있지만 수정할 수는 없습니다. 범위 는 `resource:action` 패턴: `account:read`, `organization:write`, `glossary:admin` 용어 사전 관리 등.

**정책** 사용자와 특정 리소스 간의 관계를 확인합니다. 올바른 범위를 가진 유효한 토큰이라도 사용자가 속하지 않은 조직에는 접근할 수 없습니다. 모든 요청은 두 계층에서 모두 검증됩니다.

## 페이징, 필터링 및 정렬

모든 목록 엔드포인트는 일관된 메타데이터를 포함하여 페이지화된 결과를 반환합니다:

각 응답에는 다음이 포함됩니다. `total_count`, `total_pages`, `current_page`, `page_size`, `has_next_page?`, 그리고 `has_previous_page?` 따라서 클라이언트는 추측 없이 페이지네이션 컨트롤을 구축할 수 있습니다.

인덱싱된 필드를 사용하여 필터링 `filters[field]=value` 쿼리 매개변수. 오름차순 또는 내림차순으로 정렬합니다. `order_by[]` 매개변수. 인터페이스는 모든 리소스에서 동일합니다.

## OpenAPI 및 인터랙티브 문서

OpenAPI 3.1 전체 스펙은 다음에서 확인하실 수 있습니다 `/api/openapi.json`. 이 [인터랙티브 API 참조](/docs/reference/apis/rest) Scalar 로 제공되며 브라우저에서 직접 엔드포인트를 탐색하고 스키마를 검사하며 테스트 요청을 생성할 수 있습니다.

어떤 언어든 클라이언트 라이브러리는 스펙에서 생성할 수 있습니다. 계약서는 버전 관리되어 안정적이므로, 새로운 기능을 출시하더라도 통합이 깨지지 않습니다.
