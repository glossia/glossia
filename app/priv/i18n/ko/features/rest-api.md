## 개발자 우선

REST API 는 Glossia 의 핵심입니다. 대시보드, CLI, 그리고 [MCP 서버](/features/mcp-server) 모두 동일한 엔드포인트를 사용합니다. 기능을 추가할 때 API 에 먼저 추가되고 이후 다른 곳에서 노출됩니다.

이는 UI 에 제약받지 않는다는 의미입니다. 상상 가능한 모든 워크플로우, CI/CD 통합부터 맞춤형 대시보드까지, 동일한 안정적이고 문서화된 인터페이스를 기반으로 구축할 수 있습니다.

## 인증

Glossia 는 모든 API 인증에 PKCE 와 함께 OAuth 2.1 을 사용합니다. 이 플로우 는 제 1 당 및 제 3 당 클라이언트를 모두 지원합니다. 다음 [인증 및 권한 부여 문서](/docs/reference/apis/authentication) 전체 가이드를 위해.

**동적 클라이언트 등록** -- 클라이언트는 프로그래밍 방식으로 등록됩니다. `/oauth/register` 그들의 리다이렉트 URI 와 권한 부여 유형으로. 수동 승인 단계도 없으며, 거쳐야 할 포털도 없습니다.

**PKCE 기반 인가 코드** -- 사용자는 브라우저 기반 동의 화면을 통해 클라이언트를 승인합니다. PKCE 확장은 토큰이 안전하게 유지되도록 보장하며, 비밀을 저장할 수 없는 공개 클라이언트에서도 이를 보장합니다.

**토큰 수명 주기** -- 표준 OAuth 엔드포인트를 통해 액세스 토큰은 교환, 조회, 취소될 수 있습니다. 토큰 엔드포인트의 속도 제한은 무차별 대입 공격으로부터 보호합니다.

## 권한 부여

접근 제어는 두 가지 계층을 사용합니다. [인증 문서](/docs/reference/apis/authentication) 범위, 역할, 및 전체 권한 매트릭스를 자세히 다룹니다.

**범위** 토큰이 접근할 수 있는 리소스 범주를 정의합니다. 해당 토큰은 `voice:read` 음성 설정을 읽을 수 있지만 수정할 수는 없습니다. 범위는 다음 `resource:action` 패턴: `account:read`, `organization:write`, `glossary:admin` , 용어 관리 등.

**정책** 사용자와 특정 리소스 간의 관계를 검증합니다. 올바른 범위를 가진 유효한 토큰조차 사용자가 속하지 않는 조직에는 접근할 수 없습니다. 모든 요청은 두 계층 모두에 대해 검증됩니다.

## 페이징, 필터링, 및 정렬

모든 목록 엔드포인트는 일관된 메타데이터가 포함된 페이징 결과를 반환합니다:

모든 응답에는 다음이 포함됩니다 `total_count`, `total_pages`, `current_page`, `page_size`, `has_next_page?`, 그리고 `has_previous_page?` 따라서 클라이언트는 추측 없이 페이네이션 컨트롤을 만들 수 있습니다.

인덱스된 필드를 사용하여 필터링합니다. `filters[field]=value` 쿼리 매개변수를 사용합니다. 오름차순 또는 내림차순 정렬을 지원합니다. `order_by[]` 매개변수. 인터페이스는 모든 리소스에서 동일합니다.

## OpenAPI 및 인터랙티브 문서

전체 OpenAPI 3.1 사양은 다음에서 확인 가능합니다 `/api/openapi.json`. 이 [인터랙티브 API 참조](/docs/reference/apis/rest) 는 Scalar 에서 구동되며 브라우저에서 직접 엔드포인트 탐색, 스키마 검토 및 테스트 요청 생성이 가능합니다.

모든 언어의 클라이언트 라이브러리는 사양에서 생성할 수 있습니다. 계약은 버전 관리되어 안정적이며 새 기능을 출시할 때 통합이 중단되지 않습니다.
