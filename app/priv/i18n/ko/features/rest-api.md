## 개발자 우선

REST API 는 Glossia 의 핵심입니다. 대시보드, CLI, 와 [MCP 서버](/features/mcp-server) 모두 동일한 엔드포인트를 사용합니다. 기능을 추가하면 먼저 API 에 구현되고 그로부터 다른 모든 곳에서 노출됩니다.

이는 UI 에 의해 결코 제한되지 않음을 의미합니다. 상상할 수 있는 모든 워크플로우, CI/CD 통합부터 커스텀 대시보드까지, 동일한 안정적이고 문서화된 인터페이스 위에서 구축할 수 있습니다.

## 인증

Glossia 는 모든 API 인증에 OAuth 2.1 와 PKCE 를 사용합니다. 이 프로세스는 1 차 및 3 차 클라이언트를 모두 지원합니다. 다음 [인증 및 권한 부여 문서](/docs/reference/apis/authentication) 전체 가이드를 보려면.

**동적 클라이언트 등록** -- 클라이언트는 프로그램 방식으로 등록됩니다. `/oauth/register` 클라이언트들의 리디렉션 URI 와 승인 유형으로. 수동 승인 단계가 없으며, 포털을 클릭할 필요도 없습니다.

**PKCE 와 인증 코드** -- 사용자는 브라우저 기반 동의 화면을 통해 클라이언트를 승인합니다. PKCE 확장은 공개 클라이언트라도 기밀을 저장할 수 없는 상황에서도 토큰 보안을 유지합니다.

**토큰 수명주기** -- 표준 OAuth 엔드포인트를 통해 액세스 토큰은 교환, 상태 확인 및 취소가 가능합니다. 토큰 엔드포인트의 속도 제한은 무차별 공격을 방지합니다.

## 권한 부여

접근 제어는 두 가지 계층을 사용합니다. 이 [인증 문서](/docs/reference/apis/authentication) 범위, 역할 및 전체 권한 행렬을 상세히 다룹니다.

**범위** 토큰이 접근 가능한 리소스 범주를 정의하며, 이러한 권한을 가진 토큰은 `voice:read` 음성 설정을 읽을 수 있지만 수정할 수는 없습니다. 범위는 다음 `resource:action` 패턴: `account:read`, `organization:write`, `glossary:admin` 용어 관리 등이等多项属性.

**정책** 사용자와 특정 리소스 간의 관계를 확인합니다. 올바른 범위를 가진 유효한 토큰도 사용자가 소속되지 않은 조직에 접근할 수 없습니다. 모든 요청은 두 계층에서 확인됩니다.

## 페이징, 필터링 및 정렬

모든 목록 엔드포인트는 일관된 메타데이터가 포함된 페이지네이션된 결과를 반환합니다:

각 응답에는 `total_count`재구성된 문서가 이전에 검증에 실패했습니다: 마크다운 텍스트 리터럴 복구는 일치하는 길이의 JSON 문자열 배열을 반환해야 합니다. `total_pages`이전 재조립된 문서가 검증에 실패했습니다: Markdown 텍스트 노드 복구로 인해 빈 번역이 생성되었습니다. `current_page`다시 조립된 문서는 이전에 유효성 검사를 통과하지 못했습니다: 마크다운 텍스트 리터럴 복원은 길이가 일치하는 JSON 문자열 배열을 반환해야 합니다 `page_size`이전에 검증에 실패한 조립된 문서: Markdown 텍스트 리터럴 복원은 일치하는 길이의 JSON 문자열 배열을 반환해야 합니다. `has_next_page?`, 그리고 `has_previous_page?` 따라서 클라이언트는 추측하지 않고 페이지네이션 컨트롤을 구축할 수 있습니다.

인덱싱된 필드를 사용하여 필터링 `filters[field]=value` 쿼리 매개변수. 오름차순 또는 내림차순으로 정렬 `order_by[]` 파라미터. 모든 리소스에 걸친 인터페이스는 동일합니다.

## OpenAPI 및 인터랙티브 문서

전체 OpenAPI 3.1 명세서는 다음 에서 확인 가능합니다. `/api/openapi.json`. 해당 [인터랙티브 API 참조](/docs/reference/apis/rest) Scalar 로 구동되며 브라우저에서 직접 엔드포인트를 탐색하고 스키마를 검사하며 테스트 요청을 생성할 수 있습니다.

언어별 클라이언트 라이브러리는 해당 명세서에서 생성 가능합니다. 계약은 버전 관리를 하고 안정적이므로 새 기능이 출시될 때 통합이 중단되지 않습니다.
