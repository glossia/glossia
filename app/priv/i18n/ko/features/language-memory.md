## 언어 메모리가 무엇입니까?

언어 메모리는 조직의 소통 방식을 에이전트에 전달하는 누적된 맥락입니다. 두 가지 핵심 기본 요소로 구성되어 있으며, 시간이 지남에 따라 만들고 다듬습니다:

**목소리**는 콘텐츠가 어떻게 들려야 하는지를 정의합니다. 톤앤매너, 격식, 대상 독자, 그리고 자유형 가이드라인은 모두 여기에 있으며, 계정 기반 기본 목소리를 설정한 후 개별 로케일에 대해 특정 필드를 재정의할 수 있습니다. 따라서 일본어 콘텐츠는 더 격식 있게 유지할 수 있고, 영어는 대화형으로 남아있을 수 있습니다.

**용어**는 용어의 의미와 현지화 방식을 정의합니다. 각 항목은 정의와 로케일별 번역을 포함합니다. 에이전트가 원본 콘텐츠에서 "workspace"를 마주하게 되면 용어는 이를 현지화하거나, 표기대로 올리거나, 또는 그대로 두도록 하고, 각 대상 언어에 정확히 어떤 단어를 사용해야 하는지 알려줍니다.

함께 묶인 목소리와 용어는 에이전트가 매번 참조하는 맥락 계층을 형성합니다. 이 계층에 투자할수록 결과물이 필요로 하는 검토 작업이 줄어듭니다.

## 불변 버전 관리

언어 메모리는 오직 추가 전용입니다. 목소리나 용어를 업데이트할 때 Glossia 는 기존 내용을 덮어쓰지 않고 대신 새 버전을 생성합니다. 각 버전은 누가 언제 생성했는지와, 진화된 내용을 설명하는 선택 사항 변경 주석을 기록합니다.

이는 항상 완전한 감사 기록임을 의미합니다. 한 분기 동안 톤이 어떻게 변화했는지 이해하기 위해 버전 3 과 버전 7 을 비교할 수 있습니다. 최근 변경 사항이 일관성을 해쳤다면 이전 버전으로 되돌린 다음 진행하세요.

버전 관리는 또한 협업을 더 안전하게 만듭니다. 여러 팀원이 충돌을 걱정하지 않고 목소리 변경을 제안할 수 있습니다. 각 변경 사항은 개별적이고 추적 가능한 사건이기 때문입니다.

## 로케일 인식 해결

에이전트가 특정 로케일을 위한 워크플로우를 실행할 때 Glossia 는 해당 맥락에 맞게 언어 메모리를 해결합니다. 기본 목소리 설정을 먼저 적용한 후 로케일별 특정 상황을 상부에 적용합니다. 용어도 마찬가지입니다: 대상 로케일을 위한 현지화된 용어가 있는 항목만 포함됩니다.

이 해결 단계는 에이전트가 항상 가장 관련성 높은 맥락에서 작업함을 의미합니다. 별도-config 각 언어별로 유지할 필요가 없습니다. 기본값을 한 번 정의하고 필요한 곳에서 업데이트하며 해결 시스템에 나머지를 맡기세요.

## 어디서나 활용

언어 메모리는 현지화를 위해 설계되었지만 텍스트를 생산하는 곳에서 어디든 유용합니다. 맥락이 [REST API](/features/rest-api) 와 [MCP 서버](/features/mcp-server) 를 통해 액세스 가능하기 때문에 현지화를 넘어가는 워크플로우에 통합할 수 있습니다:

**마케팅 및 소셜 콘텐츠** -- 조직의 목소리를 소셜 미디어 게시물, 이메일 캠페인 또는 랜딩 페이지 문구 초안을 작성하는 콘텐츠 에이전트로 가져옵니다. 용어는 브랜드 용어의 일관성을 유지하고 목소리 설정은 톤이 브랜드에 맞도록 보장합니다.

**문서화** -- 언어 메모리를 문서화 파이프라인에 입력하여 기술 문서 작성 전체가 나머지 콘텐츠와 동일한 스타일 규칙을 따르도록 합니다. 용어 항목은 문서, 도움말 글 및 인-products 문구 전반에 걸친 편차를 방지합니다.

**코드 검토** -- 목소리와 용어를 기준으로 Pull Request 문구 (오류 메시지, UI 레이블, 온보딩 텍스트) 를 검토하는 에이전트를 구축하세요. 출시하기 전에 불일치를 표시하세요.

**사용자 지정 에이전트** -- MCP 호환 클라이언트는 언어 메모리를 읽거나 기록할 수 있습니다. 코딩 어시스턴트에게 "새 제품 이름을 사용하여 용어 업데이트" 또는 "독일 로케일의 목소리 톤을 전문적으로 설정"이라고 요청하면 의도를 올바른 API 호출로 번역합니다.

## 점진적 다듬기

언어 메모리는 사용에 따라 개선됩니다. 리뷰어가 에이전트 출력을 보정할 때마다 그 보정은 다음 버전의 목소리나 용어로 반영됩니다. 시간이 지남에 따라 초안과 최종 출력 사이의 격차는 줄어들고 검토 단계가 빨라집니다.

이것이 Glossia 의 핵심인 피드백 루프입니다: 생성, 검토, 맥락 다듬기, 다시 생성. 에이전트들은 단순히 지시사항만 따르는 것이 아닙니다. 그들은 매 사이클마다 개선되는 맥락과 함께 작업합니다.
