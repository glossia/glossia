## 언어 메모리란 무엇인가요?

언어 메모리는 조직의 커뮤니케이션 방식을 Glossia의 에이전트에 알려 주는 누적 컨텍스트입니다. 시간이 지나면서 생성하고 개선하는 두 가지 핵심 요소로 구성됩니다.

**보이스**는 콘텐츠가 어떤 방식으로 표현되어야 하는지 정의합니다. 어조, 격식 수준, 대상 독자, 자유 형식의 지침을 모두 여기에서 관리합니다. 계정의 기본 보이스를 설정한 다음 개별 로케일의 특정 필드를 재정의할 수 있습니다. 예를 들어 영어 문구는 대화체로 유지하면서 일본어 문구에는 더 격식 있는 표현을 적용할 수 있습니다.

**용어**는 각 용어의 의미와 현지화 방식을 정의합니다. 각 항목에는 정의와 로케일별 번역이 포함됩니다. 에이전트가 원본 콘텐츠에서 "workspace"를 발견하면 용어 정보에 따라 현지화할지, 음역할지, 그대로 둘지 결정하고 각 대상 언어에서 사용할 정확한 단어를 선택합니다.

보이스와 용어는 함께 모든 실행에서 에이전트가 참조하는 컨텍스트 계층을 구성합니다. 이 계층을 충실하게 구축할수록 결과물에 필요한 검토가 줄어듭니다.

## 불변 버전 관리

언어 메모리는 추가 전용입니다. 보이스나 용어를 업데이트하면 Glossia는 이전 버전을 덮어쓰지 않고 새 버전을 생성합니다. 모든 버전에는 생성한 사람과 생성 시점이 기록되며, 변경 사항을 설명하는 메모를 선택적으로 추가할 수 있습니다.

따라서 언제든지 전체 감사 추적 기록을 확인할 수 있습니다. 버전 3과 버전 7을 비교하여 분기 동안 어조가 어떻게 바뀌었는지 파악할 수 있습니다. 최근 변경으로 일관성 문제가 발생했다면 이전 버전으로 되돌린 후 작업을 계속할 수 있습니다.

버전 관리는 협업의 안전성도 높입니다. 각 변경 사항이 독립적이며 추적 가능한 이벤트로 기록되므로 여러 팀원이 충돌을 걱정하지 않고 보이스 변경을 제안할 수 있습니다.

## 로케일 인식 기반 해석

에이전트가 특정 로케일의 워크플로를 실행하면 Glossia는 해당 컨텍스트에 맞는 언어 메모리를 해석합니다. 먼저 기본 보이스 설정을 적용한 후 로케일별 재정의가 있으면 그 위에 적용합니다. 용어도 동일하게 처리되며, 대상 로케일에 현지화된 용어가 있는 항목만 포함됩니다.

이 해석 단계 덕분에 에이전트는 항상 가장 관련성이 높은 컨텍스트를 사용합니다. 언어별로 별도의 구성을 유지할 필요가 없습니다. 기본값을 한 번 정의하고 필요한 부분만 재정의하면 나머지는 해석 시스템이 처리합니다.

## 어디서나 활용

언어 메모리는 현지화를 위해 설계되었지만 텍스트를 생성하는 모든 곳에서 유용합니다. 컨텍스트는 [REST API](/features/rest-api)와 [MCP server](/features/mcp-server)를 통해 접근할 수 있으므로 현지화 이외의 워크플로에도 통합할 수 있습니다.

**마케팅 및 소셜 콘텐츠** -- 조직의 보이스를 소셜 미디어 게시물, 이메일 캠페인 또는 랜딩 페이지 문구를 작성하는 콘텐츠 에이전트에 적용할 수 있습니다. 용어는 브랜드 관련 표현의 일관성을 유지하고, 보이스 설정은 어조가 브랜드에 부합하도록 합니다.

**문서** -- 언어 메모리를 문서 작성 파이프라인에 제공하여 기술 문서가 다른 콘텐츠와 동일한 스타일 규칙을 따르도록 할 수 있습니다. 용어 항목은 문서, 도움말 문서, 제품 내 문구 사이에서 표현이 달라지는 것을 방지합니다.

**코드 리뷰** -- 풀 리퀘스트의 문구(오류 메시지, 사용자 인터페이스 레이블, 온보딩 텍스트)를 보이스 및 용어와 대조하여 검토하는 에이전트를 구축할 수 있습니다. 배포 전에 불일치를 표시할 수 있습니다.

**사용자 지정 에이전트** -- MCP 호환 클라이언트는 모두 언어 메모리를 읽고 쓸 수 있습니다. 코딩 어시스턴트에게 "새 제품 이름으로 용어를 업데이트해 줘" 또는 "독일어 로케일의 보이스 어조를 전문적으로 설정해 줘"라고 요청하면 의도를 적절한 API 호출로 변환합니다.

## 점진적 개선

언어 메모리는 사용할수록 개선됩니다. 검토자가 에이전트의 결과물을 수정할 때마다 해당 수정 사항이 다음 버전의 보이스나 용어에 반영됩니다. 시간이 지나면 초안과 최종 결과물의 차이가 줄어들고 검토 단계도 빨라집니다.

이것이 Glossia의 핵심 피드백 루프입니다. 생성하고, 검토하고, 컨텍스트를 개선한 후 다시 생성합니다. 에이전트는 단순히 지침만 따르지 않습니다. 매 주기마다 개선되는 컨텍스트를 바탕으로 작업합니다.
