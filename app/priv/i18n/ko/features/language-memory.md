## 언어 메모리가 무엇인가요?

언어 메모리는 Glossia 에이전트가 귀하의 조직이 어떻게 소통하는지 알려주는 누적된 컨텍스트입니다. 시간에 따라 구축하고 정제할 수 있는 두 가지 핵심 기본 요소로 구성되어 있습니다:

**톤** 콘텐츠가 어떤 방식으로 발화되어야 하는지 정의합니다. 톤, 격식, 대상 독자 및 자유형 가이드라인이 모두 여기에 있습니다. 계정의 기본 톤을 설정하고 개별 로케일에 세부 필드를 오버라이드하여 일본어 콘텐츠를 더 격식 있게, 영어는 일상 대화체로 유지할 수 있습니다.

**용어집** 용어의 정의와 현지화 방법을 정의합니다. 각 항목은 정의 및 로케일별 번역을 포함합니다. 에이전트가 소스 콘텐츠에서 "workspace"를 마주쳤을 때, 용어집은 이를 현지화하거나 표기하거나 원본 상태를 유지할지 결정하며, 각 대상 언어에 사용할 정확한 단어를 지정합니다.

톤과 용어집은 에이전트가 매 실행마다 참조하는 컨텍스트 레이어를 형성합니다. 이 레이어에 더 투자할수록 결과 검토는 줄어듭니다.

## 불변 버전 관리

언어 메모리는 오직 추가만 가능합니다. 보이스 또는 용어집을 업데이트할 때 Glossia 는 기존 버전을 덮어쓰지 않고 새로운 버전을 생성합니다. 각 버전은 작성자, 시간 및 변경 내용을 설명하는 선택적 변경 노트를 기록합니다.

이는 항상 완벽한 감사 내역을 의미합니다. 버전 3 과 버전 7 을 비교하여 분기 동안 톤의 변화가 어떻게 되었는지 이해할 수 있습니다. 만약 최근 변경으로 인해 불일치가 발생했다면 이전 버전으로 되돌려 진행하세요.

버전화는 또한 협력을 더 안전하게 만듭니다. 여러 팀 구성원은 충돌을 걱정 없이 보이스 변경을 제안할 수 있습니다. 각 변경이 독립적이고 추적 가능한 이벤트이기 때문입니다.

## 로케일 기반 해결

에이전트가 특정 로케일을 위한 워크플로우를 실행할 때, Glossia 는 해당 컨텍스트에 따른 언어 메모리를 해결합니다. 기본 보이스 설정에서 시작하여 로케일별 오버라이드를 적용하고, 용어의 경우도 동일하게 적용됩니다: 목표 로케일에 대한 현지화된 용어를 가진 항목만 포함됩니다.

이 해결 단계는 에이전트가 항상 가장 관련성 높은 컨텍스트로 작업함을 의미합니다. 언어별 별도의 구성을 유지할 필요가 없습니다. 기본값을 한 번 정의하고, 필요한 부분에서는 오버라이드하고, 나머지는 해결 시스템에 맡기세요.

## 어디든 사용하세요

언어 메모리는 현지화를 위해 설계되었지만, 텍스트를 생성하는 곳에서나 유용합니다. 컨텍스트가 ... 를 통해 접근 가능하기 때문입니다. [REST API](/features/rest-api) 및 해당 [MCP 서버](/features/mcp-server), 현지화를 넘어선 워크플로우에 통합할 수 있습니다:

**마케팅 및 소셜 콘텐츠** -- 조직의 브랜드 톤을 콘텐츠 에이전트에 활용하여 소셜 미디어 게시물, 이메일 캠페인, 또는 랜딩 페이지 문구 작성에 사용합니다. 용어집은 브랜드어를 일관되게 유지하며, 브랜드 톤 설정은 브랜드와 톤의 일치를 보장합니다.

**기술 문서** -- 언어 메모리를 문서 파이프라인에 공급하여 기술 작성이 기존 콘텐츠와 동일한 스타일 규칙을 따르도록 합니다. 용어집 항목은 문서, 도움말 문서, 제품 내 문구에 걸친 편차를 방지합니다.

**코드 검토** -- 당신의 스타일과 사전에 부합하는지 풀 리퀘스트 콘텐츠 (에러 메시지, UI 레이블, 온보딩 텍스트) 를 검토하는 에이전트를 구축하세요. 출시 전에 일관성 문제를 표시하세요.

**커스텀 에이전트** -- 어떤 MCP 호환 클라이언트도 언어 메모리를 읽거나 쓸 수 있습니다. 코딩 비서를 통해 "새 제품명으로 사전 업데이트" 또는 "독일어 로케일을 위한 전문적 톤 설정" 과 같은 명령을 요청하면 의도를 올바른 API 호출로 변환합니다.

## 점진적 개선

언어 메모리는 사용에 따라 개선됩니다. 검토자가 에이전트 출력을 수정할 때마다, 해당 수정 내용은 다음 버전의 스타일 또는 사전에 반영됩니다. 시간이 지남에 따라 초안과 최종 결과 사이의 차이가 줄어들고, 검토 단계도 더 빨라집니다.

이것은 Glossia 의 핵심 피드백 루프입니다: 생성, 검토, 맥락 개선, 다시 생성. 에이전트는 단순히 지시사항을 따르는 데 그치지 않습니다. 그들은 각 사이클마다 개선되는 맥락으로 일합니다.
