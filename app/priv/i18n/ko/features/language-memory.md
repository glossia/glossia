## 언어 메모리가 무엇인가요?

언어 메모리는 Glossia 에이전트가 귀사의 조직이 어떻게 소통하는지 알려주는 누적된 맥락입니다. 시간의 흐름에 따라 생성되고 정제되는 두 가지 핵심 기본 요소로 구성되어 있습니다:

**보이스** 는 콘텐츠가 들리는 방식을 정의합니다. 톤, 공식성, 대상 범주, 그리고 자유형 지침은 모두 여기에 있습니다. 계정별 기본 보이스를 설정한 후 특정 지역을 위해 개별 필드를 오버라이드할 수 있으므로, 일본어 콘텐츠는 더 공식적이고 영어는 자연스러운 톤으로 유지할 수 있습니다.

**용어집** 은 용어가 무엇을 의미하고 현지화해야 하는지를 정의합니다. 각 항목은 정의와 해당 지역별 번역을 포함합니다. 에이전트가 소스 콘텐츠에서 "작업 공간"을 발견하면, 용어집은 이를 현지화하거나, 음의 방식으로 표기하거나, 그대로 둘지, 그리고 각 대상 언어에서 어떤 단어를 사용해야 하는지 알려줍니다.

보이스와 용어집은 에이전트가 매 실행마다 참조하는 맥락 계층을 형성합니다. 이 계층에 투자할수록 검토는 줄어듭니다.

## 불변 버전 관리

언어 메모리는 추가 전용입니다. 보이스 또는 용어집을 업데이트하면 Glossia 는 기존 항목을 덮어쓰지 않고 새 버전을 생성합니다. 각 버전은 생성자, 일시 및 진화를 설명하는 선택적 변경 주석을 기록합니다.

이렇게 하면 항상 완전한 감사 기록을 보유할 수 있습니다. 버전 3 과 버전 7 을 비교하여 어느 정도 톤이 분기 동안 어떻게 이동했는지 파악할 수 있습니다. 최근 변경 사항으로 인해 일관성이 훼손되었다면 이전 버전으로 되돌아 진행하고 계속하십시오.

버전 관리는 협업의 안전성을 높입니다. 여러 팀원은 충돌을 걱정하지 않고 보이스 변경을 제안할 수 있습니다. 각 변경 사항은 독립적이고 추적 가능한 이벤트이기 때문입니다.

## 언어별 인식 해상도

에이전트가 특정 지역을 위한 워크플로우를 실행하면 Glossia 는 해당 맥락의 언어 메모리를 처리합니다. 기본 보이스 설정에서 시작하여 지역별 오버라이드를 적용합니다. 용어집도 동일합니다: 대상 지역을 위한 현지화된 용어를 가진 항목만 포함됩니다.

이 해결 단계는 에이전트가 항상 가장 관련성 높은 맥락에서 작동한다는 것을 의미합니다. 언어별로 별도의 구성을 유지할 필요가 없습니다. 기본값을 한 번 정의하고 필요한 곳에서 오버라이드하고, 해결 시스템이 나머지 부분을 처리하도록 하십시오.

## 모든 환경에서 활용

언어 메모리는 현지화를 위해 설계되었지만 문자를 생성하는 환경 어디서나 유용합니다. 컨텍스트는 [REST API](/features/rest-api) 와 [MCP 서버](/features/mcp-server) 를 통해 접속할 수 있으므로, 현지화 초대를 넘어선 워크플로우에도 통합할 수 있습니다:

**마케팅 및 소셜 콘텐츠** -- 조직의 보이스를 콘텐츠 에이전트에 불러와서 소셜 미디어 게시물, 이메일 캠페인 또는 랜딩 페이지 콘텐츠의 초안을 작성합니다. 용어집은 브랜드 용어의 일관성을 유지하고 보이스 설정은 브랜드 톤과 일치하도록 보장합니다.

**문서화** -- 언어 메모리를 문서 파이프라인에 주입하여 기술 작문이 나머지 콘텐츠와 동일한 스타일 규칙을 따르도록 합니다. 용어집 항목은 문서, 도움말 및 제품 내 콘텐츠 간의 일관성 저하를 방지합니다.

**코드 검토** -- 귀사의 보이스와 용어집을 기준으로 풀 리퀘스트 콘텐츠 (오류 메시지, UI 레이블, 온보딩 텍스트) 를 검토하는 에이전트를 구축하십시오. 배송 전에 일관성 문제를 표시하십시오.

**사용자 지정 에이전트** -- 어디서나 MCP 호환 클라이언트는 언어 메모리를 읽을 수 있고 작성할 수 있습니다. 코딩 어시스턴트에게 "새 제품명으로 용어집 업데이트" 또는 "독일 지역 보이스 톤을 전문적으로 설정"을 요청하면 그 의도를 적절한 API 호출로 변환합니다.

## 점진적 정련

언어 메모리는 사용에 따라 발전합니다. 심사자가 에이전트 출력을 수정할 때마다 그 수정은 다음 버전의 보이스 또는 용어집으로 피드백됩니다. 시간이 흐르며 초안과 최종 결과 사이의 격차는 좁아지고 검토 단계는 빨라집니다.

이것은 Glossia 의 핵심 피드백 루프입니다: 생성, 검토, 맥락 정제, 다시 생성. 에이전트는 단순히 지시사항만 따르지 않습니다. 각 주기마다 개선되는 맥락과 함께 작업합니다.
