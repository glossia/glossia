## 언어 메모리란 무엇인가요?

언어 메모리는 Glossia 에이전트가 귀사의 조직이 어떻게 소통하는지를 알려주는 누적된 컨텍스트입니다. 이는 시간을 통해 생성하고 정제하는 두 가지 핵심 요소로 구성됩니다:

**어조** 콘텐츠가 어떻게 들릴지 정의합니다. 어조, 격식, 대상 청중, 그리고 자유형 가이드라인은 모두 이곳에 있습니다. 계정의 기본 어조를 설정하고 개별 로케일의 특정 필드를 덮어쓸 수 있으므로, 일본어 텍스트는 더 격식 있고 영어는 대화체로 유지될 수 있습니다.

**용어** 용어의 의미와 현지화 방법을 정의합니다. 각 항목은 정의와 로케일별 번역을 포함합니다. 에이전트가 소스 콘텐츠에서 "workspace"를 발견했을 때 용어는 이를 현지화할지, 음역을 표기할지, 아니면 그대로 유지할지, 그리고 각 대상 언어에서 정확히 어떤 단어를 사용할지 지시합니다.

어조와 용어는 에이전트가 각 실행마다 참조하는 컨텍스트 레이어를 형성합니다. 이 레이어에 투자할수록 출력물의 검토가 덜 필요합니다.

## 불변 버전 관리

언어 기억은 추가만 가능합니다. 스타일이나 용어를 업데이트할 때 Glossia 는 기존 버전을 덮어쓰지 않고 새로운 버전을 생성합니다. 각 버전은 생성자, 생성 시점 및 진화 내용을 설명하는 선택적 변경 메모를 기록합니다.

이를 통해 항상 완전한 감사 이력을 보유할 수 있습니다. 4 분기에 걸쳐 스타일이 어떻게 변화했는지 이해하려면 버전 3 과 버전 7 과 비교할 수 있습니다. 최근 변경 사항으로 일관성이 깨졌다면 이전 버전으로 되돌리시고 계속 진행하세요.

버전화 또한 협업을 더 안전하게 만듭니다. 여러 팀 구성원은 충돌을 걱정하지 않고 스타일 변경을 제안할 수 있으며, 각 변경은 독립적이고 추적 가능한 이벤트이기 때문입니다.

## Locale 기반 해결

에이전트가 특정 Locale 을 위한 워크플로우를 실행할 때 Glossia 는 해당 컨텍스트의 언어 기억을 해결합니다. 기본 스타일 설정을 기준으로 하고, 그 위에 Locale 특화된 오버라이드를 적용합니다. 용례 역시 동일합니다: 대상 Locale 에 현지화된 용어를 담은 항목만 포함됩니다.

이 해결 단계는 에이전트가 항상 가장 관련성 높은 컨텍스트에서 작업함을 의미합니다. 언어별로 별도의 구성을 유지할 필요는 없습니다. 기본값을 한 번 정의하고, 중요한 부분만 오버라이드 한 후 나머지는 해결 시스템이 처리합니다.

## 어디에서든 사용하세요

언어 기억은 현지화를 위해 설계되었지만, 텍스트를 생성하는 모든 곳에서 유용합니다. 컨텍스트는 다음을 통해 접근 가능합니다. [REST API](/features/rest-api) 및 [MCP 서버](/features/mcp-server), 현지화를 넘어 워크플로우에 통합할 수 있습니다:

**마케팅 및 소셜 콘텐츠** -- 조직의 브랜드 목소리를 콘텐츠 에이전트에 적용하여 소셜 미디어 게시물, 이메일 캠페인, 랜딩 페이지 콘텐츠를 작성합니다. 용어는 브랜드 용어의 일관성을 유지하고, 목소리 설정은 브랜드 톤과 맞도록 보장합니다.

**문서** -- 문서 파이프라인에 언어 정보를 입력하여 기술 작문이 전체 콘텐츠와 동일한 스타일 규칙을 따르도록 합니다. 용어 항목은 문서, 도움말, 제품 내 텍스트 전반에 걸쳐 일관성을 유지합니다.

**코드 검토** -- 당신의 목소리와 용어를 기준으로 오류 메시지, UI 레이블, 온보딩 텍스트와 같은 Pull 요청 텍스트를 검토하는 에이전트를 구축하세요. 출시기 전에 일관성 문제를 표시하세요.

**커스텀 에이전트** -- 어떤 MCP 호환 클라이언트도 언어 메모리를 읽거나 작성할 수 있습니다. 코딩 보조에게 "새로운 제품명으로 용어를 업데이트하세요" 또는 "독일 로케일의 목소리 톤을 전문적인 것으로 설정하세요"라고 요청하면, 의도를 올바른 API 호출로 변환합니다.

## 점진적 개선

언어 메모리는 사용 빈도가 높아질수록 개선됩니다. 검토자가 에이전트의 출력을 수정할 때마다, 해당 수정이 다음 버전의 목소리나 용어에 반영됩니다. 시간이 지남에 따라 초안과 최종 결과 사이에는 격차가 줄어들고, 검토 단계도 더 빨라집니다.

이것이 Glossia 의 핵심 피드백 루프입니다: 생성, 검토, 맥락 정제, 다시 생성. 에이전트는 지시사항을 단순히 따르는 것이 아닙니다. 그들은 매 사이클마다 개선되는 맥락과 함께 작동합니다.
