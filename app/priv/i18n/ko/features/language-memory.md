## 언어 메모리가 무엇인가요?

언어 메모리는 조직의 소통 방식을 에이전트에게 알려주는 누적 된 컨텍스트입니다. 이는 시간이 지나면서 생성되고 개선되는 두 가지 핵심 원소로 구성되어 있습니다:

**음성** 이 콘텐츠가 어떠해야 하는지를 정의합니다. 톤, 격식, 대상 독자 및 자유형 가이드라인이 모두 여기에 있습니다. 계정을 위한 기본 음성을 설정한 후 개별 로케일에 대해 특정 필드를 설정하여 override 하며, 일본어 카피는 더 격식 있는 톤으로, 영어는 대화 형으로 유지할 수 있습니다.

**사전** 이 용어의 의미와 어떻게 로컬라이즈 해야 하는지를 정의합니다. 각 항목은 정의와 로케일별 번역을 포함합니다. 에이전트가 소스 콘텐츠에서 "workspace"를 찾을 때, 사전을 통해 이를 로컬라이즈할지, 음차할지, 아니면 그대로 둘지 정하며 각 대상 언어마다 사용해야 할 정확한 단어를 지정합니다.

음성과 사전은 에이전트가 각 실행마다 참조하는 컨텍스트 레이어를 형성합니다. 이 레이어에 투자할수록 리뷰가 필요한 출력물은 줄어듭니다.

## 불변 버전 관리

언어 메모리는 오직 추가만 가능합니다. 음성이나 사전 을 업데이트할 때 Glossia 는 기존 것을 덮어 쓰지 않고 새 버전을 생성합니다. 각 버전은 생성 자, 생성 시간, 그리고 변경 사항을 설명하는 선택적 변경 노트를 기록합니다.

이는 항상 완전한 감사 추적이 가능 함을 의미합니다. 4 분기 동안 톨 이 어떻게 이동했는지 이해하기 위해 버전 3 과 버전 7 을 비교할 수 있습니다. 최근 변경 사항 이 일관성 문제를 발생시켰다면 이전 버전 으로 롤백 하고 계속 진행하세요.

버전 관리는 또한 더 안전한 협업을 가능하게 합니다. 여러 팀 구성원이 충돌 걱정 없이 음성 변경 사항을 제안할 수 있습니다. 각 변경 사항은 독립적이며 추적 가능한 이벤트이기 때문입니다.

## 로케일 인식 처리

에이전트가 특정 로케일을 위한 워크플로우 를 실행하면 Glossia 는 해당 컨텍스트에 대한 언어 메모리를 해결합니다. 기본 음성 설정 에서 시작하여 로케일별 오버라이드를 위에서 적용합니다. 사전도 마찬가지입니다: 대상 로케일 을 위한 로컬화된 용어가 포함된 항목 만 포함됩니다.

이 해결 단계를 통해 에이전트 가 항상 가장 관련성 높은 컨텍스트 를 사용한다는 것을 의미 합니다. 언어별 별도 구성을 유지할 필요가 없습니다. 기본값을 한 번 정의하고 필요한 곳에서 오버라이드 하며, 나머지 부분 은 해결 시스템 이 처리하게 하세요.

## 어디에나 활용

언어 메모리는 로컬라이제이션을 위해 설계되었지만, 텍스트를 생성하는 모든 곳에서 유용합니다. 컨텍스트는 [REST API](/features/rest-api) 와 [MCP 서버](/features/mcp-server) 를 통해 접근 가능하므로 로컬라이제이션 을 넘어선 워크플로우에 통합할 수 있습니다:

**마케팅 및 소셜 콘텐츠** -- 조직의 음성을 콘텐츠 에이전트에 적용하여 소셜 미디어 게시물, 이메일 캠페인, 또는 랜딩 페이지 카피를 작성하게 하세요. 사전은 브랜드 용어를 일관되게 유지하며 음성 설정은 톤 이 브랜드와 일치하도록 보장합니다.

**문서화** -- 언어 메모리를 문서화 파이프라인 에 제공하여 기술 작성이 기존 콘텐츠와 동일한 스타일 규칙을 따르도록 하세요. 사전 항목 은 문서, 도움말 기사 및 제품 내 카피 간 이동을 방지합니다.

**코드 검토** -- 소문 요청 카피 (오류 메시지, UI 레이블, 온보딩 텍스트) 를 음성 및 사본과 비교 검토 하는 에이전트를 구축하세요. 배포 전에 일관성 문제를 표시하세요.

**사용자 지정 에이전트** -- 임의 MCP 호환 클라이언트는 언어 메모리를 읽거나 작성할 수 있습니다. 코딩 어시스턴트 에게 "새 제품 명을 위한 사전 업데이트" 나 "독일 로케일을 위한 전문가 음성 톤 설정"을 요청하면, 이는 의도를 올바른 API 호출 로 변환합니다.

## 점진적 개선

사용 이 많아 질수록 언어 메모리 가 개선됩니다. 리뷰어가 에이전트 출력을 맞을 때마다, 그 수정 사항 은 음성 또는 사전 을 다음 버전 으로 피드백 합니다. 시간이 지남에 따라 초안 과 최종 출력 사이 의 간극 은 줄어들며 리뷰 단계 는 더 빨라집니다.

이것은 Glossia 의 핵심 피드백 루프입니다: 생성하고, 검토하고, 컨텍스트를 정제하고 다시 생성하세요. 에이전트는 단순히 지시사항만 따르는 것이 아닙니다. 각 사이클마다 향상 되는 컨텍스트 와 함께 작업합니다.
