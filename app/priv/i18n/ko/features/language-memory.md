## 언어 메모리는 무엇인가요?

언어 메모리는 귀사의 조직이 소통하는 방식을 알려주는 Glossia 에이전트의 누적된 컨텍스트입니다. 이는 시간이 지남에 따라 작성하고 정제하는 두 가지 핵심 구성 요소로 이루어집니다:

**목소리** 콘텐츠가 어떻게 표현되어야 하는지를 정의합니다. 톤, 격식, 대상 독자 및 자유형 가이드라인 모두 여기에 포함됩니다. 계정의 기본 목소리를 설정한 후 개별 로케일에 대해 특정 필드를 덮어씌울 수 있어 일본어 콘텐츠는 더 격식 있고 영어 콘텐츠는 대화체로 남길 수 있습니다.

**용어** 단어의 의미와 현지화 방식을 정의합니다. 각 항목에는 정의와 로케일별 번역이 포함되어 있습니다. 에이전트가 소스 콘텐츠에서 "workspace" 를 마주칠 때, 용어는 현지화, 음역, 혹은 그대로 두어야 할지 결정하며 각 대상 언어마다 정확히 어떤 단어를 사용해야 하는지 안내합니다.

목소리와 용어가 합쳐져 에이전트가 매 실행마다 참조하는 컨텍스트 레이어를 형성합니다. 여기에 더 투자할수록 결과에 필요한 검토는 줄어듭니다.

## 불변 버전 관리

언어 메모리는 오직 추가만 가능합니다. 어조 나 용어를 업데이트할 때, Glossia 는 기존 데이터를 덮어쓰지 않고 새 버전을 생성합니다. 모든 버전은 작성자, 작성 시간, 그리고 진화의 내용을 설명하는 선택적 변경 주석을 기록합니다.

이것은 항상 완전한 감사 흔적이 있다는 뜻입니다. 버전 3 과 버전 7 을 비교하여 분기 동안 어조가 어떻게 변화했는지 이해할 수 있습니다. 만약 최근 변경이 일관성 문제를 초래했다면 이전 버전으로 되돌리고 작업을 계속할 수 있습니다.

버전 관리 또한 협업을 더 안전하게 만듭니다. 여러 팀 멤버는 충돌을 걱정하지 않고 어조 변경을 제안할 수 있으며, 각 변경 사항은 독립적이고 추적 가능한 이벤트이기 때문입니다.

## 지역 기반 해결

에이전트가 특정 지역을 위한 워크플로우를 실행하면, Glossia 는 해당 컨텍스트의 언어 메모리를 해결합니다. 기본 어조 설정으로 시작하여 그 위에 지역별 오버라이드를 적용합니다. 용어의 경우도 마찬가지이며, 목표 지역을 위해 현지화된 용어를 가진 항목만 포함됩니다.

이 해결 단계는 에이전트가 항상 가장 관련성 높은 컨텍스트로 작업함을 의미합니다. 언어별 별도 구성을 유지할 필요가 없습니다. 기본값을 한 번 정의하고 중요한 부분만 오버라이드하고, 나머지 작업은 해결 시스템에 맡기세요.

## 어디서나 사용하세요

언어 메모리는 현지화를 위해 설계되었지만, 텍스트를 생성하는 곳이라면 어디서나 유용합니다. 컨텍스트는 다음을 통해 액세스 가능합니다. [REST API](/features/rest-api) 및 [MCP 서버](/features/mcp-server), 로컬라이제이션을 넘어선 워크플로우에 이를 통합할 수 있습니다:

**마케팅 및 소셜 콘텐츠** -- 조직의 브랜드 톤을 콘텐츠 에이전트로 활용하여 소셜 미디어 게시물, 이메일 캠페인, 또는 랜딩 페이지 카피를 작성합니다. 용어집은 브랜드 용어의 일관성을 유지하며, 톤 설정은 브랜드와 일치하는 어조를 보장합니다.

**문서** -- 언어 메모리를 문서 파이프라인에 제공하여 기술 문서 작성이 나머지 콘텐츠와 동일한 스타일 규칙을 따르도록 합니다. 용어 항목은 문서, 도움말 기사, 및 제품 내 카피에서 일관성 저하를 방지합니다.

**코드 검토** -- 당신의 어조와 용어집에 맞춰 풀 리퀘스트 카피 (에러 메시지, UI 레이블, 온보딩 텍스트) 를 검토하는 에이제를 구축하세요. 배포 전 일관성 문제를 표시하세요.

**사용자 지정 에이제** -- MCP 호환 클라이언트는 언어 메모리를 읽거나 쓸 수 있습니다. 코딩 어시스턴트에게 "새 제품명으로 용어를 업데이트"하거나 "독일 로케일의 어조 톤을 전문적으로 설정"하도록 요청하면 의도를 올바른 API 호출로 변환합니다.

## 점진적 개선

사용함에 따라 언어 메모리가 향상됩니다. 리뷰어가 에이제 출력을 수정할 때마다 그 수정은 다음 버전의 어조나 용어집에 반영됩니다. 시간이 지나면서 초안과 최종 출력 간의 격차가 줄어들며 검토 단계도 빨라집니다.

이를 Glossia 의 핵심에 있는 피드백 루프입니다: 생성, 검토, 컨텍스트 다듬기, 다시 생성. 에이전트는 단순한 지시를 따르는 것에 그치지 않습니다. 그들은 매 사이클마다 개선되는 컨텍스트와 함께 일합니다.
