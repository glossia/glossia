## 언어 메모리가 무엇인가요?

언어 메모리는 조직의 소통 방식을 Glossia 에이전트에게 안내하는 축적된 컨텍스트입니다. 이는 시간이 지남에 따라 만들고 다듬는 두 가지 핵심 기본 요소로 이루어져 있습니다:

**목소리** 콘텐츠가 어떻게 표현되어야 하는지를 정의합니다. 톤, 격식도, 대상 청중, 그리고 자유형 가이드라인이 모두 여기에 있습니다. 계정 전체에 기본 목소리를 설정하고 개별 로케일에 특정 필드를 덮어씌울 수 있으므로 일본어 원본은 더 격식 있고 영어 원본은 대화체로 유지할 수 있습니다.

**용어** 용어는 용어의 의미와 현지화 방식을 정의합니다. 각 항목에는 정의와 로케일별 번역이 포함됩니다. 에이전트가 소스 콘텐츠에서 "workspace"를 발견할 때, 용어는 이를 현지화할지, 음역할지, 아니면 그대로 둘지, 그리고 각 대상 언어에서 정확히 어떤 단어를 사용해야 하는지 결정합니다.

목소리와 용어는 에이전트가 각 실행에서 참조하는 컨텍스트 계층을 형성합니다. 이 계층에 투자할수록, 출력 결과에 대한 검토가 덜 필요합니다.

## 불변 버전 관리

언어 메모리는 추가 전용입니다. 보이스나 용어를 업데이트할 경우, Glossia 는 기존 데이터를 덮어쓰지 않고 새 버전을 생성합니다. 모든 버전은 작성자, 생성 시간, 그리고 변화 내용을 설명하는 선택적 변경 주석을 기록합니다.

이는 언제나 완벽한 감사 추적을 의미합니다. 분기 동안 톤이 어떻게 변했는지 이해하기 위해 3 번 버전과 7 번 버전을 비교할 수 있습니다. 최근 변경 사항이 일관성 문제를 일으켰다면 이전 버전으로 되돌리고 진행하세요.

버전 관리 또한 협업을 안전하게 만듭니다. 여러 팀원이 충돌을 걱정하지 않고 보이스 변경을 제안할 수 있는데, 각 변경 사항은 개별적이고 추적 가능한 사건이기 때문입니다.

## 로케일 인지 처리

특정 로케일용 워크플로우가 실행되면, Glossia 는 해당 컨텍스트의 언어 메모리를 처리합니다. 기본 보이스 설정에서 시작하여 로케일별 오버라이드를 그 위에 적용합니다. 용어도 동일합니다: 대상 로케일에 현지화된 용어가 있는 항목만 포함됩니다.

이 처리 단계는 에이전트가 항상 가장 관련성 높은 컨텍스트로 작동한다는 뜻입니다. 언어별로 별도의 구성을 유지할 필요가 없습니다. 기본값은 한 번 정의하고 중요한 부분만 재정의한 뒤, 해결 시스템이 나머지를 처리하도록 하세요.

## 모든 곳에서 사용하세요.

언어 메모리는 현지화를 위해 설계되었지만, 텍스트를 생성하는 곳이라면 어디든 유용합니다. 컨텍스트는 ... 를 통해 접근 가능합니다. [REST API](/features/rest-api) 및 [MCP 서버](/features/mcp-server), 현지화를 넘어 워크플로우에 통합할 수 있습니다:

**마케팅 및 소셜 콘텐츠** -- 회사의 브랜드 목소리를 콘텐츠 에이전트에 적용하여 소셜 미디어 게시물, 이메일 캠페인, 또는 랜딩 페이지 문구를 작성합니다. 용어는 브랜드 용어를 일관되게 유지하며, 목소리 설정은 브랜드 톤과 일치되도록 보장합니다.

**문서** -- 문서 파이프라인에 언어 기억을 입력하여 기술 문서 작성물이 기존 콘텐츠와 동일한 스타일 규칙을 따르도록 합니다. 용어 항목은 문서, 도움말, 제품 내 텍스트 전반에 걸쳐 편차를 방지합니다.

**코드 리뷰** -- 당신의 문체와 용어를 기준으로 풀 리퀘스트 텍스트 (오류 메시지, UI 레이블, 온보딩 텍스트) 를 검토하는 에이전트를 구축하세요. 출시에 앞서 일관성 문제를 표시하세요.

**커스텀 에이전트** -- 어떤 MCP 호환 클라이언트든 언어 메모리를 읽고 쓸 수 있습니다. 코딩 어시스턴트에게 "새 제품 이름으로 용어를 업데이트하세요" 또는 "독일 로케일의 전문적인 문체 톤으로 설정하세요"라고 요청하면 당신의 의도를 올바른 API 호출로 변환합니다.

## 점진적 개선

언어 메모리는 사용이 늘어남에 따라 개선됩니다. 검토자가 에이전트 출력을 수정할 때마다 그 수정 내용은 다음 버전의 문체나 용어로 다시 반영됩니다. 시간이 지남에 따라 초기 초안과 최종 출력 사이의 차이는 줄어들고 검토 단계를 빨라집니다.

이는 Glossia 의 핵심에 있는 피드백 루프입니다: 생성, 검토, 맥락 개선, 다시 생성. 에이전트는 단순히 지시사항만 따르는 것이 아닙니다. 매 사이클마다 향상되는 맥락과 함께 작업합니다.
