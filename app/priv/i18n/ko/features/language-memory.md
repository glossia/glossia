## 언어 메모리가 무엇인가요?

언어 메모리는 조직의 소통 방식을 Glossia 에이전트에게 알려주는 누적 컨텍스트입니다. 이는 시간의 경과에 따라 구축하고 정제해 나가는 두 가지 핵심 원리로 구성되어 있습니다:

**목소리** 콘텐츠가 어떤 소리를 내야 하는지를 정의합니다. 톤, 격식, 대상 청중, 그리고 자유형 가이드라인은 모두 여기에 있습니다. 계정의 기본 목소리를 설정한 후 개별 로케일에 특정 필드를 오버라이드하여 설정할 수 있습니다. 일본어 텍스트는 더 격식 있고 영어는 대화형일 수 있습니다.

**용어** 용어의 의미와 현지화 방법을 정의합니다. 각 항목에는 정의와 로케일별 번역이 포함됩니다. 에이전트가 소스 콘텐츠에서 "workspace"를 만났을 때, 용어는 이를 현지화할지 음차할지 그대로 둬야 하며 각 표적 언어에 사용할 정확한 단어를 알려줍니다.

목소리와 용어는 합쳐져 에이전트가 매번 참조하는 컨텍스트 레이어를 형성합니다. 이 레이어에 투자할수록 결과물에 필요한 검토는 줄어듭니다.

## 불변 버전 관리

언어 기억은 오직 추가만 가능합니다. 목소리나 전문 용어를 업데이트할 때 Glossia 는 기존 내역을 덮어쓰지 않고 새 버전을 생성합니다. 모든 버전은 생성자, 생성 시점 및 변화를 이끈 선택적 변경 주석을 기록합니다.

따라서 항상 완비된 감사 내역을 유지할 수 있습니다. 3 번 버전과 7 번 버전을 비교하여 분기 동안 어조가 어떻게 이동했는지 이해할 수 있습니다. 최근 변경으로 인한 불일치가 발생하면 이전 버전으로 돌려서 작업을 계속하세요.

버전 관리는 또한 협업을 더 안전하게 만듭니다. 여러 팀 구성원은 충돌을 염려하지 않고 목소리 변경을 제안할 수 있습니다. 각 변경사항이 개별적이고 추적 가능한 이벤트로 기록되기 때문입니다.

## Locale 기반 해결

에이전트가 특정 로케일을 위한 워크플로우를 실행하면 Glossia 는 해당 컨텍스트의 언어 기억을 처리합니다. 기본 목소리 설정으로 시작하고 로케일별 오버라이드를 위에 적용합니다. 전문 용어의 경우 또한 동일합니다. 목표 로케일에서만 현지화된 용어 항목이 포함됩니다.

이 해결 단계는 에이전트가 항상 가장 관련성 높은 컨텍스트로 작동함을 의미합니다. 언어별로 별도 구성을 유지할 필요가 없습니다. 기본값을 한 번 정의하고 중요한 곳에서 오버라이드리면 해결 시스템이 나머지를 처리합니다.

## 어디서나 사용하세요

언어 기억은 현지화를 위해 설계되었지만, 텍스트를 생성하는 곳이라면 어디나 유용합니다. 컨텍스트는 해당 ... 를 통해 접근 가능하기 때문입니다 [REST API](/features/rest-api) 및 [MCP 서버](/features/mcp-server), 로컬라이제이션을 넘어 워크플로우에도 통합할 수 있습니다:

**마케팅 및 소셜 콘텐츠** -- 조직의 목소리를 콘텐츠 에이전트에 반영하여 소셜 미디어 게시물, 이메일 캠페인 또는 랜딩 페이지 문구를 작성하게 합니다. 용어는 브랜드 용어의 일관성을 유지하며 목소리 설정은 어조가 브랜드와 일치하도록 보장합니다.

**문서** -- 문서 파이프라인에 언어 기억을 제공하여 기술 작성이 나머지 콘텐츠와 동일한 스타일 규칙을 따르도록 합니다. 용어 항목은 문서, 도움말 자료 및 제품 내 문구 전반에 걸쳐 일관성 저하를 방지합니다.

**코드 검토** -- 목소리와 용어에 맞춰 풀 리퀘스트 문구를 검토하는 에이전트를 구축하세요. (오류 메시지, UI 라벨, 온보딩 텍스트). 배포 전 일관성 문제를 표시하세요.

**사용자 정의 에이전트** -- MCP 호환 클라이언트는 언어 메모리를 읽고 작성할 수 있습니다. 코드 어시스턴트에 "새로운 제품 이름으로 용어 업데이트" 또는 "독일 로케일을 위한 전문적인 목소리 톤 설정"을 요청하면 의도를 올바른 API 호출로 변환합니다.

## 점진적 개선

언어 메모리는 사용에 따라 개선됩니다. 검토자가 에이전트 출력물을 수정할 때마다, 그 수정은 목소리나 용어의 다음 버전으로 반영됩니다. 시간이 지나면 초안과 최종 결과물 간의 격차가 줄어들고 검토 단계가 빨라집니다.

이는 Glossia 의 핵심에 있는 피드백 루프입니다: 생성, 검토, 컨텍스트 개선, 다시 생성. 에이전트는 단순히 지시를 따르는 것이 아닙니다. 매 사이클마다 개선되는 컨텍스트로 작업합니다.
