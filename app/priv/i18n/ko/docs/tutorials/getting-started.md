%{title: "시작하기", summary: "저장소를 연결하고 첫 로컬라이제이션 설정을 준비하세요.", category: "튜토리얼", order: 1}
---
이 튜토리얼은 GitHub 저장소를 Glossia 와 연결하고 첫 번째 대상 언어를 선택하며, 팀이 검토할 현지화 기준세를 준비합니다.

## 시작하시기 전에

필요한 항목:

- 설정과 프로젝트를 관리할 수 있는 Glossia 계정
- Glossia GitHub 앱에 읽기 및 업데이트 권한을 부여할 수 있는 GitHub 저장소
- 공급자 키를 위한 지원되는 [대규모 언어 모델](https://en.wikipedia.org/wiki/Large_language_model).

## 1\. 계정 모델 설정

열기 **설정**, 그런 다음 **모델**, 그리고 선택 **새 모델**.

1. 모델에 짧은 핸들을 지정하세요. 예: `translation-default`.
2. 모델 선택기를 열고 제공자 또는 모델 이름의 일부를 입력하여 목록을 필터링하세요.
3. Glossia 가 사용하도록 모델을 선택하세요.
4. 제공자 키를 입력하고 모델을 저장하세요.

핸들은 제공자 자격 증명을 소스 코드 관리에 포함하지 않고 리포지토리가 이 계정 모델을 참조할 수 있게 합니다. 자세히 [모델 제공자 구성](/docs/how-to/configure-a-model-provider) 더 자세한 내용을 확인하세요.

## 2\. 프로젝트 시작

이동하여 **프로젝트** 그리고 선택하여 **새 프로젝트**.

Glossia 가 저장소 접근 권한을 요청하면 GitHub 링크를 따라 접속하여 Glossia GitHub App 으로 저장소 접근 권한을 허용하세요. 다시 Glossia 로 돌아온 후 다시 열기 **새 프로젝트** 필요한 경우.

## 3\. 레포지토리 선택

번역하려는 레포지토리를 선택하세요. Glossia 는 현재 계정의 GitHub App 설치를 통해 이용 가능한 레포지토리만 나열합니다.

언어 단계로 계속 진행하세요.

## 4\. 대상 언어 선택

레포지토리의 소스 콘텐츠를 기반으로 생성될 언어 하나 이상을 선택하고 설정을 시작하세요.

## 5\. 설정 진행 상황 확인

Glossia 가 프로젝트를 준비하는 동안 설정 페이지를 열어두세요. 진행 카드는 현재 상태와 최근 활동을 표시하며, 여기에는 레포지토리 준비, 파일 검사, 변경 사항, 검토 및 완료 작업이 포함됩니다.

페이지를 떠났어도 설정 상태를 잃지 않고 프로젝트 개요로 돌아갈 수 있습니다. 설정이 실패할 경우 동일한 카드에서 주의가 필요한 사항을 설명하고 다음 단계를 제공합니다. **설정 재시도**.

## 6\. 결과 검토

설정이 완료되면 프로젝트 개요를 열고 저장소에서 생성된 풀 리퀘스트를 검토하세요. 제안된 기준선은 일반적으로 다음을 포함합니다:

- 루트 `L10N.md` 원본언어, 원본경로 및 대상언어를 포함한 파일입니다.
- 현지화 파일을 로드하기 위해 필요한 가장 작은 애플리케이션 또는 콘텐츠 변경 사항입니다.
- 레포지토리에 이미 제공되던 경량 검증입니다.

일반적인 GitHub 워크플로우를 통해 풀 요청을 검토 및 병합하세요. 향후 번역 실행은 병합된 `L10N.md` 컨텍스트.

프로젝트 개요는 설정용 풀 요청이 병합될 때까지 표시됩니다. 병합 없이 닫힌 경우, 설정 알림 링크에서 다시 열 수 있습니다.
