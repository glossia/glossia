이 튜토리얼은 GitHub 저장소를 Glossia 와 연결하고, 첫 번째 대상 언어를 선택하며, 팀이 검토할 수 있는 현지화 기준을 준비합니다.

## 시작하기 전

다음 사항이 필요합니다:

- 설정과 프로젝트를 관리할 수 있는 Glossia 계정입니다.
- 읽기 및 수정 권한을 Glossia GitHub App 에 부여할 수 있는 GitHub 저장소입니다.
- 지원되는 제공자 키 [대규모 언어 모델](https://en.wikipedia.org/wiki/Large_language_model).

## 1\. 계정 모델을 구성하세요

열고 **설정**, 그런 다음 **모델**, 그리고 선택하세요 **새 모델**.

1. 모델에 짧은 핸들을 지정하세요. 예를 들어 `translation-default`.
2. 모델 선택기를 열고 공급자 또는 모델 이름의 일부를 입력하여 목록을 필터링하세요.
3. Glossia 가 사용할 모델을 선택하세요.
4. 공급자 키를 입력하고 모델을 저장하세요.

핸들은 소스 제어 저장소에 공급자 인증 정보를 포함하지 않으면서도 저장소에서 이 계정 모델을 참조할 수 있게 합니다. 다음을 [모델 공급자 설정](/docs/how-to/configure-a-model-provider) 를 확인하여 자세한 내용입니다.

## 2\. 프로젝트 시작

돌아가 **프로젝트로** 선택 **새 프로젝트**.

Glossia 가 저장소 접근 권한을 요청하면 GitHub 링크를 따라 이동하여 Glossia GitHub 앱의 저장소 접근 권한을 부여하세요. Glossia 로 돌아온 후 다시 열기 **새 프로젝트** 필요한 경우.

## 3\. 저장소 선택

현지화하려는 저장소를 선택하세요. Glossia 는 현재 계정의 GitHub App 설치로 접근 가능한 저장소만 나열합니다.

언어 단계로 이동하세요.

## 4\. 대상 언어 선택

저장소의 소스 콘텐츠에서 생성될 언어 하나 이상을 선택한 후 설정을 시작하세요.

## 5\. 설정 진행 상황 확인

Glossia 가 프로젝트를 준비하는 동안 설정 페이지를 열어 두세요. 진행 카드는 현재 상태와 최근 활동을 보여줍니다. 저장소 준비, 파일 검사, 변경 사항, 검토, 완료 등이 포함됩니다.

설정 상태를 잃지 않고 이 페이지를 떠날 수도 있으며 프로젝트 개요로 돌아갈 수 있습니다. 설정 실패 시 동일한 카드는 주의가 필요한 사항을 설명하고 제공합니다 **설정 재시도**.

## 6\. 결과 검토

설정이 완료되면 프로젝트 개요를 열어 저장소에 생성된 풀 리퀘스트를 검토하세요. 제안된 베이스라인에는 일반적으로 다음이 포함됩니다:

- 루트 `L10N.md` 소스 언어, 소스 경로 및 대상 언어를 포함하는 파일.
- 로컬라이즈된 파일을 로드하기 위해 필요한 최소한의 애플리케이션 또는 콘텐츠 변경 사항.
- 이미 리포지토리에 사용 가능한 경량 유효 검증입니다.

평소 사용하는 GitHub 워크플로우를 통해 풀 요청을 검토하고 병합하세요. 이후의 번역 실행은 병합된 `L10N.md` 컨텍스트입니다.

프로젝트 개요는 병합될 때까지 셋업 풀 요청을 표시합니다. 병합되지 않고 닫힌 경우, 셋업 알림의 링크에서 다시 여세요.
