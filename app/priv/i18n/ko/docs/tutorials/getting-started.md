이 튜토리얼은 GitHub 저장소를 Glossia 와 연결하고 첫 번째 대상 언어를 선택하며 팀이 검토할 로컬라이제이션 기준을 준비합니다.

## 작업 시작 전

필수 항목:

- 설정과 프로젝트를 관리할 수 있는 Glossia 계정입니다.
- Glossia GitHub App 에 읽기와 업데이트 권한을 부여할 수 있는 GitHub 저장소입니다.
- 지원하는 [대규모 언어 모델](https://en.wikipedia.org/wiki/Large_language_model).

## 1\. 계정 모델 설정

열기 **설정**, 그 다음 **모델**, 그리고 선택 **새 모델**.

1. 모델에 짧은 핸들을 지정하세요. 예를 들어 `translation-default`.
2. 모델 선택기를 열고 제공자 또는 모델 이름의 일부를 입력하여 목록을 필터링하세요.
3. Glossia 가 사용할 모델을 선택하세요.
4. 제공자 키를 입력하고 모델을 저장하세요.

핸들은 저장소에서 소스 코드 관리에 제공자 자격 증명 없이 이 계정 모델을 참조할 수 있게 합니다. 자세히 [모델 제공자 구성](/docs/how-to/configure-a-model-provider) 자세한 내용을 확인하세요.

## 2\. 프로젝트 시작하기

돌아가서 **프로젝트** 선택하여 **새 프로젝트**.

Glossia 가 저장소 접근을 요청하면 GitHub 링크로 이동하여 Glossia GitHub App 에 저장소 접근 권한을 부여하세요. Glossia 로 돌아온 후, 다시 여세요. **새 프로젝트** 필요하면.

## 3\. 로컬라이즈할 레포지토리 선택

로컬라이즈할 레포지토리를 선택하세요. Glossia 는 현재 계정의 GitHub App 설치를 통해 사용 가능한 레포지토리만 나열합니다.

언어 단계로 계속하세요.

## 4\. 표적 언어 선택

레포지토리의 소스 콘텐츠에서 생성되어야 할 표적 언어를 하나 이상 선택하고 설정을 시작하세요.

## 5\. 설정 진행 상황 확인

Glossia 가 프로젝트를 준비하는 동안 설정 페이지를 열어두세요. 진행 상태 카드는 현재 상태와 최근 활동을 표시하며, 레포지토리 준비, 파일 검사, 변경 사항, 검토 및 완료 사항이 포함됩니다.

페이지를 떠서 프로젝트 개요 화면으로 돌아갈 수 있으며 설정 상태는 유지됩니다. 설정에 실패할 경우 동일한 카드는 다음 조치를 설명하고 **설치 다시 시도**.

## 6\. 결과 검토

설치가 완료되면 프로젝트 개요를 열고 해당 저장소에 생성된 Pull Request 를 검토하세요. 제안된 기준에는 일반적으로 다음이 포함되어 있습니다:

- 루트 `L10N.md` 소스 언어, 소스 경로 및 대상 언어가 포함된 파일입니다.
- 현지화된 파일을 로드하기 위해 필요한 가장 작은 애플리케이션 또는 콘텐츠 변경 사항입니다.
- 레포지토리에 이미 제공되던 가벼운 검증 항목도 있습니다.

GitHub 의 일반 워크플로우를 통해 풀 리퀘스트를 검토하고 병합하세요. 향후 번역 실행에는 병합된 `L10N.md` 컨텍스트입니다.

프로젝트 개요는 세팅용 풀 리퀘스트가 병합될 때까지 표시됩니다. 병합되지 않고 닫힌 경우, 세팅 안내문의 링크에서 다시 여세요.
