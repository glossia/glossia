%{title: "시작하기", summary: "저장소를 연결하고 첫 번째 현지화 설정을 준비하세요.", category: "튜토리얼", order: 1}
---

이 튜토리얼은 GitHub 저장소를 Glossia에 연결하고 첫 번째 표적 언어를 선택하며 팀의 검토를 위해 현지화 기준을 준비합니다.

## 시작하기 전에

필요한 것:

- 설정과 프로젝트를 관리할 수 있는 Glossia 계정
- Glossia GitHub 앱에 읽기 및 수정 권한을 부여할 수 있는 GitHub 저장소
- 지원되는 [large language model](https://en.wikipedia.org/wiki/Large_language_model)의 제공자 키

## 1. 계정 모델 구성

**설정**을 열고, 그런 다음 **모델**을 선택하고 **새 모델**을 클릭합니다.

1. 모델에 짧은 핸들을 지어가며 `translation-default`를 사용합니다.
2. 모델 선택기를 열고 제공자 또는 모델 이름의 일부를 입력하여 목록을 필터링합니다.
3. Glossia가 사용하려는 모델을 선택합니다.
4. 제공자 키를 입력하고 모델을 저장합니다.

핸들은 제공자 인증 정보를 소스 컨트롤에 포함하지 않고 저장소를 이 계정 모델에 참조할 수 있게 합니다. 더 자세한 내용은 [모델 제공자 구성](/docs/how-to/configure-a-model-provider)을 참조하세요.

## 2. 프로젝트 시작

**프로젝트**로 돌아가 **새 프로젝트**를 선택합니다.

Glossia가 저장소 접근을 요구할 경우 GitHub 링크를 따라 접속하고 해당 저장소에게 Glossia GitHub 앱 접근 권한을 부여하세요. Glossia로 복귀한 후 필요에 따라 **새 프로젝트**를 다시 열어주세요.

## 3. 저장소 선택

현지화하려는 저장소를 선택하세요. Glossia는 현재 계정의 GitHub 앱 설치로 사용 가능한 저장소 목록만 표시합니다.

## 4. 프로젝트 설정 방법 선택

**자동 설정**을 선택하여 Glossia가 저장소를 검사하고 풀 리퀘스트를 통해 현지화 구성을 제안하도록 합니다. 이 튜토리얼은 해당 경로로 진행합니다.

저장소에 `L10N.md` 파일이 이미 존재하거나 직접 작성하시기를 원하시면 **수동 구성**을 선택하세요. Glossia는 즉시 프로젝트를 생성하며 나머지 단계는 생략할 수 있습니다. 각 모드 수행 내용은 [프로젝트 설정](/docs/reference/project-setup)에서 확인하세요.

## 5. 표적 언어 선택

저장소의 소스 내용에서 생성될 하나 이상의 언어를 선택한 후 설정을 시작합니다.

## 6. 설정 진행 상황 확인

Glossia가 프로젝트를 준비하는 동안 설정 페이지를 열어두세요. 진행 카드는 현재 상태와 최근 활동, incluyendo 저장소 준비, 파일 검사, 변경 사항, 검토 및 완성을 표시합니다.

페이지를 떠나도 설정 상태는 유지되며 프로젝트 개요로 돌아올 수 있습니다. 설정이 실패할 경우 실패 통지를 확인하세요. 일시적인 프로젝트를 Glossia가 삭제하고 선결 조건을 해결한 후 **New project**Envelope再通过을 클릭하여 다시 시작하세요. 자세한 내용은 [Retry project setup](/docs/how-to/retry-project-setup)를 참조하세요.

## 7. 결과 검토

설정이 완료되면 프로젝트 개요를 열고 해당 저장소를 위한 풀 리퀘스트를 검토하세요. 제안된 기준은 일반적으로 다음을 포함합니다:

- 원어, 소스 경로, 표적 언어가 있는 루트 `L10N.md` 파일.
- 현지화된 파일을 로드하기 위한 최소 애플리케이션 또는 콘텐츠 변경 사항.
- 저장소에 이미 제공되던 경량 검증 사항.

일반 GitHub 워크플로우를 통해 풀 리퀘스트를 검토하고 병합하세요. 향후 번역 실행은 병합된 `L10N.md` 컨텍스트를 사용합니다.

프로젝트 개요는 병합 작업이 완료될 때까지 설정용 풀 리퀘스트를 표시됩니다. 병합 없이 닫힌 경우 설정 통지의 링크에서 다시 열 수 있습니다.
