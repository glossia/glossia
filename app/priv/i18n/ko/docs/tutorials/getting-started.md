이 튜토리얼은 GitHub 저장소를 Glossia 와 연결하고 첫 번째 목표 언어를 선택하며 팀이 검토할 로컬라이제이션 베이스라인을 준비합니다.

## 시작 전

준비물:

- 설정을 관리하고 프로젝트를 관리할 수 있는 Glossia 계정.
- Glossia GitHub App 에 읽기 및 업데이트 권한을 부여할 GitHub 저장소.
- 지원되는 제공업체 키 [대규모 언어 모델](https://en.wikipedia.org/wiki/Large_language_model).

## 1\. 계정 모델 구성

열기 **설정**, 그런 다음 **모델**, 그리고 선택 **새 모델**.

1. 모델에 짧은 별칭을 지정하세요. 다음과 같이 `translation-default`.
2. 모델 선택기를 열고 제공업체 또는 모델 이름의 일부를 입력하여 목록을 필터링하세요.
3. Glossia 가 사용할 모델을 선택하세요.
4. 제공업체 키를 입력하고 모델을 저장하세요.

이 별칭은 저장소에서 이 계정 모델을 참조할 때 제공업체 인증 정보를 소스 코드 관리에 저장하지도록 합니다. 확인하려면 [모델 제공업체 구성](/docs/how-to/configure-a-model-provider) 에 대해 더 자세히 알아보세요.

## 2\. 프로젝트를 시작하세요

되돌아가 **프로젝트** 그리고 선택 **새 프로젝트**.

Glossia 가 저장소 액세스 권한을 요청하는 경우 GitHub 링크를 따르며 Glossia GitHub 앱에 해당 저장소 접근 권한을 부여하세요. Glossia 로 돌아온 후 다시 열어주세요 **새 프로젝트** 필요한 경우.

## 3\. 저장소를 선택하세요.

현지화하고 싶은 저장소를 선택하세요. Glossia 는 현재 계정의 GitHub App 설치를 통해 접근 가능한 저장소만 나열합니다.

## 4\. 프로젝트 구축 방법을 선택하세요.

선택 **자동 설정** Glossia 가 저장소를 검토하고 현지화 구성을 풀 요청으로 제안하게 하려면. 이 튜토리얼은 이 방법을 따릅니다.

저장소가 이미 다음 사항을 가지고 있다면. `L10N.md` 파일을 사용하지 않거나 직접 작성하고 싶다면 선택하세요 **수동 설정** 대신 Glossia 는 프로젝트를 즉시 생성하고 나머지 단계를 생략할 수 있습니다. 확인 [프로젝트 설정](/docs/reference/project-setup) 각 모드가 수행하는 작업을

## 5\. 대상 언어 선택

저장소의 소스 콘텐츠에서 생성될 언어를 하나 이상 선택하고 설정을 시작하십시오

## 6\. 설정 진행 상황 확인

Glossia 가 프로젝트를 준비하는 동안 설정 페이지를 열어 두세요. 진행 카드는 현재 상태와 최근 활동 (레포지토리 준비, 파일 검사, 변경 사항, 점검 및 완료) 을 보여줍니다.

설정 상태를 유지하며 페이지를 나가도 프로젝트 개요로 돌아갈 수 있습니다. 설정 실패 시에는 실패 알림을 확인하세요. Glossia 는 임시 프로젝트를 삭제하므로 필수 조건을 수정하고 다시 시작하기 위해 **새 프로젝트**. 확인 [프로젝트 설정 재시도](/docs/how-to/retry-project-setup).

## 7\. 결과 검토

설정이 완료되면 프로젝트 개요를 열어 저장소에서 생성된 pull request 를 검토하세요. 제안된 기준선은 보통 다음을 포함합니다:

- 루트 `L10N.md` 출처 언어, 출처 경로, 및 대상 언어가 포함된 파일.
- 현지화된 파일을 로드하는 데 필요한 최소한의 애플리케이션 또는 콘텐츠 변경 사항.
- 레포지토리에 이미 존재하던 가벼운 유효성 검사.

GitHub 워크플로우를 통해 풀 리퀘스트를 검토하고 병합하세요. 향후 번역 실행은 병합된 `L10N.md` 컨텍스트를 사용합니다.

프로젝트 개요는 병합될 때까지 설정 풀 리퀘스트를 표시합니다. 병합되지 않고 닫힌 경우, 설정 알림의 링크를 통해 다시 열어주세요.
