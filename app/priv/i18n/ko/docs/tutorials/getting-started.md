이 튜토리얼에서는 GitHub 저장소를 Glossia에 연결하고, 첫 번째 대상 언어를 선택한 후, 팀에서 검토할 현지화 기준선을 준비합니다.

## 시작하기 전에

다음이 필요합니다.

- 설정과 프로젝트를 관리할 수 있는 Glossia 계정
- Glossia GitHub App에 읽기 및 업데이트 권한을 부여할 수 있는 GitHub 저장소
- 지원되는 [대규모 언어 모델](https://en.wikipedia.org/wiki/Large_language_model)의 제공업체 키

## 1. 계정 모델 구성

**설정**을 연 다음 **모델**로 이동하여 **새 모델**을 선택합니다.

1. 모델에 `translation-default`과 같은 짧은 핸들을 지정합니다.
2. 모델 선택기를 열고 제공업체 또는 모델 이름의 일부를 입력하여 목록을 필터링합니다.
3. Glossia에서 사용할 모델을 선택합니다.
4. 제공업체 키를 입력하고 모델을 저장합니다.

이 핸들을 사용하면 제공업체 자격 증명을 소스 제어에 저장하지 않고도 저장소에서 이 계정 모델을 참조할 수 있습니다. 자세한 내용은 [모델 제공업체 구성](/docs/how-to/configure-a-model-provider)을 참조하십시오.

## 2. 프로젝트 시작

**프로젝트**로 돌아가 **새 프로젝트**를 선택합니다.

Glossia에서 저장소 액세스를 요청하면 GitHub 링크로 이동하여 Glossia GitHub App에 해당 저장소에 대한 액세스 권한을 부여합니다. Glossia로 돌아온 후 필요한 경우 **새 프로젝트**를 다시 엽니다.

## 3. 저장소 선택

현지화할 저장소를 선택합니다. Glossia에는 현재 계정의 GitHub App 설치를 통해 액세스할 수 있는 저장소만 표시됩니다.

언어 단계로 계속 진행합니다.

## 4. 대상 언어 선택

저장소의 소스 콘텐츠에서 생성할 언어를 하나 이상 선택한 다음 설정을 시작합니다.

## 5. 설정 진행 상황 확인

Glossia에서 프로젝트를 준비하는 동안 설정 페이지를 열어 둡니다. 진행 상황 카드에는 저장소 준비, 파일 검사, 변경 사항, 검사 및 완료를 포함한 현재 상태와 최근 활동이 표시됩니다.

페이지를 나갔다가 프로젝트 개요로 돌아와도 설정 상태는 유지됩니다. 설정에 실패하면 동일한 카드에 주의가 필요한 항목이 표시되고 **설정 다시 시도** 옵션이 제공됩니다.

## 6. 결과 검토

설정이 완료되면 프로젝트 개요를 열고 저장소에 생성된 풀 리퀘스트를 검토합니다. 제안된 기준선에는 일반적으로 다음이 포함됩니다.

- 소스 언어, 소스 경로 및 대상 언어가 포함된 루트 `GLOSSIA.md` 파일
- 현지화된 파일을 불러오는 데 필요한 최소한의 애플리케이션 또는 콘텐츠 변경 사항
- 저장소에서 이미 사용할 수 있었던 간단한 유효성 검사

일반적인 GitHub 워크플로를 통해 풀 리퀘스트를 검토하고 병합합니다. 이후 번역 실행에서는 병합된 `GLOSSIA.md` 컨텍스트를 사용합니다.

설정 풀 리퀘스트는 병합될 때까지 프로젝트 개요에 계속 표시됩니다. 병합하지 않고 닫은 경우 설정 알림의 링크에서 다시 엽니다.
