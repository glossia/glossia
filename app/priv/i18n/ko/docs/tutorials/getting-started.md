이 튜토리얼은 GitHub 저장소를 Glossia 와 연결하고 첫 번째 대상 언어를 선택하며 팀이 검토할 로케일라이제이션 기준을 준비합니다.

## 시작하기 전에

다음 이 필요하다:

- 설정과 프로젝트를 관리할 수 있는 Glossia 계정.
- 지문과 업데이트 권한을 부여할 수 있는 GitHub 저장소.
- 지원되는 [대규모 언어 모델](https://en.wikipedia.org/wiki/Large_language_model).

## 1\. 계정 모델 구성

열기 **설정**, 그다음 **모델**, 그리고 선택 **새 모델**.

1. 모델에 짧은 핸들을 지정하세요. 예를 들어 `translation-default`.
2. 모델 선택기를 열고 제공자 또는 모델 이름의 일부를 입력하여 목록을 필터링하세요.
3. Glossia 가 사용할 모델을 선택하세요.
4. 제공자 키를 입력하고 모델을 저장하세요.

핸들은 리포지토리가 제공자 자격 정보를 소스 관리에 포함하지 않고도 이 계정 모델을 참조할 수 있습니다. 보려면 [모델 제공자 구성](/docs/how-to/configure-a-model-provider) 에서 자세한 내용을 확인하세요.

## 2\. 프로젝트 시작

프로젝트로 돌아가서 **프로젝트** 선택하고 **새 프로젝트**.

Glossia 가 레포지토리 접근 권한을 요청하면 GitHub 링크를 따라 이동하여 Glossia GitHub 앱 에 접근 권한을 부여하세요. Glossia 로 돌아온 후 다시 열기 **새 프로젝트** 필요한 경우.

## 3\. 저장소 선택

로컬라이즈하려는 저장소를 선택하세요. Glossia 는 현재 계정의 GitHub App 설치를 통해 사용 가능한 저장소만 나열합니다.

언어 단계로 계속

## 4\. 대상 언어 선택

저장소의 소스 콘텐츠에서 생성해야 하는 하나 이상의 언어를 선택한 후 설정을 시작합니다.

## 5\. 설정 진행 상황 추적

Glossia 가 프로젝트를 준비하는 동안 설정 페이지를 열어두세요. 진행 상황 카드에는 현재 상태와 최근 활동이 표시되며, 이는 저장소 준비, 파일 검사, 변경 사항, 검토 및 완료 등을 포함합니다.

페이지를 떠나도 설정 상태를 잃지 않고 프로젝트 개요로 돌아갈 수 있습니다. 설정이 실패할 경우 동일한 카드는 수정이 필요한 사항을 설명하고 제공합니다 **설정 재시도**.

## 6\. 결과 검토

설정이 완료되면 프로젝트 개요를 열고 리포지토리에 생성된 풀 리퀘스트를 검토하세요. 제안된 베이스라인에는 일반적으로 다음이 포함됩니다:

- 루트 `L10N.md` 소스 언어, 소스 경로 및 대상 언어가 포함된 파일.
- 현지화된 파일 로딩에 필요한 가장 작은 애플리케이션 또는 콘텐츠 변경 사항.
- 레포지토리에 이미 존재하던 경량 검증.

일반적인 GitHub 워크플로우를 통해 풀 리퀘스트를 검토하고 병합하세요. 향후 번역 실행은 병합된 `L10N.md` 컨텍스트입니다.

프로젝트 개요는 병합될 때까지 설정 풀 리퀘스트를 표시합니다. 병합되지 않고 닫힌 경우, 설정 안내의 링크에서 다시 열 수 있습니다.
