---
이 튜토리얼은 GitHub 저장소를 Glossia 와 연결하고, 첫 번째 대상 언어를 선택하며, 팀이 검토할 현지화 기준점을 준비합니다.

## 시작하기 전에

필요한 사항:

- 설정과 프로젝트를 관리할 수 있는 Glossia 계정.
- Glossia GitHub 앱에 읽기 및 업데이트 권한을 부여할 수 있는 GitHub 저장소입니다.
- 지원되는 제공자 키 [대규모 언어 모델](https://en.wikipedia.org/wiki/Large_language_model).

## 1\. 계정 모델 설정

열기 **설정**, 그다음 **모델**, 그리고 선택 **새 모델**.

1. 모델에 짧은 핸들을 지정하세요. 예를 들어 `translation-default`.
2. 모델 선택기를 열고 제공자 또는 모델 이름의 일부를 입력하여 목록을 필터링하세요.
3. Glossia 가 사용할 모델을 선택하세요.
4. 제공자 키를 입력하고 모델을 저장하세요.

핸들은 소스 코드 제어에 제공자 인증 정보를 등록하지 않고도 저장소에서 이 계정 모델을 참조할 수 있게 합니다. 자세히 보려면 [모델 제공자 구성](/docs/how-to/configure-a-model-provider) 에 대한 자세한 내용입니다.

## 2\. 프로젝트 시작

되돌아가 **프로젝트** 그리고 선택 **새 프로젝트**.

Glossia 가 저장소 접근을 요청하면 GitHub 링크를 따라가고 Glossia GitHub 앱에 저장소 접근 권한을 부여하세요. Glossia 로 복귀한 후 다시 열기 **새 프로젝트** 필요한 경우.

## 3\. 저장소 선택

지역화할 저장소를 선택하세요. Glossia 는 현재 계정의 GitHub App 설치를 통해 사용 가능한 저장소만 나열합니다.

언어 단계로 계속하세요.

## 4\. 대상 언어 선택

저장소의 원본 콘텐츠를 기반으로 생성할 언어 하나 이상을 선택한 후 설정을 시작하세요.

## 5\. 설정 진행 상황 확인

Glossia 가 프로젝트를 준비하는 동안 설정 페이지를 열어두세요. 진행 카드는 현재 상태와 최근 활동을 보여줍니다. 여기에는 저장소 준비, 파일 검사, 변경 사항, 검토, 완료 등이 포함됩니다.

페이지를 떠나 프로젝트 개요로 돌아갈 수 있으며 설정 상태를 유지할 수 있습니다. 설정 실패 시 동일한 카드는 주의해야 할 사항을 설명하고 제안합니다 **설정 재시도**.

## 6\. 결과 검토

설정 완료 시 프로젝트 개요를 열고 해당 저장소에 생성된 풀 리퀘스트를 검토하세요. 제안된 베이스라인은 일반적으로 다음을 포함합니다:

- 루트 `GLOSSIA.md` 원본 언어, 원본 경로 및 대상 언어가 포함된 파일입니다.
- 지역화된 파일을 로드하기 위해 필요한 가장 작은 애플리케이션 또는 콘텐츠 변경 사항입니다.
- 저장소에서 이미 제공되던 경량 검증.

자신의 일반적인 GitHub 워크플로우를 통해 풀 리퀘스트를 검토하고 병합하세요. 향후 번역 실행은 병합된 `GLOSSIA.md` 컨텍스트.

프로젝트 개요는 설정용 풀 리퀘스트가 병합될 때까지 표시됩니다. 병합되지 않고 닫힌 경우 설정 안내 링크에서 다시 열어보세요.
