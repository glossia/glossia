%{title: "시작하기", summary: "레포지토리를 연결하고 첫 로케일라이제이션 설정을 준비합니다.", category: "튜토리얼", order: 1}
---

이 튜토리얼은 GitHub 저장소를 Glossia 에 연결하고 첫 번째 대상 언어를 선택하며 팀의 검토를 위한 현지화 기준을 준비합니다.

## 시작하기 전

다음 사항이 필요합니다.

- 설정을 관리할 수 있는 Glossia 계정
- Glossia GitHub 앱에게 읽기 및 수정 권한을 부여할 수 있는 GitHub 저장소
- 지원되는 [대규모 언어 모델](https://en.wikipedia.org/wiki/Large_language_model)에 대한 제공자 키

## 1. 계정 모델 구성

**설정** 을 열고, **모델** 을 선택한 후, **새 모델** 을 선택하세요.

1. 모델에 짧은 핸들 (예로 `translation-default`) 을 부여하세요.
2. 모델 선택기를 열고 제공자 또는 모델 이름의 일부를 입력하여 목록을 필터링하세요.
3. Glossia 가 사용할 모델을 선택하세요.
4. 제공자 키를 입력하고 모델을 저장하세요.

핸들은 자격 증명을 소스 관리에 기록하지 않고 저장소들이 이 계정 모델을 참조하게 합니다. 자세한 내용은 [모델 제공자 구성](/docs/how-to/configure-a-model-provider) 을 참조하세요.

## 2. 프로젝트 시작

**프로젝트** 로 돌아가 **새 프로젝트** 를 선택하세요.

Glossia 가 저장소 액세스를 요청하면 GitHub 으로 이동하여 Glossia GitHub 앱의 저장소 액세스 권한을 부여하세요. Glossia 로 돌아온 후 필요에 따라 **새 프로젝트** 를 다시 엽니다.

## 3. 저장소 선택

현지화할 저장소를 선택하세요. Glossia 는 해당 계정의 GitHub 앱 설치를 통해 사용 가능한 저장소만 나열합니다.

## 4. 프로젝트 설정 방법 선택

**자동 설정** 을 선택하여 Glossia 가 저장소를 검사하고 풀 리퀘스트를 통해 현지화 구성을 제안하도록 하세요. 이 튜토리얼은 해당 경로를 따릅니다.

저장소에 이미 `L10N.md` 파일이 있으면, 또는 직접 작성하는 것을 선호하는 경우 **수동 구성** 을 선택하세요. Glossia 는 즉시 프로젝트를 생성하므로 나머지 단계를 건너뛸 수 있습니다. 각 모드의 역할은 [프로젝트 설정](/docs/reference/project-setup) 을 참조하세요.

## 5. 대상 언어 선택

저장소의 소스 콘텐츠를 기반으로 생성해야 하나 이상의 언어를 선택한 뒤, 설정을 시작하세요.

## 6. 설정 진행 상황 확인

Glossia 가 프로젝트를 준비하는 동안 설정 페이지를 열어 두세요. 진행 상황 카드에는 현재 상태와 최근 활동, 포함 저장소 준비, 파일 검사, 변경 사항, 확인 및 완료 등이 표시됩니다.

설정 상태를 잃지 않고 페이지를 떠날 수 있으며 프로젝트 개요로 돌아갈 수 있습니다. 설정이 실패하면 실패 알림을 읽으세요. Glossia 는 임시 프로젝트를 삭제하므로, 전제 조건을 수정한 뒤 **새 프로젝트** 를 기준으로 다시 시작하세요. [프로젝트 설정 재시도](/docs/how-to/retry-project-setup) 를 확인하세요.

## 7. 결과 검토

설정이 완료되면 프로젝트 개요를 열고 저장소에 생성된 풀 리퀘스트를 검토하세요. 제안된 기준에는 보통 다음이 포함됩니다:

- 원본 언어, 소스 경로 및 대상 언어가 포함된 루트 `L10N.md` 파일
- 현지화 파일을 로드하기 위해 필요한 최소한의 애플리케이션 또는 콘텐츠 변경 사항
- 저장소에서 이미 사용 가능한 가벼운 검증

일반 GitHub 워크플로우를 통해 풀 리퀘스트를 검토하고 병합하세요. 향후 번역 실행은 병합된 `L10N.md` 컨텍스트를 사용합니다.

프로젝트 개요는 병합될 때까지 설정 푸드 요청을 열어 둡니다. 병합 없이 닫힌 경우 설정 알림의 링크에서 다시 열어보세요.
