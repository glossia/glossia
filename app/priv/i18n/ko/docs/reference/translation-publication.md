Glossia 는 프로젝트마다 하나의 오픈 번역 속도 요청만 유지합니다. 새로운 기본 브랜치 커밋은 각 소스 커밋당 속도 요청을 열지 않고 해당 분들을 계속합니다. 이전 속도가 병합되거나 닫힌 후 새로운 속도가 생성됩니다.

발매 및 세션 교체는 데이터베이스 기반 프로젝트 잠금 키를 공유하며, 다른 애플리케이션 리플리카나 힙따힌 라너에서 실행되는 경우에도 마찬가지입니다. 라너가 속도 요청을 생성했지만 메타데이터를 저장하지 못하면 다음 발아가 GitHub 에서 오픈된 Glossia 속도 요청을 복구한 후 새로운 것을 생성합니다. 서로 충돌이 있거나 소스 역사가 다시 쓰여도 오픈된 속도 요청이 버려지지 않습니다. 세션은 실패하지만 기존 발산을 회수하여 해결합니다.

## 속도 제한

제한은 현재 **4개 التقديم投资项目 시간 단위**로 고정되어 있으며 세션과 리플리카 간에 공유됩니다. 현재는 구성되어 있지 않습니다.

화면들은 균등하게 간격을 두고 있으며 고정된 시간 단위 격자에 포함되지 않습니다. 브랜치 업데이트는 최소 15 분 간격으로 이루어집니다. 다음 시작 타이밍은 발마 시도가 완료될 때부터 시작되므로 느린 배치 직후에 빠르게 될 수 없습니다. 소스 브랜치 병급, 중간 배치, 재시도 및 최종 플러시는 모두 같은 예산을 공유합니다. 애매한 실패 시도는 슬롯을 소비합니다. 이는 GitHub 가 연결 실패 전에 브랜치가 진행되었을 수도 있기 때문입니다. 예산은 PostgreSQL 에 저장되어 세션이나 프로세스 재시작에도 인해 새로руются지 않습니다.

## 배치

런은 유효화 된 파일 변경사항을 수집하며 25 개 파일이나 15 분을 충족하면 발행을 요청합니다. 이 기준은 속도 제한을 우회하지 않습니다. 냉각 기간 동안 추가 완료 파일은 대기 중인 배치에 합류하며 같은 경로에 대한 반복 변경은 최신 콘텐츠를 유지합니다.

런이 끝나면 최종 플러시는 같은 예산을 기다립니다. 세션은 대기 중에 활성 상태를 유지하며 심박을 보냅니다. 잠자는 동안 데이터베이스 트랜잭션을 열어가지 않고 주기적으로 취소 및 진입을 다시 확인합니다.
