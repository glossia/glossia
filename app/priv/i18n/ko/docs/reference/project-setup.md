프로젝트 설정은 Glossia 와 연결된 저장소를 준비합니다. 이는 사용자가 저장소를 선택하고 적어도 하나의 목표 언어를 선택한 의 **새 프로젝트** 흐름.

## 선행조건

- 계정에 구성된 모델이 하나 이상 있어야 합니다.
- Glossia GitHub 앱은 선택한 저장소에 접근할 수 있어야 합니다.
- 사용자는 계정에 프로젝트를 생성할 수 있어야 합니다.
- 적어도 하나의 목표 언어가 선택되어 있어야 합니다.

## 상태

| 상태 | 설명 | 사용 가능한 작업 |
|---|---|---|
| **대기 중** | 프로젝트가 승인되어 시작을 기다리고 있습니다. | 진행 상황을 확인하거나 페이지를 떠나 나중에 다시 방문하세요. |
| **실행 중** | Glossia 가 저장소를 검사하고 업데이트하고 있습니다. | 실시간 활동 확인하세요. |
| **완료됨** | 로컬라이제이션 기준이 검토를 위해 준비되어 게시되었습니다. | 풀 리퀘스트를 열어 검토 후 병합하세요. |

프로젝트는 설정이 진행 중인 동안 임시입니다. **대기중** 또는 **가동 중**. 설정이 완료되거나 사용 가능한 변경을 게시할 수 없는 경우, Glossia 는 설정 환경을 정리하고 임시 프로젝트를 삭제합니다. 저장소는 **새 프로젝트** 흐름에서 다시 설정을 시도할 수 있습니다.

## 가시적인 진행

설정 카드는 새 프로젝트 흐름과 프로젝트 개요에서도 계속 표시됩니다. 다음이 포함됩니다:

- 상태 배지 및 진행 막대.
- 현재 상태에 대한 간단한 설명.
- 최근 저장소 준비, 검토, 파일 변경, 확인 및 완료 활동.
- 설정 완료에 실패할 경우 명확한 실패 메시지가 표시됩니다.

임시 프로젝트가 존재하는 동안 진행 상황은 저장됩니다. 최종 실패는 프로젝트와 표시된 설정 진행 상황을 모두 제거합니다.

## 완료됨

성공적인 연결 설정은 전용 브랜치와 리포지토리의 기본 브랜치에 대한 풀 리퀘스트를 생성합니다. 풀 리퀘스트에는 생성된 로컬라이제이션 베이스라인이 포함되어 있으며, `L10N.md` 컨텍스트 및 로컬화된 콘텐츠를 로드하기 위해 필요한 최소한의 실제 변경 사항입니다.

설정에는 헤더만 포함된 대상 카탈로그를 게시하지 않습니다. 로컬라이제이션 프레임워크가 번역 전에 대상 카탈로그를 필요로 하는 경우, 해당 카탈로그에는 추출된 소스 메시지 항목과 빈 번역 값만 포함됩니다. 아직 대상 카탈로그가 필요하지 않은 경우, 설정은 첫 번째 번역 실행을 위해 해당 카탈로그를 남겨 둡니다.

Glossia 는 해당 풀 리퀘스트를 병합하지 않습니다. 리포지토리 유지자는 정상적인 GitHub 프로세스를 통해 이를 검토하고 병합합니다.

프로젝트 개요는 이 풀 리퀘스트가 열려 있는 동안 설정 알림을 표시합니다. 풀 리퀘스트가 병합되면 해당 알림은 제거됩니다. 풀 리퀘스트가 병합되지 않고 닫힌 경우, 개요는 설정이 완료된 것으로 간주되기 전에 반드시 다시 열어야 함을 설명합니다.
