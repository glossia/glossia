Glossia 를 위한 연결된 저장소 설정은 저장소를 준비합니다. 사용자가 **New project** 흐름에서 저장소를 선택한 후, 두 가지 설정 모드 중 하나를 선택합니다.

## 설정 모드들

| 모드 | Glossia 가 수행하는 작업 | 선택 시기 |
|---|---|---|
| **자동 설정** | 선택된 대상 언어에 대한 생성된 `L10N.md` 설정을 포함하여 저장소를 검사하고 pull request 를 엽니다. | 저장소는 아직 현지화 설정이 없습니다. |
| **수동 설정** | 프로젝트를 즉시 생성합니다. 저장소를 검사하거나 변경하거나 pull request 를 엽니다. | 저장소는 이미 `L10N.md` 파일이 있거나, 관리자가 작성합니다. |

다음에 설명된 상태, 진행 정보 및 pull request 는 자동 설정에만 적용됩니다.

## 수동 설정

수동으로 구성된 프로젝트는 설정 상태가 없습니다. 생성되는 즉시 사용할 수 있으며, 실패한 설정에 의해 삭제되지 않습니다.

Glossia 는 저장소의 기본 브랜치에 대한 다음 push 에서 번역 작업을 시작합니다. 이 작업은 저장소의 [`L10N.md`](/docs/reference/l10n-md) 파일에 선언된 모든 대상으로 번역됩니다. **New project** 흐름에서 대상 언어를 선택하지 않았기 때문입니다.

첫 번역 작업이 완료될 때까지 프로젝트 개요에는 Glossia 가 `L10N.md` 파일이 포함된 push 를 기다리고 있다는 공지 메시지가 표시됩니다.

## tiền제

- 계정은 최소 하나의 설정된 모델이 있어야 합니다.
- Glossia GitHub 앱은 선택된 저장소에 접근할 수 있어야 합니다.
- 사용자는 계정의 프로젝트 생성이 가능합니다.
- 자동 설정 시 최소 하나의 대상 언어가 선택되어야 합니다.

## 상태

| 상태 | 의미 | 사용 가능한 작업 |
|---|---|---|
| **대기 중** | 프로젝트가 승인되어 시작을 기다리고 있습니다. | 진행 상태를 추적하거나 페이지를 떠나 나중에 다시 돌아옵니다. |
| **실행 중** | Glossia 가 저장소를 검사하고 업데이트 중입니다. | 실시간 활동을 추적합니다. |
| **완료** | 현지화 기준이 준비되어 검토를 위해 게시되었습니다. | pull request 를 열고 검토 및 병합합니다. |

설정이 **대기 중** 또는 **실행 중**이면 프로젝트는 임시적입니다. 설정이 완료되거나 유효한 변경을 게시할 수 없으면 Glossia 는 설정 환경을 정리하고 임시 프로젝트를 삭제합니다. 그렇게 되면 저장소는 **New project** 흐름에서 사용할 수 있게 되어 설정을 다시 시도할 수 있습니다.

## 가시적인 진행

설정 카드는 새 프로젝트 흐름과 프로젝트 개요에서 계속 표시됩니다. 다음을 포함합니다:

- 상태 배지 및 진행 상태바.
- 현재 상태에 대한 간략한 설명.
- 최근 저장소 준비, 검사, 파일 변경, 확인 및 완료 활동.
- 설정이 완료되지 않을 때 나타나는 명확한 실패 메시지입니다.

진행 상태는 임시 프로젝트가 존재하는 동안 저장됩니다. 최종 실패는 프로젝트와 가시적인 설정 진행을 모두 삭제합니다.

## 완료 결과

성공적인 연결 설정은 전용 브랜치와 저장소의 기본 브랜치에 대한 pull request 를 생성합니다. 이 pull request 에는 생성된 현지화 기준, `L10N.md` 컨텍스트 및 현지화된 콘텐츠를 로드하는 데 필요한 최소한의 실질적인 변경 사항이 포함됩니다.

설정은 헤더 전용 대상 카탈로그를 게시하지 않습니다. 현지화 프레임워크가 번역 전에 대상 카탈로그를 요구하는 경우, 카탈로그는 공백 번역 값을 지닌 추출된 소스 메시지 항목을 포함합니다. 아직 대상 카탈로그가 필요하지 않은 경우, 설정은 첫 번째 번역 작업에 맞춰 이들을 남겨둡니다.

Glossia 는 pull request 를 병합하지 않습니다. 저장소 유지자는 이를 표준 GitHub 프로세스를 통해 검토 및 병합합니다.

프로젝트 개요는 pull request 가 열려 있는 동안 설정 공지를 표시합니다. pull request 가 병합된 후 공지는 삭제됩니다. pull request 가 병합되지 않고 닫히는 경우, 개요는 설정이 완료된 것으로 간주되기 전에 다시 열어야 함을 설명합니다.
