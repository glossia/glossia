프로젝트 설정은 연결된 저장소를 Glossia에서 사용할 수 있도록 준비합니다. 사용자가 **새 프로젝트** 흐름에서 저장소와 하나 이상의 대상 언어를 선택하면 시작됩니다.

## 사전 요구 사항

- 계정에 하나 이상의 모델이 구성되어 있어야 합니다.
- Glossia GitHub App에서 선택한 저장소에 접근할 수 있어야 합니다.
- 사용자가 계정에서 프로젝트를 생성할 수 있어야 합니다.
- 하나 이상의 대상 언어가 선택되어 있어야 합니다.

## 상태

| 상태 | 의미 | 사용 가능한 작업 |
|---|---|---|
| **대기 중** | 프로젝트가 승인되어 시작을 기다리고 있습니다. | 진행 상황을 확인하거나 페이지를 나갔다가 나중에 돌아옵니다. |
| **실행 중** | Glossia가 저장소를 검사하고 업데이트하고 있습니다. | 실시간 활동을 확인합니다. |
| **완료됨** | 현지화 기준 구성이 준비되어 검토용으로 게시되었습니다. | 풀 리퀘스트를 열고 검토한 후 병합합니다. |

설정 상태가 **대기 중** 또는 **실행 중**인 동안 프로젝트는 임시 상태입니다. 설정을 완료할 수 없거나 사용 가능한 변경 사항을 게시할 수 없는 경우 Glossia는 설정 환경을 정리하고 임시 프로젝트를 삭제합니다. 그러면 저장소가 **새 프로젝트** 흐름에 다시 표시되어 설정을 재시도할 수 있습니다.

## 표시되는 진행 상황

설정 카드는 새 프로젝트 흐름과 프로젝트 개요에서 계속 확인할 수 있습니다. 설정 카드에는 다음 항목이 포함됩니다.

- 상태 배지와 진행률 표시줄
- 현재 상태에 대한 간단한 설명
- 최근 저장소 준비, 검사, 파일 변경, 확인 및 완료 활동
- 설정을 완료할 수 없을 때 표시되는 명확한 실패 메시지

진행 상황은 임시 프로젝트가 존재하는 동안 저장됩니다. 최종 실패가 발생하면 프로젝트와 표시된 설정 진행 상황이 모두 삭제됩니다.

## 완료 결과

연결된 설정이 성공하면 전용 브랜치가 생성되고 저장소의 기본 브랜치를 대상으로 하는 풀 리퀘스트가 생성됩니다. 풀 리퀘스트에는 `GLOSSIA.md` 컨텍스트와 현지화된 콘텐츠를 불러오는 데 필요한 최소한의 실질적인 변경 사항을 포함하여 생성된 현지화 기준 구성이 담깁니다.

설정은 헤더만 있는 대상 카탈로그를 게시하지 않습니다. 현지화 프레임워크에서 번역 전에 대상 카탈로그를 요구하는 경우, 카탈로그에는 추출된 원본 메시지 항목이 빈 번역 값과 함께 포함됩니다. 대상 카탈로그가 아직 필요하지 않은 경우에는 첫 번째 번역 실행 시 생성되도록 남겨 둡니다.

Glossia는 풀 리퀘스트를 병합하지 않습니다. 저장소 관리자가 일반적인 GitHub 절차에 따라 풀 리퀘스트를 검토하고 병합합니다.

이 풀 리퀘스트가 열려 있는 동안 프로젝트 개요에 설정 알림이 표시됩니다. 풀 리퀘스트가 병합되면 알림이 제거됩니다. 풀 리퀘스트가 병합되지 않은 채 닫히면 설정을 완료된 것으로 간주하기 전에 풀 리퀘스트를 다시 열어야 한다는 안내가 프로젝트 개요에 표시됩니다.
