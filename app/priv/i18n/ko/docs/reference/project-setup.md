프로젝트 설정은 Glossia 를 위한 연결된 저장소를 준비합니다. 사용자가 저장소를 선택한 후 **새 프로젝트** 플로우에서 사용자는 두 가지 설정 모드 중 하나를 선택합니다.

## 설정 모드

| 모드 | Glossia 가 수행하는 작업 | 선택 시기 |
|---|---|---|
| **자동 설정** | 저장소를 검사하고 PR 을 생성된 것으로와 함께 여는 `L10N.md` 대상 언어 설정으로 | 저장소는 아직 현지화 설정이 없습니다. |
| **수동 설정** | 프로젝트를 즉시 생성합니다. 저장소를 검사하거나 변경하거나 PR 을 여는 것은 없습니다. | 저장소는 이미 한 `L10N.md` 파일, 또는 유지 관리자가 작성합니다. |

아래에 설명된 상태, 진행 정보 및 PR 은 자동 설정에만 적용됩니다.

## 수동 설정

수동으로 설정된 프로젝트는 설정 상태가 없습니다. 생성 즉시 사용 가능하며, 실패한 설정 절차에 의해 절대 삭제되지 않습니다.

Glossia 는 저장소의 기본 브랜치로의 다음 푸시 시 번역 작업을 시작합니다. 이 작업은 저장소의 [`L10N.md`](/docs/reference/l10n-md) 파일이며, 타겟 언어가 선택되지 않은 **새 프로젝트** 흐름.

첫 번째 번역 런까지 프로젝트 개요는 Glossia 가 포함된 한 푸시를 기다리고 있음을 알림으로 표시합니다. `L10N.md` 파일입니다.

## 필수 조건

- 계정에 설정된 모델이 최소 하나 있습니다.
- Glossia GitHub App 은 선택된 저장소에 접근할 수 있습니다.
- 사용자는 계정에 프로젝트를 생성할 수 있습니다.
- 자동 설정에는 최소 하나의 대상 언어가 선택되어 있습니다.

## 상태

| 상태 | 의미 | 사용 가능한 작업 |
|---|---|---|
| **대기 중** | 프로젝트가 승인되어 시작을 기다리고 있습니다. | 진행 상황을 확인하거나 페이지를 떠나 나중에 다시 방문하세요. |
| **진행 중** | Glossia 는 저장소를 검사하고 업데이트하고 있습니다. | 실시간 진행 현황을 확인하세요. |
| **완료** | 번역 기준이 검토를 위해 게시되었습니다. | 풀 리퀘스트를 열어 검토하고 병합하세요. |

프로젝트는 설정이 **대기 중** 또는 **진행 중**. 설정을 완료하거나 사용 가능한 변경 사항을 게시할 수 없는 경우, Glossia 는 설정 환경을 정리하고 임시 프로젝트를 삭제합니다. 이후 저장소는 **새 프로젝트** 워크플로우를 통해 다시 설정을 시도할 수 있습니다.

## 가시적인 진행 상황

새 프로젝트 흐름과 프로젝트 개요에서 설정 카드가 계속 사용 가능합니다. 여기에는 다음 이 포함됩니다:

- 상태 배지 및 진행률 바.
- 현재 상태에 대한 짧은 설명.
- 최근 저장소 준비, 검사, 파일 변경, 확인 및 완료 활동.
- 설정이 완료되지 않을 때 명확한 실패 메시지.

잠정 프로젝트가 존재하는 동안 진행 상황이 저장됩니다. 최종 실패는 프로젝트와 가시적인 설정 진행을 모두 삭제합니다.

## 완료 결과

성공적인 연결 설정은 전용 브랜치와 저장소 기본 브랜치에 대한 풀 리퀘스트를 생성합니다. 해당 풀 리퀘스트에는 생성된 현지화 베이스라인이 포함되어 있으며, 다음을 포함합니다 `L10N.md` 현지화 콘텐츠를 로드하기 위해 필요한 최소한의 실질적인 컨텍스트 및 변경 사항.

세팅은 헤더만 포함하는 대상 카탈로그를 발행하지 않습니다. 현지화 프레임워크가 번역 전 대상 카탈로그를 필요로 하는 경우, 해당 카탈로그에는 빈 번역 값이 포함된 추출된 소스 메시지 항목이 있으며, 대상 카탈로그가 아직 필요 없다면 세팅은 이를 첫 번째 번역 실행을 위해 남겨둡니다.

Glossia 는 풀 리퀘스트 를 병합하지 않습니다. 저장소 관리는 GitHub 의 일반적인 프로세스 를 통해 검토하고 이를 병합합니다.

풀 리퀘스트 가 열려 있는 동안 프로젝트 개요에는 세팅 알림이 표시됩니다. 풀 리퀘스트 가 병합된 후 알림은 제거됩니다. 풀 리퀘스트 가 병합 없이 닫힌 경우, 개요는 세팅이 완료된 것으로 간주되기 전에 다시 열어야 한다고 설명합니다.
