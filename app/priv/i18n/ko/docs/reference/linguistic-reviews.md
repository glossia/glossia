## 에스컬레이션

구성된 의사결정 모델을 갖춘 리포지토리 번역 실행은 누락된 소스 의미나 도메인 컨텍스트, 상충하는 지침, 혹은 결과적인 문화적 적응을 위해 언어학적 입력을 요청할 수 있습니다. 저 신뢰도만으로는 질문이 유발되지 않습니다. 기존 컨텍스트에서 바로 수정 가능한 오류는 일반 수정 예산을 사용하며, 배정된 예산 이후에도 남은 품질 실패는 입력을 요청할 수도 있습니다. 의사결정 모델이 없는 경우, 자동 언어학적 에스컬레이션은 비활성화됩니다.

영향 받은 파일/로케일만 중단됩니다. 해당 미승인 후보는 게시되지 않습니다. 독립적인 파일은 정상적으로 완료되고 게시될 수 있습니다. 게시가 완료되면 세션은 `awaiting_input` 상태로 전환되며 러너를 해제합니다. 사람이 답변하는 동안 워커를 소모하지 않습니다.

각 에스컬레이션은 번역 세션과 연결된 **목표가 정의된 공유 토키 대화** 하나를 엽니다. 참여자는 의미를 논의하고 후속 질문을 하며 제안된 결정을 개선합니다. 논의만으로는 번역을 승인하거나 레포지토리 컨텍스트를 작성할 수 없습니다. 일반적인 토키 대화는 소유자 (관리자 포함) 에게만 비공개로 유지됩니다.

현재 사용할 수 있는 동료 중 표기된 유창 언어가 타겟 로케일과 일치하는 이들은 동일 대화에 초대됩니다. 유창성은 시각 언어와 분리되며 프로젝트 접근 권한이나 의사결정 승인 권한을 부여하지 않습니다. `es` 처럼 광범위한 언어는 `es-MX` 처럼 지역 변형을 개별적으로 맞춤합니다; 호환되지 않는 명시된 스크립트는 일치하지 않습니다. 지역 선언인 `zh-TW` 는 통상적인 CLDR 스크립트를 사용하며, 광범위한 `zh` 는 스크립트에 의해 제한받지 않습니다.

자격 요건을 갖춘 참여자는 관측_allocator 할 때만 범용 모바일 푸시 알림을 받습니다. 전달은 현재 유창성, 멤버십, 프로젝트 접근성, 열린 목표를 다시 확인합니다. 알림은 공유 대화를 엽니다. 대사와 승인은 네이티브 앱과 웹 대시보드 모두에서 사용할 수 있습니다. 제공자 구성 및 전달 정책에 관해서는 [네이티브 푸시 알림](/docs/reference/native-push-notifications) 을 참조하십시오.

## 유창 언어 프로필

`GET /api/me` 에는 `user.fluent_languages` 가 포함되어 있습니다. `PUT /api/me/fluent-languages` 는 `user:write` 를 필요로 하며 `{"fluent_languages": ["es", "ar", "zh-Hant"]}` 만 표시합니다. 인증된 사용자의 목록을 교체하고 프로필 응답을 반환합니다. 지원되는 CLDR BCP47 태그는 명시된 지역/스크립트 구체성을 유지하며 표준 대문자를 사용합니다. 중복은 제거됩니다. 빈 배열은 유창성을 지웁니다. 유효하지 않은 태그, 관련 없는 필드 또는 제출된 항목 50 개 이상은 422 를 반환합니다. 이는 UI 로케일을 변경하지 않습니다.

## 검토 API

`GET /api/:handle/projects/:project/translations/:id/reviews` 는 `translation:read` 와 프로젝트 접근 권한이 필요합니다. `{"reviews": [...]}` 를 반환하며, 열린 질문이 먼저 나열되고 그다음 가장 오래된 순서로 제출, 최대 500 개 항목까지 제한합니다. 답변 후 새로고침하여 남는 질문을 엽니다. 답변된 기록은 절대 한도 안에 열린 질문을 덮어쓰지 않습니다.

각 검토에는 `id`, `translation_session_id`, `conversation_id`, `participants` (`id` 및 nullable `name`), `status`, `source_path`, `output_path`, `locale`, `question`, 제한된 `source_excerpt` 및 `translation_excerpt`, `answer`, `guidance`, `context_path`, `resolution_message_id`, `resumed_session_id`, 및 `inserted_at` 가 있습니다. 상태는 `open`, `answered`, 또는 `stale` 입니다.

`answered_by` 는 노거인 의사결정을 승인한 인간을 `{"id": "<user UUID>", "name": "<current display name>"}` 로 식별합니다. `name` 는 null 이 될 수 있습니다. 이 필드는 승인 전이나 승인자가 없는 경우 null 입니다. 이메일이나 다른 사적인 프로파일 필드는 포함하지 않으며, 승인 재생은 승인자를 변경하지 않습니다. 동일한 필드는 공유 토키 대회의 내장 `linguistic_review` 에서도 포함됩니다. 승인 타임스탬프는 노출되지 않으며, `inserted_at` 는 검토의 생성 시간이 아닌 승인 시간입니다.

토론을 위해 기존 프로젝트 토키 대화 및 메시지 엔드포인트를 사용하십시오. 목표 공유 대화는 토키 기록에서 사용자의 사적 대화와 나란히 나타납니다. 공유 기록은 최신 토키 읽기/쓰기 정책 권한 및 번역 읽기 접근 권한이 필요합니다. 일반 기록은 소유자만입니다. 인간 메시지는 작성자 신원을 포함하며, 답글은 `status` 및 `reply_to_id` 를 포함합니다. 토키는 제한된 소스/후보 추출본과 목표를 수신하며, 레포지토리 쓰기 접근 권한은 아닙니다.

`POST /api/:handle/projects/:project/translations/:id/reviews/:review_id/answer` 는 `translation:read` 와 `translation:write` 를 모두 필요로 하며, 프로젝트 접근 권한도 필요합니다:

```json
{
  "resolution_message_id": "019a1c6d-4321-7000-8000-123456789abc",
  "answer": "Branch means a source-control release branch.",
  "guidance": "Use the source-control meaning of branch in release documentation.",
  "context_scope": "locale"
}
```

`resolution_message_id` 는 목표 대화에서 최신 완료된 어시스턴트 **답변** 을 식별해야 하며, 이는 처음 질문입니다. `answer` 는 인간 승인 의사결정도며 필수이며 공백이 없습니다. `guidance` 와 `context_scope` 는 선택 사항이며 범위는 `locale` 로 기본이며 `project` 도 가능합니다. 답변과 가이드는 각각 8,000 문자 및 32,000 UTF-8 바이트까지만 허용됩니다. 가이드는 Glossia 의 예약 검토 마커 주석을 포함할 수 없습니다. 서버가 레포지토리 경로를 선택하며, 클라이언트 제공 경로는 결코 사용되지 않습니다.

성공 응답은 `{"review": {...}}` 입니다. 동일한 의사결정, 선포 메시지, 가이드, 하나가 범위는 멱등적입니다. 바쁜 대화는 `409 conversation_busy` 를 반환하며, 새로운 메시지 또는 잘못된 선포 참조는 `409 resolution_outdated` 를 반환합니다. 승인 전에는 현재 토론을 다시로드하고 검토하십시오. 해결된 목표에 대한 다른 의사결정은 `409 already_answered` 를 반환하며, 취소 또는 자동 교체된 목표를 승인하면 `409 stale` 를 반환합니다. 유효하지 않은 텍스트 또는 사용할 수 없는 범위는 422 를 반환합니다. 누락 및 외국 프로젝트 ID 는 404 를 반환합니다. 재생 포함 하더라도 각 요청에 대한 일반적인 인증 및 프로젝트 권한이 적용됩니다. 닫힌 목표는 `409 goal_closed` 로 새 토론 메시지를 거부합니다.

## 연속성 및 유통 컨텍스트

독립적인 작업이 여전히 실행 중이면 의사결정은 승인할 수 있습니다. 그들은 그 후 두 번째 러너를 시작하지 않습니다. 러너가 해제되고 해당 실행의 모든 목표가 해결되면 Glossia 는 원자적으로 하나의 연속 세션을 대기열에 넣습니다. `resumed_session_id` 는 그것 식별합니다. 원래 세션은 역사적 `awaiting_input` 로 남아있습니다. 대시보드와 네이티브 대화 모두 연속성으로 연결됩니다.

연속 솔리라는 새로고침된 실행 신원이고 번역 게시 브랜치 및 검증된 출력을 유지합니다. 각 답변은 동일한 소스 및 해결된 번역 컨텍스트 지문에만 적용됩니다. 변경된 소스, 음성, 단어 사전, 모델, 또는 레포지토리 지침은 답변 재사용을 방지합니다. 새로운 기본 브랜치 커밋은 대기 중인 세션을 대체하며 열린 질문을 만료시킵니다. 취소 또한 열린 질문을 만료시킵니다.

## 재사용 가능한 레포지토리 지침

재사용 가능한 지침은 분리된 명시적 인간 편집입니다. 답변만으로는 레포지토리 컨텍스트가 되지 않으며, 사적인 채팅 대본은 자동으로 복사되지 않습니다.

`locale` 는 적용 가능한 locale 오버레이를 대상으로 하며, 예를 들어 `L10N/es.md`; `project` 는 적용 가능한 `L10N.md` 를 대상으로 합니다. 기존 범주화된 컨텍스트 파일은 존중됩니다. 누락된 locale 오버레이는 해당 locale 프론트매터를 받습니다. 기존 프론트매터 및 문장은 유지되며, 각 의사결정은 추적 가능성 및 멱등성을 위해 검토 UUID 가 추가됩니다.

가이드는 일반적인 번역 풀 요청에서 제안되며, 기본 브랜치에 명시적으로 작성되지 않습니다. 레포지토리는 여전히 기록된 컨텍스트 서브 와 일치해야 하며, 충돌하는 편집은 오버라이딩 대신 게시를 실패시킵니다. 경로는 레포지토리 상대 로컬라이제이션 문서여야 하며, 이동 또는 시링크 없이 제한되어야 합니다. 각 컨텍스트 문서는 1 MiB 로 제한됩니다. 풀 요청을 병합하면 가이드는 일반적인 버전 관리 로컬라이제이션 컨텍스트가 됩니다.
