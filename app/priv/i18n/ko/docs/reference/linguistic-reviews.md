## 승계

레포지토리 번역은 구성된 의사결정 모델을 사용할 경우 누락된 소스 의미 또는 도메인 컨텍스트, 충돌하는 가이드, 또는 중대한 문화적 적응을 위해 언어적 입력을 요청할 수 있습니다. 낮은 확률 자체만으로는 질문을 유발하지 않습니다. 기존 컨텍스트에서 수정 가능한 오류는 일반적인 수정 예산을 사용하며, 그 이후에 남은 품질 실패 또한 입력을 요청할 수 있습니다. 의사결정 모델이 없는 경우 자동 언어적 승계는 비활성화됩니다.

영향을 받은 파일/로케일만 중단됩니다. 승인되지 않은 후보는 게시되지 않습니다. 독립적인 파일은 완료되어 정상적으로 게시할 수 있습니다. 게시가 완료되면 세션은 `awaiting_input` 가 되어 런너를 해제합니다. 사람이 답변 중인 동안는 워커를 소비하지 않습니다.

각 심의 건의는 **명시된 언어 목표를 가진 공유 토키 대화** 하나를 여며 번역 세션과 연결됩니다. 참가자들은 의미를 논의하고 후속 질문을 하며 제안된 결정을 다듬습니다. 토론만으로는 번역을 승인하거나 리포지토리 컨텍스트를 작성할 수 없습니다. 일반적인 토키 대화는 관리자를 포함하여 소유자에게만 비공개입니다.

현재 승인된 팀원 중 표기된 유창 언어가 목표 로케일과 일치하는 사람은 동일한 대화에 초대됩니다. 유창성은 표시 언어와 별개이며 프로젝트 접근 권한이나 결정 승인 권한을 부여하지 않습니다. 광범위한 언어 코드 (`es`) 는 지역 변이 (`es-MX`) 와 일치합니다. 불일치하는 명시적 스크립트는 일치하지 않습니다. 지역성 선언 (`zh-TW`) 은 관례적인 CLDR 스크립트를 사용하는 반면, 광범위한 `zh` 는 스크립트로 제한되지 않습니다.

적격한 참여자는 동의한 경우에만 일반적인 모바일 푸시 알림을 받으며, 전달은 현재 유창성, 구성원 자격, 프로젝트 접근성, 열린 목표를 재확인합니다. 알림은 공유 대화를 엽니다. 대화 및 승인은 네이티브 앱과 웹 대시보드 모두에서 사용할 수 있습니다. 서비스 제공자 구성 및 전달 정책은 [Native push notifications](/docs/reference/native-push-notifications) 을 참조하시오.

## 유창 언어 프로필

`GET /api/me` 에는 `user.fluent_languages` 가 포함됩니다. `PUT /api/me/fluent-languages` 는 `user:write` 를 요구하며 `{"fluent_languages": ["es", "ar", "zh-Hant"]}` 만을 허용합니다. 인증된 사용자의 목록을 대체하고 프로필 엔벨로프를 반환합니다. 지원되는 CLDR BCP47 태그는 명시적인 지역/스크립트 지정성을 유지하며 정통 대기를 사용합니다; 중복 항목은 축소됩니다. 빈 배열은 유창성을 제거합니다. 유효하지 않은 태그, 관련 없는 필드, 또는 제출된 항목이 50 개를 초과하면 422 가 반환됩니다. 이는 UI 로케일을 변경하지 않습니다.

## 검토 API

`GET /api/:handle/projects/:project/translations/:id/reviews` 는 `translation:read` 와 프로젝트 에세스가 필요합니다. `{"reviews": [...]}` 를 반환하며 열린 질문을 먼저 표시한 다음 최신 질문부터 표시하고 500 개 항목으로 제한됩니다. 답변 후 새로 고침하여 남은 질문을 확인하십시오. 답변한 기록은 한Even 한 질문을 뜻으로 숨기지 않습니다.

각 검토에는 `id`, `translation_session_id`, `conversation_id`, `participants` (`id` 와 nullable `name`), `status`, `source_path`, `output_path`, `locale`, `question`, bounded `source_excerpt` 및 `translation_excerpt`, `answer`, `guidance`, `context_path`, `resolution_message_id`, `resumed_session_id`, 및 `inserted_at` 가 포함되어 있습니다. 상태는 `open`, `answered`, 또는 `stale` 입니다.

기존 프로젝트 토키 대화 및 메시지 엔드포인트를 사용하여 토론하십시오. 공유 목표 대화는 토키 이력에 사용자 개인 대화와 함께 표시됩니다. 공유 이력은 현재 토키 읽기/쓰기 정책 권한 및 번역 읽기 접근이 필요합니다; 일반 이력은 소유자 전용입니다. 인간 메시지는 저자 신원을 포함하고 응답에는 `status` 및 `reply_to_id` 가 포함되어 있습니다. 토키는 제한된 소스/후보 단편과 목표를 수신하며 레포지토리 쓰기 접근 권한은 주어지지 않습니다.

`POST /api/:handle/projects/:project/translations/:id/reviews/:review_id/answer` 는 `translation:read` 및 `translation:write` 와 함께 프로젝트 에세스가 필요합니다:

```json
{
  "resolution_message_id": "019a1c6d-4321-7000-8000-123456789abc",
  "answer": "Branch means a source-control release branch.",
  "guidance": "Use the source-control meaning of branch in release documentation.",
  "context_scope": "locale"
}
```

`resolution_message_id` 는 목표 대화에서 최신 완료된 어시스턴트 **답변** 을 식별해야 하며, 제안된 박음지를 나타내지 않습니다. `answer` 는 인간 승인의 결정이며 필수 및 비어있지 않아야 합니다. `guidance` 및 `context_scope` 는 옵션이며 범위는 `locale` 로 기본값되며 `project` 도 가능합니다. 답변 및 가이드는 각각 최대 8,000 글자 및 32,000 UTF-8 바이트를 허용합니다. 가이드에는 Glossia 의 예약된 검토 마커 주석을 포함할 수 없습니다. 서버가 레포지토리 경로를 선택하며 클라이언트 제공 경로는 절대 사용되지 않습니다.

성공적인 응답은 `{"review": {...}}` 입니다. 동일한 결정, 해결 메시지, 가이드 및 범위를 다시 실행하는 것은 멱등적입니다. 과도한 대화는 `409 conversation_busy` 를 반환하며; 새 메시지 또는 유효성 검사되지 않는 해결 참조는 `409 resolution_outdated` 를 반환합니다. 다시 승인하기 전에 현재 토론을 새로고침하여 검토하십시오. 해결된 목표에 대한 다른 결정은 `409 already_answered` 를 반환하며; 취소되거나 더 이상 세분되지 않는 목표를 승인하면 `409 stale` 가 반환됩니다. 잘못된 텍스트 또는 이용 불가능한 범위는 422 를 반환합니다. 누락 및 외국 프로젝트 ID 는 404 를 반환합니다. 모든 요청에 대해 일반적인 인증 및 프로젝트 권한이 적용되며, 이는 다시 실행에 포함됩니다. 닫힌 목표는 새 토론 메시지를 `409 goal_closed` 로 거부합니다.

## 연속 세션 및 유효성 검사 실패된 컨텍스트

결정은 독립적으로 작업이 계속 실행 중일 수 승인할 수 있습니다. 그 경우 두 번째 런너를 시작하지 않습니다. 런너가 풀리고 해당 실행의 모든 목표가 해결되면 Glossia 는 연속 세션 하나를 원자적으로 큐에 추가합니다. `resumed_session_id` 는 이를 식별하며; 원본 세션은 역사 `awaiting_input` 로 남아있으며; 두 가지 대시보드 및 네이티브 대화는 계속세션에 연결됩니다.

연속 세션은 새로운 실행 신원을 가지며 번역 게시 브랜치와 유효된 출력을 유지합니다. 각 답변은 동일한 소스와 해결된 번역 컨텍스트 지문에만 적용됩니다. 변경된 소스, 음성, 정독어, 모델 또는 레포지토리 지침은 답변 재사용을 방지합니다. 새 기본 브랜치 커밋은 대기 세션을 대체하며 열린 질문을 유효성 검사 실패로 표시합니다. 취소도 열린 질문을 유효성 검사 실패로 표시합니다.

## 재사용 가능한 레포지토리 가이드

재사용 가능한 가이드는 별도 명확한 인간 편집입니다. 답변 윤만으로는 레포지토리 컨텍스트가 되지는 않으며, 개인 채팅 기록 은 자동으로 복사되지 않습니다.

`locale` 는 적용 가능한 로케이나ForegroundColor (`L10N/es.md`) 를 대상으로 하며; `project` 는 적용 가능한 `L10N.md` 를 대상으로 합니다. 기존 범주 컨텍스트 파일이 영지합니다. 빈 로케리 오버레이는 해당 로케일 프론트매터를 받으며; 기존 프론트매터 및 문장은 보존되며, 결정마다 UUID 가 첨부되어 기원과 멱등성이 보장됩니다.

가이드는 일반적인 번역 풀 요청에 제안되며, 기본 브랜치에 침묵하여 작성되지 않습니다. 레포지토리는 기록된 컨텍스트 디제스트와 일치해야 하며, 충돌하는 편집은 이를 덮어쓰는 대신 게시에 실패시킵니다. 경로는 탐사나 심볼릭 링크 없이 레포지토리상 상대 로케화 문서여야 합니다. 각 컨텍스트 문서는 1 MiB 로 제한됩니다. 풀 요청을 병합하면 가이드는 후속 실행을 위한 일반적인 버전화된 로케화 컨텍스트가 됩니다.
