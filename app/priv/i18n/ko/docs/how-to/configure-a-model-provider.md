프로젝트 설정 및 번역 실행은 현재 Glossia 계정에 구성된 모델을 사용합니다. 프로젝트를 생성하기 전에 최소 한 개 이상의 모델을 구성해야 합니다.

## 모델 추가

1. **설정**을 열고 **모델**을 선택합니다.
2. **새 모델**을 선택합니다.
3. 고유한 핸들을 입력합니다. 예를 들어 `translation-default`.
4. 모델 선택기를 열고 제공자 이름이나 모델 이름의 일부를 입력하여 목록을 필터링합니다.
5. 모델을 선택하고 해당 제공자 키를 입력합니다.
6. 모델을 저장합니다.

나중에 뒤에 있는 제공자 모델을 변경하더라도 핸들은 안정적으로 유지됩니다. 계정에 추가된 첫 번째 모델이 기본 모델이 됩니다.

## 레포지토리에서 모델을 참조합니다.

관련 `L10N.md` 프론트매터에서 `model`를 설정합니다:

```yaml
---
model: translation-default
---
```

레포지토리는 핸들만 저장합니다. 제공자 키는 계정 설정에 유지됩니다.

## 기본적으로 사용하는 모델을 선택합니다.

`L10N.md` 에서 `model` 가 생략되면 Glossia 는 계정의 기본 모델을 사용합니다. 이를 변경하려면 기본 모델이 되어야 하는 모델을 열고 **기본으로 설정**을 선택합니다.

여러 모델에 걸쳐 예측 가능한 동작을 위해 `L10N.md` 에 명시적으로 핸들을 참조합니다.

하나의 콘텐츠 영역을 위한 계층형 `L10N.md` 에서 다른 `model` 핸들을 배치하거나, 하나의 대상 언어를 위한 `L10N/<locale>.md` 에 배치할 수 있습니다. Glossia 는 각 문서와 언어에 대해 가장 근접한 적용 가능한 설정을 사용합니다. 구성된 모델들 사이에 작업을 자동으로 분할하지 않습니다.

명시적 핸들이 계정에 존재하지 않으면 번역은 에러로 중지됩니다. 다른 모델로 대체되지 않습니다.

## 제공자 키를 변경하거나 회전합니다.

**설정**을 열고 **모델**을 선택하여 모델 핸들을 엽니다. 새 제공자 키를 입력하고 저장합니다. 키 필드를 비워 두면 현재 키가 유지됩니다.

핸들을 참조하는 레포지토리는 변경할 필요가 없습니다.

## 번역 품질 결정에 Jev 추가

1. **설정 → 모델 → 새 모델**을 열고 카테고리로 **결정**을 선택합니다.
2. `translation-quality`와 같은 핸들을 사용합니다. `typesafe/jev-latest`를 유지하거나 고정된 TypeSafe Jev 모델 버전을 입력합니다.
3. TypeSafe 제공자 키를 입력합니다. 기본 주소를 비워서 내장 TypeSafe 엔드포인트를 사용하며, 커스텀 주소는 버전 접두사를 포함해야 합니다. 예를 들어 `https://api.typesafe.ai/v1`.
4. 최소 품질 점수를 1 에서 10 으로 설정한 후 저장합니다. 첫 번째 결정 모델이 기본 결정 모델이 되며 자동으로 평가를 활성화합니다.
5. 번역을 실행합니다. 실패한 품질 차원은 레포지토리에 구성된 `retries` 예산 내에서 수정 요청을 합니다.

생성형 및 결정 모델은 별도 기본값을 가집니다. 번역 모델 핸들은 변경하지 마십시오. 결정 모델은 레포지토리 번역 핸들이나 언어 라우팅 규칙으로 선택할 수 없습니다. 평가를 비활성화하려면 모든 결정 모델을 제거합니다.
