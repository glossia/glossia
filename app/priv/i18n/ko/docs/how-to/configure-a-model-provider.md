프로젝트 설정과 번역 실행에는 현재 Glossia 계정에 구성된 모델이 사용됩니다. 프로젝트를 생성하기 전에 최소 한 개 모델을 구성해야 합니다.

## 모델 추가

1. **설정**을 열고 **모델**을 선택하세요.
2. **새 모델**을 선택하세요.
3. 고유한 핸들 (예: `translation-default`) 을 입력하세요.
4. 모델 피커를 열고 공급자나 모델 이름의 일부를 입력하여 목록을 필터링하세요.
5. 모델을 선택하고 공급자 키를 입력하세요.
6. 모델을 저장하세요.

핸들은 나중에 제공자 모델을 변경하는 경우에도 안정적입니다. 계정에 추가된 첫 번째 모델이 기본 모델이 됩니다.

## 리포지토리에서 모델 참조

관련 `L10N.md` frontmatter 에 `model` 를 입력하세요:

```yaml
---
model: translation-default
---
```

리포지토리는 핸들만 저장합니다. 공급자 키는 계정 설정에 남아 있습니다.

## 기본으로 사용할 모델 선택

`L10N.md` 가 `model` 를 생략하면 Glossia 는 계정의 기본 모델을 사용합니다. 변경하려면 기본이 되어야 할 모델을 열고 **기본으로 설정** 을 선택하세요.

여러 모델 간의 예측 가능한 동작을 위해 `L10N.md` 에서 명시적으로 핸들을 참조하세요.

하나의 콘텐츠 영역을 위한 중첩된 `L10N.md` 에 다른 `model` 핸들을, 또는 하나의 타겟 로케일을 위한 `L10N/<locale>.md` 에 배치할 수 있습니다. Glossia 는 각 문서와 로케일에 대한 가장 적절한 설정을 사용합니다. 구성된 모델 간에는 작업을 자동 분할하지 않습니다.

명시적인 핸들이 계정에 존재하지 않으면 번역이 오류로 중단됩니다. 다른 모델로 복귀하지 않습니다.

## 공급자 키 변경 또는 교체

**설정**을 열고 **모델**을 선택하고 모델 핸들을 엽니다. 새 공급자 키를 입력하고 저장하세요. 키 필드를 비우면 현재 키가 유지됩니다.

이를 참조하는 리포지토리는 변경할 필요가 없습니다.

## 번역 품질 결정에 Jev 추가

1. **설정 → 모델 → 새 모델**을 열고 **결정** 을 카테고리 선택하세요.
2. `translation-quality` 같은 핸들을 사용하세요. `typesafe/jev-latest` 를 유지하거나 고정된 TypeSafe Jev 모델 버전을 입력하세요.
3. TypeSafe 공급자 키를 입력하세요. 기본 주소를 비우면 네이티브 TypeSafe endpoint 를 사용할 수 있습니다. 커스텀 주소는 버전 접두사를 포함해야 하며, 예를 들어 `https://api.typesafe.ai/v1` 와 같습니다.
4. 최소 품질 점수를 1 에서 10 으로 설정한 후 저장하세요. 첫 번째 결정 모델이 기본 결정 모델이 되어 평가가 자동으로 활성화됩니다.
5. 번역 실행하세요. 실패한 품질 차원은 리포지토리에 구성된 `retries` 예산 내에서 교정을 요청합니다.

생성형 및 결정 모델은 별도의 기본값을 가집니다. 번역 모델 핸들은 변경하지 마세요. 결정 모델은 리포지토리 번역 핸들 또는 로케일 라우팅 규칙으로 선택할 수 없습니다. 평가를 비활성화하려면 모든 결정 모델을 제거하세요.
