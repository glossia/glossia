프로젝트 설정 및 번역 실행은 현재 Glossia 계정에 구성된 모델을 사용합니다. 프로젝트를 생성하기 전에 최소 하나의 모델을 구성해야 합니다.

## 모델 추가

1. **설정** 을 열고 **모델** 을 선택합니다.
2. **새 모델** 을 선택합니다.
3. 고유한 핸들을 입력하며 예시로 `translation-default` 와 같은 값을 사용합니다.
4. 모델 선택기를 열어 공급자 또는 모델 이름의 일부를 입력하여 목록을 필터링합니다.
5. 모델을 선택하고 해당 공급자 키를 입력합니다.
6. 모델을 저장합니다.

핸들은 나중에 나중에 숨겨진 공급자 모델을 변경하더라도 안정적으로 유지됩니다. 계정에 추가된 첫 번째 모델이 기본 모델이 됩니다.

## 저장소에서 모델을 참조합니다.

해당 `L10N.md` 프론트마터 에서 `model` 을 설정합니다:

```yaml
---
model: translation-default
---
```

저장소에는 핸들만 저장됩니다. 공급자 키는 계정 설정에 유지됩니다.

## 기본으로 사용할 모델을 선택합니다.

`L10N.md` 에서 `model` 를 생략할 경우, Glossia 는 계정의 기본 modèle 을 사용합니다. 변경하려면 기본 모델이 되는 모델을 열고 **기본값으로 설정** 을 선택합니다.

여러 모델 간의 예측 가능한 동작을 위해 `L10N.md` 에서 핸들을 명시적으로 참조합니다.

특정 콘텐츠 영역의 `L10N.md` 에 다른 `model` 핸들을 배치하거나, 특정 대상 언어를 위한 `L10N/<locale>.md` 에 배치할 수 있습니다. Glossia 는 각 문서 및 지역에 대해 가장 적합한 설정을 사용합니다. 설정된 모델 간에 작업을 자동으로 분할하지 않습니다.

명시한 핸들이 계정에 존재하지 않으면 번역이 오류로 중단됩니다. 다른 모델로 전환하지 않습니다.

## 공급자 키 변경 또는 회전

**설정** 을 열고, **모델** 을 선택하여 모델 핸들을 엽니다. 새로운 공급자 키를 입력하고 저장합니다. 키 필드를 비우면 현재 키가 유지됩니다.

해당 핸들을 참조하는 저장소는 변경할 필요가 없습니다.

## 번역 품질 결정을 위한 Jev 추가

1. **설정 → 모델 → 새 모델** 을 열고 범주로 **결정** 을 선택합니다.
2. `translation-quality` 와 같은 핸들을 사용합니다. `typesafe/jev-latest` 를 유지하거나 고정된 TypeSafe Jev 모델 버전을 입력합니다.
3. TypeSafe 공급자 키를 입력합니다. 기본 주소를 비우면 기본 TypeSafe 엔드포인트를 사용합니다; 커스텀 주소는 버전 접두사를 포함해야 하며, 예를 들어 `https://api.typesafe.ai/v1` 입니다.
4. 최소 품질 점수를 1 에서 10 사이로 설정한 후 저장합니다. 첫 번째 결정 모델이 기본 결정 모델이 되어 평가가 자동으로 활성화됩니다.
5. 번역을 실행합니다. 실패한 품질 차원은 저장소에서 설정된 `retries` 예산 내에서 수정을 요청합니다.

생성 모델과 결정 모델은 별도의 기본값을 가집니다. 번역 모델 핸들을 그대로 유지하세요. 저장소 번역 핸들 또는 지역 라우팅 규칙으로는 결정 모델을 선택할 수 없습니다. 평가 기능을 비활성화하려면 모든 결정 모델을 제거합니다.
