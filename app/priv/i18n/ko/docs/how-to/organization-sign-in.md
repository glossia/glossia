## 신원 제공자 연결

조직 관리자는 직장 신원 제공자를 **설정 → 인증** 에서 연결할 수 있습니다.

1. **Google Workspace** 또는 **Okta** 를 선택하고 팀의 직장 이메일 도메인을 입력하세요.
2. Okta 에 대해 웹 애플리케이션을 [OpenID Connect](https://developer.okta.com/docs/guides/implement-grant-type/authcode/main/) 를 사용하여 생성하세요. 해당 앱의 발권자, 클라이언트 식별자 및 클라이언트 비밀을 입력하세요. Glossia 는 표준 Okta 기관 발권자 및 `/oauth2/default` 인증 서버를 지원합니다. 비밀값은 암호화되어 저장됩니다. 편집 시 비밀값을 비워두면 저장된 값을 유지합니다.
3. Okta 의 경우 Glossia 에서 표시된 리디렉션 주소를 신원 제공자와 등록하세요. Google Workspace 의 경우 Glossia 가 Google 연결을 관리하므로 Google 애플리케이션을 만들거나 콜백 주소를 등록할 필요가 없습니다.
4. 설정을 저장하세요. 도메인 제공자를 통해 표시된 DNS TXT 기록을 추가한 다음 **도메인 확인** 을 선택하세요. 이메일 도메인을 변경하면 새 확인 토큰이 생성되며, 재확인될 때까지 조직 로그인이 잠기게 됩니다.
5. 팀 구성원은 로그인 페이지에서 직장 이메일을 입력하고 **조직 계속하기** 를 선택하세요. Google Workspace 구성원은 또한 **Google 로 로그인** 를 사용할 수 있습니다.

## Google Workspace 설정

Glossia 가 Google 애플리케이션 자격 증명을 관리합니다. Google Cloud 에서 OAuth 애플리케이션을 만들거나, Google Admin 에서 사용자 지정 SAML 애플리케이션을 추가하거나, 리디렉션 주소를 등록할 필요가 없습니다. 기존 Google Workspace 도메인의 경우 설정은 Glossia 와 도메인 제공자에서 진행됩니다:

1. **설정 → 인증** 에서 **Google Workspace** 를 선택하고 직장 이메일 도메인을 입력한 후 **인증 설정 저장** 을 선택하세요.
2. DNS 를 호스팅하는 제공자에서 도메인의 DNS 설정을 열어 Google Workspace 에 한정하지 마세요. **도메인 소유권 확인** 에서 표시된 기록을 추가하세요:

   | 필드 | 값 |
   | --- | --- |
   | 유형 | `TXT` |
   | 이름/호스트 | Glossia 에서 표시된 **레코드 이름**, 예를 들어 `_glossia-verification.example.com` |
   | 값/내용 | Glossia 에서 표시된 **레코드 값**으로, `glossia-domain-verification=` 로 시작합니다. |

   일부 DNS 제공자는 도메인을 자동으로 추가합니다. 이 경우 도메인이 두 번 포함되지 않도록 호스트에 `_glossia-verification` 만 입력하세요. 확인 후에도 기록을 유지하세요.
3. Glossia 로 돌아가 **도메인 확인** 을 선택하세요. 확인이 실패하면 이름과 값을 확인하고 DNS 변경 사항이 전파될 시간을 허용한 후 다시 시도하세요.
4. 팀 구성원을 로그인 페이지에서 직장 이메일을 입력하고 **조직 계속하기** 를 선택하라고 하거나, **Google 로 로그인** 를 사용하도록 요청하세요.

Glossia 는 Google 의 확인된 이메일과 [호스팅 도메인 클레임](https://developers.google.com/identity/openid-connect/openid-connect#an-id-tokens-payload)을 확인하며, 동일한 이메일 접미사를 가진 개인 Google 계정은 자격이 되지 않습니다.

### Google 이 로그인 차단 시

일반적으로 Google 측 구성이 필요하지 않습니다. 조직이 제 3 자 애플리케이션 액세스를 제한하는 경우, Google Workspace 관리자가 Glossia 를 승인해야 할 수 있습니다:

1. 관리자 계정으로 [Google 관리자 콘솔](https://admin.google.com/) 에 로그인하세요.
2. **보안 → 액세스 및 데이터 제어 → API 제어 → 제 3 자 앱 액세스 관리**로 이동하세요.
3. 액세스된 앱 목록에서 Glossia 를 찾으세요. 해당 앱이 목록에 없는 경우 **새 앱 구성**을 사용하여 앱 이름 또는 OAuth 클라이언트 ID 로 검색하세요. OAuth 클라이언트 ID 는 Glossia 의 공유 Google 연결에 속합니다.
4. 요청된 로그인 권한을 검토하고 조직의 정책에 따라 해당 사용자에게 액세스를 허용하세요. 액세스 수준 및 관리자 요구 사항에 대한 가이드로 Google 의 [제 3 자 및 내부 앱이 Google Workspace 데이터에 액세스하도록 제어](https://support.google.com/a/answer/7281227)를 참조하세요.
5. 정책 변경이 적용되면 직장 계정으로 로그인을 다시 시도하세요.

## 등록 및 권한 관리

정확한 직장 이메일 도메인을 가진 인증된 제공자 신원은 자동으로 조직에 가입됩니다. 기존 Glossia 계정에서 처음으로 Okta 를 연결하는 경우 조직 로그인 시작 전에 기존 방법으로 로그인하세요. 이는 Okta 관리자가 다른 Glossia 계정을 대신할 수 있도록 허용하지 않으면 제공자를 안전하게 연결합니다. 다른 제공자를 통한 공개 등록은 계속 관심 양식을 사용합니다. 제공자를 비활성화하면 기존 멤버십을 삭제하지 않고 조직 로그인 기능을 중지합니다.

새 구성원은 계정의 기본 읽기 액세스 권한을 받고, 조직, 프로젝트, 음성, 어휘, 토론, 및 티켓에 접근합니다. [구성원 권한 관리](/docs/how-to/member-permissions) 를 참조하여 합류 후 추가 액세스를 부여하세요.

## 액세스 보호 장치

도메인 소유권 확인은 30 일 지속되며 매일 자동으로 확인됩니다. 확인 기록을 유지하세요. 만약 사라지면 마지막 성공 확인이 만료되면 로그인 기능이 중지됩니다. 기록을 복원하고 인증 설정으로 다시 확인하세요. 제공자 변경 또는 조직 로그인 비활성화 시 확인이 지워지고 이전 제공자의 자격 증명이 제거됩니다. 확인되지 않은 내역은 도메인을 예약하지 않습니다.

기존 계정인 경우 먼저 기존 방법으로 로그인하고 `/auth/login` 방문하여 직장 신원 연결을 위해 직장 이메일 로그인을 시작하세요. Google 은 이미 연결된 Google 신원과 동일한 제공자 주제를 사용하여도 됩니다. 이메일 주소만 일치하면 기존 계정에 연결되지 않습니다.

구성원을 제거하면 자동 재등록이 차단됩니다. 직장 신원이 여전히 활성화되어 있더라도 관리자가 명시적으로 추가하거나 초대해야 액세스를 복원할 수 있습니다.

구성원 초대 관리, 액세스 자격 증명, 언어 모델 편집, 및 조직 삭제는 관리자의 책임입니다. 이러한 권한은 구성원 범위 확인란을 통해 전책할 수 없습니다. 인증 구성, 도메인 확인, 및 범위 변경은 감사 이벤트를 생성합니다.
