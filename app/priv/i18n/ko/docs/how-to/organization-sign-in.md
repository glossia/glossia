## 신원 제공업체 연결

조직 관리자는 업무 신원 제공업체를 연결하려면 **설정 → 인증**.

1. 선택 **Google Workspace** 또는 **Okta** 그리고 팀의 업무 이메일 도메인을 입력하세요.
2. Okta 의 경우, 웹 애플리케이션을 생성하려면 [OpenID Connect](https://developer.okta.com/docs/guides/implement-grant-type/authcode/main/). 발급자, 클라이언트 식별자 및 클라이언트 시크릿을 입력하세요. Glossia 는 표준 Okta 조직 발급자와 해당 `/oauth2/default` 인증 서버를 지원합니다. 시크릿은 암호화되어 저장됩니다. 수정할 때 시크릿을 비워 두면 저장된 값이 유지됩니다.
3. Okta 의 경우, Glossia 에서 표시된 리디렉션 주소를 인증 제공업체와 등록하세요. Google Workspace 의 경우, Glossia 가 Google 연결을 관리하므로 Google 애플리케이션을 생성하거나 콜백 주소를 등록할 필요가 없습니다.
4. 설정을 저장하세요. 도메인 제공업체를 통해 표시된 DNS TXT 레코드를 추가한 다음, **도메인 확인**. 이메일 도메인을 변경하면 새로운 인증 토큰이 생성되어 검증될 때까지 조직 로그인이 비활성화됩니다.
5. 팀원들은 로그인 페이지에서 업무 이메일을 입력하고 선택합니다. **조직으로 계속하기**. Google Workspace 구성원 또한 사용할 수 있습니다. **Google 로 로그인**.

## Google Workspace 설정

Glossia 는 Google 애플리케이션 자격 증명을 관리합니다. Google Cloud 에서 OAuth 애플리케이션을 생성하거나, Google Admin 에서 사용자 정의 SAML 애플리케이션을 추가하거나, 리디렉션 주소를 등록할 필요가 없습니다. 기존 Google Workspace 도메인의 경우 설정은 Glossia 와 DNS 제공업체에서 처리됩니다:

1. 에서 **설정 → 인증**, 선택 **Google Workspace**회사 이메일 도메인을 입력하고 선택 **인증 설정 저장**.

2. DNS 를 호스팅하는 공급자의 도메인 DNS 설정을 열고, Google Workspace 는 해당되지 않아도 되는 표시된 레코드를 추가하세요 **도메인 소유권 확인**:
   
   | 항목 | 값 |
   | --- | --- |
   | 타입 | `TXT` |
   | 이름 / 호스트 | 이 **레코드 이름** Glossia 에서 표시됩니다. 예를 들어, `_glossia-verification.example.com` |
   | 값 / 내용 | 해당 **레코드 값** Glossia 에서 표시됩니다. 다음처럼 시작합니다. `glossia-domain-verification=` |
   
   DNS 제공업체가 도메인을 자동으로 추가하는 경우, 해당만 입력하세요. `_glossia-verification` 호스트로 입력하여 도메인이 중복되지 않도록 하세요. 검증 후 레코드를 그대로 유지하세요.

3. Glossia 로 복귀하고 선택 **도메인 검증**. 검증이 실패할 경우 이름과 값을 확인하신 후 DNS 변경 사항이 전파될 시간을 기다린 뒤 다시 시도하세요

4. 로그인 페이지에서 팀 동료에게 근무 이메일을 입력하게 하시고 선택하세요 **조직으로 계속**, 또는 사용하거나 **Google 로 로그인**.

Glossia 는 Google 의 검증된 이메일과 [호스팅 도메인 주steller을](https://developers.google.com/identity/openid-connect/openid-connect#an-id-tokens-payload); 동일한 이메일 접미사를 사용하는 개인 Google 계정은 해당되지 않습니다.

### Google 이 로그인을 차단하는 경우

보통 Google 측 설정은 필요하지 않습니다. 귀하의 조직에서 제 3 자 애플리케이션 접근을 제한하는 경우, Google Workspace 관리자는 Glossia 를 승인해야 할 수 있습니다:

1. 다음 관리자 콘솔에서 로그인하여 [Google 관리 콘솔](https://admin.google.com/) 관리자 계정으로.
2. 이동 **보안 → 접근 및 데이터 관리 → API 제어 → 제 3 자 앱 액세스 관리**.
3. 접근한 앱 목록에서 Glossia 를 찾으세요. 목록에 표시되지 않는 경우, 사용 **새 앱 구성** 앱 이름 또는 OAuth 클라이언트 ID 로 검색하여 찾으세요. OAuth 클라이언트 ID 는 Glossia 의 공유 Google 연결 에 속하며, 별도로 생성해야 할 애플리케이션이 아닙니다.
4. 요청된 로그인 권한을 확인하고 조직 정책에 따라 관련 사용자에게 접근 권한을 허용하세요. Google 의 [Google Workspace 데이터 에 접근하는 제 3 자 및 내부 앱 제어](https://support.google.com/a/answer/7281227) 접근 수준 및 관리자 요구 사항 가이드.
5. 정책 변경 적용 후 회사 계정으로 다시 로그인하세요.

## 등록 및 권한 관리

정확히 일치하는 작업 이메일 도메인을 가진 인증된 제공자 신원은 자동으로 조직에 가입합니다. 기존 Glossia 계정이 처음으로 Okta 를 연결하는 경우, 조직 로그인 시작 전에 기존 방법으로 로그인하세요. 이는 Okta 관리자가 다른 Glossia 계정을 장악하는 것을 허용하지 않으면서 제공자를 안전하게 연결합니다. 다른 제공자를 통한 공개 등록은 계속해서 관심사항 폼을 사용합니다. 제공자를 비활성화하면 기존 멤버십을 삭제하지 않고 조직 로그인을 중지합니다.

새로 가입한 멤버는 계정, 조직, 프로젝트, 음성, 용어사전, 토론 및 티켓에 대한 기본 읽기 액세스 권한을 받습니다. 추가 액세스 권한을 부여하려면 그들이 가입한 후 [회원 권한 관리](/docs/how-to/member-permissions) 를 참조하세요.

## 액세스 안전장치

도메인 소유권 인증은 30 일 지속되며 매일 자동으로 확인됩니다. 인증 기록을 유지하십시오. 기록이 사라지면 마지막 성공 인증이 만료될 때 로그인이 중단되므로 기록을 복구하고 인증 설정에서 다시 인증하십시오. 제공자를 변경하거나 조직 로그인을 비활성화하면 인증이 지워지며 이전 제공자의 자격 증명도 제거됩니다. 인증되지 않은 요청은 도메인을 예약하지 않습니다.

기존 계정의 경우 먼저 기존 방법으로 로그인한 다음`/auth/login`을 방문하고 작업 신원을 연결하기 위해 작업 이메일 로그인을 시작하세요. Google 은 동일한 제공자 주제와 함께 이미 연결된 Google 신원을 사용할 수도 있습니다. 이메일 주소만 일치하면 기존 계정은 연결되지 않습니다.

멤버를 제거하면 자동 재등록이 차단됩니다. 그들의 작업 신원이 여전히 활성화되어 있더라도 접근 권한을 복원하려면 관리자가 명시적으로 추가하거나 다시 초대해야 합니다.

멤버 초대 관리, 액세스 자격 증명, 언어 모델 편집, 조직 제거는 여전히 관리자 책임입니다. 이러한 권한은 멤버 범위 체크박스를 통해 위임할 수 없습니다. 인증 구성, 도메인 인증 및 범위 변경사항은 감사 이벤트를 발생시킵니다.
