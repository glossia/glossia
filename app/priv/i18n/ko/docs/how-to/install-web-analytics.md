이 가이드는 분석 설정에서 사이트 도메인이 구성된 Glossia 프로젝트를 가지고 있다고 가정합니다. 수집은 해당 도메인으로 식별되므로 복사할 키 또는 비밀이 없습니다.

## 옵션 A: 스크립트 태그

이 스니펫을 모든 페이지, 특히 `<head>` 태그에 추가하세요:

```html
<script defer data-domain="example.com" src="https://glossia.ai/assets/glossia-web.js"></script>
```

SDK 는 자동으로 초기화되며, 로드 시 페이지 뷰를 보내고 SPA 에서 클라이언트 측 네비게이션 시 후속 페이지 뷰를 기록합니다. 생략 시 `data-domain` 은 `window.location.hostname` 로 기본값이므로, 단일 도메인 사이트에서는 생략할 수 있습니다. 커스텀 수집 엔드포인트를 사용하려면 `data-endpoint="https://collect.your-host.com"` 을 추가하세요.

사이트가 콘텐츠 보안 정책을 사용하는 경우, `https://glossia.ai` 을 `script-src` (또는 존재 시 `script-src-elem`) 와 `connect-src` 모두에서 허용하세요. 스크립트는 `/assets/glossia-web.js` 에서 로드하며, 같은 오리진에서 이벤트는 `/v1/collect` 로 전송됩니다.

## 옵션 B: npm

패키지 설치:

```bash
npm install @glossia/web
```

애플리케이션 진입점 한 번에서 이니셜라이즈하세요:

```ts
import glossia from "@glossia/web";

glossia.init({ endpoint: "https://glossia.ai/v1/collect" });
```

소쿠리 번들로 패키지를 사용할 때 수집 엔드포인트를 명시적으로 설정하세요. 추론할 호스팅된 스크립트 주소가 없기 때문입니다.

`domain` 은 `window.location.hostname` 에서 추론되므로, SDK 는 사이트로 등록한 프로젝트에 기록합니다. 오버라이드하려면 `{ domain: "example.com" }` 을 전달하세요. 예를 들어, 소니 오리진 이벤트를 프로덕션과 같은 프로젝트로 보낼 때.

커스텀 이벤트 기록, 예를 들어 가입:

```ts
glossia.track("signup");
```

## 명시적 언어 선택 기록

방문자의 선택을 브라우저 선호도에서 구분하려면, 네비게이션 전에 언어 선택기의 사용자 동작 핸들러에서 SDK 를 호출하세요:

```js
glossia.selectLanguage("zh-Hans");
```

`glossia.init()` 이후 임포트된 SDK 에서 이 메서드는 사용 가능하고, 호스팅 스크립트 `glossia` 글로벌 환경에서도 사용할 수 있습니다.

대체로, 같은 오리진 언어 전환 링크를 작성하세요:

```html
<a href="/zh-hans/docs" data-glossia-language="zh-Hans">简体中文</a>
```

각 작업당 하나의 통합만 사용하세요, 두 가지를 사용하지 않습니다. 주석 처리된 링크는 키보드 활성화를 포함한 실제 사용자 활성화를 기록합니다. 스크립트 클릭, 다운로드, 수정된 클릭, 크로스 오리진 목적지, 탭이나 프레임을 여는 링크는 네비게이션을阻止하지 않고 무시됩니다.

SDK 는 즉시 `language_selection` 이벤트를 보내고, 후속 이벤트에 선택된 언어 (`cl`) 를 포함합니다. 선택은 다른 선택에 의해 교체될 때까지 현재 탭과 오리지를 위해 `sessionStorage` 에 저장됩니다. 저장소가 사용 불가능하면, 페이지 언로딩까지만 유지됩니다. 리디렉션, URL, 또는 `<html lang>` 변경에서 선택은 추론되지 않습니다.

선택은 성공적인 네비게이션이 아닌 의도를 기록합니다. 브라우저 선호도, 실제 페이지 언어, 명시적 선택은 별도의 것으로 유지됩니다. 수집기는 로컬라이제이션 갭을 계산할 때 브라우저 선호도 대신 유효한 선택을 확인합니다. 선택은 프로젝트 목표, 광고된 번역, 또는 실제 페이지 언어와 일치할 때만 갭을 지웁니다. 사용 불가능한 선택 언어는 여전히 갭이 있습니다. 누락되거나 잘못된 선택은 이전과 같이 브라우저 선호도를 사용합니다. 대시보드 총합 및 뱃지는 각 이벤트의 저장된 결정을 사용하며, 역사적 플래그는 변경되지 않습니다.

## 도메인 확인

프로젝트의 **분석 설정** 에서 사이트 도메인을 저장하세요. 프로젝트의 정확한 레코드 이름과 값을 표시하는 **도메인 소유권 확인** 카드가 있습니다. 도메인 공급업체와 함께 텍스트 레코드를 추가하세요:

| 필드 | 값 |
| --- | --- |
| 유형 | `TXT` ([TXT 레코드](https://www.cloudflare.com/learning/dns/dns-records/dns-txt-record/)) |
| 이름 | `_glossia-verify.example.com` |
| 값 | `glossia-site-verification=YOUR_VERIFICATION_TOKEN` |

설정에서 표시된 도메인 및 토큰을 사용하세요. 일부 공급업체가 도메인을 자동으로 추가하므로 이 경우 이름으로 `_glossia-verify` 만 입력하세요. 레코드를 발행한 후 **도메인 확인** 을 클릭하세요. 변경 사항의 가용 시간이 걸릴 수 있으므로 기록을 즉시 찾지 못하면 다시 시도하세요.

도메인 레코드 편집이 불가능한 경우 **대체: 홈페이지 META 태그로 확인** 을 확장하세요. 생성된 태그를 홈페이지 `<head>` 에 복사하고 발행하세요:

```html
<meta name="glossia-site-verification" content="YOUR_VERIFICATION_TOKEN">
```

각 방법은 설정된 도메인에 대한 통제를 입증합니다. Glossia 는 해당 도메인의 레코드 또는 홈페이지를 확인하므로 토큰을 다른 웹사이트에 복사하는 것은 소유권 확인이 되지 않습니다. 토큰은 공개 증거이지 비밀번호가 아닙니다.

도메인이 확인되면 Glossia 는 추적 스니펫에서 이벤트를 기록하며, 스니펫 단독으로 소유권을 확인하지 않습니다. 설정된 도메인을 변경하려면 다시 확인이 필요합니다.

## 기능 작동 확인

1. 브라우저에서 사이트를 여세요.
2. 네트워크 탭을 열고 `POST` 요청이 `https://glossia.ai/v1/collect` 에 `202 Accepted` 도 반환하는지 확인하세요.
3. 수집 및 처리 후, 페이지 뷰는 프로젝트 대시보드 **분석** 하단에 표시됩니다. 오버뷰 페이지의 번역 실행은 웹 사이트 트래픽과 별개입니다.

`202 Accepted` 응답은 요청이 수집기에 도달했음을 확인합니다. 알려지지 않거나 검증되지 않은 도메인도 수용되지만 이벤트를 기록하지 않으므로 프로젝트 분석 설정으로 설정된 도메인이 확인되었는지 확인하세요.

## 수집 항목

브라우저는 페이지 URL, 리퍼러, `navigator.languages`, 실제 페이지 언어 (`<html lang>`), 광고 번역 (`hreflang` 링크), 관찰 시 명시적으로 선택한 언어, 시간대 및 스크린 너비, 플러스 각 탭 세션 ID 를 보냅니다. 서버는 국가 (GeoIP) 를 추가하고 프로젝트 목표 언어, 광고 번역 및 실제 페이지 언어와 비교하여 로컬라이제이션 갭을 계산합니다. 세션 ID 와 명시 선택은 `sessionStorage` 를 사용하며, 쿠키는 설정되지 않고 지문화되지 않습니다.
