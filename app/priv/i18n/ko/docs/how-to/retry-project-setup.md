자동화된 설정이 실패하면 Glossia 는 잠정 프로젝트를 폐기하여 저장소를 다시 선택할 수 있도록 합니다. 설정 흐름 과정에서 실패 알림이 표시될 수 있지만, 실패한 프로젝트와 그 진행 기록은 유지되지 않습니다.

## 1. 실패 읽기

설정 흐름을 나가기 전에 실패 알림을 읽으십시오. 일반적인 원인은 다음과 같습니다:

- 해당 계정에는 설정된 모델이 없습니다.
- 제공자 키가 누락되었거나 더 이상 유효하지 않습니다.
- Glossia GitHub 앱이 저장소에 액세스할 수 없습니다.
- 저장소를 준비하거나 검증할 수 없습니다.

## 2. 선행 작업 수정

모델 문제의 경우 **설정 → 모델**을 여십시오. 저장소 액세스 문제의 경우 GitHub 에서 Glossia GitHub 앱 설치 상태를 업데이트하고 저장소에 액세스 권한을 부여하십시오.

## 3. 설정 다시 시작

**프로젝트 → 새 프로젝트**을 여셔서 저장소를 선택하고 **자동화 설정**을 선택한 다음 목표 언어를 다시 선택하십시오. 새로운 설정 시도가 완료될 때까지 진행을 따라가십시오.

실패한 프로젝트가 여전히 표시되며 **설정 재시도**를 제공하면 해당 작업은 또 다른 시도를 시작합니다. 지속적으로 사용 가능할 수 있다고 신뢰하지 마십시오: 실패한 잠정 프로젝트는 정리 과정 중에 제거됩니다.

## 4. 완료 검토

설정 완료 후 생성된 풀 리퀘스트를 GitHub 에서 검토하십시오. 수명 주기와 정리 동작에 대해 [프로젝트 설정](/docs/reference/project-setup)을 참조하십시오.
