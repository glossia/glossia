프로젝트 설정 실패 원인을 해결한 후 **설정 다시 실행**을 사용하세요.

## 1\. 실패 확인

프로젝트 개요를 여세요. 설정 진행 카드는 실패 내용과 최신 설정 활동을 표시합니다.

일반적인 원인으로는 다음과 같습니다:

- 계정에 설정된 모델이 없습니다.
- 공급자 키가 누락되었거나 더 이상 유효하지 않습니다.
- Glossia GitHub App 이 저장소에 액세스할 수 없습니다.
- 저장소를 준비하거나 검사할 수 없습니다.

## 2\. 필수 조건 수정

모델 문제가 있는 경우 **설정**과 **모델**을 여세요. 저장소 액세스 문제가 있는 경우 GitHub 에서 Glossia GitHub App 설치 항목을 업데이트하고 저장소에 액세스할 수 있는 권한을 부여하세요.

## 3\. 재시도

프로젝트 개요로 돌아가서 **설정 다시 실행**을 선택하세요.

카드는 **대기 중** 으로 되돌린 후 **진행 중** 으로 변경되며, 작업 진행 시 새 활동이 표시됩니다. 재시도는 프로젝트가 **실패** 상태일 때만 가능하며, 이는 두 설정 시도가 동시에 실행되는 것을 방지합니다.

## 4\. 완료 확인

상태가 **완료됨** 으로 변경되면 GitHub 에서 생성된 Pull request 를 검토하세요. 다시 실패할 경우 이전 시도 대신 카드의 새활동을 사용하여 다음 조치를 식별하세요.
