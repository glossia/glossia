자동화된 설치 실패 시 Glossia 는 임시 프로젝트를 삭제하여 저장소를 다시 선택할 수 있도록 합니다. 설치 흐름에서 실패 표시가 나타날 수 있지만, 실패한 프로젝트와 진행 상태 기록은 유지되지 않습니다.

## 1. 실패 읽기

설치 흐름을 떠나기 전에 실패 표시를 확인하세요. 일반적인 원인은 다음과 같습니다:

- 계정에서 모델이 설정되지 않았습니다.
- 제공자 키가 누락되었거나 더 이상 유효하지 않습니다.
- Glossia GitHub App 이 저장소에 접근할 수 없습니다.
- 저장소에서 준비 또는 확인이 실패했습니다.

## 2. 전제 사항 해결

모델 문제인 경우 **Settings → Models** 를 열어 보세요. 저장소 접근 문제인 경우 GitHub 에서 Glossia GitHub App 설치 설정을 업데이트하고 해당 저장소에 접근 권한을 부여하세요.

## 3. 설치를 다시 시작

**Projects → New project** 를 열어, 저장소를 선택하고 **Automated setup** 을 선택한 다음 대상 언어를 다시 선택하세요. 새로운 설치 시도를 완료할 때까지 진행하세요.

실패한 프로젝트가 여전히 보이고 **Retry setup** 를 제공한다면, 해당 동작으로 또 다른 시도가 시작됩니다. 해당 사항이 계속 이용 가능한 것으로 의존하지 마세요: 실패한 임시 프로젝트는 정리 중에 제거됩니다.

## 4. 완료 확인

설치가 완료되면 GitHub 에서 생성된 풀리를 확인하세요. 생명주기와 정리 동작에 대해서는 [Project setup](/docs/reference/project-setup) 을 참조하세요.
