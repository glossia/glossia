프로젝트 설정 실패를 유발한 조건을 고친 후 **설립 재시도**를 사용하세요.

## 1\. 실패 확인

프로젝트 개요를 여세요. 설치 진행 카드는 실패와 최신 설치 활동을 표시합니다.

주요 원인은 다음과 같습니다:

- 계정에 구성된 모델이 없습니다.
- 제공업체 키가 누락되거나 더 이상 유효하지 않습니다.
- Glossia GitHub 앱이 저장소에 액세스할 수 없습니다.
- 저장소를 준비하거나 확인할 수 없습니다.

## 2\. 전제 조건 수정

모델 문제의 경우 **설정**과 **모델**을 여세요. 저장소 액세스 문제의 경우 GitHub에서 Glossia GitHub 앱 설치본을 업데이트하고 저장소에 액세스 권한을 부여하세요.

## 3\. 재시도

프로젝트 개요로 돌아가 **설립 재시도**를 선택하세요.

카드는 **보류** 상태로 돌아갔다가 **진행 중**이 되며, 작업이 진행됨에 따라 새로운 활동이 표시됩니다. 프로젝트가 **실패** 상태인 경우에만 재시도가 가능하여, 동시에 두 번의 설치 시도가 실행되는 것을 방지합니다.

## 4\. 완료 확인

상태가 **완료**로 변경되면 GitHub에서 해당 풀 요청을 검토하세요. 다시 실패하면 이전 시도 대신 카드의 새로운 활동을 사용하여 다음 다음 조치를 식별하세요.
