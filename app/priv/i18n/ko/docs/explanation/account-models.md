Glossia 는 저장소 지시사항을 모델 제공자 인증 정보에서 분리합니다. 저장소는 번역해야 할 소재가 무엇인지 설명하고, 계정은 다음을 결정합니다[대용량 언어 모델](https://en.wikipedia.org/wiki/Large_language_model)작업을 수행합니다.

## 모델이 계정에 소속되는 이유

팀 은 동일한 제공업체 관계를 가진 여러 저장소를 자주 번역합니다. 계정 범주 모델은 관리자가 모든 저장소를 편집하지 않고 한 번에 제공업체 키를 회전하거나 기반 모델을 변경할 수 있게 합니다.

이 경계는 또한 인증 정보를 소스 관리에서 분리합니다. 저장소는 읽기 가능한 핸들의 예를 갖습니다`translation-default`, 제공업체 키가 아님.

## 핸들은 안정적인 의도를 제공하며

해당`model` 필드 내 `GLOSSIA.md`, 계정 모델 핸들을 가리킵니다:

```yaml
model: translation-default
```

핸들 은 저장소의 의도를 표현합니다. 관리자는 나중에 저장소 설정이 안정적으로 유지되면서 해당 핸들이 선택하는 제공업체 모델을 업데이트할 수 있습니다.

## 여러 모델 사용 방법

Glossia 는 각 문서 번역마다 하나의 설정된 모델을 사용합니다. 여러 모델을 추가해도 앙상블이나 대체 체인, 또는 자동 품질 계층은 만들지 않습니다. 저장소 작성자는 안정적인 핸들을 통해 목적을 선택하며`translation-default`, `long-form`, 또는 `japanese-specialist`.

선택은 문서와 타겟 로케일의 컨텍스트 계층을 따릅니다:

1. 가장 가까운`GLOSSIA/<locale>.md` 파일을 선언하는 `model` 해당 로케일에서 우선합니다.
2. 그렇지 않으면 가장 가까운`GLOSSIA.md` 파일을 선언하는 `model` 해당 디렉토리에서 우선합니다.
3. 부모`GLOSSIA.md` 설정이 더 가까운 파일이 모델을 선언하지 않을 때 물려받습니다.
4. 적용 가능한 컨텍스트 파일이 핸들을 선언하지 않으면, Glossia 는 기본 계정 설정을 사용합니다.

명시적으로 구성된 핸들이 존재해야 합니다. Glossia 는 알려지지 않은 핸들에 대해 오류를 보고하여 계정 기본값으로 침묵적으로 전환하지 않습니다.

## 기본 선택

프로젝트 설정은 저장소가 자체`GLOSSIA.md` . Glossia 는 이에 따라 기본 계정을 선택합니다. 계정 에 추가된 첫 번째 모델 은 기본 모델 이 되며, 관리자는 설정 페이지 에서 다른 모델을 기본 설정 으로 만들 수 있습니다.

저장소가`GLOSSIA.md`, 명시적인 핸들을 사용하면 리뷰어로 선택이 명확해집니다. 생략하는 경우`model` 저장소 를 기본 계정 에 유지합니다.

## 인간 검토의 경계

모델 출력은 제안된 작업이지 자동 병합이 아닙니다. 설정 및 번역 활동 은 Glossia 에서 가시적으로 유지되며, 저장소 변경은 팀이 검토하기 위해 Pull Request 를 통해 발행됩니다. 이는 팀이 이미 코드에 사용하는 동일의 품질 및 소유권 경계를 유지합니다.
