Glossia 는 저장소 지시사항과 모델 제공자 자격 증명을 분리합니다. 저장소는 번역할 내용을 기술하며, 계정은 무엇을 [대규모 언어 모델](https://en.wikipedia.org/wiki/Large_language_model) 작업을 수행합니다.

## 모델이 계정에 속하는 이유

팀은 종종 동일한 제공자 관계를 가진 여러 저장소를 번역합니다. 계정 단위 모델은 관리자가 모든 저장소를 수정하지 않고도 한 번에 제공자 키를 회전하거나 기본 모델을 전환할 수 있습니다.

이 경계는 또한 자격 증명을 소스 제어 밖으로 유지합니다. 저장소는 읽을 수 있는 핸들 예를 들어 `translation-default`, 제공자 키가 아닙니다.

## 핸들은 안정적인 의도를 제공합니다.

해당 `model` 필드는 `L10N.md` 계정 모델 핸들을 나타냅니다:

```yaml
model: translation-default
```

핸들은 레포지토리의 의도를 나타냅니다. 이후 레포지토리 설정이 유지되더라도 관리자는 해당 핸들이 선택하는 제공자 모델을 변경할 수 있습니다.

## 여러 모델의 사용 방법

Glossia 는 각 문서 번역마다 설정된 하나의 모델만 사용합니다. 여러 모델을 추가한다고 해서 앙상블, 폴백 체인 또는 자동 품질 등급이 생성되지 않습니다. 저장소 작성자는 안정적인 핸들을 통해 목적을 선택합니다. 예를 들어 `translation-default`, `long-form`또는 `japanese-specialist`.

선택은 문서 및 대상 로케일의 컨텍스트 계층 구조를 따릅니다:

1. 가장 가까운 `L10N/<locale>.md` 선언하는 파일 `model` 해당 로케일에 우선합니다.
2. 그렇지 않으면, 가장 가까운 `L10N.md` 선언하는 파일 `model` 해당 디렉토리에 우선합니다.
3. 상위 `L10N.md` 보다 구체적인 파일이 모델을 명시하지 않을 경우 설정은 상속됩니다.
4. 적용 가능한 컨텍스트 파일에 핸들이 명시되지 않으면, Glossia 는 계정 기본값을 사용합니다.

명시적으로 구성된 핸들은 존재해야 합니다. Glossia 는 미지의 핸들에 대해 계정 기본값으로 소리 없이 전환하는 대신 오류를 보고합니다.

## 기본 선택

프로젝트 설정은 리포지토리가 자체 모델을 갖기 전에 모델이 필요합니다. `L10N.md`. 따라서 Glossia 는 계정 기본값을 선택합니다. 계정에 추가된 최초의 모델이 기본값이 되며, 관리자는 설정 페이지에서 다른 모델을 기본값으로 변경할 수 있습니다.

리포지토리가 갖게 되면 `L10N.md`, 명시된 핸들을 사용하면 리뷰어가 선택을 명확히 알 수 있습니다. 생략하는 경우 `model` 저장소를 계정의 기본값으로 유지합니다.

## 인간 검토의 경계

모델 출력은 제안된 작업이며 자동 병합 대상이 아닙니다. 설정 및 번역 활동은 Glossia 에서 계속 표시됩니다. 저장소 변경 사항은 팀 검토를 위해 Pull Request 를 통해 게시되므로 팀이 이미 코드에 적용해온 품질 및 소유권 경계를 유지합니다.
