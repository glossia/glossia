Glossia 는 저장소의 지시사항과 모델 공급자 인증정보를 구분합니다. 저장소는 무엇을 번역할지 서술하고 계정은 작업을 수행할 [대규모 언어 모델](https://en.wikipedia.org/wiki/Large_language_model) 을 결정합니다.

## ## 계정에 속한 모델의 이유

팀이 종종 동일한 공급자 관계로 여러 저장소를 번역합니다. 계정 범위의 모델은 관리자가 공급자 키를 교체하거나 모든 저장소를 수정하지 않고 한 번에 기반 모델을 전환할 수 있게 합니다.

이 경계는 또한 인증정보를 소스 제어 범위에 그치게 합니다. 저장소는 `translation-default` 와 같은 읽기 가능한 핸들을 포함하며 공급자 키는 아닙니다.

## ## 핸들은 안정적인 의도를 제공합니다

`L10N.md` 에 포함된 `model` 필드는 계정 모델 핸들을 참조합니다:

```yaml
model: translation-default
```

핸들은 저장소의 의도를 나타냅니다. 관리자는 저장소 설정이 안정적으로 유지되는 동안 해당 핸들이 선택하는 공급자 모델을 나중에 업데이트할 수 있습니다.

## ## 여러 모델의 사용 방식

Glossia 는 각 문서 번역마다 하나의 구성된 **생성형** 모델을 사용합니다. 여러 모델을 추가해도 앙상블이나 백업 사슬이나 자동 품질 단계를 만들지 않습니다. 저장소 작성자는 저장용량, `translation-default`, `long-form`, or `japanese-specialist` 와 같은 안정적인 핸들을 통해 목적을 선택합니다.

선택은 문서와 대상 로케일의 컨텍스트 계층을 따릅니다:

1. 해당 로케일에서 `model` 를 선언하는 가장 가까운 `L10N/<locale>.md` 파일이 승리합니다.
2. 아니면, `model` 를 선언하는 가장 가까운 `L10N.md` 파일이 해당 디렉토리에 승리합니다.
3. 더 가까운 파일에서 모델을 선언하지 않으면 상위 `L10N.md` 설정이 상속됩니다.
4. 적용 가능한 컨텍스트 파일이 핸들을 선언하지 않으면 Glossia 는 계정 기본 생성형 모델을 사용합니다.

명시적으로 구성된 핸들은 반드시 존재해야 합니다. Glossia 는 계정 기본으로 조용히 전환하는 대신 알려지지 않은 핸들에 대해 오류를 보고합니다.

## ## 기본 선택

저장소가 자신의 `L10N.md` 를 가지기 전에 프로젝트 설정에는 모델이 필요합니다. 따라서 Glossia 는 계정 기본을 선택합니다. 각 카테고리에 추가된 첫 번째 모델이 해당 카테고리의 기본이 되며, 관리자는 설정 페이지를 통해 다른 모델을 기본으로 변경할 수 있습니다.

저장소에 `L10N.md` 가 있는 경우 명시적 핸들을 사용하면 선택 사항이 검토자에게 명확해집니다. `model` 를 누락하면 저장소는 계정 기본을 유지합니다.

## ## 생성형과 결정 모델

모델 구성은 두 가지 범주로 나뉩니다:

- **생성형** 모델은 번역을 작성하고 프로젝트 설정을 지원합니다. 저장소 모델 핸들과 로케일 라우팅 규칙은 이 범주의 선택만 합니다.
- **결정** 모델은 고정된 품질 규범 기준에 번역을 평가합니다. 계정에 결정 모델이 있는 경우 해당 기본 결정 모델이 구조 유효성 검사 및 콘텐츠 엔드포인트에서 완료된 단일 문서 번역 후 각 번역된 저장소 문서를 자동으로 확인합니다. 파편 요청은 생성 기본 요소이며, 저장소 실행은 조립된 출력을 평가합니다.

범주는 각각 독립적인 기본값을 가집니다. Jev 를 추가해도 번역을 작성하는 모델을 변경하지 않습니다. 첫 번째 결정 모델은 후속 번역 실행 평가를 활성화하며 마지막 디렉트를 삭제하면 평가를 비활성화합니다. 결정 모델이 없는 계정은 기존 동작을 유지합니다.

Glossia 는 현재 [TypeSafe Jev](https://docs.typesafe.ai/introduction) 을 결정 공급자로 지원합니다. Jev 는 문장 대신 사전 정의된 선택지와 점수를 반환합니다. Glossia 는 약점 선택을 교정 힌트로 변환하면 위치가 지정되거나 독립적으로 검증된 오류로 제시하지 않습니다.

## ## 품질 검토 및 수정

평가자는 원본 텍스트, 번역, 대상 로케일, 콘텐츠 형식, 프로젝트 지시사항 및 해결된 조직 컨텍스트를 받습니다. 의미 보존, 완성도, 용어, 유창성, 문서 일관성, 목적과 대상 적합성, 그리고 로케일 적절성을 평가합니다. 음성 톤과 레지스터는 음성, 프로젝트 또는 문서 가이드가 제공될 때 평가됩니다.

각 차원은 구성된 최소 점수에 도달해야 하며 기본값은 10 점中的 7 점입니다. 주요 또는 치명적 오류는 점수 무관하게 교정을 항상 요청합니다. 신뢰도는 실시간 평가 이벤트에 포함되지만 합격 여부는 변경하지 않습니다. 이러한 이벤트는 현재 대시보드에 보유되거나 표시되지 않습니다. 임계값 10 은 완벽한 가중 점수가 필요하며 보통 너무 엄격합니다.

실패한 차원은 미리 정의된 교정 힌트를 다음 번역 시도로 전달합니다. 저장소의 기존 `retries` 설정은 이러한 수정을 제한하며; 콘텐츠 엔드포인트는 `retries` 필드를 통해 0 에서 3 회 교정 재시도를 허용합니다. 전체 수정 문서는 수용되기 전에 구조적 검토와 품질 평가를 다시 거치게 됩니다.

일시적 공급자 오류는 세 번까지 지수적 백오프로 재시도됩니다. 유효하지 않은 인증정보 및 잘못된 형식의 응답은 즉시 실패합니다. 사용된 공급자 오류는 파일 번역을 중단하며 확인되지 않은 출력은 승인되지 않습니다. 평가는 전체 문서를 사용하며, 지나치게 큰 평가 입력은 폐기됨이 아닌 단축되지 않고 거부됩니다. 직렬화된 입력은 상태 및 가장 긴 질문을 위해 보수적으로 30,000 바이트로 제한되며 전체 요청을 거쳐 [Jev 의 컨텍스트 한계](https://docs.typesafe.ai/models) 내에 60,000 바이트로 유지됩니다. 자동 점수는 모델 판단이며 여전히 양국어 인간 검토와 비교하여 보정해야 합니다.

평가자 설정과 규범 버전은 번역 잠금 파일에 참여합니다. 평가를 활성화하거나 모델이나 임계치 변경, 또는 평가를 제거하면 이전 번역 결과가 다음 실행에서 상거로 간주됩니다. 공급자 키는 잠금 파일에서 제외됩니다.

## ## 인간 검토 경계

모델 출력은 제안된 작업이며 자동 병합이 아닙니다. 설정 및 번역 활동은 Glossia 에서 계속 가시적으로 유지되지만, 저장소 변경 사항은 팀이 검토할 수 있는 pull request 를 통해 게시됩니다. 이는 이미 코드에 사용하는 팀의 동일한 품질 및 소유권 경계를 유지합니다.
