Glossia 는 저장소 지시사항과 모델 제공자 자격 증명을 분리합니다. 저장소는 번역할 항목을 설명하며, 계정은 어떤 [대형 언어 모델](https://en.wikipedia.org/wiki/Large_language_model) 작업을 수행합니다.

## 모델이 계정에 속하는 이유

팀은 종종 동일한 제공자 관계를 가진 여러 리포지토리를 번역합니다. 계정 범위의 모델은 관리자가 모든 리포지토리를 편집하지 않고 한 번에 제공자 키를 회전하거나 기본 모델을 변경할 수 있게 합니다.

이 경계는 또한 자격 증명을 소스 코드 관리 밖으로 유지합니다. 리포지토리는 읽을 수 있는 핸들, 예를 들어 `translation-default`, 제공자 키가 아닙니다.

## 핸들은 안정적인 의도를 제공합니다.

이 `model` 필드 `L10N.md` 계정 모델 핸들에 해당합니다:

```yaml
model: translation-default
```

핸들은 레포지토리의 의도를 나타냅니다. 관리자는 이후 핸들이 선택하는 제공자 모델을 변경할 수 있으며 레포지토리 설정은 안정적으로 유지됩니다.

## 여러 모델 사용 방법

Glossia 는 각 문서 번역마다 하나의 설정된 모델을 사용합니다. 여러 모델을 추가하면 앙상블, 대체 체인, 또는 자동 품질 계층이 생성되지 않습니다. 레포지토리 작성자는 안정적인 핸들을 통해 목적을 선택합니다, 예 `translation-default`, `long-form`또는 `japanese-specialist`.

선택은 문서 및 대상 로케일의 컨텍스트 계층 구조를 따릅니다.

1. 가장 가까운 `L10N/<locale>.md` 로케일을 선언하는 파일이 `model` 해당 로케일에서 우선됩니다.
2. 그렇지 않으면 가장 가까운 `L10N.md` 로케일을 선언하는 파일이 `model` 해당 디렉토리에서 우선됩니다.
3. 부모 `L10N.md` 상위 파일 이 모델을 선언하지 않으면 설정 이 상속됩니다.
4. 적용 가능한 컨텍스트 파일이 핸들을 선언하지 않을 때 Glossia 는 계정 기본 설정 을 사용합니다.

명시적으로 구성된 핸들은 존재해야 합니다. Glossia 는 알려지지 않은 핸들의 경우 오류 를 보고하며, 대신 계정의 기본 설정 으로 묵시적으로 전환하지 않습니다.

## 기본 선택

프로젝트 설정 은 저장소가 자체 모델을 갖기 전에 모델 이 필요합니다 `L10N.md`.". 따라서 Glossia 는 계정 기본 설정 을 선택합니다. 계정에 추가된 첫 번째 모델 은 기본 설정 으로 됩니다. 관리자는 설정 페이지 에서 다른 모델을 기본 설정 으로 만들 수 있습니다.

저장소가 모델을 갖는 경우 `L10N.md`, 명시적인 핸들을 사용하면 선택이 검토자들에게 명확해집니다. 생략하는 `model` 계정의 기본값으로 저장소를 유지합니다.

## 인적 검토의 경계

모델의 출력은 제안된 작업이며 자동 병합이 아닙니다. 설정 및 번역 활동은 Glossia 에서 계속 표시됩니다. 저장소 변경 사항은 팀 검토를 위해 풀 리퀘스트로 게시됩니다. 이는 팀이 코드 작업을 위해 평소 사용하던 품질 및 소유권 경계를 그대로 유지합니다.
