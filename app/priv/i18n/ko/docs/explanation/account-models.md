Glossia 는 저장소 지시사항과 모델 제공자 자격 증명을 분리합니다. 저장소는 번역해야 할 내용을 기술하며, 계정은 무엇을 선택합니다 [대규모 언어 모델](https://en.wikipedia.org/wiki/Large_language_model) 작업을 수행합니다.

## 모델이 계정에 속해야 하는 이유

팀이 종종 동일한 공급자 관계를 가진 여러 저장소를 번역합니다. 계정 범위의 모델은 관리자가 모든 저장소를 수정하지 않아도 공급자 키를 교체하거나 기본 모델을 한 번에 전환할 수 있게 합니다.

이 경계는 또한 인증 정보를 소스 관리 밖으로 격리합니다. 저장소는 읽기 가능한 핸들, 예를 들어 를 포함합니다. `translation-default`공급자 키가 아닙니다.

## 핸들은 안정된 의도를 제공합니다.

해당 `model` 필드 `L10N.md` 계정 모델 핸들을 의미합니다:

```yaml
model: translation-default
```

핸들은 저장소의 의도를 나타냅니다. 관리자는 나중에 저장소 구성이 안정적으로 유지되는 동안 해당 핸들이 선택하는 제공자 모델을 업데이트할 수 있습니다.

## 여러 모델이 사용되는 방법

Glossia 는 각 문서 번역마다 하나의 구성된 모델을 사용합니다. 여러 모델을 추가하더라도 앙상블, 대체 체인, 또는 자동 품질 등급을 생성하지 않습니다. 저장소 작성자는 안정적인 핸들 (예를 들어) 을 통해 목적을 선택합니다. `translation-default`, `long-form`, 또는 `japanese-specialist`.

선택은 문서와 대상 로케일의 컨텍스트 계층 구조를 따릅니다:

1. 가장 가까운 `L10N/<locale>.md` 선언하는 파일 `model` 해당 로кен에서 우선합니다.
2. 그렇지 않으면, 가장 가까운 `L10N.md` 선언하는 파일 `model` 해당 디렉터리에서 우선합니다.
3. 부모 `L10N.md` 모델이 명시되지 않은 더 가까운 파일이 있을 때 설정은 상속됩니다.
4. 적용 가능한 컨텍스트 파일이 핸들을 선언하지 않을 경우 Glossia 는 계정 기본값을 사용합니다.

명시적으로 구성된 핸들은 반드시 존재해야 합니다. Glossia 는 알려지지 않은 핸들에 대해 오류를 보고하며, 대신 조용히 계정 기본값으로 전환하지 않습니다.

## 기본 선택

프로젝트 설정은 레포지토리에 자체 모델을 갖기 전에 모델을 갖춰야 합니다. `L10N.md`. Glossia 는 따라서 계정 기본값을 선택합니다. 계정에 추가된 첫 번째 모델이 기본이 되며, 관리자는 설정 페이지에서 다른 모델을 기본으로 만들 수 있습니다.

레포지토리가 갖는 경우 `L10N.md`명시적인 핸들을 사용하면 리뷰어가 선택이 명확해집니다. 생략하는 경우 `model` 계정 기본값으로 저장소를 유지합니다.

## 인간 검토의 경계

모델 출력은 제안된 작업이며 자동 병합이 아닙니다. 설정 및 번역 활동은 Glossia 에서 계속 표시됩니다. 저장소 변경 사항은 팀 검토를 위해 Pull Request 를 통해 게시됩니다. 이는 팀이 코드를 사용할 때 이미 사용하는 품질과 소유권 경계를 유지합니다.
