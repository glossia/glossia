Glossia 는 리포지토리 지시사항과 모델 제공자 자격 증명을 분리합니다. 리포지토리는 번역해야 할 내용을 설명하고, 계정은 무엇을 [대규모 언어 모델을](https://en.wikipedia.org/wiki/Large_language_model) 작업을 수행합니다.

## 모델이 계정에 속하는 이유

팀 은 종종 동일한 공급자 관계를 가진 여러 리포지토리를 번역합니다. 계정 범위 내 모델은 관리자가 모든 리포지토리를 수정하지 않고 한 번에 공급자 키를 회전하거나 기반 모델을 변경할 수 있게 합니다.

이 경계 는 또한 인증 정보를 소스 제어 에서 제외합니다. 리포지토리는 가독성 있는 핸들, 예를 들어 `translation-default`, 공급자 키가 아닙니다.

## 핸들은 안정적인 의도를 제공합니다.

이 `model` 필드 내 `L10N.md` 는 계정 모델 핸들을 참조합니다:

```yaml
model: translation-default
```

해당 핸들은 리포지토리의 의도를 표현합니다. 관리자는 리포지토리 구성이 안정적으로 유지되는 동안 나중에 해당 핸들이 선택하는 공급자 모델을 업데이트할 수 있습니다.

## 여러 모델이 어떻게 사용되는지

Glossia 는 각 문서 번역마다 하나의 설정된 모델을 사용합니다. 여러 모델을 추가해도 앙상블, 대체 체, 또는 자동 품질 계층을 생성하지 않습니다. 저장소 작성자는 안정적인 핸들과 같은 `translation-default`, `long-form`, 또는 `japanese-specialist`.

선택은 문서와 대상 로컬의 컨텍스트 계층 구조를 따릅니다:

1. 가장 가까운 `L10N/<locale>.md` 선언하는 파일 `model` 해당 로컬에서 우선합니다.
2. 그렇지 않으면, 가장 가까운 `L10N.md` 선언하는 파일 `model` 해당 디렉토리를 우선합니다.
3. 부모 설정 `L10N.md` 가까운 파일이 모델을 선언하지 않을 때 설정은 상속됩니다.
4. 적용 가능한 컨텍스트 파일이 handle 을 선언하지 않을 때 Glossia 는 계정 기본값을 사용합니다.

명시적으로 구성된 handle 은 반드시 존재해야 합니다. Glossia 는 알려지지 않은 handle 의 경우 계정 기본값으로 알림 없이 전환하는 대신 오류를 보고합니다.

## 기본 선택

프로젝트 설정은 저장소가 자체 모델을 보유하기 전에 모델이 필요합니다 `L10N.md`. 따라서 Glossia 는 계정 기본값을 선택합니다. 계정에 추가된 첫 번째 모델이 기본값이 되며, 관리자는 설정 페이지에서 다른 모델을 기본값으로 설정할 수 있습니다.

저장소가 갖을 때 `L10N.md`,명시적인 핸들을 사용하면 검토자가 선택을 명확히 할 수 있습니다. 생략하는 경우 `model` 계정 기본값으로 저장소를 유지합니다.

## 인간 검토 경계

모델 출력은 제안된 작업이며 자동 병합이 아닙니다. 설정 및 번역 활동은 Glossia 에서 가시적으로 유지되고, 저장소 변경은 팀 검토를 위해 병합 요청을 통해 게시됩니다. 이는 팀이 코드에 이미 사용하는 것과 동일한 품질 및 소유권 경계를 유지합니다.
