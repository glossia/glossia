Glossia 는 레포지토리 지침과 모델 제공자 자격 증명을 분리합니다. 레포지토리는 번역할 내용을 설명하고, 계정은 어떤 [large language model](https://en.wikipedia.org/wiki/Large_language_model) 작업을 수행합니다.

## 모델이 계정에 속하는 이유

팀은 종종 같은 공급자 관계로 여러 저장소를 번역합니다. 계정 단위 모델은 관리자가 공급자 키를 교체하거나 기본 모델을 한 번 변경하여 모든 저장소를 수정하지 않아도 됩니다.

이 경계는 또한 자격 증명을 소스 컨트롤 밖으로 유지합니다. 저장소에는 읽을 수 있는 핸들, 예: `translation-default`, 공급자 키가 아닙니다.

## 핸들은 안정적인 의도를 제공합니다.

해당 `model` 필드 내 `L10N.md` 는 계정 모델 핸들을 가리킵니다:

```yaml
model: translation-default
```

이 핸들은 저장소의 의도를 표현합니다. 관리자는 저장소 설정이 안정적으로 유지되는 동안 해당 핸들이 선택하는 제공자 모델을 나중에 업데이트할 수 있습니다.

## 여러 모델이 어떻게 사용되는가

Glossia 는 각 문서 번역마다 설정된 하나의 모델을 사용합니다. 여러 모델을 추가해도 앙상블, 대체 체인, 또는 자동 품질 등급이 생성되지 않습니다. 저장소 작성자는 안정적인 핸들 등을 통해 목적을 선택합니다. `translation-default`, `long-form`, 또는 `japanese-specialist`.

선택은 문서와 대상 로케일의 컨텍스트 계층 구조를 따릅니다:

1. 가장 가까운 `L10N/<locale>.md` 설정을 명시하는 파일은 `model` 해당 로케일에서 우선 적용됩니다.
2. 그렇지 않으면 가장 가까운 `L10N.md` 설정을 명시하는 파일은 `model` 해당 디렉터리에서 우선 적용됩니다.
3. 상위 `L10N.md` 더 가까운 파일에 모델이 명시되지 않았을 때 설정이 상속됩니다.
4. 적용 가능한 맥락 파일에서 핸들이 선언되지 않으면, Glossia 는 계정 기본값을 사용합니다.

명시적으로 구성된 핸들은 존재해야 합니다. Glossia 는 알려지지 않은 핸들에 대해 오류를 보고하며, 계정 기본값으로 조용히 전환하지 않습니다.

## 기본 선택

프로젝트 설정은 저장소가 자체 모델을 가지기 전에 모델을 필요로 합니다. `L10N.md`따라서 Glossia 는 계정 기본값을 선택합니다. 계정에 추가된 첫 번째 모델이 기본값이 되며, 관리자 는 설정 페이지 에서 다른 모델을 기본값으로 설정할 수 있습니다.

저장소가 갖은 경우 `L10N.md`, 명시적 핸들을 사용하면 리뷰어들이 선택을 명확히 알 수 있습니다. 생략하는 경우. `model` 계정의 기본값으로 저장소를 유지합니다.

## 인간 검토의 경계

모델 출력은 제안된 작업이며, 자동 병합이 아닙니다. 설정 및 번역 활동은 Glossia 에서 계속 표시됩니다. 저장소 변경은 팀이 검토할 수 있도록 Pull Request 를 통해 게시됩니다. 이는 팀이 코드에 이미 사용하는 동일한 품질 및 소유권 경계를 유지합니다.
