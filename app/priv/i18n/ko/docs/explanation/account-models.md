Glossia 는 레포지토리 지침과 모델 제공자 자격 증명을 분리합니다. 레포지토리는 번역해야 할 내용을 설명하고, 계정이 어떤 [대규모 언어 모델을](https://en.wikipedia.org/wiki/Large_language_model) 작업을 수행합니다.

## 모델이 계정에 속해야 하는 이유

팀은 종종 같은 제공자 관계를 가진 여러 레포지토리를 번역합니다. 계정 범위의 모델은 관리자가 모든 저장소를 편집하지 않고 한 번에 제공자 키를 회전하거나 기반 모델을 변경할 수 있게 합니다.

이 경계는 자격 증명을 소스 관리 밖으로 유지합니다. 레포지토리에 가독성 있는 핸들은 예를 들어 `translation-default`, 공급자 키가 아닙니다.

## 핸들은 안정적인 의도를 제공합니다.

해당 `model` 필드는 `L10N.md` 계정 모델 핸들을 지시합니다:

```yaml
model: translation-default
```

이 핸들은 레포지토리의 의도를 나타냅니다. 관리자는 나중에 해당 핸들에서 선택하는 제공자 모델을 업데이트할 수 있으며, 레포지토리 설정은 안정적으로 유지됩니다.

## 여러 모델을 사용하는 방법

Glossia 는 각 문서 번역에 하나의 설정된 모델을 사용합니다. 여러 모델을 추가해도 앙상블, 폴백 체인 또는 자동 품질 계층을 생성하지 않습니다. 저장소 작성자는 안정적인 핸들 등을 통해 목적을 선택합니다 `translation-default`, `long-form`, 또는 `japanese-specialist`.

선택은 문서 및 대상 locale 의 컨텍스트 계층 구조를 따릅니다:

1. 가장 가까운 `L10N/<locale>.md` 선언하는 파일은 `model` 해당 locale 에 우선합니다.
2. 그 외에는 가장 가까운 `L10N.md` 선언하는 파일은 `model` 해당 디렉토리에 우선합니다.
3. 상위 항목 `L10N.md` 가장 가까운 파일이 모형을 명시하지 않으면 설정이 상속됩니다.
4. 적용 가능한 컨텍스트 파일이 핸들을 지정하지 않으면 Glossia 는 계정 기본값을 사용합니다.

명시적으로 설정된 핸들은 존재해야 합니다. 알려지지 않은 핸들에 대해 오류를 보고하며, 침묵적으로 계정 기본값으로 전환하지 않습니다.

## 기본 선택

프로젝트 설정은 저장소가 자체 모델을 갖기 전에 모델을 필요로 합니다. `L10N.md`. 따라서 Glossia 는 계정 기본값을 선택합니다. 계정에 추가된 첫 번째 모델은 기본이 되며, 관리자는 설정 페이지에서 다른 모델을 기본으로 설정할 수 있습니다.

저장소가 갖는 경우 `L10N.md`, 명시적인 핸들은 선택 사항이 검토자에게 명확해집니다. 제외 `model` 계정 기본값으로 레포지토리를 유지합니다.

## 인간 검토 경계

모델 출력은 제안된 작업이며 자동 병합이 아닙니다. 설정 및 번역 활동은 Glossia에서 계속 표시됩니다. 반면 레포지토리 변경 사항은 팀 검토를 위해 풀 리퀘스트를 통해 게시됩니다. 이는 팀이 이미 사용하는 코드와 동일한 품질 및 소유권 경계를 유지합니다.
