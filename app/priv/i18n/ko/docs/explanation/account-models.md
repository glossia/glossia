Glossia 는 저장소 지침을 모델 제공자 자격 증명과 분리합니다. 저장소는 번역할 내용을 설명하고, 계정은 어떤 것 [대형 언어 모델](https://en.wikipedia.org/wiki/Large_language_model) 작업을 수행합니다.

## 모델이 계정에 소속되는 이유

팀들은 종종 동일한 제공자 관계에 있는 여러 저장소를 번역합니다. 계정 단위의 모델은 관리자가 모든 저장소를 수정하지 않고 한 번에 공급자 키를 회전하거나 기본 모델을 변경할 수 있게 합니다.

이 경계는 또한 자격 증명을 소스 컨트롤 밖으로 제외합니다. 저장소에는 읽을 수 있는 핸들이 포함되어 있으며, 예를 들어 `translation-default`, 공급자 키가 아닙니다.

## 핸들은 안정적인 의도를 제공합니다.

해당 `model` 필드 `L10N.md` 는 계정 모델 핸들을 나타냅니다.

```yaml
model: translation-default
```

핸들은 저장소의 의도를 나타냅니다. 관리자는 나중에 저장소 구성이 안정적으로 유지되는 동안 해당 핸들이 선택하는 제공자 모델을 업데이트할 수 있습니다.

## 여러 모델 사용

Glossia 는 각 문서 번역마다 하나의 구성된 모델을 사용합니다. 여러 모델을 추가하는 것은 앙상블이나 폴백 체인이나 자동 품질 단계를 생성하지 않습니다. 저장소 작성자는 안정적인 핸들 `translation-default`, `long-form`또는 `japanese-specialist`.

선택은 문서 및 대상 로케일의 컨텍스트 계층 구조를 따릅니다:

1. 가장 가까운 `L10N/<locale>.md` 로케일을 선언하는 파일 `model` 해당 로케일에 우선합니다.
2. 그렇지 않으면 가장 가까운 `L10N.md` 로케일을 선언하는 파일 `model` 해당 디렉터리에 우선합니다.
3. 부모 `L10N.md` 모델이 선언되지 않은 더 가까운 파일에서는 설정이 상속됩니다.
4. 적용 가능한 컨텍스트 파일에 핸들이 선언되지 않으면 Glossia 는 계정 기본값을 사용합니다.

명시적으로 구성된 핸들은 반드시 존재해야 합니다. 알 수 없는 핸들에 대해서는 계정 기본값으로 전환하지 않고 오류를 보고합니다.

## 기본 선택

프로젝트 설정은 저장소가 자체 모델을 갖기 전에 모델을 필요로 합니다. `L10N.md`따라서 Glossia 는 계정 기본값을 선택합니다. 계정에 추가된 첫 번째 모델은 기본값이 되며, 관리자는 해당 설정 페이지에서 다른 모델을 기본값으로 만들 수 있습니다.

저장소가 갖게 되면 `L10N.md`, 명시적인 핸들을 사용하면 선택 사항이 검토자에게 명확해집니다. 생략하는 `model` 계정의 기본값으로 레포지토리를 유지합니다.

## 인간 검토의 경계

모델 출력은 제안된 작업이며 자동 병합이 아닙니다. 설정 및 번역 활동은 Glossia 에서 계속 표시됩니다. 레포지토리의 변경 사항은 팀이 검토할 수 있도록 풀 리퀘스트를 통해 게시됩니다. 이는 팀이 이미 코드에 사용하는 동일한 품질 및 소유권 경계를 유지합니다.
