Glossia 는 저장소 지침과 모델 제공업체 인증 정보를 분리합니다. 저장소는 번역해야 할 내용을 설명하며, 계정은 어떤 [대규모 언어 모델](https://en.wikipedia.org/wiki/Large_language_model) 작업을 수행합니다.

## 모델이 계정에 속하는 이유

같은 제공자 관계를 가진 여러 저장소를 번역하는 팀이 많습니다. 계정 범위의 모델은 관리자가 모든 저장소를 편집하지 않고도 한 번에 제공자 키를 회전하거나 기반 모델을 전환할 수 있게 합니다.

이 경계는 또한 자격 증명을 소스 코드 관리 밖으로 유지합니다. 저장소는 가독 가능한 핸들의 예를 들어 `translation-default`, 제공자 키는 아닙니다.

## 핸들은 안정적인 의도를 제공합니다.

이 `model` 필드 내 `L10N.md` 계정 모델 핸들을 참조합니다:

```yaml
model: translation-default
```

핸들은 저장소의 의도를 표현합니다. 관리자는 나중에 해당 핸들로 선택된 공급자 모델을 업데이트할 수 있으며, 저장소 설정은 안정적으로 유지됩니다.

## 여러 모델 사용 방법

Glossia 는 각 문서 번역마다 하나의 설정된 모델을 사용합니다. 여러 모델을 추가해도 앙상블, Fallback 체인, 또는 자동 품질 계층을 생성하지 않습니다. 리포지토리 작성자는 안정적인 핸들, 예를 들어 를 통해 목적을 선택합니다. `translation-default`재조립된 문서가 이전 검증에서 실패했습니다: Markdown 텍스트 리터럴 복구는 길이가 일치하는 JSON 문자열 배열을 반환해야 합니다 `long-form`재조립된 문서는 이전에 유효성 검사에 실패했습니다: 마크다운 텍스트 리터럴 복구에서 유효하지 않은 JSON 이 반환되었습니다. `japanese-specialist`.

선택은 문서와 대상 로케일의 컨텍스트 계층 구조를 따릅니다:

1. 가장 가까운 `L10N/<locale>.md` 로케일을 정의하는 파일 `model` 해당 로케일에서 우선합니다.
2. 그렇지 않으면, 가장 가까운 `L10N.md` 로케일을 정의하는 파일 `model` 해당 디렉터리에서 우선합니다.
3. 부모 `L10N.md` 모델을 선언하지 않은 더 가까운 파일이 있을 때 설정 이 상속됩니다.
4. 적용 가능한 컨텍스트 파일 에서 핸들을 선언하지 않을 때, Glossia 는 계정 기본값 을 사용합니다.

명시적으로 구성된 핸들이 존재해야 합니다. 알려지지 않은 핸들의 경우 Glossia 는 계정 기본값 으로 암묵적으로 전환하지 않고 오류를 보고합니다.

## 기본 선택

프로젝트 설정 은 레포지토리 가 자체 모델을 갖기 전에 모델 이 필요합니다. `L10N.md`. 따라서 Glossia 는 계정 기본값 을 선택합니다. 계정에 추가된 첫 번째 모델 이 기본값 이 되며, 관리자는 해당 설정 페이지 에서 다른 모델을 기본값 으로 지정할 수 있습니다.

레포지토리가 갖게 되면 `L10N.md`, 명시적인 핸들을 사용하면 리뷰어가 선택을 명확히 이해할 수 있습니다. 제외하는 경우 `model` 계정 기본값에 저장소를 유지합니다.

## 인간 검토 경계

모델 출력은 제안된 작업이며 자동 병합이 아닙니다. 설정 및 번역 활동은 Glossia 에서 유지 표시됩니다. 반면 저장소 변경은 팀 검토를 위해 Pull Request 를 통해 게시됩니다. 이는 팀이 이미 사용하는 코드에 대한 동일한 품질 및 소유권 경계를 유지합니다.
