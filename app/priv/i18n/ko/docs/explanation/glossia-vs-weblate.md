**소프트웨어 배포의 나머지 부분과 동일한 방식으로 언어 자동화가 작동하기를 원하면 Glossia 를 선택하세요:** 소스 제어된 지침, 자신만의 모델 토큰, 저장소 네이티브 체크 및 검토를 위한 풀 리퀘스트.

[Weblate](https://weblate.org/) 는 웹 번역 인터페이스, 버전 관리 통합 및 자체 호스팅 옵션을 갖는 오픈소스 현지화 시스템입니다. 공개 코드 및 Git 통합은 Glossia 에만 해당되지 않습니다. Glossia 를 선택하는 이유는 저장소 중심 배포, 모델 기반 변환, 인간 및 에이전트를 위한 재사용 가능한 언어 컨텍스트의 조합 때문입니다.

## 왜 Glossia 를 선택해야 하는가

| 우선순위 | Glossia 의 강점 |
|---|---|
| 제품 워크플로우에서 검토 유지 | 저장소 변경 및 풀 리퀘스트를 통해 실제 소스 제어된 출력을 검토하세요. |
| 빠른 변경의 소스 저장소와 일치 | 변경 감지 및 배치 게시는 변경되지 않는 입력을 반복 번역하지 않고도 지속적인 현지화 루프를 지원합니다. |
| 자신만의 모델 토큰 가져오기 | 계정 수준의 제공자 자격을 사용하여 지원되는 모델을 구성하고 저장소 소유 핸들링으로 선택하세요. |
| 네이티브 유효성 검사 재사용 | 후보의 실제 타겟 경로에서 저장소의 자체 유효성 검사 명령을 실행하세요. |
| 번역 너머 컨텍스트 재사용 | 공유 음성 및 속어는 MCP 및 REST 인터페이스를 통해 새로운 콘텐츠와 에이전트 통합을 안내할 수 있습니다. |

## 저장소를 검토 표리로 유지

Glossia 는 배포 준비 상태를 결정하는 팀이 Git 을 이미 사용하는 경우를 위해 설계되었습니다. 현지화 설정은 콘텐츠와 함께 있으며 제안된 출력은 제품 변경과 동일한 프로세스를 통해 검토할 수 있습니다.

Weblate 도 버전 관리와 통합됩니다. 브라우저 기반 번역 인터페이스는 기여자 커뮤니티가 필요로 하는 것이 바로 그 것일 수 있습니다. Glossia 의 강조점은 다릅니다: 편집 인터페이스를 팀 업무의 중심으로 만들기보다 저장소 검토 경계를 유지하고 언어 자동화를 그곳으로 가져오세요.

## 자신만의 토큰 가져오기 및 모델 선택 명시하기

Glossia 는 제공자 API 토큰으로 구성된 지원 모델을 사용합니다. 저장소 구성은 안정적인 모델 핸들을 참조하며 시크릿은 계정 설정에 유지됩니다. 콘텐츠 범위 또는 타겟 로케일대로 다른 구성된 모델을 선택하고 모든 저장소를 변경하지 않고 자격 증명을 회전할 수 있습니다.

이는 팀이 콘텐츠를 쓰는 모델을 선택할 수 있는 명시적인 장소를 제공합니다. 어떤 토큰이나 모델이 지원되는지 또는 생성이 인간의 검토 필요성을 제거한다는 약속을 하지 않습니다. [Provide a model provider](/docs/how-to/configure-a-model-provider) 를 참조하세요.

## 지시 변경을 정의하는 체크punkt 재사용

Glossia 의 내장 구조적 체크는 품질 경계의 일부일 뿐입니다. `L10N.md`, 를 통해 후보자의 실제 타겟 경로에서 저장소의 네이티브 유효성 검사 스크립트, 파서, 컴파일러 또는 문서 검사를 실행할 수 있습니다.

번역된 콘텐츠가 단순 문자를 넘어 복잡할 때 (애플리케이션별 포맷, Markdown 구성 요소, 구조화된 메타데이터, 프로젝트가 이미 검증할 수 있는 제약) 이 유용합니다. 유효성 검사 및 복구 는 파이프라인 이 게시할 실제 파일과 연결됩니다.

실행 환경은 여전히 유효성 검사의 의존성을 필요로 하며, 구조적 유효성 검사는 언어적 정확성을 확립하지 않습니다. [L10N.md](/docs/reference/l10n-md) 와 [번역 복구](./translation-recovery) 를 참조하세요.

## 공개 소스는 기준선이며 전체 비교가 아닙니다

Glossia의 코어에는 [Apache-2.0](https://github.com/glossia/glossia/blob/main/LICENSE-APACHE)이 적용되며, 해당 조건에 따라 상업적 이용, 수정, 배포, 자체 호스팅 및 경쟁 호스팅 서비스를 제공할 수 있습니다. `ee/`의 코드에는 별도의 [Enterprise 라이선스](https://github.com/glossia/glossia/blob/main/ee/LICENSE.md)가 적용되며 프로덕션 사용에는 서면 상업 계약이 필요합니다. 이 오픈 코어 모델은 Weblate의 GPL 기반 라이선스와 다릅니다.

무제한 오픈소스 라이선스 및 확립된 웹 번역 인터페이스가 일차적 기준이라면 Weblate 를 고려해 볼 가치가 있습니다. 목표가 **자신의 모델 자격 증명, 기존 저장소 체크, 소프트웨어 배포를 따르는 언어 작업** 인 경우, Glossia 는 이러한 선택을 언어 OS 에 통합합니다.

이 비교는 Weblate 가 자동화, 유효성 검사 기능 또는 제공자 통합이 부족하다는 주장을 아니며 자동 이주나 기능 균등을 유효하지 않습니다. 현재 기능 앞에 [Weblate 문서](https://docs.weblate.org/) 를 참조하세요.
