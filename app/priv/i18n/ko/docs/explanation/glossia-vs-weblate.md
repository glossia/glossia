**소프트웨어 배포의 나머지 부분처럼 언어 자동화를 작동시키기를 원할 때 Glossia 를 선택하세요:** 소스 제어 지침, 자체 모델 토큰, 리포지토리에 내장된 검사, 그리고 검토를 위한 풀 리퀘스트.

[Weblate](https://weblate.org/) 는 오픈 소스 현지화 시스템으로 웹 번역 인터페이스, 버전 제어 통합 및 자체 호스팅 옵션을 지원합니다. 공개 코드와 Git 통합은 Glossia 에만 국한되지 않습니다. Glossia 를 선택하는 이유는 레포지토리 중심의 배포, 모델 기반 변환, 그리고 인간과 에이전트 모두를 위한 재사용 가능한 언어 컨텍스트의 결합 때문입니다.

## Glossia 선택의 이유

| 당신의 우선순위 | Glossia 의 장점 |
|---|---|
| 제품 워크플로우 내 검토 유지 | 실제 소스 제어 출력을 리포지토리 변경 및 풀 리퀘스트를 통해 검토하세요. |
| 빠른 소스 리포지토리와 일치시키기 | 변경 감지 및 배치 출덕은 변경되지 않는 입력을 반복하여 번역하지 않으면서 지속적인 현지화 루프를 지원합니다. |
| 자체 모델 토큰 가져오기 | 지원되는 모델을 계정 범위로 설정하고, 리포지토리가 소유한 핸들 로 선택하세요. |
| 네이티브 유효성 검사 재사용 | 후보를 실제 타겟 경로에서 리포지토리의 자체 유효성 검사 명령을 실행하세요. |
| 번역 이상의 컨텍스트 재사용 | 공유 음성과 용어가 MCP 와 REST 인터페이스를 통해 새로운 콘텐츠 및 에이전트 통합을 안내할 수 있습니다. |

## 리포지토리를 리뷰 표면으로 유지

Glossia 는 이미 Git 을 사용하여 배포 준비 중인 사항을 결정하는 팀을 위해 설계되었습니다. 현지화 구성은 콘텐츠 옆에 위치하며, 제안된 출력은 제품 변경과 동일한 프로세스를 통해 검토할 수 있습니다.

Weblate 또한 버전 제어와 통합됩니다. 브라우저 기반 번역 인터페이스는 기여자 커뮤니티에게 정확한 것이 될 수 있습니다. Glossia 의 강조점은 다릅니다: 팀 작업의 중심을 다른 편집 인터페이스로 만드는 대신, 리포지토리 검토 경계를 보존하고 언어 자동화를 해당 측면으로 가져옵니다.

## 자체 토큰 가져오고 모델 선택 명시화

Glossia 는 지원되는 모델을 제공자 API 토큰으로 구성하여 사용합니다. 리포지토리 구성은 안정적인 모델 핸들을 지칭하며, 시크릿은 계정 설정에 유지됩니다. 콘텐츠 범위 또는 타겟 로케일에 따라 다른 구성된 모델을 선택하고 모든 리포지토리를 변경하지 않으면 자격 증명을 회전시킬 수 있습니다.

이것은 팀이 자신의 콘텐츠를 작성하는 모델을 선택할 수 있는 명시적인 장소를 제공합니다. 이는 어떤 토큰이나 모델이 지원되거나, 생성이 인간의 검토 필요성을 제거한다는 약속은 하지 않습니다. [모델 제공자 구성](/docs/how-to/configure-a-model-provider)을 참조하세요.

## 배포 가능한 변경 사항을 정의하는 검사를 재사용합니다.

Glossia 의 내장 구조적 검증은 품질 경계 중 일부일 뿐입니다. `L10N.md` 를 통해 리포지토리의 네이티브 유효성 검사 스크립트, 파서, 컴파일러 또는 문서 검사를 실제 타겟 경로에서 후보에 대해 실행할 수 있습니다.

이것은 번역된 콘텐츠가 단순 문자열을 넘어 응용 프로그램별 포맷, 마크다운 컴포넌트, 구조화된 메타데이터, 이미 프로젝트가 검증할 수 있는 제약조건을 포함할 때 유용합니다. 유효성 검사 및 복구는 파이프라인이 배포할 실제 파일과 연결됩니다.

이 실행 환경은 여전히 유효성 검사기의 의존성을 필요로 하며, 구조적 유효성 검사는 언어적 정확성을 확립하지 않습니다. [L10N.md](/docs/reference/l10n-md) 및 [번역 복구](./translation-recovery)를 참조하세요.

## 공개 소스는 비교의 전부가 아닌 기준선입니다

Glossia의 코어에는 [Apache-2.0](https://github.com/glossia/glossia/blob/main/LICENSE-APACHE)이 적용되며, 해당 조건에 따라 상업적 이용, 수정, 배포, 자체 호스팅 및 경쟁 호스팅 서비스를 제공할 수 있습니다. `ee/`의 코드에는 별도의 [Enterprise 라이선스](https://github.com/glossia/glossia/blob/main/ee/LICENSE.md)가 적용되며 프로덕션 사용에는 서면 상업 계약이 필요합니다. 이 오픈 코어 모델은 Weblate의 GPL 기반 라이선스와 다릅니다.

제한 없는 오픈소스 라이선싱과 확립된 웹 현지화 인터페이스가 주요 기준이라면 Weblate 가 고려될 가치가 있습니다. 목표가 **소프트웨어 배포를 따르는 언어 작업, 기존 리포지토리 검사, 및 당신의 자체 모델 자격 증명**이라면, Glossia 는 언어 OS 에서 이러한 선택을 하나로 모읍니다.

이 비교는 Weblate 가 자동화, 검증 기능 또는 제공자 통합이 부족하다고 주장하지 않으며, 자동 이동이나 기능 균등을 약속하지도 않습니다. [Weblate 의 문서](https://docs.weblate.org/) 를 참조하여 현재의 기능을 확인하세요.
