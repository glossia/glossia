용어사전은 번역물이 매번 동일한 방식으로 렌더링되도록 정리된 용어의 세트입니다. 버전 관리 의미의 "Commit" 은 스페인어에서는 `commit` 로 유지되고, 웹 간중국에서는 `提交` 로, 그리고 일본어에서는 `コミット` 가 됩니다. 언어마다 하나의 결정이며, 전역에 강제됩니다.

## 용어사전이 존재할 두 곳

Glossia 는 용어사전 항목을 위한 두 곳을 검색하며, 번역 시간에 병합합니다:

- **귀하의 저장소** 에서 번역 설정으로 이미 사용하고 있는 파일에서. `L10N.md` 가 용어를 선언하며, 각 언어의 `L10N/<locale>.md` 는 번역을 선언합니다. 이는 개발자가 주도하는 용어사전입니다: 변경 사항은 Pull request 를 통해 전달되며, 각 언어별 리뷰러는 자신의 파일을 관리하며, 중첩 파일은 저장소의 일부 용어를 세밀하게 다듬을 수 있습니다.
- **귀하의 Glossia 계정**, 호스팅 되는 대시보드로 관리되며, 이것은 번역가가 주도하는 용어사전입니다: 리뷰러와 로컬라이제이션 기여자가 코드를 건드리지 않고 대시보드, [REST API](/docs/reference/apis), 또는 [MCP 서버](/docs/reference/mcp) 를 통해 항목을 추가하거나 수정할 수 있습니다. 이는 계정이 번역하는 모든 저장소에 적용됩니다.

두 곳 모두 유용하며, 서로를 대체하지 않습니다.

## 어떤 것을 사용하는 경우

다음과 같은 경우 **귀하의 Glossia 계정** 에서 용어를 정의합니다:

- **여러 저장소에 적용됩니다.** 제품 이름, 브랜드 용어, 그리고 기업 용어는 한 번에 정의되어 전 세계 어디서나 사용됩니다.
- **설정을 하는 사람들이 저장소에 근무하지 않습니다.** 번역가, 리뷰러, 외부 기여자는 저장소가 폐쇄 소스이거나 작성 권한이 없더라도 용어사전을 세밀하게 다듬을 수 있습니다.
- **코드 변경 없이 용어를 수정하고 싶을 때.** 수정된 번역은 다음 런에서 적용되며, 코드베이스에 대한 Pull request 를 생성하지 않습니다.
- **변경 사항의 검토와 이력이 필요합니다.** 모든 편집은 변경 주석을 갖는 새로운 버전을 생성하며, 기여자는 승인 요청을 위한 제안으로 변경을 제안할 수 있고, 이전 버전은 계속 이용 가능합니다.
- **다른 도구들이 필요합니다.** 에이전트와 통합은 REST API 와 MCP 서버를 통해 용어사전을 읽을 수 있습니다. 예를 들어 승인된 용어를 이미 사용하는 새 콘텐츠를 작성하는 경우.

다음과 같은 경우 **귀하의 저장소** 에서 용어를 정의합니다:

- **이 코드베이스에 속합니다.** 특정 주에만 의미를 갖는 용어의 경우, 예를 들어 버전 관리 작업인 "commit" 의미의 용어는 해당 용어를 사용하는 코드 옆에 있습니다.
- **원문과 함께 변경되어야 합니다.** 용어와 이를 개입한 어안 (copy) 은 같은 Pull request 에 도착하며, 함께 검토됩니다.
- **저장소의 일부분만 필요합니다.** 중첩 `L10N.md` 또는 `L10N/<locale>.md` 는 마케팅 페이지 등 하나의 디렉터리에 항목을 추가하거나 오버라이드할 수 있습니다.
- **계정용어사전을 강제해야 합니다.** 같은 용어에 대해 저장소 항목은 계정 항목보다 우선하며, 번역하는 언어에 따라 적용됩니다.

## 병합 방법

각 파일과 대상 언어마다, Glossia 는 두 용어사전을 하나의 효과적인 집합으로 해결합니다:

1. 대상 언어의 계정용어사전 항목부터 시작합니다.
2. 해당 언어의 저장소 항목을 오버레이합니다: 해당 파일의 `L10N.md` 체인에서 `L10N/<locale>.md` 체인에서 번역 항목이 있는 용어입니다. 저장소 항목이 계정 항목과 동일한 소스 용어를 가질 때, 저장소 항목이 우선합니다.
3. 저장소 용어가 해당 언어에 대한 번역을 가지지 않는 경우, 해당 언어의 계정 항목이 여전히 적용됩니다. 저장소는 번역하지 않은 언어를 결코 차단하지 않습니다.

병합은 **대상 언어마다** 발생하며, 각 항목마다 발생하지 않습니다. `L10N/es.md` 의 "Commit"의 스페인어 번역은 계정 스페인어 항목을 "commit" 대신 해치환하지만, 같은 용어의 계정 일본어 항목에는 변화를 주지 않습니다. 리뷰러는 대체된 계정 항목을 볼 수 있습니다: 번역 세션 요약은 오버라이드된 개수가 표시됩니다, 그리고 각 파일의 lockfile 은 `glossary.shadowed` 아래에 그들을 나열합니다.

## 용어사전이 변경되면 파일이 다시 번역됨

용어사전 항목을 편집하면 Glossia 는 *효과적인 용어사전이 변경된* 파일만 다시 번역합니다. 파일의 원문에 편집된 용어와 일치하는 것이 없다면 번역은 그대로 유지됩니다. 파일이 해당 용어를 사용할 경우, 다음 번역 두통은 업데이트된 지침을 포함합니다.

동일한 원리가 역으로 적용됩니다: 일부 파일에서만 사용되는 용어를 추가해도 전체 리런을 강요하지 않습니다.

## 용어사전이 아닌 것

- 머신 번역 사전이 아닙니다. Glossia 는 주변 컨텍스트를 읽으며 문구가 요구하면 용어를 다르게 렌더링할 수 있습니다. 용어사전은 지침이지 치환이 아닙니다.
- 스타일 가이드 전체가 아닙니다. Voice, 감정, 형식, 그리고 청중은 귀하의 계정 Voice 설정과 `L10N.md` 에 있습니다. 용어사전은 개별 용어와 승인된 번역에만 해당됩니다.
- 침묵하지 않습니다. 적용된 용어는 파일의 lockfile 에 기록되어 있어 리뷰러가 정확히 어떤 용어사전 항목이 모델에 도달했는지 추적할 수 있습니다.
