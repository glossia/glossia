사전은 번역이 매번 동일한 방식으로 렌더링해야 하는 정제된 용어 집합입니다. 버전 관리 의미의 "Commit" 은 스페인어에서는 `commit` 로 그대로 남으며, 간체 중语文教学에서는 `提交` 로 바뀌고, 일본어에서는 `コミット` 가 됩니다. 각 언어당 하나의 결정으로, 전체에서 강제적으로 시행됩니다.

## 사전이 존재할 수 있는 두 곳

Glossia 는 번역 시점에 사전 항목을 두 곳에서 찾아 합칩니다:

- **저장소**, 이미 번역 설정에 사용하는 파일에서 찾을 수 있습니다. `L10N.md` 는 용어를 선언하며, 각 언어의 `L10N/<locale>.md` 는 해당 번역을 선언합니다. 이는 개발자 권한이 있는 사전입니다: 변경 사항은 풀 리퀘스트를 통해 전달되며, 각 언어의 검토자는 고유한 파일을 보유하고, 중첩된 파일은 저장소의 일부를 위한 것만으로 이를 정교화할 수 있습니다.
- **본 사용자의 Glossia 계정** 은 호스팅 대시보드를 통해 관리됩니다. 이는 언어 전문가 권한이 있는 사전입니다: 검토자와 로컬라이제이션 기여자는 코드를 만지거나 수정하지 않고 대시보드, [REST API](/docs/reference/apis), 또는 [MCP 서버](/docs/reference/mcp) 를 통해 항목을 추가하거나 정교화합니다. 이는 계정이 번역하는 모든 저장소에 적용됩니다.

두 곳 모두 유용하며, 서로를 대체하지 않습니다.

## 어떤 것을 언제 사용해야 하나요

다음과 같은 경우 **본 사용자의 Glossia 계정** 에서 용어를 정의하세요:

- **여러 저장소에 적용됩니다.** 제품 이름, 브랜드 용어, 회사 어휘는 한 번만 정의되고 전역에서 사용됩니다.
- **결정을 내리는 사람들이 저장소에 소속되지 않는 경우.** 언어 전문가, 검토자, 외부 기여자는 저장소가 비공개이거나 작성 권한이 없는 경우에도 사전에 기여할 수 있습니다.
- **코드 변경 없이 용어를 수정하고 싶을 때.** 수정된 번역은 다음 실행 시점에 적용되며 코드베이스에 대한 풀 리퀘스트가 필요하지 않습니다.
- **변경 사항에 검토 및 이력이 필요함.** 각 편집은 변경 주음을 포함하여 새 버전을 생성하며, 기여자는 승인을 위한 제안으로 변경 사항을 제안할 수 있고 이전 버전도 항상 사용 가능합니다.
- **다른 도구가 필요할 때.** 에이전트와 통합은 REST API 와 MCP 서버 를 통해 사전에 읽을 수 있으며, 예를 들어 승인된 용어를 이미 사용하는 새 콘텐츠를 작성할 수 있습니다.

다음과 같은 경우 **저장소** 에서 용어를 정의하세요:

- **코드가 해당되는 경우.** 한 프로젝트에 특화된 의미를 가지며, 예를 들어 버전 관리 동작 을 의미하는 "commit" 은 사용하는 코드 옆에 위치합니다.
- **소스 텍스트와 함께 변경되어야 합니다.** 용어와 이를 도입한 홍보물은 동일한 풀 리퀘스트에 포함되며 함께 검토됩니다.
- **저장소의 일부만 필요할 때.** 중첩된 `L10N.md` 또는 `L10N/<locale>.md` 는 마케팅 페이지처럼 특정 디렉토리의 항목을 추가하거나지우거나 정교화할 수 있습니다.
- **계정 사전을 대체해야 합니다.** 동일한 용어의 경우 저장소 항목이 계정 항목보다 우선하며, 이 번역 언어에 적용됩니다.

## 두 사전의 결합 방식

각 파일 및 대상 언어 당, Glossia 는 두 개의 사전을 하나의 유효한 집합으로 해결합니다:

1. 대상 언어의 계정 사전 항목부터 시작합니다.
2. 해당 언어의 저장소 항목을 중첩합니다: 파일의 `L10N.md` 체인에서 가져온 용어 중 `L10N/<locale>.md` 체인에서도 번역된 것입니다. 저장소 항목과 계정 항목이 동일한 소스 용어를 가질 때 저장소 항목이 우선합니다.
3. 저장소 용어가 해당 언어에 번역이 없다면, 해당 언어의 계정 항목이 여전히 적용됩니다. 저장소는 번역하지 않은 언어를 차단하지 않습니다.

합병은 항목별이 아닌 **대상 언어 당** 발생합니다. `L10N/es.md` 에 있는 "commit" 의 스페인어 번역은 "commit" 의 계정 스페인어 항목을 대체하지만, 동일한 용어의 계정 일본어 항목에는 영향을 미치지 않습니다. 검토자는 대체된 계정 항목을 볼 수 있습니다: 번역 세션 요약은 overridden 수를 보여주며, 각 파일의 lockfile 은 `glossary.shadowed` 아래에 해당 항목을 나열합니다.

## 사전 변경 시 파일 재 번역

사전 항목을 수정할 때, Glossia 는 *유효한 사전이 변경되었을 경우* 해당 파일만 재 번역합니다. 파일의 소스 텍스트가 수정된 용어와 일치하지 않으면 번역이 그대로 유지됩니다. 용어를 사용하는 파일의 경우 다음 번역 패스에 업데이트된 지침이 포함됩니다.

반대로 동일한 원칙이 적용됩니다: 일부 파일만 사용하는 용어를 추가하더라도 전체 재 실행은 강제되지 않습니다.

## 사전이 아닌 것

- 기계 번역 사전이 아닙니다. Glossia 의 모델은 주변 컨텍스트를 읽으며 문장이 요구할 경우 용어를 다르게 렌더링할 수 있습니다. 사전은 지침이며 교체가 아닙니다.
- 전체 스타일 가이드가 아닙니다. 투움, 톤, 일반화 및 대상자는 계정의 Voice 설정 및 `L10N.md` 에 삽니다. 사전은 개별 용어 및 승인 번역물에에만 사용됩니다.
- 무음 상태가 아닙니다. 적용된 모든 용어가 파일의 lockfile 에 기록되므로 검토자가 어떤 사전 항목이 모델에 도달했는지 정확히 추적할 수 있습니다.
