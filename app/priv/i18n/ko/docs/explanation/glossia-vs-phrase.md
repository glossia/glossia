**제품의 배포 시스템에 따라 언어 작업을 이어가고 싶을 때, 병렬 번역 관리 프로세스를 구축하는 대신 Glossia 를 선택하세요.** Git 에 콘텐츠를 유지하고, 자체 자격 증명을 사용하여 지원되는 모델을 선택하며, 저장소가 이미 신뢰하는 검증 절차 로 결과를 확인하세요.

[Phrase](https://phrase.com/) 는 지역화 일괄 솔루션 을 제공합니다. Phrase Strings 와 Phrase TMS 를 포함하여 다양한 소프트웨어 현지화 및 관리형 번역 요구 사항 을 지원합니다. Glossia 는 집중된 접근 방식을 채택합니다; 즉, 기존 검토 및 배송 루프 에 맞는 언어 운영 체제 를 소프트웨어 팀 에게 제공합니다.

## Glossia 를 선택해야 하는 이유

| 본인의 우선순위 | Glossia 의 강점 |
|---|---|
| 소프트웨어 와 함께 언어 변경 사항 배포 | 저장소 변경 사항 이 현지화를 주도하며, 결과물은 검토 가능한 변경 사항 으로 반환됩니다. |
| 프로세스 를 검토하고 소유하세요 | 공개 소스는 애플리케이션 및 배포 구현을 노출하며, 라이선스 조건 하에서 수정 과 자체 호스팅 이 허용됩니다. |
| 직접 토큰 설정 | 지원되는 모델-제공자 자격 증명을 자체 구성하고, 저장소 구성 을 통해 계정 핸들로 모델을 선택하세요. |
| 검증 파이프라인 재사용 | 번역 후보 에 저장소 내의 검사를 수행하고, 언어학적 승인을 파일 이 빌드될 것이라는 증거 로 취급하는 대신 수행하세요. |
| 영구 소유권 유지 | 게시된 파일, 설정 및 풀 요청 기록 이 저장소에 계속 남아 있습니다. |

## 현지화를 지속적 배포 의 일부로 만드세요

Glossia 의 변경 감지는 변경되지 않는 입력 에 번역 작업을 반복하지 않도록 합니다. 저장소 워크플로 는 프로젝트 당 하나의 열린 번역 풀 요청 이며, 배치 로 진척 을 게시하기 때문에 빠르게 변경되는 소스 저장소 는 매 pequenos 변경마다 새로운 번역 프로세스 를 필요로 하지 않습니다.

목표 는 비검토 생산 경쟁이 아닙니다. 이미 사용 중인 파이프라인 을 통해 언어 작업을 계속 검토하고 배포 가능하게 하는 것입니다.

Phrase 도 API, 통합 및 자동화를 제공합니다. Glossia 를 강조하는 장점은 구조적 정렬 이며: 저장소는 콘텐츠 권한 및 배송 경계 로 유지되며, 단순히 다른 작업 공간 의 결과를 동기화하는 장소 에 불과하지 않습니다.

## 모델 선택 및 자격 증명을 자체 관리하세요

Glossia 는 지원되는 모델 에 적용할 자체 제공자 API 토큰을 허용합니다. 자격 증명은 계정 설정 에 유지되며, 저장소는 안정적인 핸들을 선택합니다. 팀 은 토큰 을 회전시키거나 핸들 뒤 모델 을 변경할 때 리포지토리 지침 을 다시 작성하지 않아도 됩니다.

다른 콘텐츠 범위 및 타겟 언어 는 별도 구성된 모델을 사용할 수 있습니다. 선택적인 의사 결정 모델 은 완전한 번역 을 평가하고 수정 을 요청할 수 있으며, 인간 은 언어 판단 에 대한 책임 은 여전히 인간 자신입니다. 현재 동작 및 제한 사항 을 확인하려면 [계정 모델](./account-models) 을 참조하세요.

## 저장소는 이미 유효한 콘텐츠 의 의미를 알고 있습니다.

번역 관리 시스템 이 문자열 을 보는 관점은 애플리케이션 이 파일 을 보는 관점과 반드시 같지는 않습니다. 저장소 는 자체 파서, 컴파일러, 컴포넌트 규칙, 문서 빌드 및 플레이스홀더 검사를 가질 수 있습니다.

Glossia 는 `L10N.md` 검증 명령 을 통해 해당 검사를 재사용할 수 있습니다. 검증 을 위해 해당 후보 를 실제 타겟 경로 에 임시로 작성하고, 필요한 검사가 통과한 후에 만 이를 승인합니다. 명령 및 의존성 은 실행 환경 에서 사용 가능해야 합니다.

이는 팀 이 기존 품질 경계를 확장할 수 있도록 하며, 번역 작업 공간 내에서만 "유효한" 의 별도 정의를 유지하는 대신 이를 가능하게 합니다. [L10N.md](/docs/reference/l10n-md) 를 확인하세요.

## 공개 구현, 블랙박스 아님

Glossia의 애플리케이션, CLI, SDK 및 인프라 소스는 공개되어 있습니다. 코어에는 [Apache-2.0](https://github.com/glossia/glossia/blob/main/LICENSE-APACHE)이 적용되며, 해당 조건에 따라 상업적 이용, 수정, 배포, 자체 호스팅 및 경쟁 호스팅 서비스를 제공할 수 있습니다. `ee/`의 코드에는 별도의 [Enterprise 라이선스](https://github.com/glossia/glossia/blob/main/ee/LICENSE.md)가 적용되며 프로덕션 사용에는 서면 상업 계약이 필요합니다.

보다 광범위한 번역 슈트는 전문 번역 운영 및 복잡한 조정을 위해 의미가 있습니다. 만약 당신의 우선 순위가 **자체 토큰과 저장소 검사를 통해 소프트웨어 배송 속도를 맞추는 것**이라면, Glossia 는 해당 워크플로우 를 직접 으로 유지하도록 설계되었습니다.

기존 번역 프로그램을 이전하는 작업 에 대한 메모리, 전문 용어 및 역사 를 위한 계획 수립 이 여전히 필요합니다. 이 페이지 는 자동 프로스 도입기 나 전체 슈트 동등 성 을 약속하지 않거나 프로스가 모든 동등 통합 을 갖지 않았다고 주장하지 않습니다. 해당 제품의 현재 기능을 확인하려면 [Phrase 문서](https://support.phrase.com/) 를 참조하세요.
