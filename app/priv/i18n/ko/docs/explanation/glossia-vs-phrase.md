**언어 작업이 제품 전달 시스템의 흐름을 따르기를 원할 때 Glossia 를 선택하세요. 제품 전달 시스템을 감싸는 병렬 번역 관리 프로세스를 구축하는 대신입니다.** 콘텐츠를 Git 에서 유지하고, 자격 증명에 따라 지원되는 모델을 선택하며, 이미 신뢰하는 저장소 검사를 통해 결과를 검증하세요.

[Phrase](https://phrase.com/) 는 다양한 소프트웨어 현지화 및 관리 번역 요구를 충족하기 위한 현지화 솔루션을 제공합니다. Glossia 는 집중적인 접근 방식을 취합니다: 기존 검토 및 전달 루프에 맞춘 소프트웨어 팀을 위한 언어 OS 를 제공하십시오.

## Glossia 선택 이유

| 시작 순위 | Glossia 의 장점 |
|---|---|
| 소프트웨어와 함께 언어 변경 사항 전달 | 저장소 변경 사항이 현지화를 주도하며, 결과물은 검토 가능한 변경 사항으로 반환됩니다. |
| 처리 과정 검토 및 소유 | 공개 소스 코드는 응용 프로그램 및 배포 구현을 공개하며, 라이선스 조건에 따라 수정 및 자체 호스팅이 허용됩니다. |
| 자체 토크 사용 | 대상 모델 제공자의 자격 증명을 구성하고, 저장소 설정을 통해 계정 핸들을 통해 모델을 선택하세요. |
| 검증 파이프라인 재사용 | 언어 승인 증거로 취급하는 대신, 파일 빌드를 보장하기 위해 번역 후보 사항에 저장소 네이티브 검사를 실행하세요. |
| 소유권 유지 | 배포된 파일, 구성 및 풀리퀘스트 기록은 저장소에 유지됩니다. |

## 현지화를 지속적 배포의 일부로 만드세요

Glossia 의 변경 감지 제는 변경되지 않은 입력에 대해 번역 작업을 반복하지 않습니다. 저장소 워크플 low 는 프로젝트 하나당 하나의 열려있는 번역 풀리퀘스트를 유지하고 배치로 진행 상황을 게시하므로, 빠르게 이동하는 소스 저장소에는 모든 작은 변경 사항마다 새로운 번역 프로세스가 필요하지 않습니다.

목적은 검토되지 않은 프로덕션 경주가 아닙니다. 그것은 언어 작업을 지속적으로 검토 가능하고 전달 가능하게 만드는 것입니다. 팀 이미 사용하는 파이프라인의 통해.

Phrase 도 API, 통합 및 자동화를 제공합니다. Glossia 가 강조하는 이점은 구조적 정렬입니다: 저장소는 콘텐츠 관리자 및 전달 경계를 유지하고, 오로지 다른 워크스페이스 결과 동기화 공간일 수 없습니다.

## 모델 선택 및 자격 증명 직접 관리

Glossia 는 지원 모델에 대해 제공자 API 토큰을 사용합니다. 자격 증명은 계정 설정에 유지되며, 저장소는 안정적인 핸들을 선택합니다. 팀은 토큰을 회전하거나 핸들을 통해 모델을 변경할 때 저장소 지침을 재작성하지 않아도 됩니다.

다른 콘텐츠 범위 및 대상 언어는 구성된 모델을 사용할 수 있습니다. 선택적 의사결정 모델은 완전 번역을 평가하고 수정을 요청할 수 있으며, 인간은 언어적 판단 책임을 다합니다. [계정 모델](./account-models) 을 확인하여 현재 동작 및 제한을 확인하세요.

## 저장소는 이미 유효한 콘텐츠의 의미를 알고 있습니다.

번역 관리 시스템의 문자열 시야는 반드시 애플리케이션의 파일 시야가 아닙니다. 저장소는 자신의 파서, 컴파일러, 구성 요소 규칙, 문서 빌드 및 플레이스홀더 검사를 가질 수 있습니다.

Glossia 는 `L10N.md` 를 통한 검증 명령을 재사용할 수 있습니다. 그것은候选자를 임시로 실제 타겟 경로에 작성하고 검증하며, 필요한 검사가 통과해야만 승인합니다. 명령과 의존성은 실행 환경에서 사용 가능합니다.

이렇게 팀은 현재 품질 경계를 확장하며, 번역 워크스페이스 내에 "valid"인 정의만 유지하는 대신 가능합니다. [L10N.md](/docs/reference/l10n-md) 를 참조하세요.

## 공개 구현, 블랙박스 아님

Glossia 의 응용 프로그램, CLI, SDK 및 배포 소스는 공개적입니다. 핵심은 수정, 배포, 자체 호스팅 및 경쟁 호스팅 서비스를 허용하는 [Apache-2.0](https://github.com/glossia/glossia/blob/main/LICENSE-APACHE) 라이선스에 따라 오픈 소스입니다. `ee/` 하에 있는 기업용 코드는 별도의 [라이선스](https://github.com/glossia/glossia/blob/main/ee/LICENSE.md)를 사용하며, 프로덕션 사용을 위해 서면 상업적 계약이 필요합니다.

광범위한 번역 솔루션은 전문 번역 운영 및 복잡한 조정에 적합합니다. 만약 우선 순위가 **소프트웨어 전달 속도와 자체 토큰 및 저장소 검사를 일치시키는** 것이라면, Glossia 는 해당 워크플로우를 직접 유지하도록 설계되었습니다.

기존 번역 프로그램을 마이그레이션하려면 번역 메모리, 용어 및 역사 계획을 여전히 필요로 합니다. 이 페이지는 자동 Phrase 입력기 또는 전체 솔루션 동등성을 약속하거나 Phrase 가 모든 동등한 통합이 부족하다고 주장하지 않습니다. [Phrase 의 문서](https://support.phrase.com/) 의 현재 기능을 상담하세요.
