**제품 배송 시스템에 따라 언어 작업이 따르도록 하길 원할 때 Glossia 를 선택하세요. 병렬 번역 관리 프로세스를 구축하지 마세요.** Git 에 콘텐츠를 유지하고, 자체 자격 증명을 사용하여 지원 모델을 선택하며, 저장소가 이미 신뢰하는 검사로 결과를 확인하세요.

[Phrase](https://phrase.com/) 는 로컬라이제이션 스위트,\_phrase Strings 와 Phrase TMS\_ 를 포함한 다른 소프트웨어 로컬라이제이션 및 관리 번역 요구를 충족합니다. Glossia 는 집중한 접근 방식을 취합니다: 기존 검토 및 배포 루프에 맞는 언어 OS 를 소프트웨어 팀에게 제공하세요.

## Glossia 선택 이유

| 귀사의 우선순위 | Glossia 의 장점 |
|---|---|
| 소프트웨어 배포 시 언어 변경사항 발송 | 저장소 변경이 로컬라이제이션을 주도하며, 생성된 결과는 검토 가능한 변경 사항으로 반환됩니다. |
| 처리 과정 점검 및 소유권 확보 | 공개 소스는 애플리케이션 및 배포 구현을 노출하며, 라이선스 조건에 따라 수정 및 자체 호스팅을 허용합니다. |
| 자체 토큰 가져오기 | 자신의 지원 모델 제공업체 자격 증명을 설정하고, 저장소 설정 내에서 계정 핸들을 통해 모델을 선택하세요. |
| 검증 파이프라인 재사용 | 번역 후보에 대해 저장소 내제 검사를 실행하고, 언어학적 승인을 파일 빌드 성공의 증명으로 취급하지 마세요. |
| 장기 소유권 유지 | 배포된 파일, 설정 및 Pull-request 기록이 저장소에 유지됩니다. |

## 로컬라이제이션을 지속적 배포의 일부로 만드세요

Glossia 의 변경 감지는 변경되지 않은 입력에 대한 번역 작업을 반복하지 않습니다. 저장소 워크플로는 프로젝트당 한 개의 공개 번역 Pull request 를 유지하며 배치로 진행을 게시하므로, 빠르게 변하는 소스 저장소는 작은 변경마다 새로운 번역 프로세스를 필요로 하지 않습니다.

목표는 검토되지 않은 프로덕션 출시 경쟁이 아닙니다. 기존 워크플루를 통해 언어 작업을 계속적으로 검토 가능하고 배포 가능하게 만드는 것입니다.

Phrase 는 API, 통합 및 자동화도 제공합니다. Glossia 가 강조하는 우위는 아키텍처 정렬입니다: 저장소는 콘텐츠 권한과 배포 경계를 유지하며, 타 워크스페이스 결과를 동기화하는 장소가 아닙니다.

## 모델 선택 및 자격 증명 통제 유지

Glossia 는 지원 모델에 대한 자체 제공 API 토큰을 허용합니다. 자격 증명은 계정 설정에 저장되며, 저장소는 안정적인 핸들을 선택합니다. 팀은 토큰을 회전하거나 핸들 뒤 모델을 변경해도 저장소 지시를 다시 쓸 필요가 없습니다.

다른 콘텐츠 범주와 목표 언어는 다른 설정된 모델을 사용할 수 있습니다. 선택적 결정 모델은 완전한 번역 평가 및 수정 요청을 수행할 수 있으며, 인간은 언어적 판단을 담당합니다. 현재 행동과 제한 사항에 대해서는 [계정 모델](./account-models) 을 참조하세요.

## 저장소는 이미 유효한 콘텐츠가 무엇을 의미하는지 알고 있습니다.

번역 관리 시스템의 문자열 관점은 반드시 애플리케이션의 파일 관점인 것은 아닙니다. 저장소는 자체 파서, 컴파일러, 컴포넌트 규칙, 문서 빌드 및 플레이스홀더 검사를 가질 수 있습니다.

Glossia 는 해당 검사를 `L10N.md` 검증 명령어를 통해 재사용할 수 있습니다. 검증 목적으로 대상 경로를 임시로 작성하고, 필요한 검사가 통과한 경우에만 받아들입니다. 실행 환경에서 명령어 및 의존성이 사용 가능합니다.

이는 팀이 별도 "유효" 정의보다는 기존 품질 경계를 확장하게 합니다. [L10N.md](/docs/reference/l10n-md) 를 참조하세요.

## 공개 구현, 블랙박스 아님

Glossia 의 애플리케이션, CLI, SDK, 배포 소스는 공개적입니다. 콘텐츠 처리 방법을 점검하고, [O'Saasy license](https://github.com/glossia/glossia/blob/main/LICENSE.md) 하에 구현을 수정하거나 자체 호스팅할 수 있습니다. 이 라이선스는 경쟁 호스팅 서비스를 제한하며 무제한 오픈소스 라이선스가 아닙니다.

보다 광범위한 번역 스위트는 전문 번역 운영 및 복잡한 조정에도 타당할 수 있습니다. 우선순위가 **자체 토큰 및 저장소 검사와 소프트웨어 배포 속도 일치** 인 경우 Glossia 는 해당 워크플로우를 직관적으로 유지하도록 설계되어 있습니다.

확립된 번역 프로그램 이동에도 기억, 단서 및 역사의 계획이 필요합니다. 이 페이지는 자동 Phrase 수입기나 전체 스위트 동등성을 약속하거나 Phrase 가 모든 동등한 통합을 결여했다고 단언하지 않습니다. 해당 제품의 현재 기능에 대해 [Phrase 의 문서](https://support.phrase.com/) 를 참조하세요.
