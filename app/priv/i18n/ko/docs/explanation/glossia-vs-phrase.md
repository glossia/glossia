**제품의 배포 시스템을 따라 언어 작업을 수행하려는 경우 병렬 번역 관리 프로세스를 구축하는 대신 Glossia 를 선택하세요.** Git 에 콘텐츠를 유지하고, 지원되는 모델을 자체 자격 증명을 사용하여 선택하며, 저장소가 이미 신뢰하는 검사를 통해 결과를 검증하세요.

[Phrase](https://phrase.com/) 는 서로 다른 소프트웨어 현지화 및 관리 번역 요구를 충족하는 Phrase Strings 와 Phrase TMS 를 포함한 현지화 수트를 제공합니다. Glossia 는 집중된 접근 방식을 취합니다: 기존 검토 및 배송 루프로 파악된 언어 OS 를 소프트웨어 팀에 제공합니다.

## 왜 Glossia 를 선택해야 하나요

| 우선 순위 | Glossia 의 장점 |
|---|---|
| 소프트웨어와 마지막으로 언어 변경 사항 제공 | 저장소 변경 사항이 현지화를 주도하며, 출력은 검토 가능한 변경 사항으로 반환됩니다. |
| 프로세스 검토 및 회계 소유 | 공개 소스는 애플리케이션 및 배포 구현을 노출하며, 라이선스 조항 하에서 수정 및 자체 호스팅이 허용됩니다. |
| 자체 토큰 가져오기 | 자신 지원 모델 제공자 자격 증명을 구성하고, 저장소 설정 플랫폼을 통해 계정 핸들을 사용하여 모델을 선택하세요. |
| 검증 파이프라인 재사용 | 파일 빌드가 가능할 것이라는 언어학적 승인을 증거로 취급하는 대신 번역 후보문서에 저장소 네이티브 검사를 실행하세요. |
| 영속적인 소유권 유지 | 발행된 파일, 설정 및 풀 리퀘스트 기록은 저장소에 남습니다. |

## 현지화를 지속적인 배송의 일부로 만드세요.

Glossia 의 변경 감지는 변경되지 않는 입력에 대한 번역 작업을 반복하지 않습니다. 저장소 워크플로는 프로젝트당 한 개의 열린 번역 풀 리퀘스트를 유지하며 배치로 진행 사항을 발표하므로, 빠르게 이동하는 소스 저장소는 작은 변경 사항마다 새로운 번역 프로세스를 필요로 하지 않습니다.

목표는 검토되지 않은 프로덕션 출력 경쟁이 아닙니다. 바로는 팀이 이미 사용하는 파이프라인을 통해 언어 작업을 지속적으로 검토 가능하고 배송 가능하게 만드는 것입니다.

Phrase 는 또한 API, 통합 및 자동화를 제공합니다. Glossia 가 강조하는 장점은 구조적 정렬입니다: 저장소는 콘텐츠 권한 및 배포邊界로 남아 있으며, 단순히 다른 워크스페이스의 결과를 동기화하는 데 사용되는 장소가 아닙니다.

## 모델 선택 및 자격 증명을 자체적으로 통제하세요.

Glossia 는 지원되는 모델에 대한 자체 제공자 API 토큰을 받습니다. 자격 증명은 계정 설정에 유지되며, 저장소는 안정적인 핸들을 선택합니다. 팀은 저장소 지시를 다시 작성하지 않고 토큰을 회전하거나 핸들 뒤 모델을 변경할 수 있습니다.

다양한 콘텐츠 범위 및 대상 언어는 서로 다른 구성된 모델을 사용할 수 있습니다. 선택 가능한 결정 모델은 전체 번역을 평가하고 수정을 요청할 수 있으며, 인간은 여전히 언어학적 판단에 책임을집니다. 현재 동작 및 한계에 대하여 [Account models](./account-models) 를 참조하세요.

## 저장소는 이미 유효한 콘텐츠의 의미를 알고 있습니다.

번역 관리 시스템의 문자열 보기는 애플리케이션의 파일 보기에 필연적으로 일치하지 않습니다. 저장소에는 자체 파서, 컴파일러, 컴포넌트 규칙, 문서 빌드 및 플레이스홀더 검사가 있을 수 있습니다.

Glossia 는 `L10N.md` 검증 명령을 통해 그러한 검사를 재사용할 수 있습니다. 이 후보는 검증을 위해 실제 타겟 경로에 임시로 작성받으며, 필요한 검사를 통과한 후에만 받아들여집니다. 명령과 그 의존성은 실행 환경에 반드시 있어야 합니다.

이는 팀이 번역 워크스페이스 안에서만 "유효"의 별도 정의를 유지하는 대신 기존의 품질 경계를 확장하게 합니다. [L10N.md](/docs/reference/l10n-md) 를 참조하세요.

## 공개된 구현, 블랙 박스는 아닙니다.

Glossia 의 애플리케이션, CLI, SDK, 배포 소스는 공개적입니다. 콘텐츠가 어떻게 처리되는지 점검하거나 [O'Saasy 라이선스](https://github.com/glossia/glossia/blob/main/LICENSE.md) 하에서 구현을 수정하거나 자체 호스팅할 수 있습니다. 이 라이선스는 경쟁 호스팅 서비스에 제한을 가하며 무제한 오픈 소스 라이선스가 아닙니다.

보다 광범위한 번역 수스는 전문 번역 운영 및 복잡한 조정에서 타당할 수 있습니다. 우선순위가 **자체 토큰 및 저장소 검사를 통해 소프트웨어 배포 속도를 맞추는넷**인 경우, Glossia 는 해당 워크플로우를 직접적으로 유지하도록 설계되었습니다.

설립된 번역 프로그램의 이동을 위해서는 그 기억력, 전문어 및 기록에 대한 계획이 여전히 필요합니다. 이 페이지는 자동 Phrase import 나 전체 수트 동등성을 약속하지 않으며Phrase 가 모든 동등한 통합을 갖지 않았다고 주장하지 않습니다. 현재 제품 기능을 위해 [Phrase 의 문서](https://support.phrase.com/) 를 참조하세요.
