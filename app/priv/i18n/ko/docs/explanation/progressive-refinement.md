초기 초안 [대규모 언어 모델](https://en.wikipedia.org/wiki/Large_language_model) 구조적으로는 맞으나 뉘앙스나 톤 또는 특정 도메인의 표현을 놓칠 수 있습니다. 이는 의도된 설계입니다. Glossia 는 콘텐츠 생성을 소프트웨어 팀이 코드를 다룰 때와 마찬가지로 작동하는 버전을 배포하고 검토하며 반복적으로 개선합니다.

## 정제 루프

1. **초안**: Glossia 는 귀하의 소스 파일과 문맥에서 구조적으로 유효한 첫 번째 초안을 생성합니다 `L10N.md`.
2. **검토**: 팀은 Pull Request 와 Diff 를 통해 문제를 식별하며, 이는 이미 코드 작업에 사용 중인 동일한 워크플로우입니다.
3. **정제**: 개선된 컨텍스트 파일, 용어 수정, 그리고 리뷰 피드백이 다음 실행에 반영됩니다.
4. **수렴**: 각 주기는 프로덕션 품질과의 거리를 줄입니다. 시스템은 제공하신 컨텍스트를 통해 제품의 톤앤매너를 학습합니다.

## 이것이 작동하는 이유

핵심 인사이트는 컨텍스트가 축적된다는 것입니다. 리뷰 코멘트 중 업데이트로 이어지는 `L10N.md` 또는 수정된 용어 항목은, 리뷰를 트리거한 파일뿐만 아니라 향후 모든 실행을 개선합니다.

이는 제조업의 카이젠 원칙과 공학의 순차 근사 원칙에 부합합니다. 적합한 기준선에서 시작하여, 사람의 판단이 개입되도록 체계적으로 개선해 나갑니다.

## 실무적 시사점

- 첫 실행 단계에서 완벽함을 기대할 필요는 없습니다. 1~2 개의 검토 사이클을 계획하세요.
- 명확한 컨텍스트 파일 작성에 시간을 투자하세요. 이는 적용 가능한 가장 효율적인 개선 사항입니다.
- 서버 번역 세션을 사용하여 어떤 파일이 번역되었는지 추적하십시오,
  건너뜀, 또는 실패한 경우까지.
