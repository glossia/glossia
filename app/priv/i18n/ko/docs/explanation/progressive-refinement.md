초안 생성부터 [대규모 언어 모델](https://en.wikipedia.org/wiki/Large_language_model) 구조적 정확성을 유지하지만 뉘앙스, 톤, 또는 도메인 특화 표현은 놓칠 수 있습니다. 이는 의도입니다. Glossia 는 콘텐츠 생성을 소프트웨어 팀이 코드를 대하는 것과 동일하게 취급합니다. 작동 가능한 버전을 배포하고, 검토하며, 반복적으로 개선합니다.

## 다듬기 루프

1. **초안**: Glossia 는 귀하의 소스 파일과 컨텍스트 정보를 기반으로 구조적으로 유효한 첫 번째 초안을 생성합니다. `L10N.md`.
2. **검토**: 팀의 구성원들은 diff 와 pull request 를 통해 이슈를 플래그합니다. 이미 코드를 다루는 데 사용 중인 워크플로우와 맞습니다.
3. **Refine**: 컨텍스트 파일 업데이트 및 용어 교정, 리뷰 피드백이 다음 실행에 반영됩니다.
4. **Converge**: 각 사이클은 프로덕션 품질과의 거리를 줄입니다. 시스템은 제공하는 컨텍스트를 통해 제품의 목소리를 배웁니다.

## Why this works

컨텍스트가 누적된다는 것이 핵심 통찰입니다. 업데이트된 `L10N.md` 또는 수정된 용어 항목이 향후 실행 전반에 걸쳐 개선을 가져옵니다. 이는 리뷰关工委된 파일에만 국한되지 않습니다.

이는 제조업의 카이젠 원리와 공학의 점진적 근사와 같은 원칙을 따릅니다: 충분한 기준선에서 시작하여 인간의 판단이 개입된 채로 체계적으로 개선합니다.

## 실무적 시사점

- 첫 번째 실행에서 완벽함을 기대하지 마십시오. 한두 차례의 검토 사이클을 계획하십시오.
- 명확한 컨텍스트 파일 작성에 시간을 투자하십시오. 이것이 여러분이 할 수 있는 가장 영향력 있는 개선 사항입니다.
- 서버 번역 세션을 사용하여 어떤 파일이 번역되었는지 추적하십시오,
  건너뛰거나 실패한 경우입니다.
