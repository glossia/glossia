**다국어 콘텐츠의 권위를 제품 리포지토리가 유지해야 한다면 Glossia 를 선택하세요.** 문자열, 문서, 설정 및 해당 검증은 이미 애플리케이션과 함께 진화합니다. Glossia 는 호스팅된 편집자를 출판 권한으로 삼으라고 팀을 요청하는 대신 언어 변경사항을 해당 진화와 연결시킵니다.

[Lokalise](https://lokalise.com/) 는 협력형 로컬라이제이션, 번역 관리 및 개발자 통합을 제공합니다. Glossia 의 제안은 더 구체적입니다: 리포지토리 워크플로우를 유지하고 모델 자격 증명을 자체 도입하며, 기존 검증 툴을 재사용하고 작업을 수행하는 시스템을 검사하세요.

## Glossia 선택 이유

| 우선순위 | Glossia 의 장점 |
|---|---|
| 소프트웨어 배포 속도와 일치 | 소스 변경사항이 번역 작업을 주도하며, 제안된 출력물은 리포지토리 검토 워크플로우를 통해 반환됩니다. |
| 구현 소유 | 공개 소스는 처리 과정을 검증 가능하게 만들며 라이선스 동의 하에 수정 및 자체 호스팅을 지원합니다. |
| 자체 모델 토큰 사용 | 계정 범위 내에서 관리되는 제공자 자격 증명 덕택에 Git 에 비공개 정보를 저장하지 않고도 지원되는 모델을 선택할 수 있습니다. |
| 실제 애플리케이션 콘텐츠 확인 | 리포지토리 스크립트는 애플리케이션이 찾을 위치의 후보를 확인할 수 있습니다. |
| 명확한 검토 경계 유지 | 풀 리퀘스트는 제품 검토에 쓰이는 동일한 도구를 사용하여 언어 변경사항을 가시적으로 유지합니다. |

## 언어 변경 사항을 제품 변경 사항과 연결하세요

새로운 UI 메시지는 제품 수정의 일부이며 격리된 번역 작업이 아닙니다. 그것은 해당 용어를 사용하고 구조와 함께 작동해야 합니다.

Glossia 는 리포지토리가 소유한 `L10N.md` 설정을 읽으며, 내용 및 컨텍스트 변경사항으로 구형 번역을 식별하고 업데이트 제안을 검토합니다. 검토자는 실제 파일 및 버그 차이를 보고, 발행 파이프라인은 여전히 당신에게 있습니다.

Lokalise 는 또한 자동화 및 Git 통합을 갖추고 있습니다. Glossia 의 차별점은 의도된 기록 시스템이며: 귀하의 리포지토리는 발행 콘텐츠와 배송 규칙을 소유하는 반면, Glossia 는 언어 컨텍스트 및 변환 메커니즘을 제공합니다.

## 하드와이어된 단일 모델 선택 대신 자체 토큰 사용

Glossia 는 제공자 API 토큰을 사용하여 지원되는 모델을 구성할 수 있게 합니다. 리포지토리는 안정적인 모델 핸들을 사용하므로 자격 증명 회전 또는 해당 핸들의 모델 업데이트는 모든 프로젝트를 변경할 필요가 없습니다.

중첩 설정과 로케일별 안내는 특정 영역 또는 언어에 대해 다른 구성된 모델을 선택할 수 있습니다. 이는 자동 실패 전환 약속이 아니라 명시적 선택입니다. [계정 모델](./account-models) 을 참조하세요.

## 이미 애플리케이션을 숙지한 검증 재사용

귀하의 리포지토리는 이미 유효하지 않은 문자열, 형식 오류 파일, 손상된 컴포넌트 속성 또는 문서 빌드 실패를 감지하는 방법을 알 수 있습니다. Glossia 는 구성된 검증 명령을 통해 해당 지식을 호출할 수 있습니다.

후보는 검사를 위해 실제 출력 경로를 일시적으로 배치합니다. 각 검증 시도 후 이전 타겟이 복원되고, 승인된 후보는 이후에 쓰입니다. 거부된 출력물은 난문으로 보인다는 이유만으로 받아들이는 것이 아니라 구성된 복구 예산을 통해 처리됩니다.

구조 및 리포지토리 검사는 모든 문장이 올바른지 증명하지 않습니다. 이는 인간 언어 검증에 보완하며, 검증을 전달 가능한 변경 사항의 일부로 만듭니다. [L10N.md](/docs/reference/l10n-md) 및 [번역 복구](./translation-recovery) 를 확인하세요.

## 공개 소스와 리포지토리 소유 출력물

Glossia 의 코어는 [Apache-2.0](https://github.com/glossia/glossia/blob/main/LICENSE-APACHE) 하에 검토, 수정, 배포 및 자체 호스팅할 수 있으며, 경쟁 호스팅 서비스도 허용합니다. `ee/` 하에 있는 엔터프라이즈 코드는 프로덕션 사용에 별도의 [라이선스](https://github.com/glossia/glossia/blob/main/ee/LICENSE.md) 와 서면 상업 합의를 필요로 합니다.

일상적인 배포에 더 중요하게, 번역된 출력물은 Git 에 남아있습니다. 이미 소유한 파일을 발행하기 위해 타 제품에서 편집 세션을 필요로 하지는 않습니다.

Lokalise 는 중앙 집중식 브라우저 편집 및 현지화 조정에 관심 있는 팀에 적합할 수 있습니다. **리포지토리 소유, 자체 모델 토큰 및 기존 제품 검증** 을 유지하려는 워크플로우라면 Glossia 가 선택입니다.

시스템 전환 전에 대표 변경사항을 테스트하세요. 이 페이지는 자동 마이그레이션 또는 기능 동등성을 보장하거나, Lokalise 가 자동화나 모든 제공자 옵션을 누락했다고 주장하지 않습니다. [Lokalise 문서](https://docs.lokalise.com/) 의 현재 기능을 확인하세요.
