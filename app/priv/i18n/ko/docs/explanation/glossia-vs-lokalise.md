**다국어 콘텐츠를 위한 권위자로 제품 저장소가 유지되어야 할 때 Glossia 를 선택하세요.** 문자열, 문서화, 설정 및 그에 따른 검사는 이미 애플리케이션과 함께 진화합니다. Glossia 는 팀이 호스팅된 에디터를 출판권자가 될 수 있게 만드는 대신 언어 변경을 그러한 진화에 연결합니다.

[Lokalise](https://lokalise.com/) 는 협업 현지화, 번역 관리, 및 개발자 연동을 제공합니다. Glossia 의 제안은 더 구체적입니다: 저장소 워크플로우 유지, 사용자自备 인증정보 사용, 기존 검사의 재사용 및 작업을 수행하는 시스템을 검사하십시오.

## Glossia 선택 이유

| 당신의 우선순위 | Glossia 의 장점 |
|---|---|
| 소프트웨어 배포 속도 매칭 | 소스 변경이 번역 작업을 추진하고, 제안된 출력이 저장소 검토 워크플로우를 통해 귀환합니다. |
| 구현권 소유 | 공개 소스는 처리 과정을 보이고inspectable하며 라이선스 조건하에 수정과 자체 호스팅을 지원합니다. |
| 사용자自备 모델 토큰 사용 | 계정 스코프 포함된 제공자 인증정보는 시크릿을 Git 에 넣지 않고 지원 모델을 선택하게 합니다. |
| 실제 애플리케이션 콘텐츠 검증 | 저장소 스크립트는 애플리케이션이 찾아야 할 위치에 후보를 검사할 수 있습니다. |
| 명확한 검토 경계 유지 | 풀 리퀘스트를 통해 언어 변경 사항을 제품 검토에 사용되는 동일한 도구의 범위 내에서 가시적으로 유지합니다. |

## 언어 변경 사항을 제품 변경 사항과 연결

새로운 UI 메시지 또는 문서 섹션은 고립된 번역 작업이 아닙니다. 제품 릴리스의 일부이며 해당 용어를 사용하며 구조와 함께 작동해야 합니다.

Glossia 는 저장소 소유의 `L10N.md` 설정, 콘텐츠 및 컨텍스트 변경을 사용하여 구식 번역을 식별하고 검토를 위한 업데이트를 제안합니다. 검토자는 실제 파일과 차이를 보며, 출판 파이프라인은 계속 소유됩니다.

Lokalise 는 또한 자동화 및 Git 연동을 보유합니다. Glossia 의 차이점은 의도된 기록 시스템입니다: 저장소가 발행 콘텐츠와 배포 규칙을 소유하고 있으며, Glossia 는 언어 컨텍스트와 변환 메커니즘을 제공합니다.

## 단일 모델 선택 대신 사용자自备 토큰 사용

Glossia 는 제공자 API 토큰을 사용하여 지원되는 모델을 구성할 수 있게 합니다. 저장소는 안정적인 모델 핸들을 사용하여 인증정보 회전이나 모델 업데이트 일 때 해당 핸들을 거치지 않고 모든 프로젝트를 변경할 필요 없이 수행합니다.

중첩 설정 및 지역별 안내는 특정 영역이나 언어를 위한 다른 구성 완료 모델을 선택할 수 있습니다. 이는 명시적 선택이며 자동 제공자 실패 전환 약속이 아닙니다. [계정 모델](./account-models) 을 참조하세요.

## 이미 애플리케이션을 아는 검증을 재사용

저장소는 이미 잘못된 문자열, 형식화된 파일, 손상된 컴포넌트 속성, 또는 문서화 빌드 실패를 감지하는 방법을 알고 있을 수 있습니다. Glossia 는 구성된 유효성 검사 명령을 통해 그 지식을 호출할 수 있습니다.

후보는 검사를 위해 실제 출력 경로에 일시적으로 배치됩니다. 이전 타겟은 각 유효성 검사 시도 후 복원되며, 승인된 후보는 그 뒤에 작성됩니다. 거부된 출력은 텍스트가 그럴듯해 보이는 것이 아닌 구성된 복구 예산을 통해 처리됩니다.

구조 및 저장소 검사는 모든 문장이 맞是否正确를 증명하지 않습니다. 그들은 인간 언어 검토를 보완하며 해당 검토가 전달 가능한 변경 사항의 일부가 되도록 합니다. [L10N.md](/docs/reference/l10n-md) 및 [번역 복구](./translation-recovery) 참조.

## 공개 소스와 저장소 소유 출력

Glossia는 오픈 코어 모델을 따릅니다. 코어에는 [Apache-2.0](https://github.com/glossia/glossia/blob/main/LICENSE-APACHE)이 적용되며, 해당 조건에 따라 상업적 이용, 수정, 배포, 자체 호스팅 및 경쟁 호스팅 서비스를 제공할 수 있습니다. `ee/`의 코드는 열람할 수 있지만 오픈 소스는 아닙니다. 별도의 [Enterprise 라이선스](https://github.com/glossia/glossia/blob/main/ee/LICENSE.md)가 적용되며 프로덕션 사용에는 서면 상업 계약이 필요합니다.

매일 배송을 위해 번역된 출력은 Git 에 남아있습니다. 당신이-existing 파일 소유하더라도 편집 세션을 위해 다른 제품을 방문할 필요가 없습니다.

Lokalise 는 중앙 집중식 브라우저 편집 및 현지화 조율이 필요한 팀에 적합할 수 있습니다. **저장소 소유, 사용자自备 모델 토큰, 그리고 기존 제품 검사** 가 유지하려는 워크플로우일 때 Glossia 가 선택됩니다.

시스템 전환 전에 대표 변경 사항을 테스트하십시오. 이 페이지는 자동 이주 또는 기능 동등성을 보장하거나 Lokalise 가 자동화나 모든 제공자 옵션이 부족하다고 주장은 하지 않습니다. 현재 기능을 확인하려면 [Lokalise 문서](https://docs.lokalise.com/) 를 참조하세요.
