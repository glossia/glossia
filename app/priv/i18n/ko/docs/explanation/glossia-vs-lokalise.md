**제품 레포지토리가 다국어 콘텐츠 관리의 주권으로 남아야 하는 경우 Glossia 를 선택하세요.** 문자열, 문서, 구성 및 해당 검사들은 이미 애플리케이션과 함께 진화합니다. Glossia 는 언어 변경 사항을 진화와 연결하여 유지하며, 팀에게 호스팅된 편집기를 출판 주권으로 만드는 것을 요구하지 않습니다.

[Lokalise](https://lokalise.com/) 는 협력적 로케일라이제이션, 번역 관리, 개발자 통합을 제공합니다. Glossia 의 제안은 더 구체적입니다: 레포지토리 워크플로우 유지, 자체 모델 자격 증명 가져오기, 기존 검사 재사용, 실제 작업을 수행하는 시스템을 점검하세요.

## Glossia 왜 선택하는가

| 귀하의 우선순위 | Glossia 의 장점 |
|---|---|
| 소프트웨어 배포 속도와 일치 | 소스 변경이 번역 작업을 주도하며, 제안된 출력이 레포지토리 검토 워크플로우를 통해 돌아옵니다. |
| 구현 주도 권한 유지 | 공개 소스는 처리 과정을 점검 가능하게 하며, 라이선스 조건 하에 수정과 자체 호스팅을 지원합니다. |
| 자신의 모델 토큰 사용 | 계정 범위의 제공자 자격 증명을 사용하여 기밀 정보를 Git 에 저장하지 않고도 지원되는 모델을 선택할 수 있습니다. |
| 실제 애플리케이션 내용 확인 | 레포지토리 스크립트는 애플리케이션이该内容 찾아야 할 곳에서 후보 항목을 확인할 수 있습니다. |
| 명확한 검토 경계 유지 | 풀 리퀘스트는 제품 검토에 사용되는 동일한 툴에서 언어 변경 사항을 가시적으로 유지합니다. |

## 언어 변경 사항을 제품 변경 사항과 연결하세요

새 UI 메시지 또는 문서 섹션은 고립된 번역 작업이 아닙니다. 그것은 제품 버전의 일부이며, 해당 전문 용어를 사용하며 구조와 함께 작동해야 합니다.

Glossia 는 레포지토리가 소유한 `L10N.md` 구성을 판독하고, 콘텐츠 및 컨텍스트 변경을 사용하여 구식 번역을 식별하며 검토를 위해 업데이트를 제안합니다. 검토자는 실제 파일과 차이를 보며; 발행 파이프라인은 여전히 여러분의 것입니다.

Lokalise 는 또한 자동화와 Git 통합을 제공합니다. Glossia 의 차이점은 의도된 기록 시스템입니다: 레포지토리는 발행 콘텐츠 및 배포 규칙을 소유하며, Glossia 는 언어 컨텍스트 및 변환 메커니즘을 제공합니다.

## 하드와이어링 한 모델 선택 대신 자체 토큰 가져오기

Glossia 는 자신의 제공자 API 토큰을 사용하여 지원되는 모델을 구성할 수 있게 합니다. 레포지토리는 안정적인 모델 핸들을 사용하므로, 자격 증명을 교체하거나 해당 핸들 뒤의 모델을 업데이트하더라도 모든 프로젝트를 변경할 필요는 없습니다.

중첩된 구성과 로케일별 안내는 특정 지역이나 언어를 위해 다른 구성된 모델을 선택할 수 있습니다. 이는 명시적인 선택이며 자동화된 제공자 페일오버 약속이 아닙니다. [계정 모델](./account-models) 을 참조하세요.

## 이미 애플리케이션을 알고 있는 검증 재사용

레포지토리는 이미 잘못된 문자열, 형식이 잘못된 파일, 손상된 컴포넌트 속성, 또는 문서 빌드 실패를 감지하는 방법을 알고 있을 수 있습니다. Glossia 는 구성된 검증 명령을 통해 해당 지식을 호출할 수 있습니다.

후보 항목은 검사를 위해 일시적으로 실제 출력 경로에 배치됩니다. 각 검증 시도 후 이전 대상이 복원되고, 승인된 후보 항목이 이후에 기록됩니다. 거부된 출력은 문서가 그럴듯해 보이기 때문이라는 이유보다는 구성된 복구 예산을 통과하게 됩니다.

구조적 및 레포지토리 검사는 모든 문장이 정확한지 증명하지 않습니다. 그들은 인간 언어 검토를 보완하며 해당 검토를 전달 가능 변경의 일부로 만듭니다. [L10N.md](/docs/reference/l10n-md) 및 [번역 복구](./translation-recovery) 를 참조하세요.

## -public source and repository-owned outputs

Glossia 의 구현은 [O'Saasy](https://github.com/glossia/glossia/blob/main/LICENSE.md) 하에 점검, 수정 및 자체 호스팅 가능합니다. 해당 라이선스는 경쟁 호스팅 서비스를 제한하며 무제한 오픈소스 라이선스가 아닙니다.

일상 배포에서 더 중요한 점은 번역된 출력이 Git 에 유지된다는 것입니다. 자신의 파일을 발표하기 위해 다른 제품에서 편집 세션이 아니를 필요하지 않습니다.

Lokalise 는 중앙 집중식 브라우저 편집 및 로케일라이제이션 조정 조율이 필요한 팀에 적합할 수 있습니다. **레포지토리 소유권, 자체 모델 토큰, 기존 제품 검사** 가 유지하려는 워크플로우일 때 Glossia 가 선택입니다.

시스템 전환 전에 대표 변경 사항을 테스트하세요. 이 페이지는 자동 마이그레이션 또는 기능 동등성을 약속하지 않으며, Lokalise 가 자동화 또는 모든 제공자 옵션을 갖추지 않았다고 주장하지 않습니다. [Lokalise 의 문서](https://docs.lokalise.com/) 의 현재 기능을 참조하세요.
