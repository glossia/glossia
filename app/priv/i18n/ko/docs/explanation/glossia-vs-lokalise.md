**제품 레포지토리가 다국어 콘텐츠의 출판 권한으로 남아있어야 할 때 Glossia 를 선택하세요.** 문자열, 문서, 설정, 그리고 이를 검증하는 작업은 이미 애플리케이션과 함께 진화해 왔습니다. Glossia 는 언어 변경사항을 해당 진보에 연결하여 유지하며, 팀이 호스팅된 편집자를 출판 권한으로 만들도록 요구하는 대신 그렇게 처리합니다.

[Lokalise](https://lokalise.com/) 는 협업형 로컬라이제이션, 번역 관리 및 개발자 통합을 제공합니다. Glossia 의 제안은 더 구체적입니다: 레포지토리 워크플로우를 유지하고, 모델을 직접 가져오며, 기존 검증을 재사용하고, 작업을 펼치는 시스템을 점검하세요.

## Glossia 를 선택해야 하는 이유

| 당신의 우선순위 | Glossia 의 장점 |
|---|---|
| 소프트웨어 배포 속도와 일치 | 소스 변경이 번역 작업을 주도하며, 제안된 출력물은 레포지토리 검토 워크플로우를 통해 반환됩니다. |
| 구현을 소유하세요 | 공개 소스는 처리 과정을 점검할 수 있게 하며, 라이선스 조건 하에서 수정 및 자체 호스팅을 지원합니다. |
| 자체 모델 토큰 사용 | 계정 범위의 제공자 자격 증명을 사용하면 Git 에 비밀을 저장하지 않고 지원 가능한 모델을 선택할 수 있습니다. |
| 실제 애플리케이션 내용 검증 | 레포지토리 스크립트는 애플리케이션이 찾아야 하는 위치에서 후보를 점검할 수 있습니다. |
| 명확한 검토 경계 유지 | 풀 리퀘스트는 제품 검토와 같은 도구에서 언어 변경사항을 가시적으로 유지합니다. |

## 제품 변경 사항에 언어 변경 사항을 연결하세요

새 UI 메시지나 문서 섹션은 고립된 번역 작업이 아닙니다. 그것은 제품 복수에 속하며, 해당 용어를 사용해야 하며 기존 구조와 함께 작동해야 합니다.

Glossia 는 레포지토리가 소유한 `L10N.md` 구성을 읽습니다. 콘텐츠 및 컨텍스트 변경사항을 사용하여 구형 번역을 식별하고 검토를 위한 업데이트를 제안합니다. 검토자는 실제 파일과 차이를 보며, 출판 파이프라인은 여전히 귀소인에게 남습니다.

Lokalise 도 자동화 및 Git 통합이 있습니다. Glossia 의 차이점은 의도된 기록 체계입니다: 귀하의 레포지토리가 출판된 콘텐츠와 배송 규칙을 소유하며, Glossia 는 언어 컨텍스트와 변환 메커니즘을 제공합니다.

## 하나의 모델 선택만 하드와이어링하지 말고, 자체 토큰으로 구성하세요

Glossia 는 제공자 API 토큰을 사용하여 지원 가능한 모델을 구성할 수 있습니다. 레포지토리는 안정적인 모델 핸들을 사용하므로, 자격 증명 회전이나 해당 핸들의 모델 업데이트는 모든 프로젝트를 변경하지 않아도 됩니다.

중첩된 설정 및 지역 지침은 특정 영역이나 언어를 위해 다른 설정된 모델을 선택할 수 있습니다. 이는 명시적 선택이며, 자동 제공자 페일오버의 약속이 아닙니다. [계정 모델](./account-models) 을 참조하세요.

## 이미 애플리케이션을 아는 검증 작업 재사용

레포지토리는 이미 유효하지 않은 문자열, 형식 오류 파일, 손상된 컴포넌트 속성 또는 문서 빌드 실패를 감지하는 방법을 알 수 있습니다. Glossia 는 설정된 검증 명령을 통해 해당 지식을 호출할 수 있습니다.

후보는 검사를 위해 실제 출력 경로에 일시적으로 배치됩니다. 각 검증 시도 후 이전 대상이 복원되며, 승인된 후보가 이후 기록됩니다. 기각된 출력은 설정된 복구 예산을 거치며, 텍스트가 그럴듯해 보이기만 해서 승인되지 않습니다.

구조적 및 레포지토리 검증은 모든 문장이 정확한지 증명하지 않습니다. 그들은 인간의 언어 검토를 보완하여 해당 검토를 최종 변경의 일부로 만듭니다. [L10N.md](/docs/reference/l10n-md) 와 [번역 복구](./translation-recovery) 를 참조하세요.

## 공개 소스와 레포지토리 소유 출력물

Glossia는 오픈 코어 모델을 따릅니다. 코어에는 [Apache-2.0](https://github.com/glossia/glossia/blob/main/LICENSE-APACHE)이 적용되며, 해당 조건에 따라 상업적 이용, 수정, 배포, 자체 호스팅 및 경쟁 호스팅 서비스를 제공할 수 있습니다. `ee/`의 코드는 열람할 수 있지만 오픈 소스는 아닙니다. 별도의 [Enterprise 라이선스](https://github.com/glossia/glossia/blob/main/ee/LICENSE.md)가 적용되며 프로덕션 사용에는 서면 상업 계약이 필요합니다.

일상적인 배송 측면에서 더 중요한 것은, 번역된 출력물이 Git 에 남아있다는 것입니다. 기존 파일을 소유하는 것만으로 다른 제품에서 편집 세션을 시작할 필요가 없습니다.

Lokalise 는 중앙화된 브라우저 편집 및 현지화 조정이 필요한 팀에 적합할 수 있습니다. **레포지토리 소유권, 자체 모델 토큰, 그리고 기존 제품 검증** 을 유지하려는 워크플로우라면 Glossia 가 선택입니다.

시스템 전환 전에 대표적인 변경 사항을 테스트하세요. 이 페이지는 자동 마이그레이션 또는 기능 동등성을 약속하거나 Lokalise 가 자동화나 모든 제공자 옵션이 부족하다고 주장하지 않습니다. [Lokalise 의 문서](https://docs.lokalise.com/) 에서 현재 기능을 확인하세요.
