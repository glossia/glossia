**제품 저장소에서 다국어 콘텐츠의 주도권이 유지되어야 할 때 Glossia 를 선택하세요.** 문자열, 문서, 설정 및 이에 대한 검증은 이미 애플리케이션의 진화와 함께 발전합니다. Glossia 는 언어 변경 사항을 그 진화의 맥락으로 처리하며, 팀이 호스팅된 편집기를 출판 권한으로 설정하도록 요구하지 않습니다.

[Lokalise](https://lokalise.com/) 는 협업 현지화, 번역 관리 및 개발자 통합을 제공합니다. Glossia 의 제안은 더 구체적입니다: 직접 저장소 워크플로우를 유지하세요, 자체 모델 자격 증명을 가져오고, 기존 검사를 재사용하고, 실제 작업을 수행하는 시스템을 검토하세요.

## Glossia 를 선택해야 하는 이유

| 귀사의 우선 순위 | Glossia 의 장점 |
|---|---|
| 소프트웨어 배포 속도와 일치 | 소스 변경사항이 번역 작업을 주도하며, 제안된 출품 결과는 저장소 검토 워크플로우를 통해 반환됩니다. |
| 구현 소유 | 공개 소스는 처리 과정을 검토 가능하게 만들며, 라이선스 약정 하에서 수정 및 자체 호스팅을 지원합니다. |
| 자체 모델 토큰 사용 | 계정 단위 제한된 제공자 자격 증명을 사용하면 기밀 정보를 Git 에 저장하지 않고 지원되는 모델을 선택할 수 있습니다. |
| 실제 애플리케이션 콘텐츠 검증 | 저장소 스크립트는 애플리케이션이 찾을 위치에서 후보를 확인할 수 있습니다. |
| 명확한 검토 경계 유지 | 풀 리퀘스트는 제품 검토에 사용되는 동일한 도구에 언어 변경 사항을 가시화 합니다. |

## 언어 변경사항을 제품 변경사항과 연결 유지

새 UI 메시지 또는 문서 섹션은 고립된 번역 작업이 아닙니다. 이는 제품 수정에 속하며 해당 전문 용어를 사용하며 구조와 함께 작동해야 합니다.

Glossia 는 저장소 소유 `L10N.md` 구성을 읽으며, 내용과 컨텍스트 변경 사항을 사용하여 구 번역을 식별하고 검토를 위해 업데이트를 제안합니다. 검토자는 실제 파일과 diff 를 보며, 출판 파이프라인은 다시 여러분 것으로 남아 있습니다.

Lokalise 도 자동화와 Git 통합을 제공합니다. Glossia 의 차별점은 명시된 기록 시스템입니다: 저장소가 출판 콘텐츠와 배송 규칙을 소유하며, Glossia 는 언어 컨텍스트와 변환 메커니즘을 제공합니다.

## 단일 모델 선택을 하드 와이어링하지 않고 자체 토큰 가져오기

Glossia 는 제공자 API 토큰을 사용하여 지원되는 모델을 구성할 수 있게 합니다. 저장소는 안정적인 모델 핸들을 사용하므로 자격 증명 회전이나 그 핸들을 통해의 모델 업데이트는 모든 프로젝트를 변경할 필요가 없습니다.

중첩 구성과 로케일별 가이드는 특정 영역이나 언어에 대해 다른 구성된 모델을 선택할 수 있습니다. 이는 명시적 선택이며 자동 제공자 페일오버의 약속이 아닙니다. [Account models](./account-models) 를 참조하세요.

## 이미 애플리케이션을 알고 있는 검증 재사용

귀사의 저장소는 이미 잘못된 문자열, 형식 오류 파일, 손상된 컴포넌트 속성 또는 문서 빌드 실패를 검출하는 방법을 알 수 있습니다. Glossia 는 구성된 검증 명령을 통해 그 지식을 호출할 수 있습니다.

후보물은 검증의 목적을 위해 실제 출력 경로를 일시적으로 위치됩니다. 각 검증 시도 후 이전 타겟이 복원되며, 승인된 후보는 그 이후에 기록됩니다. 기각된 출력은 텍스트가 그럴듯해 보여도 단순히 승인되는 것이 아니라 구성된 복구 예산을 통과합니다.

구조 및 저장소 검사는 모든 문장이 올바른지 증명하지 않습니다. 이는 인간 언어 검토를 보완하며 해당 검토를 전달 가능한 변경 사항의 일부로 만듭니다. [L10N.md](/docs/reference/l10n-md) 와 [번역 복구](./translation-recovery) 를 참조하세요.

## 공개 소스 및 저장소 소유 출력

Glossia 의 구현은 [O'Saasy](https://github.com/glossia/glossia/blob/main/LICENSE.md) 라이선스 하에 검토, 수정 및 자체 호스팅을 이용할 수 있습니다. 이 라이선스는 경쟁 호스팅 서비스를 제한하며 무제한 오픈소스 라이선스가 아닙니다.

일상적인 배포에 중요한 점은 번역된 출력이 Git 에 남아있다는 것입니다. 이미 소유한 파일만 게시하기 위해 다른 제품의 편집 세션이 불필요합니다.

Lokalise 는 중앙 집중식 브라우저 편집 및 현지화 조정을 원하는 팀에 적합할 수 있습니다. **저장소 소유, 자체 모델 토큰 및 기존 제품 검증** 이 유지하고자 하는 워크플로우인 경우 Glossia 가 선택입니다.

시스템 전환 전 대표 기능을 테스트하세요. 이 페이지는 자동 마이그레이션이나 기능 동등성을 약속하지 않으므로 Lokalise 가 자동화나 모든 제공자 옵션이 부족하다고 주장하지 않습니다. [Lokalise 의 문서](https://docs.lokalise.com/) 에서 해당 명세서 확인.
