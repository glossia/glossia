**로컬라이제이션 작업이 소프트웨어 배포 속도를 따라잡아야 하는 경우 Glossia 를 선택하세요.** 기존 리포지토리에서는 이미 변경 사항이 어떻게 검토되고, 검증되어, 송출되는지를 정의하고 있습니다. Glossia 는 별도의 번역 작업 공간을 진행의 중심으로 만들지 않고 언어 작업을 해당 루프에 포함시킵니다.

[Crowdin](https://crowdin.com/) 은 협력적 번역 관리, 검토 워크플로우, 번역 메모리, 그리고 리포지토리 통합을 제공합니다. 소프트웨어 팀을 위한 Glossia 의 장점은 리포지토리 소유 콘텐츠, 검사 가능한 소스, 자체 모델 인증서, 그리고 실제 프로젝트를 이해하는 검증의 결합입니다.

## ## Glossia 를 선택하는 이유

| 우선 순위 | Glossia 의 장점 |
|---|---|
| 지속적 배포 | 번역 실행은 소스 변경 사항을 따르며 검토 가능한 리포지토리 업데이트를 반환합니다. 콘텐츠는 별도의 관련 없는 릴리스 프로세스가 필요하지 않습니다. |
| 구현 통제 유지 | 공개 애플리케이션, CLI, 배포 코드는 라이선스 조건 하에 검토, 수정 및 자체 호스팅이 가능합니다. |
| 토큰 직접 가져오기 | 지원 모델을 직접 제공자 API 토큰으로 구성하세요. 리포지토리 파일은 안정된 모델 핸들을 참조하며 비밀 정보는 사용하지 않습니다. |
| 신뢰할 수 있는 검증 단계를 재사용 | 수락하기 전에 실제 타겟 경로에서 후보에 대해 리포지토리 검증 명령을 실행하세요. |
| 콘텐츠 소유권 유지 | 소스 파일, 번역 출력물, 설정 및 풀 리퀘스트 이력은 리포지토리에 남아있습니다. |

## 커밋 속도를 따라잡는 현지화

Glossia 는 버전화된 `L10N.md` 지시에서 작동하며 업데이트가 필요한 콘텐츠를 감지합니다. 변경되지 않은 입력물은 다시 번역할 필요가 없습니다. 프로젝트는 하나의 열린 번역 풀 리퀘스트를 유지하며 일괄 처리로 진보를 게시하여, 소스가 발전함에 따라 불필요한 풀 리퀘스트 및 반복된 CI 실행을 줄입니다.

결과는 이미 배포되는 팀의 동일한 작고 검토 가능한 변경 사항을 중심으로 설계된 언어 워크플로우입니다. 지속적은 검토되지 않은 것을 의미하지 않으며, 검토자는 여전히 병합이 안전한지를 결정합니다.

Crowdin 또한 Git 통합 및 자동화를 지원합니다. Glossia 를 선택하는 이유는 Crowdin 이 리포지토리에 연결할 수 없는 것이 아니라, 리포지토리 배포가 Glossia 워크플로우의 기반이며 단순한 통합 경계보다 중요합니다.

## 여러분의 토큰, 모델 선택

제공자 토큰 회전이나 번역 워크플로우 뒤의 모델 변경을 위해 리포지토리 구성을 다시 구축할 필요는 없습니다. Glossia 는 자격 증명을 계정 설정에 저장하고 리포지토리에 안정적인 핸들을 노출합니다. 다른 콘텐츠 영역이나 타겟 로케일은 서로 다른 구성된 모델을 선택할 수 있습니다.

이는 팀이 지원하는 제공자 관계 및 모델을 사용할 수 있는 제어권을赋予합니다. [모델 제공자 구성하기](/docs/how-to/configure-a-model-provider) 를 참조하세요.

## 제품의 일부로 출력 검증

번역은 읽기 부드럽게 작성되더라도 문서 빌드, 컴포넌트, 플레이스홀더 또는 애플리케이션 파서를 손상시킬 수 있습니다. Glossia 는 편집자의 텍스트 평가에서 주저하지 않고 리포지토리 검사를 재사용할 수 있게 합니다.

리포지토리에 이미 문서 검증 스크립트가 제공된다면, 직접 참조하세요:

```yaml
validation:
  - ./scripts/validate-docs.sh
  - --strict
```

검증기는 실제 타겟 경로의 후보를 받고, 실패 시 0 이 아닌 상태 코드를 반환하며, 구성된 재시도 예산 내에서 실행됩니다. 검증 환경에는 해당 의존성이 반드시 있어야 합니다. 계약은 [L10N.md](/docs/reference/l10n-md) 를 참조하세요.

## 리포지토리 포기하지 않는 공개 소스

Glossia 의 플랜 작동 방식, 자격 증명 처리, Markdown 유지, 결과 검증을 검사할 수 있습니다. 언어 서비스가 사용 불가능하더라도 기존 번역 파일은 리포지토리 파이프라인을 통해 게시될 수 있습니다.

Glossia 는 [O'Saasy 라이선스](https://github.com/glossia/glossia/blob/main/LICENSE.md) 하에서 소스 공개 가능하며, 자체 호스팅은 허용하지만 경쟁 호스팅 서비스를 제한합니다. 이는 제한 없는 오픈소스 라이선스가 아닙니다.

기여자 조정과 전용 번역 편집이 중심인 프로그램은 Crowdin 이 여전히 적절할 수 있습니다. **Git 소유 콘텐츠, 기존 검증, 그리고 배포를 따라가는 현지화** 가 최우선인 소프트웨어 팀을 위한 Glossia 는 해당 작업에 설계되었습니다.

이 비교는 Crowdin 이 자동화나 모든 형태의 제공자 통합을 갖추지 못했거나, Glossia 가 자동으로 메모리 및 이력을 마이그레이션한다는 주장을 하지 않습니다. 현재 기능은 [Crowdin 의 기술 문서](https://support.crowdin.com/) 를 참조하세요.
