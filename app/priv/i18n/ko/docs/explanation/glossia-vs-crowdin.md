**소프트웨어 배포 속도에 맞춰 현지화가 필요할 때 Glossia 를 선택하세요.** 이미 귀하의 저장소는 변경 사항 검토, 검증 및 배포 방식을 정의합니다. Glossia 는 별도의 번역 워크스페이스가 공정의 중심이 되지 않도록 해당 루프에 언어 작업을 통합합니다.

[Crowdin](https://crowdin.com/) 은 협력 번역 관리, 검토 워크플로우, 번역 메모리 및 저장소 통합을 제공합니다. 소프트웨어 팀에 대한 Glossia 의 장점은 저장소 소유 콘텐츠, 검증 가능한 소스, 자체 모델 자격 증명, 실제 프로젝트를 이해하는 검증을 결합한 것입니다.

## Glossia 선택 이유

| 귀하의 우선순위 | Glossia 의 장점 |
|---|---|
| 지속적 출시 | 번역 실행은 소스 변경 사항을 따르고 검토 가능한 저장소 업데이트를 반환합니다. 콘텐츠는 별도의 관련 없는 릴리스 프로세스가 필요하지 않습니다. |
| 실시 사항 제어요유 | 공개 애플리케이션, CLI, 및 배포 코드는 라이선스 조건 하에서 검토, 수정 및 자체 호스팅할 수 있습니다. |
| 제공자 토큰 직접 제공 | 지원된 모델은 자체 제공자 API 토큰으로 구성할 수 있습니다. 저장소 파일은 비밀이 아닌 안정적인 모델 핸들을 참조합니다. |
| 신뢰할 수 있는 검사 재사용 | 수용하기 전에 실제 목표 경로에서 저장소 유효성 검사 명령어를 실행합니다. |
| 콘텐츠 소유권 유지 | 소스 파일, 번역 결과, 구성 및 풀 리퀘스트 이력은 귀하의 저장소에 남아 있습니다. |

## 커밋 흐름을 따라가는 현지화

Glossia 는 버전화된 `L10N.md` 지침에서 작동하며 업데이트가 필요한 콘텐츠를 감지합니다. 변경되지 않은 입력은 다시 번역할 필요가 없습니다. 프로젝트는 하나의 열린 번역 풀 리퀘스트를 유지하며 진보를 배치로 발표하여 불필요한 풀 리퀘스트와 반복 CI 실행을 줄입니다.

결과는 귀사의 팀이 이미 타겟으로 하고 있는 동일한 작은 검토 가능한 변경 작업을 중심으로 설계된 언어 워크플로우입니다. '지속적'은 검토되지 않은 것을 의미하지 않습니다: 검토자는 병합할 것을 안전한지를 여전히 결정합니다.

Crowdin 은 또한 Git 통합과 자동화를 지원합니다. Glossia 를 선택하는 이유는 Crowdin 이 저장소에 연결할 수 있기 때문이 아니라, 저장소 배포가 Glossia 워크플로우의 기반이기 때문입니다.

## 자신의 토큰, 자체 선택 모델

영구 토큰 교체나 번역 워크플로우 후방 모델 변경을 위해 저장소 구성을 다시 구축해야 할 필요는 없습니다. Glossia 는 자격 증명을 계정 설정에 저장하고 저장소에 안정적인 핸들을 공개합니다. 다른 콘텐츠 영역 또는 대상 로케일은 서로 다른 구성된 모델을 선택할 수 있습니다.

이는 팀이 지원되는 공급자 관계와 사용하는 모델 선택을 제어할 수 있게 합니다. [모델 제공자 구성](/docs/how-to/configure-a-model-provider) 을 확인하세요.

## 제품 사용의 일부로 출력 검증

번역이 잘 읽히기도 하지만 여전히 문서 빌드, 컴포넌트, 플레이스홀더 또는 애플리케이션 파서를 손상시킬 수 있습니다. Glossia 는 편집자의 텍스트 평가에서 멈추지 않고 저장소 검사를 재사용할 수 있게 허용합니다.

이미 저장소에 문서 유효성 검사 스크립트가 제공되는 경우 직접 참조하세요:

```yaml
validation:
  - ./scripts/validate-docs.sh
  - --strict
```

검증기는 실제 목표 경로를 통해 후보자를 받으며, 실패 시 0 보다 큰 상태를 반환하고 설정된 재시도 예산 내에서 실행됩니다. 의존성은 실행 환경에 있어야 합니다. 계약 사항에 대해서는 [L10N.md](/docs/reference/l10n-md) 를 확인하세요.

## 보유를 포기하지 않는 공개 소스

Glossia 계획이 어떻게 작동하고, 자격 증명을 따르고, 마크다운을 보존하며, 결과를 검증하는지 점검할 수 있습니다. 기존 번역 파일은 언어 서비스가 이연되어도 저장소의 파이프라인을 통해 게시될 수 있습니다.

Glossia는 오픈 코어 모델을 따릅니다. 코어에는 [Apache-2.0](https://github.com/glossia/glossia/blob/main/LICENSE-APACHE)이 적용되며, 해당 조건에 따라 상업적 이용, 수정, 배포, 자체 호스팅 및 경쟁 호스팅 서비스를 제공할 수 있습니다. `ee/`의 코드는 열람할 수 있지만 오픈 소스는 아닙니다. 별도의 [Enterprise 라이선스](https://github.com/glossia/glossia/blob/main/ee/LICENSE.md)가 적용되며 프로덕션 사용에는 서면 상업 계약이 필요합니다.

Crowdin 은 기여자 조정과 전용 번역 편집자에 중점을 둔 프로그램에 여전히 적합할 수 있습니다. 우선순위가 **Git 기반 콘텐츠, 기존 검증, 배포 흐름에 따른 현지화** 인 경우 Glossia 는 해당 작업에 적합하도록 설계되었습니다.

이 비교는 Crowdin 이 자동화 의 또는 모든 형태의 제공자 통합이 부족하거나, Glossia 가 자동으로 제 기억원과 역사를 이전한다고 주장하지 않습니다. 현재 기능을 확인하려면 [Crowdin 의 문서](https://support.crowdin.com/) 를 참조하세요.
