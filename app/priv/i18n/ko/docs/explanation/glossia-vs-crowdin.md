**소프트웨어 배포 속도와 함께 현지화가 진행되어야 할 때 Glossia 를 선택하세요.** 귀사의 저장소는 이미 변경 사항의 검토, 검증, 및 배포 방식을 정의합니다. Glossia 는 별도의 번역 워크스페이스를 프로세스의 중심으로 두지 않고 언어 작업을 해당 루프에 포함시킵니다.

[Crowdin](https://crowdin.com/) 은 협업형 번역 관리, 검토 워크플로우, 번역 메모리, 및 저장소 통합을 제공합니다. 소프트웨어 팀을 위한 Glossia 의 강점은 저장소 소유 콘텐츠, 검증 가능한 소스, 자체 모델 자격 증명, 및 실제 프로젝트를 이해하는 검증 기능의 조합에 있습니다.

## Glossia 를 선택하는 이유

| 귀사의 우선순위 | Glossia 의 장점 |
|---|---|
| 지속적인 배포 | 번역 실행은 소스 변경에 따라 발생하며 검토 가능한 저장소 업데이트를 반환합니다. 콘텐츠는 별도의 관련 없는 릴리스 프로세스가 필요 없습니다. |
| 구현 통제권 유지 | 공개 애플리케이션, CLI, 및 배포 코드는 라이선스 조건 내에서 검사, 수정, 및 자체 호스팅할 수 있습니다. |
| 자체 토큰 사용 | 지원 가능한 모델을 제공자 API 토큰으로 구성하세요. 저장소 파일은 안정적인 모델 핸들을 참조하며 비밀 정보를 사용하지 않습니다. |
| 신뢰하는 검증 항목 재사용 | 수용하기 전에 실제 목표 경로의 후보에 대해 저장소 유효성 검사 명령을 실행합니다. |
| 콘텐츠 소유권 유지 | 소스 파일, 번역 결과, 설정 및 풀 리퀘스트 기록은 저장소에 유지됩니다. |

## 커밋과 함께 가는 현지화

Glossia 는 버전화된 `L10N.md` 지침에서 작동하며 업데이트가 필요한 콘텐츠를 감지합니다. 변경 사항이 없는 입력은 다시 번역할 필요가 없습니다. 프로젝트는 하나의 열린 번역 풀 리퀘스트를 유지하며, 소스가 진화함에 따라 불필요한 풀 리퀘스트와 반복 CI 실행을 줄이기 위해 배치로 진행 상황을 게시합니다.

결과적으로 팀이 이미 배포하는 동일한 작은 검토 가능한 변경을 중심으로 설계된 언어 워크플로우입니다. 지속적인 것은 검토되지 않았다는 의미가 아닙니다: 검토자는 여전히 병합할 수 있는지 여부를 결정합니다.

Crowdin 도 Git 통합 및 자동화를 지원합니다. Glossia 를 선택하는 이유는 Crowdin 이 저장소에 연결할 수 없기 때문이 아니라, 저장소 배포가 Glossia 워크플로우의 기초이며 단순한 통합 경계가 아닙니다.

## 귀하의 토큰, 모델 선택

제공자 토큰을 회전시키거나 번역 워크플로우 뒤의 모델을 변경하기 위해 저장소構成을 재빌드할 필요가 없습니다. Glossia 는 계정 설정에서 자격 증명을 저장하고 저장소에 안정적인 핸들을 노출합니다. 다른 콘텐츠 영역이나 타겟 로케일은 서로 다른 구성 모델을 선택할 수 있습니다.

[모델 제공자 구성](/docs/how-to/configure-a-model-provider) 을 참조하십시오.

## 제품의 일부로서의 출력 검증

번역은 읽기 잘하지만 문서 빌드, 컴포넌트, 플레이스홀더, 또는 애플리케이션 파서를 손상시킬 수 있습니다. Glossia 는 편집자의 텍스트 평가로만 끝낼 것이 아니라 저장소 검증을 재사용할 수 있게 합니다.

저장소에 문서 유효성 검사 스크립트가 이미 제공되면 이를 직접 참조하세요:

```yaml
validation:
  - ./scripts/validate-docs.sh
  - --strict
```

검증기는 실제 목표 경로에서 후보를 받아들이고 실패 시 제로가 아닌 상태를 반환하며 설정된 재시도 예산 내에서 실행합니다. 이에 필요한 종속 항목은 검증 환경에 있어야 합니다. 계약은 [L10N.md](/docs/reference/l10n-md) 에서 확인하세요.

## 저장소를 양도하지 않는 공개 소스

Glossia 의 계획 작동 방식, 자격 증명 처리, Markdown 보존, 및 결과 검증을 확인하세요. 언어 서비스가 불가능하더라도 기존 번역 파일은 저장소 파이프라인을 통해 게시 가능합니다.

Glossia 는 [O'Saasy license](https://github.com/glossia/glossia/blob/main/LICENSE.md) 하에서 소스 형태로 제공 가능하여 자체 호스팅이 가능하지만 경쟁하는 호스팅 서비스를 제한합니다. 이는 제한되지 않는 오픈 소스 라이선스가 아닙니다.

Crowdin 은 기여자 조정 및 전용 번역 편집자를 중심으로 한 프로그램에 여전히 적합할 수 있습니다. 소프트웨어 팀의 우선순위가 **Git 소유 콘텐츠, 기존 유효성 검사, 배포를 따른 현지화**인 경우 Glossia 는 해당 작업을 위해 설계되었습니다.

본 비교는 Crowdin 이 자동화나 모든 제공자 통합 형태를 결여했으며 Glossia 가 자동으로 기억과 역사를 마이그레이션한다고 주장하지 않습니다. 현재 기능을 확인하기 위해 [Crowdin 의 문서](https://support.crowdin.com/) 를 참조하십시오.
