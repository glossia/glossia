로컬라이제이션이 소프트웨어 출시 속도와 함께 진행해야 할 때 **Glossia**를 선택하세요. 저장소는 이미 변경 사항이 어떻게 검토, 검증 및 배포되는지를 정의하고 있습니다. Glossia 는 별도의 번역 워크스페이스를 프로세스의 중심에 두는 대신 언어 작업을 해당 문맥에 통합합니다.

[Crowdin](https://crowdin.com/) 은 협업 번역 관리, 검토 워크플로우, 번역 메모리 및 저장소 통합을 제공합니다. 소프트웨어 팀에게 Glossia 의 이점은 저장소 소유 컨텐츠, 검토 가능한 소스, 사용자 직접의 모델 인증정보, 그리고 실제 프로젝트를 이해하는 검증의 조합에 있습니다.

## Glossia 를 선택하는 이유

| 귀하의 우선순위 | Glossia 의 장점 |
|---|---|
| 지속적으로 배포 | 번역 실행은 소스 변경 사항을 따라가고 검토 가능한 저장소 업데이트를 반환합니다. 컨텐츠는 별도의 관련 없는 릴리스 프로세스가 필요 없습니다. |
| 구현에 대한 권한 유지 | 공개 애플리케이션, CLI 및 배포 코드는 라이선스 조항에 따라 검토, 수정 및 자체 호스팅할 수 있습니다. |
| 본인의 토큰 가져오기 | 지원하는 모델을 본인의 제공자 API 토큰과 함께 구성하세요. 저장소 파일은 비밀정보 대신 안정적인 모델 핸들을 참조합니다. |
| 신뢰하는 검사를 다시 사용 | 승인 전에 후보의 실제 타겟 경로를 기준으로 저장소 유효성 검사 명령을 실행하세요. |
| 내러티브 보호 유지 | 소스 파일, 번역된 출력물, 설정 및 풀 요청 기록은 귀하의 저장소에 유지됩니다. |

## 커밋과 맞춰가는 로컬라이제이션

Glossia 는 버전화된 `L10N.md` 지침에서 작동하고 업데이트해야 하는 콘텐츠를 감지합니다. 변경되지 않은 입력은 다시 번역할 필요가 없습니다. 프로젝트는 하나의 열린 번역 풀 요청을 유지하며, 배치 단위로 진보를 공개하고 소스가 진화함에 따라 불필요한 풀 요청 및 반복 CI 실행을 줄입니다.

결과물은 귀 팀이 이미 배포하는 것과 동일한 미세한, 검증 가능한 변화를 중심으로 설계된 언어 워크플로우입니다. 지속적은 미검토를 의미하지 않습니다: 검토자는 여전히 병합해도 안전한 것을 결정합니다.

Crowdin 도 Git 통합 및 자동화를 지원합니다. Glossia 를 선택하는 이유는 Crowdin 이 저장소에 연결할 수 없기 때문이 아니라, 저장소 배포는 Glossia 워크플로우의 기초이자 단순한 통합 경계를 넘어섰기 때문입니다.

## 본인의 토큰, 본인의 모델 선택

제공자 토큰을 교체하거나 번역 워크플로우의 모델을 변경하기 위해 저장소 설정을 재작성할 필요가 없습니다. Glossia 는 자격 증명을 계정 설정에 저장하고 저장소에 안정적인 핸들을 공개합니다. 다른 콘텐츠 영역 또는 타겟 로케일은 다른 설정된 모델을 선택할 수 있습니다.

이것은 귀 팀에 지원된 제공자 관계 및 사용하는 모델 선택에 대한 통제를赋予합니다. [모델 제공자 구성](/docs/how-to/configure-a-model-provider) 을 참조하세요.

## 제품의 일부로서 결과 검증

번역은 읽기에 문제가 없더라도 문서 빌드, 컴포넌트, 플레이스홀더, 또는 애플리케이션 파서를 손상시킬 수 있습니다. Glossia 는 편집자의 텍스트 평가에서 그치지 않고 저장소 검사를 다시 사용하도록 허용합니다.

저장소가 이미 문서 유효성 검사 스크립트를 제공하는 경우, 직접 참조하세요:

```yaml
validation:
  - ./scripts/validate-docs.sh
  - --strict
```

검증기는 실제 타겟 경로에서 후보를 받고, 실패 시 제로가 아닌 상태를 반환하며, 설정된 재시도 예산 내에서 실행됩니다. 의존성은 검증 환경에서 사용 가능해야 합니다. 계약에 대해 [L10N.md](/docs/reference/l10n-md) 를 참조하세요.

## 저장소를 포기하지 않은 공개 소스

Glossia 의 작동 방식, 인증정보 처리, Markdown 보존 및 결과 검증 방법을 검토할 수 있습니다. 언어 서비스가 비가용하더라도 기존 번역 파일은 세부 저장소 파이프라인을 통해 발행 가능합니다.

Glossia는 오픈 코어 모델을 따릅니다. 코어에는 [Apache-2.0](https://github.com/glossia/glossia/blob/main/LICENSE-APACHE)이 적용되며, 해당 조건에 따라 상업적 이용, 수정, 배포, 자체 호스팅 및 경쟁 호스팅 서비스를 제공할 수 있습니다. `ee/`의 코드는 열람할 수 있지만 오픈 소스는 아닙니다. 별도의 [Enterprise 라이선스](https://github.com/glossia/glossia/blob/main/ee/LICENSE.md)가 적용되며 프로덕션 사용에는 서면 상업 계약이 필요합니다.

Crowdin 은 기여자 조정과 전문 번역 편집자로 구성된 프로그램에 여전히 적합할 수 있습니다. 우선순위가 **저장소 소유 컨텐츠, 기존 검증 및 출시에 따른 로컬라이제이션** 인 소프트웨어 팀에게는 Glossia 가 해당 작업을 위해 설계되었습니다.

이 비교는 Crowdin 이 자동화나 제공자 통합의 모든 형태를 결여했거나 Glossia 가 자동으로 메모리와 역사를 마이그레이션한다는 주장을 하지 않습니다. 현재 기능을 위해 [Crowdin 의 문서](https://support.crowdin.com/) 를 참조하세요.
