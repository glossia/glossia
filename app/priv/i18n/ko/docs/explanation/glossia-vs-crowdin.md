**로컬라이제이션 작업이 소프트웨어 배포 속도와 맞아야 할 때 Glossia 를 선택하세요.** 저장소는 이미 변경 사항이 어떻게 심의되고, 검증되며, 배포되는지를 정의하고 있습니다. Glossia 는 별도의 번역 워크스페이스를 프로세스의 중추로 삼는 대신 언어 작업을 그 루프에 포함시킵니다.

[Crowdin](https://crowdin.com/) 은 협업적 번역 관리, 검토 워크플로우, 번역 메모리, 그리고 저장소 통합을 제공합니다. Glossia 의 장점으로서 소프트웨어 팀에게는 저장소 소유 콘텐츠, 검증 가능한 소스, 자체 모델 인증 정보, 그리고 실제 프로젝트를 이해하는 검증의 결합이 있습니다.

## Glossia 를 선택하는 이유

| 당신의 우선순위 | Glossia 의 장점 |
|---|---|
| 지속적인 배포 | 번역 실행은 소스 변경 사항을 따라가며 검증 가능한 저장소 업데이트를 반환합니다. 콘텐츠는 별도의 관련 없는 릴리스 프로세스를 필요로 하지 않습니다. |
| 구현에 대한 통제권 유지 | 공개 애플리케이션, CLI, 및 배포 코드는 라이선스 조건 하에서 검증, 수정 및 자체 호스팅할 수 있습니다. |
| 자체 토큰 가져오기 | 지원하는 모델을 자체 제공자 API 토큰으로 구성하세요. 저장소 파일은 비밀이 아닌 안정적인 모델 핸들을 참조합니다. |
| 신뢰하는 검증 항목 재사용 | 수락하기 전에 실제 대상 경로에서 후보에 대해 저장소 검증 명령어를 실행하세요. |
| 콘텐츠 소유권 유지 | 소스 파일, 번역 출력물, 설정 및 풀 리퀘스트 이력은 저장소에 남아 있습니다. |

## 커밋과 함께 진행되는 로컬라이제이션

Glossia 는 버전화된 `L10N.md` 지침을 기반으로 작동하며 어떤 콘텐츠가 업데이트가 필요한지 감지합니다. 변경되지 않은 입력은 다시 번역할 필요가 없습니다. 프로젝트는 하나의 열린 번역 풀 리퀘스트를 유지하며, 진화하는 소스에 따라 불필요한 풀 리퀘스트와 반복적인 CI 실행을 줄이기 위해 배치로 진행사항을 게시합니다.

결과물은 팀이 이미 배포하는 동일한 작은 검증 가능한 변경 사항을 중심으로 설계된 언어 워크플로우입니다. 연속적이라는 말은 심사가 필요 없는 것이 아니며, 검토자는 여전히 병합해도 안전한 것을 결정합니다.

Crowdin 또한 Git 통합 및 자동화를 지원합니다. Glossia 를 선택하는 이유는 Crowdin 이 저장소에 연결할 수 없음이 아니라, 저장소 배포가 Glossia 워크플로우의 기반이며 단순 통합 경계가 아님이기 때문입니다.

## 당신의 토큰, 당신의 모델 선택

제공자 토큰을 회전시키거나 번역 워크플로우 뒤의 모델을 변경하기 위해 저장소 구성을 다시 구축할 필요는 없습니다. Glossia 는 인증 정보를 계정 설정에 저장하고 저장소에 안정적인 핸들을 노출합니다. 다른 콘텐츠 영역이나 대상 로케일은 다른 구성된 모델을 선택할 수 있습니다.

세부 정보를 위해 [모델 제공자 구성](/docs/how-to/configure-a-model-provider) 을 참조하세요.

## 제품 제작의 일부로 출력 검증

번역은 읽기에 좋아도 문서 빌드, 컴포넌트, 플레이스홀더, 또는 애플리케이션 파서를 손상시킬 수 있습니다. Glossia 는 편집자의 텍스트 평가에 그치지 않고 저장소 검사를 재사용할 수 있게 합니다.

저장소에 이미 문서 검증 스크립트가 제공된다면, 직접 참조하세요:

```yaml
validation:
  - ./scripts/validate-docs.sh
  - --strict
```

검증기는 실제 대상 경로의 후보를 받아 실패 시 0 이 아닌 상태를 반환하고, 구성된 재시도 예산 내에서 실행됩니다. 의존성은 검증 환경에 존재해야 합니다. 계약에 대해 [L10N.md](/docs/reference/l10n-md) 를 확인하세요.

## 저장소를 포기하지 않는 공개 소스

Glossia 계획의 작동 방식, 인증 정보 처리, Markdown 보존 및 결과 검증을 확인할 수 있습니다. 존재하는 번역 파일은 언어 서비스가 이용 불가능하더라도 저장소 파이프라인을 통해 게시 가능합니다.

Glossia 는 오픈 코어입니다: [Apache-2.0](https://github.com/glossia/glossia/blob/main/LICENSE-APACHE) 이 코어를 포함하며 자체 호스팅 및 경쟁 호스팅 서비스를 허용합니다. `ee/` 하에 있는 소스 가용성 기업용 코드는 별도의 [라이선스](https://github.com/glossia/glossia/blob/main/ee/LICENSE.md) 를 요구하며, 프로덕션 사용을 위해 서면상의 상업 계약이 필요합니다.

Crowdin 은 여전히 기여자 조정 및 전용 번역 편집자를 중심으로 구성된 프로그램에 적합할 수 있습니다. **Git 소유 콘텐츠, 기존 검증, 그리고 배포를 따르는 로컬라이제이션** 을 우선순위로 갖는 소프트웨어 팀의 경우 Glossia 는 해당 업무를 위해 설계되었습니다.

이 비교는 Crowdin 이 자동화나 모든 형태의 제공자 통합이 결여되어 있거나, Glossia 가 자동으로 메모리 및 역사를 이전한다는 주장을 하지 않습니다. 현재 기능에 대해 [Crowdin 문서](https://support.crowdin.com/) 를 참조하세요.
