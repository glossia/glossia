Glossia 는 게시하기 전에 번역된 콘텐츠를 검증합니다. 복구는
이 요구사항을 유지합니다: 재시도는 여전히 원본 구조와 필요한
플레이스홀더, 그리고 모든 조립된 파일은 설정된 검증 명령을 통과합니다.

## 마크다운 번역

Glossia 는 번역된 Markdown 문서를 다시 렌더링하지 않습니다. 소스를 파싱합니다
단지 텍스트만 찾기 위해: 단락, 제목, 목록 항목, 표 셀, 해당
컴포넌트 및 HTML 의 사용자 표시 속성(`title`이전에 재조립된 문서의 유효성 검증이 실패했습니다: Markdown 텍스트 리터럴 복원에서 잘못된 JSON 이 반환되었습니다. `details`, `alt`,
`label`, `description`, `summary`, `placeholder`, `aria-label`, `caption`), 및
HTML 의 텍스트 `<summary>`. 각 번역은 정확한
바이트. 소스가 차지한 바이트 그대로, 따라서 코드, 링크 주소, 구성 요소, GitHub
경고, 명시적인 제목 앵커 등의 `{#install}`, 목록 마커 및 빈
줄은 바이트 단위 동일하게 유지됩니다.

각 단락이나 제목은 전체 문장이 그대로 번역됩니다. 인라인 포맷팅
번호가 매겨진 태그로 변환됩니다: `<gN>...</gN>` 연결되거나 강조된 단어 주변에, 그리고
`<gN/>` 변경되어서는 안 되는 콘텐츠에 대해, 예를 들어 inline code 나 구성 요소입니다.
모델은 목표 언어의 단어 순서를 따르도록 태그를 이동할 수 있지만, 반드시
각 태그를 정확히 한 번만 유지해야 합니다. 모든 요청 또한 주변의 소스
문서이며, 동일한 파일의 최신 번역을 참고하기 위해.

태그를 누락하거나 새로 만드는 단위는 이유와 함께 그 자체로 다시 전송되며,
최대 세 번까지. 유효하게 돌아온 단위들은 유지되며, 병합 후 Glossia
결과를 파싱하고 구조를 원본과 비교합니다. 번역이
제목, 목록, 또는 강조로 독립적으로 변환될 수 있는 내용은 그 본문이 이스케이프 처리됩니다,
추가적인 모델 호출이 불필요합니다.

## 캐탈로그 번역

Gettext 카탈로그는 번역 전에 문자열로 파싱됩니다. 요청에는 최대
8 개 문자열이며, 8,000 바이트 배치 목표가 있습니다. 단일 더 큰 문자열
원래 그대로 유지됩니다. 모델은 동일한 수의 문자열로 구성된 배열을 반환합니다 에
동일한 순서입니다. Glossia 는 인터폴레이션 변수를 확인하고 빈 번역을 거부합니다.

헤더는 목표 로케의 복수 규칙을 사용하여 코드에서 생성됩니다. 원본 메시지
식별자, 주석 및 카탈로그 구조는 파싱된 소스에서 비롯됩니다. 만약 한
배치가 형식 오류 콘텐츠를 반환하면 Glossia 는 한 번 재시도한 후 분할하고 있습니다
더 작은 배치로 분할합니다. 성공적으로 처리된 인접 배치들은 다시 번역할 필요가 없습니다.

## 제공자 속도 제한

Glossia 는 동일한 자격 증명과 모델을 사용하는 번역 요청을 조정합니다. 속도 제한
응답은 공유 쿨다운 기간을 연장하고 새 요청 사이의 간격을 증가시킵니다.
속도 제한 없이 성공적인 트래픽은 1 분 뒤 해당 간격을 서서히 줄입니다.
이미 진행 중인 요청들은 완료될 수 있습니다.

제공자 재시도 힌트는 최소 지연 시간입니다. 반복된 실패 또한
백오프를 증가시키며, 최대 30 초 기본 지연 시간과 지터까지; 더 긴 제공자 힌트는
우선순위가 적용되며 5 분으로 제한됩니다. Together 의 `x-ratelimit-reset` 헤더는
함께 인정 받습니다 `retry-after`.

요청 실패 8 회 후 저장소 실행이 새
파일 생성을 중단합니다. 지연된 지속은 번역 브랜치를 상속하여 재개합니다.
처리되지 않은 작업입니다. 이전 시도는 세션 이력에 연결되었으며,
계속을 통해 이어집니다. 지연 시간은 1 분에서 5 분으로 증가하며,
최대 6 회의 자동 재연결이 가능합니다. 최신 활성 세션이 우선권을 가지며,
취소된 세션은 재개되지 않습니다. 검증 실패만으로는 공급자 복구를 계획하지
공급자 복구.

## 지속 가능한 진행

완료된 파일과 해당 락 파일은 번역 브랜치에 배치로 게시되는데
배치: 25 개 파일당 또는 15 분마다 한 커밋이며 최종 커밋
작업이 종료될 때입니다. 각 푸시는 저장소의 풀 리퀘스트 체크를 실행하므로
배치는 대규모 작업이 파일당 하나의 체크 실행을 시작하는 것을 방지합니다. 프로젝트에는
단일 번역 풀 리퀘스트입니다. 기본 브랜치에 새 커밋이 추가되면
열린 것을 이어가고 변경된 사항만 번역합니다. 해당 풀 리퀘스트가
병합되거나 닫히면 다음 작업은 새 것으로 시작합니다. 미완료 파일 내에서 로컬 검증된 섹먼트 및 복구 배치는
7 일 동안 데이터베이스에도 저장됩니다. 이러한 체크포인트는 워커가 종료되더라도 유지됩니다.
프로세스 중단됩니다. 이는 계정, 프로젝트, 문서 입력 범위에 적용되며,
유효한 인증정보 및 모델, 맥락, 시그먼트 또는 수정 시도입니다.

재개된 실행은 입력이 여전히 일치하는 경우에만 시그먼트를 재사용할 수 있습니다. 항상
최종 조립 문서를 다시 검증합니다. 거절된 모델 응답은
체크포인트입니다. 문서 수준의 검증 실패는 별도의 수정 시도를 시작합니다.
이는 검증기가 책임 소재가 있는 단일 시그먼트를 식별할 수 없기 때문입니다.

만료된 체크포인트 및 비활성 제공자 속도 조정 기록은 ...에 의해 제거됩니다.
계획된 세션 복구 작업자입니다. 이는 운영 기록입니다; 사용자는
저장소에 추가하거나 설정해야 합니다 `L10N.md`.
