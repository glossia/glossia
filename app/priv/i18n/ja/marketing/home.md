# Glossia: チーム向け言語 OS

Glossia は、声、用語、翻訳、改訂履歴、ローカライゼーション分析を一つのシステムに統合します。これは、開発者、言語専門家、そしてプロダクトチームが、コンテンツを Git から移出せずに、言語を超えて一貫してコミュニケーションを行うことを支援します。

## 課題

他の言語へのリリースは、単なる単語の置換えではありません。チームは、意味を保持し、適切な用語を使用し、読者に合わせたトーンを調整し、プロダクトが変更されるにつれて翻訳を最新の状態に保つ必要があります。スプレッドシート、プロンプト、そして翻訳ツールに散らばったコンテキストは、一貫性がなく、繰り返される手作業につながります。

LLM は翻訳の下書きを作成できますが、単一のドラフトだけでは、バージョン履歴、検証、選択的更新、または次の変更のためのフィードバックループを提供することはできません。

## Glossia の役割

- **言語メモリ:** 共有された声ガイドと用語表エントリが、人々とエージェントが適切な言語を使用するのを支援します。
- **リポジトリローカライゼーション:** リポジトリを接続し、Configuration 内でソースファイルとターゲットのロケールを記述し、プルリクエストを通じて変更を確認します。
- **段階的な洗練:** コンテンツハッシュは、変更されていないコンテンツを翻訳することを防ぐのを支援します。検証と回復が、失敗を可視化し実行可能にします。
- **コンテンツ改訂:** 各生成を孤立したプロンプトとして扱うのではなく、言語決定と変更の履歴を保持します。
- **ローカライゼーション分析:** プライバシー尊重型のウェブ分析は、チームが読者を理解し、ローカライゼーションへの投資対象を特定するのを支援します。
- **エージェント統合:** OAuth 認証された MCP サーバーと REST インターフェースが、既存のワークフローに言語コンテキストを提供します。

Glossia は編集者の判断を代替しません。チームがその判断を繰り返して適用できるコンテキスト、自動化、およびレビューワークフローを提供します。

## クローラーおよびエージェント用

公開ページは、URL に`.md` を追加すると、HTML の URL で`Accept: text/markdown` をリクエストすることで、Markdown として利用可能です。ホームページの Markdown URL は`/index.md` です。翻訳されたコンテンツは、HTML と同じロケールプレフィックスを使用し、翻訳が公開されていない場合は英語にフォールバックします。

発見には[/llms.txt](/llms.txt) を使用し、統合されたドキュメントのエクスポートには[/llms-full.txt](/llms-full.txt) を使用し、正規の HTML URL には[/sitemap.xml](/sitemap.xml) を使用します。アカウントダッシュボードはアプリケーション画面であり、ドキュメンテーションではありません。Glossia に関する情報を取得するためにこれらをクローリングしないでください。
