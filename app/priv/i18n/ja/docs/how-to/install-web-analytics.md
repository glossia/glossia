このガイドでは、プロジェクトの分析設定にサイトドメインを設定された Glossia プロジェクトをお持ちであると仮定します。収集は、そのドメインによって識別されるため、コピーするキーやシークレットはありません。

## オプション A: script tag

このスニペットをすべてのページに、理想的には `<head>` に追加してください。

```html
<script defer data-domain="example.com" src="https://glossia.ai/assets/glossia-web.js"></script>
```

SDK は自動的に初期化され、ロード時にページビューを送信し、シングルページアプリでのクライアント側ナビゲーション後に以降のページビューを記録します。`data-domain` は省略された場合、`window.location.hostname` にデフォルトされるため、シングルドメインサイトでは削除しても問題ありません。カスタム収集エンドポイントを使用するには、`data-endpoint="https://collect.your-host.com"` を追加してください。

サイトにかんじゅちセキュリティポリシーを使用している場合、`https://glossia.ai` を `script-src`（または存在する `script-src-elem`）の両方に、`connect-src` に許可してください。スクリプトは `/assets/glossia-web.js` から読み込まれ、同じオリジン上の `/v1/collect` にイベントを送信します。

## オプション B: npm

パッケージをインストールしてください。

```bash
npm install @glossia/web
```

アプリケーションのエントリーポイントで一度初期化してください。

```ts
import glossia from "@glossia/web";

glossia.init({ endpoint: "https://glossia.ai/v1/collect" });
```

自分のバンドルでパッケージを使用する際に、収集エンドポイントを明示的に設定してください。なぜなら、推測するホストされたスクリプトアドレスがないからです。

`domain` は `window.location.hostname` から推測されるため、SDK はサイトのプロジェクトに対して記録されます。`{ domain: "example.com" }` を渡して上書きしてください。例えば、ステージングのオリジンからイベントを送信し、プロダクションと同じプロジェクトにする場合です。

カスタムイベントを記録するには、例えばサインアップが:

```ts
glossia.track("signup");
```

## ドメインを検証する

プロジェクトの **分析設定** でサイトドメインを保存してください。**ドメインの所有権を検証** カードには、プロジェクトのレコード名と値が正確に表示されます。ドメインプロバイダーとテキストレコードを追加してください:

| フィールド | 値 |
| --- | --- |
| 種類 | `TXT` ([テキストレコード](https://www.cloudflare.com/learning/dns/dns-records/dns-txt-record/)) |
| 名前 | `_glossia-verify.example.com` |
| 値 | `glossia-site-verification=YOUR_VERIFICATION_TOKEN` |

設定に表示されたドメインとトークンを使用してください。一部のプロバイダーはドメインを自動的に追加するため、その場合 `_glossia-verify` のみ名前に入力します。レコードを公開した後、**ドメインを検証** をクリックしてください。変更の有効になるには時間がかかるため、レコードが見つからない場合は再試行してください。

ドメインレコードを編集できない場合は、**代替：ホームページのメタタグで確認** を展開し、生成されたタグをホームページの`<head>` にコピーして公開してください:

```html
<meta name="glossia-site-verification" content="YOUR_VERIFICATION_TOKEN">
```

どちらの方法も、設定されたドメインのコントロールを証明します。Glossia はそのドメインのレコードまたはホapte を確認するため、トークンを別のウェブサイトにコピーしても所有権を認証しません。トークンは公開可能な証拠であり、パスワードではありません。

ドメインが検証された後、Glossia はトラッキングスニペットからのイベントを記録します。スニペットのみのみ所有権を認証しません。設定されたドメインを変更する場合は再度検証が必要です。

## 動作を検証する

1. ブラウザでいうサイトを開いてください。
2. ネットワークタブを開き、`POST` リクエストが `https://glossia.ai/v1/collect` に対して `202 Accepted` を返すことを確認してください。
3. 収集と処理後、ページビューはプロジェクトのダッシュボードの **分析** 下に表示されます。アバゼクションページの翻訳実行はウェブサイトのトラフィックとは別まります。

`202 Accepted` 応答は、リクエストがコレクターに到達したことを確認します。不明または検証されていないドメインも受け入れられますがイベントを記録しないため、プロジェクトの分析設定で設定されたドメインが検証されていることを確認してください。

## 何が収集される

ブラウザはページ URL、リファラ、`navigator.languages`、タイムゾーン、および画面幅を、タブごとのセッション ID を含めて送ります。サーバーは国（GeoIP から）を追加し、プロジェクトのターゲット言語に対するローカライズギャップを計算します。クッキーは設定され、一切フィンガープリントされません。
