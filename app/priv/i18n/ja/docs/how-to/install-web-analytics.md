このガイドは、プロジェクトのアナリティクス設定にサイトのドメインを既に設定済みの Glossia プロジェクトを使用していることを前提としています。収集はあのドメインで識別されるため、コピーするキーやシークレットはありません。

## オプション A: スクリプトタグ

すべてのページにこのスニペットを追加してください。理想的には `<head>` に含めてください：

```html
<script defer data-domain="example.com" src="https://glossia.ai/assets/glossia-web.js"></script>
```

SDK は自動で初期化され、読み込み時にページビューを送信し、SPA におけるクライアントサイドのナビゲーション時に以降のページビューを記録します。`data-domain` は省略された場合に `window.location.hostname` でデフォルト設定されるため、シングルドメインのサイトであれば省略可能です。カスタム収集エンドポイントを使用するには、`data-endpoint="https://collect.your-host.com"` を追加してください。

サイトがコンテンツセキュリティポリシーを使用している場合、`https://glossia.ai` を `script-src`（または `script-src-elem` が存在する場合）の 2 つともおよび `connect-src` に許可してください。スクリプトは `/assets/glossia-web.js` から読み込まれ、同じオリジンの `/v1/collect` にイベントを送信します。

## オプション B: npm

パッケージをインストールしてください：

```bash
npm install @glossia/web
```

アプリケーションのエントリーポイントで一度初期化してください：

```ts
import glossia from "@glossia/web";

glossia.init({ endpoint: "https://glossia.ai/v1/collect" });
```

パッケージを独自のバンドルで使用する場合、収集エンドポイントを明示的に設定する必要があります。推測するホストされたスクリプトのアドレスが存在しないためです。

`domain` は `window.location.hostname` から推測されるため、SDK はサイトのプロジェクトに対して記録します。上書きするには `{ domain: "example.com" }` を渡します。例えば、ステージングオリジンからイベントを同じプロジェクト（本番）に送信する場合など。

カスタムイベントを記録するには、例えば登録：

```ts
glossia.track("signup");
```

## ドメインの確認

プロジェクトの **アナリティクス設定** で您的網站ドメインを保存してください。**ドメイン所有権の確認** カードでは、プロジェクトの正確なレコード名と値が表示されます。ドメインプロバイダーでテキストレコードを追加：

| 項目 | 値 |
| --- | --- |
| タイプ | `TXT` ([テキストレコード](https://www.cloudflare.com/learning/dns/dns-records/dns-txt-record/)) |
| 名前 | `_glossia-verify.example.com` |
| 値 | `glossia-site-verification=YOUR_VERIFICATION_TOKEN` |

設定画面に表示されているドメインとトークンを使用してください。一部の提供業者はドメインを自動的に追加する場合があります。その場合は `_glossia-verify` だけを名前に入力します。レコードを公開後、**ドメインの確認** をクリックしてください。有効になるまで時間がかかる場合がありますので、すぐにレコードが見つからない場合は再試行してください。

ドメインレコードを編集できない場合は、**代替：ホームページのメタタグでの確認** を展開。生成されたタグをホームページの `<head>` にコピーして公開：

```html
<meta name="glossia-site-verification" content="YOUR_VERIFICATION_TOKEN">
```

どちらの方法も、設定されたドメインの管理権を証明します。Glossia はそのドメインのレコードまたはホームページを確認するため、トークンを他のサイトにもコピーしても所有権の確認にはなりません。トークンはパスワードの公開証明ではありません。

ドメインが確認されると、Glossia は監視スニペットからのイベントを記録します。スニペット自体は所有権を確認しません。設定されたドメインを変更するには、再度確認が必要です。

## 動作の確認

1. ブラウザでサイトを開いてください。
2. ネットワークタブを起動し、`POST` リクエストが `https://glossia.ai/v1/collect` に `202 Accepted` を返すことを確認してください。
3. 収集・処理後、ページビューはプロジェクトダッシュボードの **アナリティクス** セクションに表示されます。Overview ページでの翻訳実行は、Web サイトトラフィックとは別です。

`202 Accepted` レスポンスはリクエストが収集サーバーに到達したことを確認します。不明なドメインや未検証ドメインは受け付けられますが、イベントは記録されませんので、プロジェクトのアナリティクス設定で設定されたドメインが検証されていることを確認してください。

## 収集内容

ブラウザはページ URL、リファラ、`navigator.languages`、タイムゾーン、画面幅を送信し、さらにタブごとにセッション ID を付与します。サーバーは国（GeoIP に対応）を追加し、プロジェクトのターゲット言語に対するローカリゼーションギャップを計算します。クッキーは設定されず、指紋化も行われません。
