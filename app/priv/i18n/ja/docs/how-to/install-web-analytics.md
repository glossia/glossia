このガイドは、プロジェクトの分析設定にサイトのドメインが設定されている Glossia プロジェクトがあることを前提としています。収集は、そのドメインで識別されるため、コピーする キーやシークレットはありません。

## オプション A: script tag

すべてのページにこのスニペットを追加し、できれば `<head>` に追加してください：

```html
<script defer data-domain="example.com" src="https://glossia.ai/assets/glossia-web.js"></script>
```

SDK は自動的に初期化され、ロード時にページビューを送信し、シングルページアプリケーションのクライアント サイド ナビゲーション時のその後のページビューも記録します。省略した場合、`data-domain` は `window.location.hostname` でデフォルトとなるため、単一ドメインのサイトでは省略可能です。カスタムコレクション エンドポイントを使用するには、`data-endpoint="https://collect.your-host.com"` を追加してください。

サイトがコンテンツ セキュリティ ポリシーを使用している場合、`script-src`（存在する場合 `script-src-elem`）および `connect-src` に `https://glossia.ai` を許可してください。スクリプトは `/assets/glossia-web.js` から読み込まれ、同じオリジンの `/v1/collect` へイベントを送信します。

## オプション B: npm

パッケージをインストールします:

```bash
npm install @glossia/web
```

アプリケーションのエントリーポイントで一度初期化します:

```ts
import glossia from "@glossia/web";

glossia.init({ endpoint: "https://glossia.ai/v1/collect" });
```

実行バンドルでパッケージを使用する場合、収集エンドポイントを明示的に設定する必要があります。推論するためにホストされたスクリプトアドレスが存在しないためです。

`domain` は `window.location.hostname` から推論されるため、SDK はあなたのサイトのプロジェクトに対する記録を行います。上書きするには`{ domain: "example.com" }` を渡してください。例えば、ステージングオリジンからのイベントを本番と同じプロジェクトに送信する場合。

カスタムイベント（例えば、サインアップ）を記録するには:

```ts
glossia.track("signup");
```

## ドメインを確認する

プロジェクトの**分析設定** でサイトのドメインを保存します。**ドメインの所有権を確認** カードには、あなたのプロジェクトの正確なレコード名と値が表示されます。ドメインプロバイダーとテキストレコードを追加します:

| フィールド | 値 |
| --- | --- |
| タイプ | `TXT`([テキストレコード](https://www.cloudflare.com/learning/dns/dns-records/dns-txt-record/)) |
| 名前 | `_glossia-verify.example.com` |
| 値 | `glossia-site-verification=YOUR_VERIFICATION_TOKEN` |

設定に表示されているドメインとトークンを使用します。一部のプロバイダーはドメインを自動的に追加します。その場合、名前には`_glossia-verify` のみを入力します。レコードを公開した後、**ドメインを確認** をクリックします。変更の反映には時間がかかるため、レコードが見つからない場合はすぐにもう一度お試しください。

ドメインレコードを編集できない場合、**代替：ホームページメタタグでの確認** を展開します。生成されたタグをホームページの`<head>`&gt; にコピーして公開します:

```html
<meta name="glossia-site-verification" content="YOUR_VERIFICATION_TOKEN">
```

いずれの手法も設定されたドメインに対する制御権を示します。Glossia はそのドメインのレコードまたはホームページを確認するため、トークンを別のウェブサイトにコピーしても所有権を確認することはできません。トークンは公開証明書であり、パスワードではありません。

ドメインが確認されると、Glossia はトラッキングスニippet からイベントを記録します。スニペットだけでは所有権を確認できません。設定されたドメインを変更するには、再度確認が必要です。

## 動作を確認する

1. ブラウザでサイトを開きます。
2. ネットワークタブを開き、`https://glossia.ai/v1/collect` に対する`POST` リクエストが`202 Accepted` を返すことを確認します。
3. 収集と処理後、ページビューはプロジェクトのダッシュボードで**分析** 下に表示されます。オーバービューページで実行される翻訳タスクのトラフィックとは異なります。

`202 Accepted` レスポンスはリクエストがコレクターに到達したことを確認します。未知または確認されていないドメインも受け入れられますがイベントを記録しないため、プロジェクトの分析設定で設定されたドメインが確認されていることを確認してください。

## 何が収集されているか

ブラウザはページ URL、リファラ、`navigator.languages`, タイムゾーン、および画面幅を送信し、さらにタブごとにセッション ID を送信します。サーバーは国（GeoIP からの）を追加し、あなたのプロジェクトのターゲット言語に対するローカライズギャップを計算します。クッキーは設定されず、指紋化は行われません。
