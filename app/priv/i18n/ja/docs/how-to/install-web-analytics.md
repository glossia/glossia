このガイドは、プロジェクトのアナリティクス設定にサイトのドメインが設定済みの Glossia プロジェクトをお持ちであることを前提としています。収集 (Collection) はそのドメインにより識別されるため、コピーするキーやシークレットはありません。

## オプション A: スクリプトタグ

各ページにこのスニペットを追加します。可能であれば `<head>` 内に。

```html
<script defer data-domain="example.com" src="https://glossia.ai/assets/glossia-web.js"></script>
```

SDK は自動的に初期化され、読み込み時にページビューを送信し、シングルページアプリケーションのクライアントサイドナビゲーションでその後のページビューを記録します。`data-domain` を省略した場合、デフォルトは `window.location.hostname` であり、したがって單一ドメインのサイトではそれを削除しても構いません。カスタム収集エンドポイントを使用するには、`data-endpoint="https://collect.your-host.com"` を追加します。

サイトがコンテンツセキュリティポリシーを使用している場合は、`script-src`（または存在する場合の`script-src-elem`）および `connect-src` に両方に`https://glossia.ai`を許可してください。スクリプトは `/assets/glossia-web.js` から読み込まれ、`/v1/collect` に同じオリジン上のイベントを送信します。

## オプション B: npm

パッケージをインストールします:

```bash
npm install @glossia/web
```

アプリケーションのエントリーポイントで一度初期化します:

```ts
import glossia from "@glossia/web";

glossia.init({ endpoint: "https://glossia.ai/v1/collect" });
```

自身のバンドルでパッケージを使用する場合、収集エンドポイントを明示的に設定してください。ホストされたスクリプトアドレスから推論できるものが何もないためです。

`domain` は `window.location.hostname` から推測されるため、SDK はサイトの登録されているプロジェクトに対して記録します。オーバーライドするには`{ domain: "example.com" }`をパスします。例えば、ステージングオリジンからのイベントを本番環境と同じプロジェクトに送るために。

カスタムイベント（例えばサインアップ）を記録するには:

```ts
glossia.track("signup");
```

## 明示的な言語選択を追跡する

訪問者の選択とブラウザの優先的な設定を区別するには、ナビゲーション前に言語選択機能のユーザーアクションハンドラで SDK を呼び出します:

```js
glossia.selectLanguage("zh-Hans");
```

このメソッドは、`glossia.init()` 後のインポートした SDK 上で利用でき、またホストされたスクリプトを使用する `glossia` グローバルでも利用可能です。

あるいは、同じオリジンの言語切り替えリンクを注釈します:

```html
<a href="/zh-hans/docs" data-glossia-language="zh-Hans">简体中文</a>
```

アクションごとに 1 つの統合のみを使用し、両方を使用しないでください。注釈されたリンクは、キーボード操作を含む真のユーザーアクティベーションを記録します。計画されたクリック、ダウンロード、修正されたクリック、クロスオリジンの宛先、および別タブやフレームを開くリンクは、ナビゲーションを妨げずに無視されます。

SDK はすぐに`language_selection`イベントを送信し、その後のイベントに選択された言語 (`cl`) を含めます。選択は`sessionStorage` に保存され、現在のタブとオリジンで別の選択が置換するまで続きます。ストレージが利用できない場合、ページが読み込まれて終了するまで続きます。リダイレクト、URL、または`<html lang>` の変更から選択は推測されません。

選択は成功したナビゲーションではなく意図を記録します。ブラウザの優先度、実際のページ言語、および明示的な選択は別々に残ります。 Kolekشنはローカライズギャップを計算する際にブラウザの優先度ではなく有効な選択を確認します。選択がプロジェクトのターゲット、広告された翻訳、または実際のページ言語に一致した場合のみ、ギャップがクリアされます。利用できない選択された言語にもギャップがあります。欠落または不正な選択は以前と同様にブラウザの優先度を使用します。ダッシュボードの集計とバッジは各イベントの保存された決定を使用し、履歴フラグに変更はありません。

## ドメインを確認する

プロジェクトの**分析設定** にサイトのドメインを保存します。**ドメインの所有権の確認** カードは正確な記録名と値を示します。ドメインプロバイダーのテキスト記録を追加:

| フィールド | 値 |
| --- | --- |
| タイプ | `TXT` ([テキスト記録](https://www.cloudflare.com/learning/dns/dns-records/dns-txt-record/)) |
| 名前 | `_glossia-verify.example.com` |
| 値 | `glossia-site-verification=YOUR_VERIFICATION_TOKEN` |

設定に示されたドメインとトークンを使用します。一部のプロバイダーはドメインを自動的に追加するため、その場合は名前に `_glossia-verify` のみを入力します。記録を公開した後、**ドメインの確認** をクリックします。変更はすぐに利用可能になるまで時間がかかりますので、記録が見つからない場合は再試行します。

ドメイン記録を編集できない場合は、**代替方法：ホームページのメタタグで検証** を展開します。生成されたタグをホームページの`<head>` にコピーして公開します:

```html
<meta name="glossia-site-verification" content="YOUR_VERIFICATION_TOKEN">
```

いずれかの方法が設定されたドメインの制御を証明します。Glossia はそのドメインの記録またはホームページを確認するため、トークンを別のウェブサイトにコピーしても所有権の確認にはなりません。トークンは共有証明で、パスワードではありません。

ドメインが検証されると、Glossia はフォロワーのスニペットからイベントを記録します。スニペットのみでは所有権を証明しません。設定されたドメインを変更する場合、再度確認が必要です。

## 動作を確認する

1. ブラウザでサイトをオープンします。
2. ネットワークタブをオープンし、`POST` リクエストに `https://glossia.ai/v1/collect` が `202 Accepted` を返すことを確認します。
3. 収集と処理後、ページビューはプロジェクトダッシュボードの**分析** セクションに出現します。見通しページで実行される翻訳はウェブサイトのトラフィックとは別です。

`202 Accepted` レスポンズはリクエストがコレクターに到達したことを確認します。不明または未検証のドメインも受け入れられますが、イベントは記録されません。設定されたドメインがプロジェクトのアナリティクス設定で検証されていることを確認してください。

## 収集内容

ブラウザはページ URL、参照元、`navigator.languages`、実際のページ言語 (`<html lang>`）、広告された翻訳 (`hreflang` リンク)、観察された場合の明示的な言語選択、タイムゾーン、およびスクリーン幅を送信し、タブごとにセッションIDを追加します。サーバーは国 (GeoIP) を追加し、プロジェクトのターゲット言語、広告された翻訳、および実際のページ言語に対してローカライズギャップを計算します。セッションID と明示的な選択は`sessionStorage`を使用し、クッキーは設定され、フィンガープリンティングは行われません。
