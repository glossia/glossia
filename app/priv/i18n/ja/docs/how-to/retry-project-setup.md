%{title: "プロジェクトセットアップの再試行", summary: "セットアップの失敗後のプロジェクトの回復", category: "チュートリアル", order: 4}
---
使用 **セットアップの再試行** プロジェクトのセットアップに失敗した原因を修正した後。

## 1\. 失敗内容を確認

プロジェクト概要を開きます。セットアップの進行状況カードには、失敗と最新のセットアップのアクティビティが表示されます。

一般的な原因は以下の通りです：

- アカウントに設定済みのモデルがありません。
- プロバイダーキーが見つからないか、もはや有効ではありません。
- Glossia GitHub App はリポジトリにアクセスできません。
- リポジトリの準備または確認に失敗しました。

## 2\. 予備条件を修正する

モデルの問題については、開いてください **設定** および **モデル**。リポジトリへのアクセス問題については、GitHub の Glossia GitHub App の設定を更新し、リポジトリへのアクセス権を付与してください。

## 3\. 再試行

プロジェクトの概要に戻り、選択してください **セットアップの再試行**.

カードはに戻ります **保留中**、その後 **実行中**, 作業が進行するにつれて新しいアクティビティが表示されます。再試行はプロジェクトが **失敗** 状態にある間のみで利用可能で、同時に 2 つのセットアップ試行を実行することを防ぎます。

## 4\. 完了の確認

状態が に変更されたら **完了**、GitHub で生成されたプルリクエストを確認してください。再度失敗した場合は、前回の試行ではなく、カード内の新しいアクティビティを使用して次のアクションを特定してください。
