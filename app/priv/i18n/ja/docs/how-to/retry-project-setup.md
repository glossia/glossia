自動化されたセットアップが失敗すると、Glossia は一時的なプロジェクトを破棄し、リポジトリを再度選択できるようにします。セットアップフローには失敗通知が表示される場合がありますが、失敗したプロジェクトとその進捗履歴は保持されません。

## 1\. 失敗を確認

セットアップフローを完了する前に失敗通知を確認してください。一般的な原因には以下のものがあります：

- アカウントに設定済みのモデルがありません。
- プロバイダーキーが存在しないか、無効です。
- Glossia GitHub アプリはリポジトリにアクセスできません。
- リポジトリの準備または確認ができませんでした。

## 2\. 前提条件を修正

モデルの問題の場合、を開きます **設定 → モデル**。リポジトリアクセスの問題の場合、GitHub 上で Glossia GitHub App のインストールを更新し、リポジトリへのアクセス権限を付与してください。

## 3\. セットアップを再度開始

開く **プロジェクト → 新規プロジェクト**, リポジトリを選択し、を選択 **自動セットアップ**、対象言語を再度選択し、完了するまで新しいセットアップを実行.

もし失敗したプロジェクトがまだ表示されていて、 **セットアップの再試行**、このアクションは別の試みを開始します。利用でき続けるとは限らないため、依存しないでください：失敗した一時的なプロジェクトはクリーンアップ中に削除されます。

## 4\. 完了を確認

セットアップが完了したら、GitHub に結果となるプルリクエストを確認してください。詳細は [プロジェクト設定](/docs/reference/project-setup) ライフサイクルとクリーンアップの動作については。
