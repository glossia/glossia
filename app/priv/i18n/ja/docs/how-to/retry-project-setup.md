使用 **セットアップを再試行** プロジェクトのセットアップ失敗の原因を修正した後

## 1\. 失敗を確認

プロジェクトの概要を開きます。セットアップの進捗カードには、失敗と最新のセットアップ活動が表示されます。

一般的な原因には以下のものがあります:

- このアカウントではモデルが設定されていません。
- プロバイダーキーが欠落しているか、または無効になっています。
- Glossia の GitHub アプリは、リポジトリにアクセスできません。
- リポジトリの準備またはチェックに失敗しました。

## 2\. 前提条件を修正

モデルの問題については、 **設定** と **モデル**。リポジトリへのアクセス問題については、GitHub 上の Glossia の GitHub アプリのインストールを更新し、リポジトリへのアクセス権限を付与してください。

## 3\. リトライ

プロジェクト概要に戻り、選択してください **セットアップを再試行**.

カードは次の状態に戻ります **保留中**, その後 **実行中**、作業が進行すると新しいアクティビティが表示されます。再試行は、プロジェクトが **失敗** 状態であり、同時に 2 つのセットアップ試行を実行することを防ぎます。

## 4\. 完了確認

状態が **完了**、生成された GitHub のプルリクエストを確認してください。再度失敗した場合は、前回の試行ではなく、カード内の新しいアクティビティを使用して次のアクションを特定してください。
