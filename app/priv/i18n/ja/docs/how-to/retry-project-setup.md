---
使用 **セットアップの再試行** プロジェクトのセットアップに失敗した原因を修正した後。

## 1\. 失敗を確認

プロジェクトの概要を開きます。セットアップの進行状況カードには、失敗と最新のセットアップ活動が表示されます。

一般的な原因は以下の通りです：

- アカウントに構成済みのモデルがありません。
- プロバイダーのキーが欠落しているか、もう無効になっています。
- Glossia GitHub アプリは、リポジトリにアクセスできません。
- リポジトリの準備または確認ができませんでした。

## 2\. 前提条件を修正する

モデルの問題の場合は、 **設定** と **モデル**。

## 3\. 再試行

プロジェクトの概要に戻り、選択してください **セットアップを再試行する**.

カードは **保留中**, その後 **実行中**、作業の進行に伴って新しいアクティビティを表示します。再試行は、プロジェクトが **失敗** 状態であり、2 つのセットアップ試行が同時に実行されることを防止します。

## 4\. 完了の確認

状態が「完了」に変化した場合は **完了**、生成されたプルリクエストを確認してください。再失敗した場合、カード上の新しいアクティビティを使用して、前回の試行ではなく次のアクションを特定してください。
