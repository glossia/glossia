使用する **セットアップを再試行する** プロジェクトのセットアップ失敗の原因を修正した後

## 1\. 失敗を確認する

プロジェクト概要を開きます。セットアップの進行状況カードには、失敗と最新のセットアップ活動が表示されます。

一般的な原因には以下のものがあります：

- アカウントに設定されたモデルがありません。
- プロバイダーキーが設定されていないか、または無効です。
- Glossia GitHub App はリポジトリにアクセスできません。
- リポジトリの準備またはチェックができませんでした。

## 2\. 前提条件を修正してください。

モデルの問題には、 **設定** および **モデル**。リポジトリへのアクセスに問題がある場合、GitHub 内の Glossia GitHub App のインストールを更新し、リポジトリへのアクセス権限を付与してください。

## 3\. 再試行

プロジェクト概要に戻り、選択 **セットアップを再試行**。

カードは戻り **保留中**、その後 **実行中**,作業が進むと新しいアクティビティが表示されます。再試行はプロジェクトが **失敗** 状態にあり、2 つのセットアップ試行が同時に実行されることを防ぎます。

## 4\. 完了確認

状態が変更されるときに **完了**、結果として生成されたプルリクエストを GitHub でレビューし、再度失敗した場合は、過去の試行ではなくカード内の新しい活動を使用して次のアクションを特定してください。
