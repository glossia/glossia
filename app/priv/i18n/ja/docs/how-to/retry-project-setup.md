使用する **セットアップを再試行** プロジェクトのセットアップが失敗した原因を修正した後。

## 1\. 失敗を確認する

プロジェクトの概要を開きます。設定進捗カードには、失敗と最新のセットアップ活動が表示されます。

一般的な原因には以下のものがあります:

- アカウントには設定済みのモデルがありません。
- プロバイダーキーが見つからない場合、または無効になっている場合があります。
- Glossia GitHub App はリポジトリにアクセスできません。
- リポジトリの準備または確認を行うことができませんでした。

## 2\. 前提条件を修正する

モデルの問題については、開いて **設定** と **モデル**。リポジトリへのアクセス問題については、GitHub 上の Glossia GitHub App インストールを更新し、リポジトリへのアクセス権限を付与してください。

## 3\. 再試行

プロジェクトの概要に戻り、選択してください **セットアップを再試行**.

カードは戻り **保留**、 次に **実行中**, 作業の進行に伴い新しいアクティビティが表示されます。再試行はプロジェクトが **失敗** 状態であり、2 つのセットアップ試行を同時に実行することを防止します。

## 4\. レビュー完了

状態が に変更されたら **完了**, GitHub で生じたプルリクエストをレビューしてください。再度失敗した場合は、前回の試行ではなく、カード内の新しいアクティビティを使用して次のアクションを特定してください。
