%{title: "プロジェクトセットアップの再試行", summary: "セットアップに失敗した場合、プロジェクトを復旧します。", category: "使い方", order: 4}
---
使用 **セットアップを再試行** プロジェクトのセットアップ失敗の原因を修正した後。

## 1\. 失敗を確認する

プロジェクト概要を開きます。設定の進捗カードには、失敗と最新の設定活動が表示されています。

一般的な原因には以下が含まれます：

- アカウントに設定されたモデルがありません。
- プロバイダーキーが欠落しているか、もう無効になっています。
- Glossia GitHub アプリはリポジトリにアクセスできません。
- リポジトリの準備または確認ができませんでした。

## 2\. 前提条件を修正する

モデルの問題の場合は、 **設定** および **モデル**．リポジトリへのアクセス問題の場合は、GitHub で Glossia GitHub アプリのインストールを更新し、リポジトリへのアクセス権限を付与してください。

## 3\. リトライ

プロジェクト概要に戻り、選択してください **セットアップをリトライ**.

カードは **保留中**、その後 **実行中**、作業が進行するにつれて新しい更新が表示されます。再試行はプロジェクトが **失敗** 状態、これにより 2 回のセットアップ試行を同時に実行することを防止します。

## 4\. 完了の確認

状態が以下に変更されたとき **完了**, GitHub で生成されたプルリクエストをレビューしてください。再度失敗した場合は、カード内の新しいアクティビティを使用し、以前の試行ではなく次のアクションを特定してください。
