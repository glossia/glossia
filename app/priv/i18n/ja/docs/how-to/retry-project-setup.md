自動化されたセットアップが失敗した場合、Glossia は予備プロジェクトを破棄し、リポジトリを再度選択できるようにします。セットアップフロー中に失敗の通知が表示される場合がありますが、失敗したプロジェクトとその進捗履歴は保持されません。

## 1. 失敗の確認

セットアップフローを終了する前に、失敗のお知らせを確認してください。共通の原因には以下が含まれます:

- アカウントに設定されたモデルがありません。
- プロバイダーキーがありません、または無効になっています。
- Glossia GitHub アプリはリポジトリにアクセスできません。
- リポジトリの準備または確認ができませんでした。

## 2. 前提条件の修正

モデルの問題については、**設定 → モデル** を開いてください。リポジトリへのアクセスの問題については、GitHub での Glossia GitHub アプリのインストールを更新し、リポジトリへのアクセス権限を付与してください。

## 3. セットアップを再度開始

**プロジェクト → 新規プロジェクト** を開き、リポジトリを選択し、**自動セットアップ** を選択して、再度ターゲット言語を選択します。新しいセットアップの試行が完了するまで、その手順に従ってください。

失敗したプロジェクトが表示されており、**セットアップの再試行** が利用可能な場合は、その操作で新しい試行を開始します。継続して利用可能であると依存しないでください：失敗した予備プロジェクトはクリーンアップ中に削除されます。

## 4. 完了の確認

セットアップが完了したら、GitHub で結果のプルリクエストを確認してください。ライフサイクルとクリーンアップの動作については [プロジェクト設定](/docs/reference/project-setup) を参照してください。
