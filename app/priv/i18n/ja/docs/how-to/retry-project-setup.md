自動設定が失敗すると、Glossia は一時的なプロジェクトを破棄し、リポジトリを再度選択できるようにします。設定フロー中に失敗の通知が表示される可能性がありますが、失敗したプロジェクトとその進行履歴は保持されません。

## 1. 失敗の確認

設定フローから離れる前に失敗の通知を確認してください。一般的な原因には次のようなものがあります：

- アカウントに設定済みのモデルがありません。
- プロバイダーキーが欠落しているか、もはや無効です。
- Glossia GitHub アプリがリポジトリにアクセスできません。
- リポジトリの準備または確認に失敗しました。

## 2. 前提条件の修正

モデルの問題については、**設定 → モデル**を開いてください。リポジトリへのアクセスの問題については、GitHub で Glossia GitHub アプリのインストールを更新し、リポジトリへのアクセス権を付与してください。

## 3. 設定の再開始

**プロジェクト → 新規プロジェクト**を開き、リポジトリを選択し、**自動設定**を選択して、再度ターゲット言語を選択します。新しい設定試行が完了するまで進めてください。

失敗したプロジェクトがまだ表示され **設定の再試行** が利用可能な場合、そのアクションは別の試行を開始します。利用できると依存しすぎないでください：失敗した一時的なプロジェクトはクリーンアップ処理中に削除されます。

## 4. 完了の確認

設定が完了したら、GitHub 内の生成されたプルリクエストを確認してください。[プロジェクト設定](/docs/reference/project-setup) を参照して、ライフサイクルとクリーンアップの挙動を確認してください。
