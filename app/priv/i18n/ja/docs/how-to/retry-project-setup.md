%{title: "プロジェクト設定の再試行", summary: "設定失敗後にプロジェクトを回復します。", category: "チュートリアル", order: 4}
---
使用 **セットアップの再試行** プロジェクトセットアップを失敗させた原因を修正した後。

## 1\. 失敗を確認

プロジェクトの概要を開きます。セットアップの進捗カードには、失敗と最新のセットアップ状況が表示されます。

一般的な原因は以下の通りです:

- アカウントには設定済みのモデルがありません。
- プロバイダーキーがないか、もはや有効ではありません。
- Glossia GitHub App はリポジトリにアクセスできません。
- リポジトリの準備または確認に失敗しました。

## 2\. 前提条件を修正

モデルの問題の場合は、開いて **設定** と **モデル**。リポジトリへのアクセス問題の場合は、GitHub 内の Glossia GitHub App のインストールを更新し、リポジトリへのアクセスを付与してください。

## 3\. 再試行

プロジェクトの概要画面に戻り、選択してください **セットアップを再試行する**.

カードが戻ります **保留中**、次に **実行中**, 作業が進行するにつれ新しいアクティビティが表示されます。再試行はプロジェクトが **Failed** 状態、これは 2 回のセットアップ試行を同時に実行することを防止します。

## 4\. 完了レビュー

ステータスが变为る場合 **Completed**GitHub で生成されたプルリクエストをレビューしてください。再度失敗した場合は、以前の実行ではなくカード上の新しいアクティビティを使用して次回のアクションを特定してください。
