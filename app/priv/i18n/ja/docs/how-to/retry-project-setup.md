%{title: "プロジェクトセットアップを再試行する", summary: "セットアップに失敗したプロジェクトを回復する。", category: "チュートリアル", order: 4}
---
使用する **セットアップを再試行** プロジェクトのセットアップ失敗の原因を修正した後

## 1\. 失敗の原因を確認

プロジェクトの概要を開きます。セットアップの進行状況カードには、失敗の内容と最新のセットアップの活動が表示されます。

主な原因は以下の通りです。

- アカウントには設定済みのモデルがありません。
- プロバイダーキーが存在しないか、または無効になっています。
- Glossia GitHub App はリポジトリにアクセスできません。
- リポジトリの準備または確認ができませんでした。

## 2\. 前提条件を修正する

モデルの問題については、開いて **設定** と **モデル**。リポジトリへのアクセス問題については、GitHub で Glossia GitHub App のインストールを更新し、リポジトリへのアクセス権を付与してください。

## 3\. 再試行

プロジェクト概要に戻り、選択する **セットアップの再試行**。

カードは戻り **保留中**, その後 **実行中**、作業が進行するにつれて新しいアクティビティが表示されます。再試行は、プロジェクトが **失敗** 、状態に、複数のセットアップ試行を同時に実行することはできません。

## 4\. 完了の確認

状態が に変更されたら **完了**、結果のプルリクエストを GitHub で検討してください。再度失敗した場合は、以前の実行ではなく、カード内の新しいアクティビティを使用して、次のアクションを特定してください。
