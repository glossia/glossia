自動化された初期設定が失敗すると、Glossia は一時的プロジェクトを破棄し、リポジトリを再度選択できるようにします。失敗の通知は初期設定フローに表示される可能性がありますが、失敗したプロジェクトとその進行状況の履歴は保持されません。

## 1. 失敗を読む

初期設定フローを離れる前に失敗の通知を読み取る。一般的な原因には以下が含まれます:

- アカウントに設定済みのモデルがない。
- プロバイダキーが欠落しているか、もうすぐ期限切れになっている。
- Glossia GitHub アプリはリポジトリにアクセスできない。
- リポジトリの準備またはチェックが完了しなかった。

## 2. 先決条件を修正する

モデルの問題の場合は**設定 → モデル**を開く。リポジトリアクセスの問題の場合は、GitHub で Glossia GitHub アプリのインストールを更新し、リポジトリへのアクセス権限付与を行う。

## 3. 初期設定を再度開始する

**プロジェクト → 新規プロジェクト**を開き、リポジトリを選択、**自動化された設定**を選択し、再度対象言語を選択する。新しい設定試行は完了まで追従する。

失敗したプロジェクトがまだ表示され、**設定を再試行**を提供する場合、その操作は別の試行を開始する。利用可能であることに依存しない：失敗した一時的プロジェクトはクリーンアップ時に削除される。

## 4. 完了を確認する

設定完了時、GitHub で結果のプル要求を確認する。ライフサイクルとクリーンアップの動作については[プロジェクト設定](/docs/reference/project-setup)を参照
