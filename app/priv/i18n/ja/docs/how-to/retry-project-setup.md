プロジェクトのセットアップが失敗した原因を修正した後、**セットアップの再試行**を使用してください。

## 1\. 失敗を確認

プロジェクトの概要を開きます。セットアップの進行状況カードには、失敗と最新のセットアップのアクティビティが表示されます。

一般的な原因は以下の通りです：

- アカウントに設定済みのモデルがありません。
- プロバイダーキーが欠落しているか無効になっています。
- Glossia GitHub App はリポジトリにアクセスできません。
- リポジトリの準備または検証に失敗しました。

## 2\. 前提条件の修正

モデルの問題の場合、**設定** と **モデル** を開きます。リポジトリアクセスの問題の場合、GitHub 上で Glossia GitHub App のインストールを更新し、リポジトリへのアクセス権限を付与してください。

## 3\. 再試行

プロジェクトの概要に戻り、**セットアップの再試行**を選択します。

カードは **保留中** に戻り、その後 **実行中** となり、作業が進行するに従って新しいアクティビティが表示されます。再試行はプロジェクトが **失敗** 状態にある間のみ利用可能であり、これにより同時に複数のセットアップの試行が実行されるのを防止します。

## 4\. 完了の確認

状態が **完了** に変更されたら、結果となるプルリクエストを GitHub で確認してください。再度失敗した場合は、前回の試行ではなくカード内の新しいアクティビティを使用して次のアクションを特定してください。
