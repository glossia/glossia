このチュートリアルでは、GitHub リポジトリを Glossia に接続し、最初の対象言語を選択し、チームが確認できるようローカライゼーションのベースレインを準備します。

## 始める前に

必要なもの：

- 設定とプロジェクトを管理できる Glossia アカウント。
- Glossia GitHub アプリの読み書き権限を付与できる GitHub リポジトリ。
- 対応済みの [大規模言語モデル](https://en.wikipedia.org/wiki/Large_language_model) 用のプロバイダーキー。

## 1. アカウントモデルを構成する

**設定** を開き、**モデル** を選択して **新しいモデル** を選択します。

1. モデルに短いハンドル（例：`translation-default`）を付けてください。
2. モデルピッカーを開き、プロバイダーまたはモデル名の一部を入力してリストをフィルタリングしてください。
3. Glossia が使用することを希望するモデルを選択します。
4. プロバイダーキーを入力し、モデルを保存します。

ハンドルにより、リポジトリはこのアカウントモデルを参照できます。プロバイダーの資格情報をソース管理に配置する必要はありません。詳細は [モデルプロバイダーの設定](/docs/how-to/configure-a-model-provider) を参照してください。

## 2. プロジェクトを開始する

**プロジェクト** に戻り、**新しいプロジェクト** を選択します。

Glossia がリポジトリアクセスを求めた場合は、GitHub のリンクに従って Github に移動し、Glossia GitHub アプリにリポジトリのアクセス権を付与してください。Glossia に戻ったら、必要に応じて **新しいプロジェクト** を再度開いてください。

## 3. リポジトリを選択する

ローカライズしたいリポジトリを選択します。Glossia は現在のアカウントの GitHub アプリインストールを通じて利用可能なリポジトリのみをリストします。

## 4. プロジェクトの設定方法を選択する

**自動化設定** を選択することで、Glossia がリポジトリを検査し、プラーリクエストでローカライゼーション設定の提案を行います。このチュートリアルはそのパスに従います。

すでに `L10N.md` ファイルがある場合、または自分で書きたい場合は **手動設定** を選択してください。Glossia はすぐにプロジェクトを作成し、残りのステップをスキップできます。[プロジェクト設定](/docs/reference/project-setup) について各部モードの動作を確認してください。

## 5. 対象言語を選択する

リポジトリのソースコンテンツから生成する言語を 1 つ以上選択して、セットアップを開始します。

## 6. セットアップの進捗を確認する

プロジェクトの準備中に Glossia がセットアップページを開いておいてください。進捗カードには現在の状態と最近のアクティビティが表示されます。リポジトリの準備、ファイルの検査、変更、チェック、完了が含まれます。

ページを离开してプロジェクトの見通しに戻ることもできます。セットアップのステータスは失われません。セットアップに失敗した場合は、失敗のお知らせを確認してください。Glossia は仮予約プロジェクトを破棄します。 prerequisite を修正して **新しいプロジェクト** からやり直してください。[プロジェクト設定のやり直し](/docs/how-to/retry-project-setup) を参照してください。

## 7. 結果を確認する

セットアップが完了したら、プロジェクトの見通しを開き、リポジトリに作成されたプラーリクエストを確認してください。提案されたベースレインには通常次のものが含まれます：

- ソース言語、ソースパス、対象言語を含むルート `L10N.md` ファイル。
- ローカライズされたファイルをロードするために必要な最小限のアプリケーションまたはコンテンツの変更。
- リポジトリに最初から利用可能な軽量な検証。

通常の GitHub ワークフローを通じてプラーリクエストを確認してマージしてください。将来の翻訳実行はマージされた `L10N.md` コンテキストを使用します。

プロジェクトの見通しはマージされるまでセットアップのプラーリクエストを表示します。マージされない状態でも閉じられた場合、セットアップお知らせのリンクから再度開いてください。
