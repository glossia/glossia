このチュートリアルでは、GitHub リポジトリを Glossia に接続し、最初の翻訳先言語を選択して、チームがレビューするためのローカライゼーションのベースラインを準備します。

## 始める前に

以下が必要です。

- 設定とプロジェクトを管理できる Glossia アカウント。
- Glossia GitHub App に読み取り権限と更新権限を付与できる GitHub リポジトリ。
- サポート対象の[大規模言語モデル](https://en.wikipedia.org/wiki/Large_language_model)用のプロバイダーキー。

## 1. アカウントモデルを設定する

**設定**、**モデル**の順に開き、**新規モデル**を選択します。

1. モデルに `translation-default` などの短いハンドルを指定します。
2. モデル選択画面を開き、プロバイダー名またはモデル名の一部を入力して一覧を絞り込みます。
3. Glossia で使用するモデルを選択します。
4. プロバイダーキーを入力し、モデルを保存します。

このハンドルを使用すると、プロバイダーの認証情報をソース管理に保存せずに、リポジトリからこのアカウントモデルを参照できます。詳細については、[モデルプロバイダーを設定する](/docs/how-to/configure-a-model-provider)を参照してください。

## 2. プロジェクトを開始する

**プロジェクト**に戻り、**新規プロジェクト**を選択します。

Glossia からリポジトリへのアクセスを求められた場合は、リンクから GitHub を開き、Glossia GitHub App にリポジトリへのアクセス権を付与します。Glossia に戻った後、必要に応じて **新規プロジェクト**をもう一度開きます。

## 3. リポジトリを選択する

ローカライズするリポジトリを選択します。Glossia には、現在のアカウントにインストールされた GitHub App からアクセスできるリポジトリのみが表示されます。

言語の選択手順に進みます。

## 4. 翻訳先言語を選択する

リポジトリのソースコンテンツから生成する言語を 1 つ以上選択し、セットアップを開始します。

## 5. セットアップの進行状況を確認する

Glossia がプロジェクトを準備している間は、セットアップページを開いたままにします。進行状況カードには、リポジトリの準備、ファイルの検査、変更、チェック、完了など、現在の状態と最近のアクティビティが表示されます。

ページを離れてプロジェクト概要に戻っても、セットアップの状態は失われません。セットアップに失敗した場合は、同じカードに対応が必要な内容が表示され、**セットアップを再試行**を選択できます。

## 6. 結果を確認する

セットアップが完了したら、プロジェクト概要を開き、リポジトリ用に作成されたプルリクエストを確認します。提案されるベースラインには通常、以下が含まれます。

- ソース言語、ソースパス、翻訳先言語を指定したルートの `GLOSSIA.md` ファイル。
- ローカライズされたファイルを読み込むために必要な、アプリケーションまたはコンテンツへの最小限の変更。
- リポジトリですでに利用可能な軽量の検証。

通常の GitHub ワークフローでプルリクエストをレビューし、マージします。以降の翻訳では、マージされた `GLOSSIA.md` コンテキストが使用されます。

プロジェクト概要には、セットアップ用プルリクエストがマージされるまで表示され続けます。マージせずにクローズした場合は、セットアップ通知内のリンクから再度開いてください。
