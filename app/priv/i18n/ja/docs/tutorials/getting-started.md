---
このチュートリアルでは、GitHub リポジトリを Glossia に接続し、最初のターゲット言語を選択し、チームによる確認のためのローカライゼーション基準を準備します。

## 始める前に

必要なもの:

- 設定やプロジェクトを管理できる Glossia アカウントです。
- Glossia GitHub App に読み取りおよび更新の権限を付与できる GitHub リポジトリです。
- サポートされた提供元キー [大規模言語モデル](https://en.wikipedia.org/wiki/Large_language_model)。

## 1\. アカウントモデルを設定します

開く **設定**、次に **モデル**、選択します **新規モデル**.

1. モデルに短いハンドル名を指定（例えば、 `translation-default`、
2. モデル選定ダイアログを開き、プロバイダー名またはモデル名の一部を入力してリストを絞り込みます。
3. Glossia で使用したいモデルを選択します。
4. プロバイダーキーを入力し、モデルを保存します。

ハンドルは、ソースコントロールにプロバイダー認証情報が含まれることなくリポジトリがアカウントモデルを参照できるようにします。詳細については、 [モデルプロバイダーを設定](/docs/how-to/configure-a-model-provider) より詳細については。

## 2\. プロジェクトを開始する

戻る **プロジェクト** を選択し **新規プロジェクト**。

Glossia がリポジトリへのアクセスを要求する場合は、GitHub のリンクに移動し、リポジトリに対して Glossia GitHub アプリへのアクセス権を付与してください。Glossia に戻った後、再度 **新規プロジェクト** 必要な場合。

## 3\. リポジトリを選択

ローカライズ対象のリポジトリを選択してください。Glossia は、現在のアカウントでインストールされた GitHub App 経由で利用可能なリポジトリのみを表示します。

言語設定のステップに進む。

## 4\. 対象言語を選択

リポジトリのソースコンテンツから生成される 1 つ以上の言語を選択し、セットアップを開始してください。

## 5\. セットアップの進捗を確認

Glossia がプロジェクトを準備する間、セットアップページを開いたままにしてください。進捗カードには、現在の状態および直近のアクティビティ（リポジトリの準備、ファイルの検査、変更、チェック、完了）が含まれます。

ページを離れてプロジェクトの概要に戻ることもでき、設定の状態は失われません。設定に失敗した場合、同じカードは必要な対応を説明し、 **設定を再試行**。

## 6\. 結果を確認

設定完了後、プロジェクトの概要を開き、リポジトリに作成されたプルリクエストを確認してください。提案されたベースラインには通常以下が含まれます：

- ルート `L10N.md` ソース言語、ソースパス、およびターゲット言語を指定したファイル。
- ローカライズされたファイルをロードするために必要な最小限のアプリケーションまたはコンテンツの変更。
- すでにリポジトリに利用可能な軽量な検証。

通常の GitHub ワークフローを通じてプルリクエストを確認し、マージしてください。今後の翻訳実行ではマージされた `L10N.md` コンテキストを使用します。

プロジェクト概要では、マージされるまでセットアップのプルリクエストが表示されます。マージされずに閉じられた場合は、セットアップの通知にあるリンクから再び開いてください。
