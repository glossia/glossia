このチュートリアルでは、GitHub リポジトリを Glossia に接続し、最初のターゲット言語を選択し、チームがレビューするための局所化の基準を準備します。

## 実際に始める前に

必要なもの:

- 設定とプロジェクトを管理できる Glossia アカウント
- Glossia GitHub App に読み取り・更新の権限を付与できる GitHub リポジトリ
- サポートされるためのプロバイダーキー [大規模言語モデル](https://en.wikipedia.org/wiki/Large_language_model)。

## 1\. アカウントモデルを設定する

開く **設定**、次に **モデル**、を選択 **新しいモデル**。

1. モデルに短いハンドルを割り当ててください。例えば `translation-default`。
2. モデル選択ツールを開き、プロバイダー名またはモデル名の一部を入力してリストをフィルターしてください。
3. Glossia で使用するモデルを選択してください。
4. プロバイダーキーを入力してモデルを保存してください。

ハンドルは、リポジトリがソースコントロールにプロバイダーの資格情報を置かずにこのアカウントモデルを参照可能にします。詳細 [モデルプロバイダーを構成](/docs/how-to/configure-a-model-provider) 詳しくご覧ください。

## 2\. プロジェクトを開始

戻る **プロジェクト** と選択 **新規プロジェクト**.

Glossia がリポジトリへのアクセスを求めたら、GitHub のリンクに従って、Glossia GitHub App にリポジトリへのアクセス権を付与してください。その後、Glossia に戻って、開く **新規プロジェクト** 必要に応じて。

## 3\. リポジトリを選択

ローカライズ対象のリポジトリを選択してください。Glossia では、現在のアカウントでインストールされた GitHub アプリを通じて利用可能なリポジトリのみがリストされます。

言語ステップへ進む。

## 4\. 対象言語を選択

リポジトリのソースコンテンツから生成すべき言語を 1 つ以上選択し、セットアップを開始してください。

## 5\. セットアップの進捗を確認

Glossia がプロジェクトの準備している間、セットアップページを開いておいてください。進捗カードは、リポジトリ準備、ファイル検証、変更、チェック、完了を含む現在のステータスと最近のアクティビティを表示します。

ページを離れてプロジェクト概要に戻っても、セットアップの状態は失われません。セットアップに失敗した場合、同じカードは必要な対応を説明し、 **セットアップを再試行**.

## 6\. 結果を確認

セットアップが完了したら、プロジェクト概要を開いてリポジトリに作成されたプルリクエストを確認してください。提案されたベースラインには通常、

- ルート `L10N.md` 、ソース言語、ソースパス、およびターゲット言語を含んだファイル。
- ローカライズされたファイルを読み込むために必要な最小限のアプリケーションまたはコンテンツの変更。
- リポジトリに既に存在していた軽量な検証です。

通常の GitHub ワークフローを用いてプルリクエストをレビューし、マージしてください。今後の翻訳実行にはマージされた `L10N.md` コンテキスト。

プロジェクトの概要では、設定用プルリクエストはマージされるまで表示されます。マージされずに閉じた場合は、設定通知のリンクから再度開いてください。
