このチュートリアルは、GitHub リポジトリを Glossia に接続し、最初のターゲット言語を選び、チームがレビューするための翻訳の基準を準備します。

## 開始前に

必要なもの:

- 設定やプロジェクトを管理できる Glossia アカウント
- Glossia GitHub アプリに読み取りと更新の権限を付与できる GitHub リポジトリ
- サポートされているプロバイダーキー [大規模言語モデル](https://en.wikipedia.org/wiki/Large_language_model)。

## 1\. アカウントモデルを設定

開く **設定**、次に **モデル**、を選択し **新しいモデル**。

1. モデルに短いハンドルを指定し、例えば `translation-default`.
2. モデルのピッカーを開いて、プロバイダー名またはモデル名の一部を入力してリストを絞り込みます。
3. Glossia が使用するモデルを選択してください。
4. プロバイダーキーを入力してモデルを保存します。

このハンドルを使用すると、リポジトリがこのアカウントモデルを参照でき、プロバイダー認証情報をソース管理に含める必要がなくなります。詳細は [モデルプロバイダーの構成](/docs/how-to/configure-a-model-provider) 詳細をご覧ください。

## 2\. プロジェクトを開始する

戻る **プロジェクト** を選択し **新規プロジェクト**。

Glossia がリポジトリへのアクセスを求めた場合、GitHub のリンクをクリックし、Glossia GitHub アプリにリポジトリへのアクセス権を付与してください。Glossia に戻った後、もう一度開いてください。 **新規プロジェクト** 必要に応じて。

## 3\. リポジトリを選択

ローカライズ対象のリポジトリを選択します。Glossia は、現在のアカウントの GitHub App インストールを介して利用可能なリポジトリのみを表示します。

言語ステップへ続行

## 4\. 対象言語を選択

リポジトリのソースコンテンツから生成する言語を 1 つ以上選択し、セットアップを開始します。

## 5\. セットアップの進捗を確認

プロジェクト準備中は、セットアップページを開いたままにしてください。進捗カードには、現在の状態と最近のアクティビティ（リポジトリ準備、ファイル検査、変更、チェック、完了など）が表示されます。

ページから離れてプロジェクト概要に戻っても、セットアップの状態は失われません。セットアップに失敗した場合、同じカードで必要な対応を説明し、オプションを提供します **セットアップを再試行**.

## 6\. 結果を確認

セットアップが完了したら、プロジェクト概要を開き、リポジトリで作成されたプルリクエストを確認してください。提案されるベースラインには、通常、以下のものが含まれます：

- ルート `L10N.md` ソース言語、ソースパス、およびターゲット言語を含むファイル。
- ローカライズされたファイルを読み込むために必要な、最小限のアプリケーションまたはコンテンツの変更です。
- リポジトリに既に用意されていた軽量なバリデーションです。

通常の GitHub ワークフローに従ってプルリクエストのレビューとマージを行ってください。将来の翻訳実行はマージされた `L10N.md` コンテキストを使用します。

プロジェクト概要はセットアップのプルリクエストがマージされるまで表示されます。マージされずに閉じられた場合は、セットアップ通知のリンクから再度開いてください。
