---
このチュートリアルでは、GitHub リポジトリを Glossia に接続し、最初のターゲット言語を選択して、チームがレビューするためのローカライズ基準を準備します。

## 作業を開始する前に

必要なもの:

- 設定とプロジェクトを管理できる Glossia アカウント。
- Glossia GitHub アプリに読み取りと更新の権限を付与できる GitHub リポジトリ。
- サポートされているプロバイダーキーの [大規模言語モデル](https://en.wikipedia.org/wiki/Large_language_model).

## 1\. アカウントモデルを設定

開く **設定**, 次に **モデル**, 選択して **新しいモデル**.

1. モデルに短いハンドルを指定します。例 `translation-default`。
2. モデル選択ダイアログ opened を開き、プロバイダーまたはモデル名の一部を入力してリストを絞り込みます。
3. Glossia で使用したいモデルを選択します。
4. プロバイダーキーを入力し、モデルを保存します。

ハンドルを使用すると、リポジトリはプロバイダー認証情報をソースコントロールに置くことなく、このアカウントモデルを参照できます。詳しくは、 [モデルプロバイダーを構成](/docs/how-to/configure-a-model-provider) の詳細をご覧ください。

## 2\. プロジェクトを開始する

戻る **プロジェクト** を選択して **新しいプロジェクト**。

Glossia がリポジトリへのアクセスを求めた場合は、GitHub のリンクに従い、Glossia GitHub App のリポジトリへのアクセス権限を付与してください。Glossia に戻った後、もう一度 **新しいプロジェクト** 必要なら。

## 3\. リポジトリを選択

ローカライズしたいリポジトリを選択します。Glossia は、現在のアカウントの GitHub App インストールを通じて利用可能なリポジトリのみを表示します。

## 4\. プロジェクトのセットアップ方法を選択

選択 **自動セットアップ** Glossia にリポジトリを検査させ、プルリクエストでローカライズ構成を提案します。このチュートリアルはその手順に従います。

もしリポジトリに既に `L10N.md` ファイル、あるいはご自身で記述されたい場合は選択 **手動設定** 代わりに。Glossia はすぐにプロジェクトを作成し、残りの手順をスキップできます。参照 [プロジェクト設定](/docs/reference/project-setup) 各モードが何を行うかについて。

## 5\. ターゲット言語を選択

リポジトリのソースコンテンツから生成される言語を 1 つ以上選択し、その後、設定を開始してください。

## 6\. 設定の進捗を確認する

Glossia がプロジェクトを準備中は、セットアップ画面を開いておいてください。進捗カードには、現在の状況や、リポジトリの準備、ファイルのチェック、変更、チェック、完了までの最新活動が表示されます。

ページを離れて概要に戻ってもセットアップ状態は失われません。失敗時はエラーメッセージを確認してください。Glossia は仮プロジェクトを破棄します。前提を修正し、再度 開始を 経て **新規プロジェクト**。ご参照 [プロジェクトセットアップの再試行](/docs/how-to/retry-project-setup)。

## 7\. 結果を確認

セットアップ完了後、プロジェクト概要を開き、リポジトリ用に作成されたプルリクエストを確認してください。提案されたベースラインには、通常以下が含まれています：

- ルート `L10N.md` ソース言語、ソースパス、およびターゲット言語を指定するファイル。
- ローカライズ済みファイルをロードするために必要な最小限のアプリケーションまたはコンテンツの変更。
- リポジトリですでに利用可能なあらゆる軽量な検証。

通常の GitHub ワークフローでプルリクエストをレビューし、マージってください。今後の翻訳実行はマージされた `L10N.md` 文脈。

プロジェクトの概要はマージされるまで設定のプル リクエストを表示します。マージされていない状態で閉じられた場合は、設定のお知らせのリンクから再度開いてください。
