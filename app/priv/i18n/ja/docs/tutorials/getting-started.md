---
このチュートリアルでは、GitHub リポジトリを Glossia に接続し、最初のターゲット言語を選択し、チームのレビュー用ローカライゼーション基線を作成します。

## 始める前に

必要なもの：

- 設定とプロジェクトを管理できる Glossia アカウント
- Glossia GitHub App に読み取りおよび更新権限を与えることができる GitHub リポジトリ
- サポートされたプロバイダーキー [大規模言語モデル](https://en.wikipedia.org/wiki/Large_language_model)。

## 1\. アカウントモデルを設定する

開く **設定**, 次に **モデル**, そして選択 **新しいモデル**.

1. モデルに短いハンドル名、例えば `translation-default`.
2. モデルの選択リストを開き、プロバイダーまたはモデル名の一部を入力してリストを絞り込みます。
3. Glossia に使用したいモデルを選択します。
4. プロバイダーキーを入力し、モデルを保存します。

ハンドルを使用すると、リポジトリがソース管理にプロバイダー認証情報を置かずこのアカウントモデルを参照できます。詳しくは、 [モデルプロバイダーの設定](/docs/how-to/configure-a-model-provider) 詳細については

## 2\. プロジェクトを開始する

プロジェクトへ **戻り** 選択し **新しいプロジェクト**。

Glossia がリポジトリへのアクセスを求めた場合は、GitHub のリンクに従ってアクセス権限を付与し、Glossia に戻った後、 **新しいプロジェクト** 必要に応じて。

## 3\. リポジトリを選択

ローカライズするリポジトリを選択します。Glossia は、現在のアカウントの GitHub App インストールにより利用可能なリポジトリのみが表示されます。

言語ステップに進む。

## 4\. ターゲット言語を選択

リポジトリのソースコンテンツから生成する 1 つ以上の言語を選択し、セットアップを開始します。

## 5\. セットアップの進行状況を確認

Glossia がプロジェクトを準備している間、セットアップページを開いたままにしてください。進捗カードには、現在の状態と最近のアクティビティ（リポジトリの準備、ファイルの検査、変更、確認、および完了）が表示されます。

ページを離れてプロジェクトの概要に戻ることもでき、セットアップ状態は失われません。セットアップが失敗した場合は、同じカードで必要な対応を説明し、提供する **セットアップを再試行**。

## 6\. 結果を確認

セットアップが完了したら、プロジェクトの概要を開き、リポジトリに作成されたプルリクエストを確認してください。提案されたベースラインには通常、以下のものを含みます:

- ルート `L10N.md` ソース言語、ソースパス、およびターゲット言語を含むファイルです。
- ローカライズファイルをロードするために必要な最小限のアプリケーションまたはコンテンツの変更です。
- リポジトリに既に利用可能な軽量なバリデーション。

普段の GitHub ワークフローを使って Pull リクエストを確認し、マージしてください。今後の翻訳実行はマージされた `L10N.md` コンテキスト。

プロジェクトの概要では、セットアップ用 Pull リクエストがマージされるまで表示されます。マージされないままクローズされた場合は、セットアップ通知内のリンクから再度開いてください。
