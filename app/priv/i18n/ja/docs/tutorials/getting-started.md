このチュートリアルでは、GitHub リポジトリを Glossia に接続し、最初のターゲット言語を選択して、チームが検討するためのローカライズ基準を準備します。

## 開始する前に

必要なもの:

- 設定やプロジェクトを管理できる Glossia アカウント
- Glossia GitHub App に読み取りおよび更新の権限を付与できる GitHub リポジトリ
- サポートされているプロバイダーキーの [大規模言語モデル](https://en.wikipedia.org/wiki/Large_language_model).

## 1\. アカウントモデルを設定する

開く **設定**、次に **モデル**、を選択して **新しいモデル**。

1. モデルに短いハンドル名を設定してください。例えば `translation-default`.
2. モデル選択画面を開き、プロバイダー名またはモデル名の一部を入力してリストを絞り込んでください。
3. Glossia で使用するモデルを選択してください。
4. プロバイダーキーを入力し、モデルを保存してください。

このハンドルにより、リポジトリはプロバイダー認証情報をソース管理に含めずにアカウントモデルを参照できます。詳細は [モデルプロバイダーの設定](/docs/how-to/configure-a-model-provider) 詳しくお読みください。

## 2\. プロジェクトを開始する

戻る **プロジェクト** を選択して **新規プロジェクト**。

Glossia がリポジトリへのアクセスを求めている場合、GitHub のリンク先へ移動して、Glossia GitHub App にリポジトリへのアクセス権限を付与してください。Glossia に戻ったら、再度 **新規プロジェクト** 必要に応じて。

## 3\. リポジトリを選択

翻訳対象のリポジトリを選択してください。Glossia は、現在のアカウントの GitHub App インストールにより利用可能なリポジトリのみを表示します。

言語ステップへすすむ。

## 4\. 目標言語を選択

リポジトリのソースコンテンツから翻訳される 1 つ以上の言語を選択し、セットアップを開始してください。

## 5\. セットアップの進捗を確認

Glossia がプロジェクトを準備している間は、セットアップページを開いておいてください。進捗カードは現在の状態と最近のアクティビティを表示します。これにはリポジトリの準備、ファイルの検証、変更、チェック、完了が含まれます。

ページを離れてプロジェクト概要に戻っても、セッティングの状態は失われません。 セッティングに失敗した場合は、同じカードで必要な対応が説明され、 **セッティングをリトライする**,

## 6\. 結果を確認

セッティング完了後、プロジェクト概要を開き、リポジトリ向けに作成されたプルリクエストを確認してください。提案されるベースラインには通常以下が含まれます:

- ルート `L10N.md` ソース言語、ソースパス、およびターゲット言語を含むファイル。
- ローカライズされたファイルをロードするために必要な、最小限のアプリケーションまたはコンテンツの変更。
- リポジトリに既に利用可能な軽量な検証です。

通常の GitHub ワークフローを通じてプルリクエストをレビューし、マージしてください。今後の翻訳実行はマージされた `L10N.md` コンテキストを使用します。

プロジェクト概要はセットアップのプルリクエストをマージされるまで表示します。マージなしでクローズされた場合、セットアップ通知のリンクからこれを取り直してください。
