本チュートリアルでは、GitHub リポジトリを Glossia に接続し、最初のターゲット言語を選択し、チームのレビューのためのローカライゼーションの基準を準備します。

## 始める前に

必要なもの:

- 設定やプロジェクトを管理できる Glossia アカウントが必要です。
- Glossia GitHub App に読み書き権限を与えることができる GitHub リポジトリが必要です。
- サポートされている [大規模言語モデル](https://en.wikipedia.org/wiki/Large_language_model) 用のプロバイダーキーが必要です。

## 1. アカウントモデルを設定

**設定** を開き、**モデル** をクリックし、**新しいモデル** を選択してください。

1. モデルに短いハンドル名（例：`translation-default`）を付けてください。
2. モデル選択画面を開き、プロバイダーまたはモデル名の一部を入力してリストを絞り込みます。
3. Glossia で使用したいモデルを選択します。
4. プロバイダーキーを入力し、モデルを保存します。

このハンドルにより、ソースコントロールにプロバイダー認証情報を配置せずにリポジトリがアカウントモデルを参照できます。詳細については [モデルプロバイダーの設定](/docs/how-to/configure-a-model-provider) をご参照ください。

## 2. プロジェクトを開始

**プロジェクト** に戻り、**新しいプロジェクト** を選択します。

Glossia がリポジトリへのアクセスを求める場合は、リンクから GitHub へ移動し、Glossia GitHub App がリポジトリへのアクセス権限を与えるようにします。Glossia に戻った後、必要に応じて **新しいプロジェクト** を再度開きます。

## 3. リポジトリを選択

ローカライズしたいリポジトリを選択します。Glossia は、現在のアカウントの GitHub App インストールを通じて利用可能なリポジトリのみを一覧表示します。

## 4. プロジェクトを設定する方法を選択

**自動設定** を選択して、Glossia にリポジトリを検査させ、プルリクエストでローカライゼーション構成を提案させます。このチュートリアルは、その手順に基づいています。

リポジトリに `L10N.md` ファイルが既に存在する場合、または自分で書きたい場合は、**手動設定** を選択してください。Glossia はプロジェクトを即座に作成するため、残りの手順をスキップできます。各モードの機能については [プロジェクト設定](/docs/reference/project-setup) をご参照ください。

## 5. ターゲット言語を選択

リポジトリのソースコンテンツから生成される言語を 1 つ以上選択し、設定を開始します。

## 6. 設定の進捗状況を確認

Glossia がプロジェクトを準備する間は、設定ページを開いておいてください。進捗カードには、リポジトリの準備、ファイル検査、変更、チェック、完了などの現在のステータスと最近のアクティビティが表示されます。

ページから離れても、設定ステータスは失われません。設定に失敗した場合は、失敗通知を確認してください。Glossia は仮プロジェクトを破棄するため、前提条件を修正し、**新しいプロジェクト** から再度開始してください。[プロジェクト設定の再試行](/docs/how-to/retry-project-setup) をご参照ください。

## 7. 結果を確認

設定が完了したら、プロジェクト詳細を開き、リポジトリ向けに作成されたプルリクエストを確認してください。提案される基準には、通常以下が含まれます:

- ソース言語、ソースパス、ターゲット言語が含まれるルートの `L10N.md` ファイルを。
- ローカライズされたファイルをロードするために必要な最小限のアプリケーションまたはコンテンツの変更。
- リポジトリに既に提供されていた軽量の検証。

通常の GitHub ワークフローでプルリクエストをレビューしてマージしてください。将来の翻訳実行には、マージされた `L10N.md` コンテキストが使用されます。

プロジェクト詳細では、マージされるまで設定のプルリクエストを表示し続けます。マージされずにクローズされた場合は、設定通知のリンクから再度開きます。
