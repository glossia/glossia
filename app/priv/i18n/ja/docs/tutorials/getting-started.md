このチュートリアルでは、GitHub リポジトリを Glossia に接続し、最初のターゲット言語を選択し、チームによるレビューのためのローカライズ基盤を準備します。

## 開始前に

必要なもの:

- 設定とプロジェクトを管理できる Glossia アカウント
- Glossia GitHub App に読み取りおよび更新の権限を付与できる GitHub リポジトリ。
- サポートされるプロバイダーキー [大規模言語モデル](https://en.wikipedia.org/wiki/Large_language_model)。

## 1\. アカウントモデルを設定する

開く **設定**, 次に **モデル**, そして選択する **新モデル**.

1. モデルに短いハンドルを設定してください。例えば `translation-default`.
2. モデル選択器を開き、プロバイダーまたはモデル名の一部を入力してリストをフィルタリングします。
3. Glossia で使用するモデルを選択してください。
4. プロバイダーキーを入力してモデルを保存してください。

ハンドルにより、リポジトリはこのアカウントモデルを参照でき、プロバイダー認証情報をバージョン管理に配置する必要はありません。詳しくは [モデルプロバイダーを設定する](/docs/how-to/configure-a-model-provider) をご参照ください。

## 2\. プロジェクトを開始

戻る **プロジェクト** を選択 **新しいプロジェクト**。

Glossia がリポジトリへのアクセスを求めた場合、GitHub のリンクを開いて、Glossia GitHub App にリポジトリへのアクセス権を付与してください。Glossia に戻った後、再開 **新しいプロジェクト** もし必要であれば。

## 3\. リポジトリを選択

ローカライズしたいリポジトリを選択してください。Glossia では、現在のアカウントの GitHub App インストールで利用可能なリポジトリのみがリストされます。

言語のステップへ続行

## 4\. 対象言語を選択

リポジトリのソースコンテンツから生成したい言語（1 つ以上）を選択し、セットアップを開始します。

## 5\. セットアップの進行状況を確認

Glossia がプロジェクトを準備する間、セットアップページを開いておいてください。進行状況カードにおいて、現在の状態と最近の活動状況（リポジトリの準備、ファイルチェック、変更、検証、完了）が表示されます。

ページを離れてプロジェクトの概要に戻っても、設定の状態は失われません。設定に失敗した場合は、同じカードで必要な対応が説明され、提示し、 **セットアップのリトライ**.

## 6\. 結果を確認

設定完了後、プロジェクトの概要ページを開いて、リポジトリのために作成されたプルリクエストを確認してください。提案されるベースラインには、通常以下の要素が含まれます：

- ルート `GLOSSIA.md` ソース言語、ソースパス、ターゲット言語を含むファイル。
- ローカライズされたファイルをロードするために必要な、最小限のアプリケーションまたはコンテンツの変更。
- リポジトリに既に利用可能な軽量な検証です。

通常の GitHub ワークフローでプルリクエストを確認し、マージしてください。今後の翻訳実行ではマージされた `GLOSSIA.md` コンテキスト。

プロジェクト概要では、セットアップのプルリクエストはマージされるまで表示されます。マージされないままクローズされた場合は、セットアップの通知のリンクから再オープンしてください。
