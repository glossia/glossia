プロジェクト設定は接続済みのリポジトリを Glossia 用に準備します。ユーザーが「**New project**」のフローでリポジトリと少なくとも 1 つのターゲット言語を選択した後に開始されます。

## 前提条件

- アカウントに少なくとも 1 つの構成済みモデルが設定されています。
- Glossia GitHub App が選択されたリポジトリにアクセスできます。
- ユーザーはアカウント内でプロジェクトを作成できます。
- 少なくとも 1 つのターゲット言語が選択されています。

## 状態

| 状態 | 意味 | 利用可能なアクション |
|---|---|---|
| **Pending** | プロジェクトは受諾され、起動を待っています。 | 進捗を確認するか、ページを後にして後で戻ります。 |
| **Running** | Glossia がリポジトリを検査し、更新しています。 | ライブアクティビティを確認します。 |
| **Completed** | 定本地元基準は準備され、レビューのために公開されました。 | プルリクエストを開き、レビューしてマージします。 |

プロジェクトはセットアップが **Pending** または **Running** の間は仮の状態です。セットアップが完了しないか、使用可能な変更を公開できない場合、Glossia はセットアップ環境をクリーンアップし、仮のプロジェクトを削除します。その後、リポジトリは「**New project**」のフローで利用可能になり、セットアップを再度試すことができます。

## 表示される進捗

設定カードは新規プロジェクトフローとプロジェクト概要で利用可能です。含まれる内容は以下の通りです：

- ステータスバッジと進捗バー。
- 現在の状態の説明。
- 最近のリポジトリ準備、検査、ファイル変更、チェック、完了のアクティビティ。
- セットアップが完了できない場合の明確な失敗メッセージ。

進捗情報は仮のプロジェクトが存在する間保存されます。致命的な失敗は、プロジェクトとその表示されるセットアップ進捗の両方を破棄します。

## 完了結果

成功した接続設定は、専用のブランチとリポジトリのデフォルトブランチへのプルリクエストを作成します。プルリクエストには生成された定本地元基準が含まれ、`GLOSSIA.md` コンテキストと定本地元コンテンツをロードするために必要な最小限の実践的な変更が含められています。

セットアップはヘッダーだけのターゲットカタログを公開しません。ローカライゼーションフレームワークが翻訳前にターゲットカタログを必要とする場合、カタログは抽出されたソースメッセージ項目を空の翻訳値として含みます。ターゲットカタログがまだ必須ではない場合、セットアップはそれを最初の翻訳実行のために残します。

Glossia はプルリクエストをマージしません。リポジトリ管理者は通常の GitHub プロセスを通じてレビューしてマージします。

このプルリクエストが開かれている間、プロジェクト概要にはセットアップの通知が表示されます。プルリクエストがマージされた後、通知は削除されます。もしプルリクエストがマージなしで閉じられた場合、概要はセットアップを完了とみなす前に再オープンする必要があることを説明します。
