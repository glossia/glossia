%{title: "プロジェクトのセットアップ", summary: "リポジトリのセットアップの状態、進捗情報、および結果。", category: "参考", order: 2}
---
プロジェクト設定は、Glossia 向けに接続されたリポジトリを準備します。ユーザーがリポジトリと少なくとも 1 つのターゲット言語を選択した後、の **新規プロジェクト** フロー。

## 前提条件

- アカウントには設定済みのモデルが少なくとも 1 つあります。
- Glossia GitHub App は選択したリポジトリにアクセスできます。
- ユーザーはアカウント内でプロジェクトを作成できます。
- 少なくとも 1 つのターゲット言語が選択されています。

## ステータス

| ステータス | 意味 | 利用可能なアクション |
|---|---|一|
| **待機中** | プロジェクトは承認され、開始待ちです。 | 進捗を確認するか、ページを離れて後で戻ってください。 |
| **実行中** | Glossia はリポジトリを検証および更新しています。 | リアルタイムアクティビティを確認してください。 |
| **完了** | 翻訳の基準はレビューのために準備され、公開されました。 | プルリクエストを開いて、レビューし、マージしてください。 |

セットアップ中は、プロジェクトは暫定的です。 **保留中** または **実行中**. セットアップが完了できず、有効な変更を公開できない場合、Glossia はセットアップ環境をクリーンアップし、仮プロジェクトを削除します。リポジトリはその後、利用可能になります。 **新規プロジェクト** フローでセットアップを再度試行可能です。

## 表示される進行状況

セットアップカードは、新規プロジェクトフローおよびプロジェクトの概要ページで引き続き利用可能です。含まれます:

- ステータスバッジと進行状況バー。
- 現在の状況に関する短い説明。
- 最近のリポジトリ準備、点検、ファイル変更、検証、および完了のアクティビティ。
- セットアップが完了しない場合に明確な失敗メッセージが表示されます。

一時的プロジェクトが存在する間、進捗は保存されます。致命的な失敗は、プロジェクトおよびその表示されるセットアップの進捗の両方を廃棄します。

## 完了結果

正常に接続されたセットアップが作成されると、専用ブランチとリポジトリのデフォルトブランチに対する Pull Request 作成されます。この Pull Request には、生成されたローカライゼーション ベースラインが含まれており、 `L10N.md` 文脈、およびローカライズされたコンテンツを読み込むために必要な最小限の実用的な変更。

セットアップはヘッダーのみのターゲットカタログを公開しません。ローカライゼーションフレームワークが翻訳前にターゲットカタログを必要とする場合、カタログには抽出されたソースメッセージ項目を含み、翻訳値が空になります。ターゲットカタログがまだ必要ない場合、セットアップはそれらを最初の翻訳実行のために残しておきます。

Glossia は Pull Request をマージしません。リポジトリの管理者は通常の GitHub プロセスを通じてそれをレビューし、マージします。

プロジェクトの概要は、この Pull Request が開かれている間、セットアップの通知を表示します。通知は Pull Request がマージされた後に削除されます。Pull Request がマージなしでクローズされた場合、概要ではセットアップが完了とみなされる前にその Pull Request を再オープンする必要があると説明します。
