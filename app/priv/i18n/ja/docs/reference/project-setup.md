プロジェクト設定は Glossia 向けに接続されたリポジトリを準備します。開始は ユーザーが リポジトリ と少なくとも 1 つの ターゲット言語 を選択したの **新規プロジェクト** フロー。

## 前提条件

- アカウントには少なくとも 1 つの構成済みモデルがあります。
- Glossia GitHub アプリは選択されたリポジトリにアクセスできます。
- ユーザーはアカウント内でプロジェクトを作成できます。
- 少なくとも 1 つのターゲット言語が選択されています。

## ステータス

| ステータス | 意味 | 利用可能なアクション |
|---|---|---|
| **待機中** | プロジェクトが承認され、開始を待っています。 | 進捗を確認するか、ページを離れて後ほど戻ってください。 |
| **実行中** | Glossia はリポジトリを検査・更新しています。 | 進行状況を確認してください。 |
| **完了** | ローカライゼーションの基準が準備され、レビューのために公開されました。 | プルリクエストを開いてレビューし、マージしてください。 |

プロジェクトは一時的です。設定が **保留中** または **実行中**. セットアップが完了せず、または利用可能な変更を公開できない場合、Glossia はセットアップ環境を整理し、仮プロジェクトを削除します。リポジトリはその後、 **新プロジェクト** フロー中でセットアップを再試行できます。

## 進行状況の可視化

セットアップカードは、新プロジェクトフローおよびプロジェクト概要ページで引き続き利用可能です。以下の項目が含まれます:

- ステータスバッジと進捗バー。
- 現在のステータスの簡単な説明。
- 最近のリポジトリ準備、点検、ファイル変更、チェック、および完了のアクティビティ。
- セットアップが完了できない場合に示される明確な失敗メッセージです。

一時的なプロジェクトが存在する間、進捗は保存されます。致命的な失敗が発生すると、プロジェクトと表示されているセットアップの進捗の両方が破棄されます。

## 完了結果

成功した接続されたセットアップは、リポジトリのデフォルトブランチに対する専用ブランチとプルリクエストを作成します。このプルリクエストには、生成されたローカライゼーションのベースラインなどを含み、 `L10N.md` コンテキストと、ローカライズされたコンテンツをロードするために必要な最小限の実用的な変更です。

セットアップはヘッダー単体のターゲットカタログを公開しません。ローカライゼーションフレームワークが翻訳前にターゲットカタログを必要とする場合、カタログには空の翻訳値を持つ抽出されたソースメッセージエントリが含まれます。ターゲットカタログがまだ必要ない場合、セットアップはそれらを最初の翻訳実行のために残します。

Glossia はプルリクエストをマージしません。リポジトリの管理者は、通常の GitHub プロセスを通じてレビューおよびマージを行います。

このプルリクエストが開かれている間、プロジェクトの概要にはセットアップ通知が表示されます。このプルリクエストがマージされた後、通知は削除されます。もしマージなしでクローズされた場合、概要にはセットアップ完了とみなされる前に再オープンされなければならないことを説明します。
