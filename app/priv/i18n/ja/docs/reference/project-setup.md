プロジェクト設定は Glossia 用に連携したリポジトリを準備します。ユーザーがリポジトリと少なくとも 1 つのターゲット言語を選択した後の **新規プロジェクト** フロー。

## 前提条件

- アカウントには少なくとも 1 つのモデルが構成済みです。
- Glossia GitHub アプリは選択したリポジトリにアクセスできます。
- ユーザーはアカウント内でプロジェクトを作成できます。
- 少なくとも 1 つのターゲット言語を選択済みです。

## ステータス

| ステータス | 説明 | アクション |
|---|---|---|
| **待機中** | プロジェクトは承認され、開始を待っています。 | 進捗を確認するか、ページを離れてから後で戻ることができます。 |
| **実行中** | Glossia がリポジトリの確認および更新を行っています。 | リアルタイムのアクティビティをご確認ください。 |
| **完了** | ローカライゼーションの基準が準備され、レビュー用に公開されました。 | プルリクエストを開き、レビューし、マージしてください。 |

设定中は、プロジェクトは一時的です。 **保留中** または **実行中**. セットアップが完了せず、または利用可能な変更を公開できなければ、Glossia はセットアップ環境をクリーンアップし、暫定的なプロジェクトを削除します。その後、リポジトリは **新規プロジェクト** フローでセットアップを再度試すことができます。

## 進捗状況

セットアップカードは、新規プロジェクトのフローとプロジェクトの概要ページでも利用可能です。これには以下が含まれます：

- 状態バッジと進捗バー。
- 現在の状態の簡潔な説明。
- 最近のリポジトリ準備、検証、ファイル変更、チェック、完了のアクティビティ。
- セットアップが完了できない場合、明確な失敗メッセージが表示されます。

仮プロジェクトが存在する間は進行状況が保存されます。致命的な失敗が発生すると、プロジェクトとその目に見えるセットアップの進行状況の両方が破棄されます。

## 完了結果

成功した接続セットアップは、リポジトリのデフォルトブランチに対して専用ブランチとプルリクエストを作成します。プルリクエストには生成されたローカライゼーションの基準が含まれ、 `L10N.md` コンテキストおよびローカリゼーション済みコンテンツをロードするために必要な最小限の実用的な変更。

セットアップはヘッダーだけのターゲットカタログを公開しません。ローカリゼーションフレームワークが翻訳前にターゲットカタログを要求する場合、カタログには抽出されたソースメッセージのエントリが含まれ、翻訳値は空のままです。ターゲットカタログがまだ不要な場合、セットアップは最初の翻訳実行のためにそれらを保持します。

Glossia はプルリクエストをマージしません。リポジトリの維持者は、通常の GitHub プロセスを通じてレビューおよびマージを行います。

プロジェクトの概要では、このプルリクエストが開いている間はセットアップの通知が表示されます。プルリクエストがマージされた後、通知は表示されなくなります。プルリクエストがマージされずに閉じられた場合、プロジェクトの概要はセットアップが完了とみなされるには再オープンされる必要があることを説明します。
