プロジェクト設定は、Glossia 用に接続されたリポジトリを準備します。ユーザーがリポジトリと少なくとも 1 つのターゲット言語を選択したの **新規プロジェクト** フロー。

## 前提条件

- アカウントには少なくとも 1 つの設定済みのモデルが必要です。
- Glossia GitHub App は選択されたリポジトリにアクセスできます。
- ユーザーはアカウント内でプロジェクトを作成できます。
- 少なくとも 1 つのターゲット言語が選択されています。

## ステータス

| ステータス | 説明 | 利用可能なアクション |
|---|---|---|
| **待機中** | プロジェクトは受け入れられ、開始を待っています。 | 進捗を確認するか、ページを離れて後で戻ってください。 |
| **実行中** | Glossia がリポジトリを検査および更新しています。 | ライブアクティビティを確認してください。 |
| **完了** | ローカライズ基準線が準備され、レビュー用に公開されました。 | プルリクエストを開き、レビューしてマージしてください。 |

プロジェクトはセットアップ中は暫定的です **保留中** または **実行中**. セットアップが完了できず、利用可能な変更を公開できない場合、Glossia はセットアップ環境をクリーンアップし、一時的なプロジェクトを削除します。その後、リポジトリは次の **新しいプロジェクト** のフローで、セットアップを再度試すことができます。

## 可視化された進捗状況

セットアップカードは、新プロジェクトフローおよびプロジェクト概要でも引き続き利用可能です。これには以下が含まれます:

- ステータスバッジと進捗バー。
- 現在の状態に関する短い説明。
- 最近のリポジトリの準備、点検、ファイル変更、チェック、および完了の活動。
- 設定が完了できない場合に提示される、明確な失敗メッセージ。

暫定的なプロジェクトが存在している間、進捗は保存されます。致命的な障害が発生すると、プロジェクトとその見えている設定の進捗が両方とも破棄されます。

## 完了結果

成功した接続済み設定では、専用のブランチとリポジトリのデフォルトブランチに対するプルリクエストが作成されます。プルリクエストには生成された翻訳基準が含まれ、これに `L10N.md` コンテキストと、ローカライズされたコンテンツを読み込むために必要な最小限の実用的な変更。

設定はヘッダーのみの対象カタログを公開しません。翻訳前に対象カタログが必要な翻訳フレームワークの場合、カタログには抽出されたソースメッセージエントリと空の翻訳値が含まれます。対象カタログはまだ不要な場合、設定はそれらを最初の翻訳実行のために残しておきます。

Glossia はプルリクエストをマージしません。リポジトリ管理者は通常の GitHub プロセスを通じて確認し、マージします。

このプルリクエストが開いている間、プロジェクト概要に設定通知が表示されます。プルリクエストがマージされたら通知は削除されます。プルリクエストがマージされずにクローズされた場合、概要は設定が完了とみなされる前に再オープンする必要があることを説明します。
