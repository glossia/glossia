プロジェクト設定では、Glossia 用の接続済みリポジトリが準備されます。ユーザーがリポジトリと少なくとも 1 つの目標言語を選択した後の **新しいプロジェクト** フロー。

## 前提条件

- アカウントには少なくとも 1 つの設定済みモデルが必要です。
- Glossia GitHub アプリは選択されたリポジトリにアクセスできます。
- アカウント内のユーザーはプロジェクトを作成できます。
- 少なくとも 1 つの目標言語が選択されています。

## ステート

| ステート | 意味 | 利用可能なアクション |
|---|---|---|
| **保留中** | プロジェクトは承認され、開始を待っています。 | 進捗を確認するか、ページを離れて後で戻ってください。 |
| **実行中** | Glossia がリポジトリを確認・更新しています。 | ライブアクティビティをご確認ください。 |
| **完了** | ローカリゼーションの基準がレビュー用に準備され公開されました。 | プルリクエストを開き、レビューし、マージしてください。 |

プロジェクトは、セットアップが の間、暫定的です **保留中** または **執行中**. セットアップが正常に完了せず、利用可能な変更を公開できない場合、Glossia はセットアップ環境をクリーンアップし、暫定的なプロジェクトを削除します。その後、リポジトリは次の **新しいプロジェクト** フローにてセットアップを再試行できます。

## 可視化された進捗状況

セットアップカードは、新プロジェクトフローとプロジェクトの概要画面で引き続き利用可能です。以下の項目が含まれます:

- ステータスバッジと進捗バー。
- 現在のステータスに関する簡潔な説明。
- 最近のリポジトリの準備、点検、ファイル変更のチェック、完了状況などの活動履歴。
- セットアップが完了できない場合の明確なエラーメッセージ。

仮プロジェクトが存在する間、進捗は保存されます。致命的なエラーが発生すると、プロジェクトとその表示されているセットアップの進捗の両方が破棄されます。

## 完了結果

正常なセットアップが完了すると、専用ブランチとリポジトリのデフォルトブランチに対するプルリクエストが作成されます。このプルリクエストには、生成されたローカライゼーションのベースラインが含まれており、 `L10N.md` コンテキスト、およびローカリゼーション済みのコンテンツをロードするために必要な最小限の変更

セットアップは、ヘッダーだけのターゲットカタログを公開しません。ローカライゼーションフレームワークが翻訳前にターゲットカタログを必要とする場合、カタログには、空の翻訳値を持つ抽出されたソースメッセージエントリが含まれます。ターゲットカタログがまだ不要な場合、セットアップはそれらを最初の翻訳実行のために残します。

Glossia はプルリクエストをマージしません。リポジトリの管理者が通常の GitHub プロセスを通じてレビューとマージを行います。

このプルリクエストが開いている間、プロジェクトの概要にはセットアップの通知が表示されます。マージされたら通知は削除されます。プルリクエストがマージされないままで閉じられた場合、概要では、セットアップが完了とみなされる前に再オープンする必要がありますと説明されます。
