プロジェクトのセットアップは、Glossia 用の接続されたリポジトリを準備します。ユーザーがリポジトリと少なくとも 1 つのターゲット言語を選択した後、その **新しいプロジェクト** フロー。

## 前提条件

- アカウントには少なくとも 1 つの設定済みのモデルがあります。
- Glossia GitHub アプリは選択されたリポジトリにアクセスできます。
- ユーザーはアカウント内でプロジェクトを作成できます。
- ターゲット言語が少なくとも 1 つ選択されています。

## ステータス

| ステータス | 説明 | 利用可能なアクション |
|---|---|---|
| **待機中** | プロジェクトは承認され、開始を待っています。 | 進捗を確認するか、ページを離れて後で戻ることができます。 |
| **進行中** | Glossia はリポジトリを検査し更新しています。 進行状況を確認してください。 |
| **完了** | ローカリゼーション基準がレビュー用として準備され公開されました。 プルリクエストを開き、レビューしマージしてください。 |

セットアップ中はプロジェクトが暫定的です **待機中** または **実行中**. セットアップが完了できない、または有効な変更を公開できない場合、Glossia はセットアップ環境をクリーンアップし、一時的なプロジェクトを削除します。その後、リポジトリは再度 **新規プロジェクト** のフローで、再度セットアップを試すことができます。

## 進捗状況

セットアップカードは、新規プロジェクトのフローとプロジェクトの概要画面で引き続き利用可能です。これには：

- 状態バッジと進捗バー。
- 現在の状態の簡単な説明。
- 最近のリポジトリの準備、確認、ファイル変更、チェック、および完了のアクティビティ。
- セットアップが完了できない場合に、明確な失敗メッセージが表示されます。

仮プロジェクトが存在している間は進捗が保存されます。致命的な失敗の場合は、プロジェクトと表示されているセットアップの進捗の両方が破棄されます。

## 完了結果

成功したセットアップは、専用ブランチを作成し、リポジトリのデフォルトブランチに対するプルリクエストを作成します。プルリクエストには、生成されたローカライズベースラインを含んでおり、 `L10N.md` コンテキスト情報と、ローカライズされたコンテンツを読み込むために必要な最小限の実用的な変更です。

セットアップはヘッダーのみを含むターゲットカタログを公開しません。ローカライズフレームワークが翻訳前にターゲットカタログを必要とする場合、カタログには抽出されたソースメッセージエントリが含まれ、翻訳値が空になります。ターゲットカタログがまだ必要ない場合、セットアップはそれらを最初の翻訳実行のために残します。

Glossia はプルリクエストをマージしません。リポジトリ維持担当者は、通常の GitHub プロセスを通じてレビューおよびマージを行います。

プルリクエストが開いている間は、プロジェクトの概要にセットアップの通知が表示されます。プルリクエストがマージされた後、この通知は削除されます。マージされずにプルリクエストが閉じられた場合、概要ではセットアップ完了とみなされる前に再開する必要があると説明されます。
