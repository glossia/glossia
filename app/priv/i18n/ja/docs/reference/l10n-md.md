`L10N.md` が、翻訳対象のファイル、翻訳ファイルが格納される場所、ターゲット言語、ならびに結果を導くべきコンテキストを Glossia に指定します。リポジトリには、ルートファイルとサブディレクトリにある追加のスコープ付きファイルを有することができます。

## 構造

各ファイルには 2 つの部項目があります：

1. [YAML はマークアップランゲージではない](https://yaml.org/) frontmatter は `---` マーカーの間にあります。
2. フロントマターの後、プロダクト、対象読者、トーン、またはドメインのコンテキストを含む Markdown。

```yaml
---
source_language: en
model: translation-default
sources:
  "docs/**/*.md": "docs/i18n/{locale}/{relpath}"
targets:
  - es
  - ja
validation:
  - ./scripts/validate-docs.sh
  - --strict
frontmatter: preserve
preserve:
  - placeholders
  - urls
---

Write for software developers. Keep product names and code samples unchanged.
```

プロバイダーの認証情報はアカウント設定に格納され、`L10N.md` には決して格納してはいけません。オプションの `model` 値はアカウントモデルハンドルです。

## フロントマターフィールド

| フィールド | 型 | 必須 | 説明 |
|---|---|---|---|
| `source_language` | 文字列 | なし | このスコープのソースロケール。デフォルトは `en`。 |
| `model` | 文字列 | なし | アカウントモデルハンドル。省略された場合はアカウントデフォルトを使用し、明示的なハンドルが存在しない場合はエラーを報告します。 |
| `sources` | マップまたはリスト | トップレベルの規則の場合 | ソースファイルパターン。マップ値は出力テンプレートを定義できます。 |
| `targets` | マップまたはリスト | ソースが設定されている場合 | ターゲットロケールコード。マップはロケールコードを言語名に関連付けることができます。 |
| `output` | 文字列 | ソースマッピングがない、または `target_path` が目的地を提供していない場合 | 出力ファイルテンプレート。 |
| `target_path` | 文字列 | ソースマッピングがない、または `output` が目的地を提供していない場合 | 翻訳ファイルのベースディレクトリテンプレート。 |
| `translate` | リスト | なし | 複数の翻訳規則。それぞれ独立したソースとオプションのオーバーライドを持ちます。 |
| `exclude` | リスト | なし | スキップするファイルパターン。 |
| `preserve` | リスト | なし | 変更せずに残す必要があるコンテンツの種類、例えばプレースホルダーまたは統一リソース識別子など。 |
| `frontmatter` | 文字列 | なし | `preserve` ではデフォルト、または `translate`. |
| `prompt` | 文字列 | なし | このスコープまたは規則の追加のガイダンス。 |
| `validation` | リスト | ビルトインアダプターを備えていないファイル拡張子の場合 | 引数を伴うバリデーションコマンド。このコマンドは候補を実際のターゲットパスで受け取り、ファイルが無効な場合はゼロ以外のステータスを返す必要があります。 |
| `check_cmd` | 文字列 | なし | 翻訳ワークフローで利用可能なチェックコマンド。 |
| `check_cmds` | マップ | なし | 翻訳ワークフローで利用可能な名前付きチェックコマンド。 |
| `retries` | 整数 | なし | チェックの失敗后的な再試行回数。デフォルトは `2`。 |
| `locale` | 文字列 | なし | ロケール固有のコンテキストファイルに付されたロケール。 |
| `glossary` | リストまたはマップ | なし | `L10N.md` では、用語集用語のリスト。`L10N/<locale>.md` では、各用語とその言語の翻訳へのマップです。ネストされたファイルは継承されたエントリに追加し、上書きします。[用語集参照](/docs/reference/glossary) を参照してください。 |

不明なフロントマターフィールドは無視されます。

## ファイル形式

Glossia は Markdown、JavaScript Object Notation、YAML Ain't Markup Language、ポータブルオブジェクト、およびプレーンテキストファイルに対してネイティブな処理を有しています。適用的な `L10N.md` が `validation` コマンドを宣言しない限り、他のファイル拡張子は計画に失敗します。これにより、プロプライエタリな構造化フォーマットを制約のないテキストとして静かに扱うことが回避されます。

Markdown ではプロースのみが翻訳されます：段落、見出し、リストアイテム、表セル、コンポーネントおよび HTML の `title`, `details`, `alt`, `label`, `description`, `summary`, `placeholder`, `aria-label`, および `caption` 属性、および HTML `<summary>` のテキスト。残りのバイト、つまりコード、リンク先、コンポーネント、アラート、および明示的な見出しアンカーはすべてソースと同じまま保持されます。[翻訳の復元](/docs/explanation/translation-recovery) を参照して、この仕組みをどのように機能しているか確認してください。

バリデーションコマンドは、候補が実際のターゲットパスに一時的に書き出された後に実行されます。リポジトリのネイティブパーサー、コンパイラー、またはビルドコマンドを呼び出します。Glossia は各バリデーション試行後に以前のターゲットを復元し、後でのみ許可された候補のみを書き込みます。

## ソースマッピング

最も明確な形式はすべてのソースパターンを出力テンプレートにマップします:

```yaml
sources:
  "docs/**/*.md": "docs/i18n/{locale}/{relpath}"
  "content/*.json": "content/{locale}/{basename}.{ext}"
```

ソースリストも有効ですが、`output` または `target_path` を用いて目的地を定義する必要がある:

```yaml
sources:
  - "docs/**/*.md"
target_path: "docs/i18n/{locale}"
```

## ターゲット言語

リストは各ロケールコードを言語識別子として使用します:

```yaml
targets:
  - es
  - ja
```

マップは読みやすい言語名を追加できます:

```yaml
targets:
  es: Spanish
  ja: Japanese
```

## 出力変数

| 変数 | 値 |
|---|---|
| `{locale}` または `{lang}` | ターゲットロケールコード。 |
| `{relpath}` | 一致したパターンに対するソースパス。 |
| `{basename}` | 拡張子を含まないソースファイル名。 |
| `{ext}` | 先頭のドットを含まないソースファイルの拡張子。 |

## 複数のルール

異なるコンテンツグループが異なる目的地またはチェックを必要とする場合に `translate` を使用します：

```yaml
---
source_language: en
targets:
  - es
translate:
  - sources:
      - "docs/**/*.md"
    output: "docs/i18n/{locale}/{relpath}"
  - source: "messages/*.json"
    output: "messages/{locale}/{basename}.{ext}"
---
```

ルール値は周囲のファイルから継承された値を上書きします。

## スコープコンテキスト

Glossia は `L10N.md` ファイルをリポジトリのルートからソースファイルに向かって読み取ります：

- 親設定はデフォルトを提供します。
- より深いファイルは、そのディレクトリのフィールドを上書きします。
- Markdown コンテキストは親から子へ蓄積されます。
- ロケール固有のガイダンスとロケール固有のモデルハンドルは `L10N/<locale>.md` に配置できます。

これにより、リポジトリはルートに広範なボイスガイダンスを維持しつつ、製品領域または言語固有のガイダンスを影響するコンテンツの近くに配置できます。
