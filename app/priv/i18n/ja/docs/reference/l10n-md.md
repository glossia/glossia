`L10N.md` は翻訳対象ファイル、翻訳後ファイルが配置される場所、ターゲット言語、および結果を導くコンテキストを Glossia に示します。リポジトリにはルートファイルとサブディレクトリ内の追加のスコープ付きファイルを持つことができます。

## 構造

各ファイルには 2 つの部分があります:

1. [YAML はマークアップ言語ではありません](https://yaml.org/) フロントマターの `---` マーカーの間にあります。
2. フロントマターの以下の Markdown は、製品、聴衆、トーン、またはドメインのコンテキストを含みます。

```yaml
---
source_language: en
model: translation-default
sources:
  "docs/**/*.md": "docs/i18n/{locale}/{relpath}"
targets:
  - es
  - ja
validation:
  - ./scripts/validate-docs.sh
  - --strict
frontmatter: preserve
preserve:
  - placeholders
  - urls
---

Write for software developers. Keep product names and code samples unchanged.
```

資格情報はアカウント設定に属し、決して `L10N.md` には属しません。オプションの `model` 値はアカウントモデルハンドルです。

## フロントマターのフィールド

| フィールド | タイプ | 必須 | 説明 |
|---|---|---|---|
| `source_language` | 文字列 | なし | このスコープのソースロケールです。デフォルトは `en` です。 |
| `model` | 文字列 | なし | アカウントモデルハンドルです。省略の場合はアカウントデフォルトを使用し、明示的なハンドルが存在しない場合はエラーを報告します。 |
| `sources` | マップまたはリスト | トップレベルの規則の場合 | ソースファイルパターンです。マップ値は出力テンプレートを定義できます。 |
| `targets` | マップまたはリスト | ソースが設定されている場合 | ターゲットロケールコードです。マップはロケールコードを言語名に関連付けることができます。 |
| `output` | 文字列 | ソースマッピングや `target_path` が宛先を指定しない場合 | 出力ファイルテンプレートです。 |
| `target_path` | 文字列 | ソースマッピングや `output` が宛先を指定しない場合 | 翻訳されたファイルの基本ディレクトリテンプレートです。 |
| `translate` | リスト | なし | 複数の翻訳規則をそれぞれ独自のソースとオプションのオーバーライドを含みます。 |
| `exclude` | リスト | なし | スキップするファイルパターン。 |
| `preserve` | リスト | なし | 変更せずに残す必要があるコンテンツの種類、プレースホルダーや統一リソースロケーターなど。 |
| `frontmatter` | 文字列 | なし | デフォルトでは `preserve` または `translate` です。 |
| `prompt` | 文字列 | なし | このスコープまたは規則のための追加ガイダンス。 |
| `validation` | リスト | 構築済みのアダプタがないファイル拡張子の場合 | 引数を伴う検証コマンドです。コマンドは候補を実際のターゲットパスで受け取り、ファイルが無効な場合はゼロ以外のステータスを返す必要があります。 |
| `check_cmd` | 文字列 | なし | 翻訳ワークフローで使用できるチェックコマンド。 |
| `check_cmds` | マップ | なし | 翻訳ワークフローで使用できる命名チェックコマンド。 |
| `retries` | 整数 | なし | 失敗したチェック後の再試行回数の数です。デフォルトは `2` です。 |
| `locale` | 文字列 | なし | ラオニカルコンテキストファイルに関連付けられるラオニラル。 |
| `glossary` | リストまたはマップ | なし | `L10N.md` には用語のリストがあります。`L10N/<locale>.md` には各用語とその言語の翻訳のマップがあります。ネストされたファイルは継承されたエントリを追加し、上書きします。[用語集参照](/docs/reference/glossary) を参照してください。 |

不明なフロントマターのフィールドは無視されます。

## ファイルフォーマット

Glossia には Markdown、JavaScript Object Notation、YAML Ain't Markup Language、ポータブルオブジェクト、およびプレーンテキストファイルの組み込み処理があります。`L10N.md` で `validation` コマンドを宣言しない限り、他のファイル拡張子は計画に失敗します。これにより、専有構造フォーマットを非制約テキストとして沈黙で扱うことを避けます。

マークダウンでは、プロースのみが翻訳されます：パラグラフ、見出し、リストアイテム、テーブルセル、およびコンポーネントと HTML の `title`、`details`、`alt`、`label`、`description`、`summary`、`placeholder`、`aria-label`、および `caption` 属性、および HTML `<summary>` のテキスト。すべてコード、リンク宛先、コンポーネント、アラート、および明示的な見出しアンカーを含む他のバイトも、ソースと同じように保持されます。[翻訳の回復](/docs/explanation/translation-recovery) でこの仕組みについてご覧ください。

検証コマンドは、候補をPontin トマネに実際のターゲットパスに書き込む後に実行されます。レポジトリのネイティブ解析器、コンパイラ、またはビルドコマンドを呼び出すことができます。Glossia は検証試みのたびに以前のターゲットを復元し、その後にはじめて受け入れられた候補のみを書きます。

## ソースマッピング

最も明確な形式はソースパターンを出力テンプレートにマップします：

```yaml
sources:
  "docs/**/*.md": "docs/i18n/{locale}/{relpath}"
  "content/*.json": "content/{locale}/{basename}.{ext}"
```

ソースリストも有効ですが、宛先を定義するには `output` または `target_path` が必要です：

```yaml
sources:
  - "docs/**/*.md"
target_path: "docs/i18n/{locale}"
```

## ターゲット言語

リストは各ロケールコードを言語識別子として使用します：

```yaml
targets:
  - es
  - ja
```

マップは読める言語名を追加できます：

```yaml
targets:
  es: Spanish
  ja: Japanese
```

## 出力変数

| 変数 | 値 |
|---|---|
| `{locale}` または `{lang}` | ターゲットロケールコード。 |
| `{relpath}` | 一致パターンの相対のソースパス。 |
| `{basename}` | 拡張子のないソースファイル名。 |
| `{ext}` | 先頭ドットを除くソースファイルの拡張子。 |

## 複数のルール

異なる内容グループが別の宛先またはチェックを必要とする場合は、`translate` を使用します：

```yaml
---
source_language: en
targets:
  - es
translate:
  - sources:
      - "docs/**/*.md"
    output: "docs/i18n/{locale}/{relpath}"
  - source: "messages/*.json"
    output: "messages/{locale}/{basename}.{ext}"
---
```

ルールの値は周囲のファイルから継承された値を上書きします。

## スコープ付きコンテキスト

Glossia はリポジトリのルートからソースファイルに向かって `L10N.md` ファイルを読み込みます：

- 親設定はデフォルト値を提供します。
- より深いファイルは、ディレクトリのフィールドを上書きします。
- マークダウンのコンテキストは親から子に累積されます。
- ロケール固有のガイダンスとロケール固有のモデルハンドルは、`L10N/<locale>.md` に格納できます。

これにより、リポジトリはルートに広範なボイスガイダンスを維持しつつ、影響するコンテンツに近い場所に製品領域または言語固有のガイダンスを配置できます。
