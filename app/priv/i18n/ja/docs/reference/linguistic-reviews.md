## エスカレーション

設定された決定モデルの作成された翻訳セッションは、欠落したソースの意味またはドメインコンテキスト、矛盾するガイダンス、または結果を招く文化的適応のために言語的入力を実行できます。低い自信だけでは質問はありません。既存のコンテキストから修正可能なエラーは通常の修正予算を使用します。予算の使用後に残る品質の失敗も入力実行が可能です。決定モデルがない場合、自動的な言語的エスカレーションは無効化されます。

影響を受けるファイル/ローカルのみ停止します。承認されていない候補は公開されません。独立したファイルは完了し、通常通り公開できます。公開が完了した後、セッションは `awaiting_input` となりランナーを解放します。人間が回答している間はワーカを消費しません。

各エスカレーションは翻訳セッションにリンクされた、定義された言語的ゴールを備えた 1 つの**共有トキ会話を定義する会話**を開きます。参加者は意味を話し合い、フォローアップの質問をし、提案された決定を洗練させます。議論だけで翻訳を承認したりリポジトリのコンテキストを書き込んだりは決してありません。通常のトキ会話は管理者を含む所有者にのみプライベートで留まります。

標的のローカルの宣言された熟練言語に対応する現在承認されたチームメート全員は同様の会話に招待されます。熟練度はディスプレイ言語とは別のものであり、プロジェクトへのアクセスや決定を承認する権限を与えません。広範な言語は`es`のように地域バリアント`es-MX`のように一致します。互換性のない明示的なスクリプトは一致しません。地域宣言`zh-TW`は習わし CLDR スクリプトを使用し、広範な`zh`はスクリプトに関わらず制限を受けません。

適格な参加者はオプトインした場合のみ汎用モバイルプッシュ通知を受信します。配信は現在の熟練度、メンバーシップ、プロジェクトアクセス、および開かれたゴールを再確認します。通知は共有会話を開きます。会話と承認はネイティブアプリとウェブダッシュボードの両方から利用できます。プロバイダー設定と配信ポリシーについては、[ネイティブプッシュ通知](/docs/reference/native-push-notifications)を確認してください。

## 熟練言語プロフィール

`GET /api/me` は `user.fluent_languages` を含みます。`PUT /api/me/fluent-languages` は `user:write` を必要とし、`{"fluent_languages": ["es", "ar", "zh-Hant"]}` のみを受け入れます。認証済みユーザーのリストを置き換え、プロフィールエンベロープを返します。サポート対象の CLDR BCP47 タグは明示的な地域/スクリプトの特定性を維持し、カンボジア表記を使用します。重複は collapses。空の配列は熟練をクリアします。無効なタグ、関連のないフィールド、または 50 件以上の提出エントリーは 422 を返します。これ universally は UI ローカを一切変更しません。

## レビュー API

`GET /api/:handle/projects/:project/translations/:id/reviews` は`translation:read` とプロジェクトアクセスを必要とし、プロジェクトアクセスである必要があります。`{"reviews": [...]}` を返し、開かれた質問最初、次に最も古い順で制限され 500 エントリです。回答した後、刷新して残りの質問を明らかにします。回答した履歴は決して制限の後ろに開かれた質問を隠しません。

各レビューには`id`、`translation_session_id`、`conversation_id`、`participants`（`id` および空可能性`name`）、`status`、`source_path`、`output_path`、`locale`、`question`、`source_excerpt`、`translation_excerpt`、`answer`、`guidance`、`context_path`、`resolution_message_id`、`resumed_session_id`、および `inserted_at` が含まれています。ステータスは `open`、`answered`、または `stale` です。

`answered_by` は決定を承認した人間を `{"id": "<user UUID>", "name": "<current display name>"}` として識別し；`name` は null で可能です。フィールドは承認前または承認者が利用できない場合に null です。これはメールアドレスや他のプライベートプロフィールフィールドを含んでおらず、承認の再生は承認者を変えません。同じフィールドは共有トキ会話 のネスト`linguistic_review`にも含まれs。承認時刻は露出しません；`inserted_at` はレビューの作成時刻であり、承認時刻ではありません。

既存のプロジェクト トキ会話とメッセージエンドポイントを使用して議論します。共有ゴール会話はレームョーアクターのプライベート会話と並んでトキ履歴に表示されます。共有履歴には最新のトキ読み/書きポリシー許可と翻訳読みアクセスが必要です。通常履歴は所有者のみで留まります。人間のメッセージは著者身元を含み、返信には`status` と`reply_to_id`が含まれます。ロジキはバウンデッドソース/候補系抜粋とゴールを受け取り、リPOSITORY 書き込みアクセスは受け取りません。

`POST /api/:handle/projects/:project/translations/:id/reviews/:review_id/answer` は両方の`translation:read` と`translation:write`を、さらにプロジェクトアクセスを要求します：

```json
{
  "resolution_message_id": "019a1c6d-4321-7000-8000-123456789abc",
  "answer": "Branch means a source-control release branch.",
  "guidance": "Use the source-control meaning of branch in release documentation.",
  "context_scope": "locale"
}
```

`resolution_message_id` は、目標会話の最新の完了したアシスタント**返信**を特定する必要があり、最初の質問ではありません。`answer` は人間が承認した決定であり、必須かつ空白ではありません。`guidance` と`context_scope` はオプションです。スコープのデフォルトは`locale` で、`project` も可能です。回答とガイダンスはそれぞれ最大 8,000 文字および 32,000 バイトの UTF-8 を対応します。ガイダンスには Glossia の予約済みのレビューマーカーコメントを含んではなりません。サーバーがリポジトリパスを選択します。クライアントから提供されたパスは使用されません。

成功する応答は`{"review": {...}}`です。同じ決定、解決メッセージ、ガイダンス、およびスコープの再生は冪等です。忙しい会話は`409 conversation_busy`を返します；新しいメッセージまたは無効な解決参照は`409 resolution_outdated`を返します。承認する前に現在のディスカッションをリロードしてレビューします。解決されたゴール上の異なる決定は`409 already_answered`；キャンセルまたは代替されたゴールの承認は`409 stale`。無効なテキストまたは利用可能なスコープは 422 を返します。欠落および外国プロジェクトの ID は 404 を返します。通常の認証とプロジェクト承認はすべてのリクエスト、再生を含む適用されます。閉じたゴールは`409 goal_closed`で新しいディスカッションメッセージを却下します。

## 継続および陳腐なコンテキスト

独立したワークがまだ進行している間に決定は承認できます。それらがその後決して 2 番目のランナーを開始しません。ランナーが解放され、そのランのすべてのゴールが解決されると、Glossia は原子で 1 つの継続セッションをキューに入れます。`resumed_session_id` はそれを識別し；オリジナルセッションは歴史的`awaiting_input`に留まります。ロジキおよびネイティブ会話はどちらも継続にリンクします。

継続は新しい実行身元を持ち、翻訳公開ブランチと検証済み出力を維持します。各回答は同一のソースと解決された翻訳コンテキストフィンガープリントのみ適用されます。変更されたソース、音声、辞書、モデル、またはリポジトリ指示は回答を再利用しません。新しいデフォルトブランチコミットは待機セッションを優先し、開かれた質問を陳腐化します。キャンセルも開かれた質問を陳腐化します。

## 再利用可能なリポジトリガイダンス

再利用可能なガイダンスは、別の明確な人間の編集です。回答だけではリポジトリコンテキストにはなりません、またプライベートなチャット履歴は決して自動的にコピーされません。

`locale` は有効なローカライズオーバーレイ、すなわち `L10N/es.md` をターゲットとし；`project` は有効な`L10N.md` をターゲットとします。既有着ساتコンテキストファイルは尊重されます。欠落しているローカライズオーバーレイにはそのローカライズフロントマターが付与されます。既存のフロントマターと本文は保存され、各決定にはそのレビュー UUID が追記され、用途と冪等性を確保します。

ガイダンスは通常の翻訳プルリクエスト案に提案され、デフォルトブランチに無言で書き込まれることはありません。リポジトリは依然として記録されたコンテキストダイジェストと一致する必要があります；矛盾する編集はこれを上書きする代わりに公開を失敗させます。パスは透過またはシンボリックリンクのないリポジトリ相対のローカライズドキュメントである必要があります。各コンテキストドキュメントは 1 MiB に制限されます。プルリクエストのマージはガイダンスを将来の走査用の通常のバージョン管理されたローカライズコンテキストにします。
