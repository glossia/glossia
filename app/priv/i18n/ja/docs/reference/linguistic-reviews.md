## Escalation

倉庫翻訳実行が構成された意思決定モデルは、欠落したソースの意味やドメインコンテキスト、矛盾するガイダンス、またはそれによる文化的適応のために言語的入力をリクエストできます。低い巡視だけでは質問をトリガーしません。既存のコンテキストから修正可能なエラーは通常の修正予算を使用します。その予算後に残る品質の失敗は、入力もリクエストできます。意思決定モデルがない場合、自動的な言語的エスカレーションは無効化されます。

影響を受けたファイルまたはロケールのみが停止します。未承認の候補は公開されません。独立したファイルは完了し、通常の通り公開できます。公開完了後、セッションは`awaiting_input`となり、ランナーは解放されます。人間が回答している間は、ワーカーを消費しません。

各エスカレーションは、翻訳セッションにリンクされた 1 つの**定義された言語的目標を持つ共有トキ会話**を開きます。参加者は意味を議論し、フォローアップ質問を行い、提案された意思決定を改善します。議論自体は翻訳を承認またはリポジトリコンテキストを書くことには決してなりません。通常のトキ会話は、管理者を含めて、所有者にプライベートのままです。

宣言されたフレエント言語がターゲットロケールと一致するすべての現在承認されたチームメンバーが、同じ会話に招待されます。流暢さは表示言語とは独立しており、プロジェクトへのアクセスや意思決定の承認権限を付与しません。広い言語である`es`は、地域バリエーションである`es-MX`とも一致しますが、互換性が欠落する明示的なスクリプトは一致しません。地域宣言である`zh-TW`は、その慣用的な CLDR スクリプトを使用しますが、広い`zh`はスクリプトに制限されません。

対象の参加者は、オプトインした場合のみ一般的モバイルプッシュ通知を受け取ります。配信は現在の流暢さ、会員資格、プロジェクトアクセス、およびオープンしたゴールを再チェックします。通知は共有会話を開きます。会話と承認はネイティブアプリと Web ダッシュボードの両方から利用可能です。プロバイダ設定と配信ポリシーについては[ネイティブプッシュ通知](/docs/reference/native-push-notifications)を参照してください。

## フレエント言語プロフィール

`GET /api/me` に`user.fluent_languages` を含みます。 `PUT /api/me/fluent-languages` は`user:write` を要求し、`{"fluent_languages": ["es", "ar", "zh-Hant"]}` のみを受け入れます。認証されたユーザーのリストを置き換え、プロフィールエンベロープを返します。サポートされた CLDR BCP47 タグは明示的な地域/スクリプト特性を保ち、正規の大文字文字列を使用します。重複は結合されます。空の配列は流暢さをクリアします。無効なタグ、関連性のないフィールド、または提出された書式が 50 件以上の入力は 422 が返されます。これは UI のロケールを決して変更しません。

## レビュー API

`GET /api/:handle/projects/:project/translations/:id/reviews` は `translation:read` とプロジェクトへのアクセスが必要です。返されるのは `{"reviews": [...]}` で、最初に見えるのは開いている問い合わせ、次に古い問い合わせです（最大 500 項目）。回答後に再読み込みを行い、残りの問い合わせを表示します。回答済の履歴に開いている問い合わせが制限によって隠されることはありません。

各レビューには`id`、`translation_session_id`、`conversation_id`、`participants`（`id` とオプション`name`）、`status`、`source_path`、`output_path`、`locale`、`question`、制限された`source_excerpt` と`translation_excerpt`、`answer`、`guidance`、`context_path`、`resolution_message_id`、`resumed_session_id`、および`inserted_at` が含まれます。ステータスは`open`、`answered`、または`stale` です。

既存のプロジェクト トキ会話とメッセージエンドポイントを使用して議論してください。共有目標の会話は、アクターのプライベート会話をトーキ履歴の中で並べて表示されます。共有履歴には現在のあるトキ読み書きポリシー許可と翻訳読み取りアクセスが必要です；通常の履歴は所有者専用です。人間メッセージには著者アイデンティティが含まれ、返信には`status` と`reply_to_id` が含まれます。トキには制限されたソース/候補切り抜きとゴールは渡され、リポジトリ書き込みアクセスは渡されません。

`POST /api/:handle/projects/:project/translations/:id/reviews/:review_id/answer` は`translation:read` と`translation:write`、およびプロジェクトアクセスが必要です：

```json
{
  "resolution_message_id": "019a1c6d-4321-7000-8000-123456789abc",
  "answer": "Branch means a source-control release branch.",
  "guidance": "Use the source-control meaning of branch in release documentation.",
  "context_scope": "locale"
}
```

`resolution_message_id` は、この最後の完了したアシスタント**回答**を特定し、それらの開いた質問がそれを始めるわけではありません。`answer` は人間が承認した意思決定であり、必須であり、空白ではありません。`guidance` と`context_scope` はオプションです；スコープは`locale` にデフォルトされ、また`project` にもなります。回答とガイダンスはそれぞれ文字 8,000、UTF-8 バイト 32,000 まで許可されます。ガイダンスには Glossia の予約済レビューマーカーコメントを含めることはできません。サーバーがリポジトリパスを選択し、クライアントが提供したパスは決して使用されません。

成功した返答は `{"review": {...}}` です。同じ決定、解決メッセージ、ガイダンス、スコープを再送すると、冪等です。忙しい会話は `409 conversation_busy` を返します。新しいメッセージか無効な解決参照は `409 resolution_outdated` を返します。承認前に、現在の対話を再読み込みして確認してください。解決された目標に基づく別の決定は `409 already_answered` を返します。キャンセルまたは上書きされた目標の承認は `409 stale` を返します。無効なテキストか利用可能なスコープがない場合は 422 を返します。欠落しているまたは外部プロジェクトの ID は 404 を返します。通常の認証とプロジェクト認可は、すべてのリクエスト、再送を含むたびに適用されます。閉じた目標は、新しい議論メッセージを受け付けるのを `409 goal_closed` で拒否します。

## 継続と陳腐化コンテキスト

意思決定は、独立した処理がまだ実行中の間に承認できます。それらはこれにより二度目のランナーを開始しません。ランナーが解放され、その実行のどのようなゴールも解決された後、Glossia は 1 つの継続セッションを原子的にキューにします。`resumed_session_id` はそれを特定します；元のセッションは過去の`awaiting_input` として残ります。両方のダッシュボードとネイティブ会話は継続にリンクします。

継続は新しい実行アイデンティティを持っており、翻訳公開ブランチと検証された出力を維持します。各回答は、同一のソースと解決された翻訳コンテキストフィンガープリントにのみ適用されます。変更されたソース、ボイス、辞書、モデル、またはリポジトリ指令は回答の再利用を防ぎます。新しいデフォルトブランチコミットは待ち受けるセッションを上書きし、開いている質問を陳腐化します。キャンセルも開いている質問を陳腐化します。

## 再利用可能なリポジトリガイダンス

再利用可能なガイダンスは、別の明確な人間編集です。回答だけではリポジトリコンテキストにはならない、およびプライベートチャットトランスクリプトは決して自動的にコピーされません。

`locale` は、適用可能なロケールオーバーレイ、例えば`L10N/es.md` に適用されます；`project` は、適用可能な`L10N.md` に適用されます。既存スコープコンテキストファイルは尊重されます。欠落したロケールオーバーレイは、ロケール Frontmatter を受け取ります。既存 Frontmatter an 本文は保持され、各意思決定は検証および冪等のためにレビュー UUID を追記されます。

ガイダンスは通常の翻訳プルリクエストに提案され、デフォルトブランチに静かに書き込まれることはありません。リポジトリは記録されたコンテキストダイジェストと一致していなければなりません。矛盾する編集は、それを上書きするのではなく公開が失敗します。パスは、リポジトリ相対のローカリゼーションドキュメントであり、トラバーサルやシンボリックリンクを含んではなりません。各コンテキストドキュメントは 1 MiB に制限されます。プルリクエストのマージにより、ガイダンスは今後の実行のための通常のバージョン管理されたローカリゼーションコンテキストとなります。
