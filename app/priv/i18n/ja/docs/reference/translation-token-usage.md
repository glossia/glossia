## ダッシュボード

開く **設定 → モデル → トークン使用量** 生成翻訳のプロバイダー報告の使用量を確認するには、モデル設定の読み取り権限が必要です。

ダッシュボードは、UTC を基準として、今日を含む過去 7 日、30 日、または 90 日間のカレンダー期間をサポートします。合計、日次チャート、および内訳に対し、モデル、プロジェクト、および言語フィルターが適用されます。検索は内訳行のみを対象とします。選択された期間、次元、フィルター、検索、ソート、およびページは URL に保持されます。

## メトリクス

| メトリック | 意味 |
| --- | --- |
| 入力トークン | プロバイダーが処理する入力。報告されたキャッシュ読取およびキャッシュ書き込みを含む。 |
| 出力トークン | プロバイダーから報告される出力。プロバイダーが出力カウントに含める場合、推論も含まれる。 |
| キャッシュ入力トークン | キャッシュ読取。入力トークンの一部であり、合計への追加請求ではありません。 |
| 合計トークン | 入力トークンと出力トークンの合計。 |
| レスポンス | 入力・出力のカウントと正のトークン合計を有するレスポンス。ゼロ化された欠落した使用量のフォールバックは無視されます。 |

トークン数は金銭的なコストではありません。プロバイダーは入力、出力、キャッシュ入力、およびキャッシュ書き込みに対して異なる料率を適用できる場合があります。

報告された各レスポンスはカウントされます。バリデーションリトライ、品質修正リトライ、および出力制限に達して却下されたレスポンスを含みます。スキップされたファイルとモデルを呼び出さないチェックポイントヒットは使用量を加えません。使用量のない失敗リクエストはカウントされません。

## 次元

- **プロジェクト** プロジェクトごとの使用状況をグループ化します。プロジェクトフィルタを使用して、すべてのメトリクスを単一のプロジェクトに限定できます。
- **言語** ターゲットロケールごとにグループ化、例えば `es` または `ja`、現在の範囲内のプロジェクト間で。
- **ファイル** ソースパスとプロジェクトごとにグループ化します。複数の言語に翻訳された同一ソースファイルは 1 つとして表示され、異なるプロジェクトの同名ファイルは別々に扱われます。

**未割り当て** プロジェクトまたはソースパスメタデータがないリクエストは表示されます。リポジトリ翻訳では両方が自動的に提供されます。単一コンテンツの API リクエストでは `project_id` また `source_path` 出典情報のため; 認証済みアカウント外のプロジェクト ID は未割り当てとして扱われます。無効または大きすぎるオプションメタデータは、トークン数を破棄せずに未割り当てとなります。

## 被覆

利用状況は、ReqLLM API キーおよび OAuth レスポンス、Together 生成、およびローカル Codex ターンの完了から収集されます。プロバイダ報告数のみ保持されます。ローカル Pi セッションおよび判断モデルの評価は含まれません。歴史的な翻訳は埋め戻しまたは見積もられません。したがって、合計は記録された利用状況を記述するだけであり、完全なプロバイダ請求書ではありません。

台帳は、アカウント、プロジェクト、モデル識別子およびハンドル、ターゲットローカル、ソースパス、数、およびタイムスタンプを保存します。プロンプト、翻訳コンテンツ、認証情報、または生プロバイダレスポンスは保存しません。利用記録の失敗は、翻訳を中断することなくログに記録されます。
