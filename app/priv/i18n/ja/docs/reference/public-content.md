Glossia は、アカウントおよびプロジェクトのアプリケーション画面とは別に、公開されたウェブサイトのコンテンツを提供します。

## 表現形式

| インターフェース | 動作 |
|---|---|
| 公開された HTML URL | ブラウザの表現形式は、規範的なメタデータを含み、Markdown の代替 `Link` レスポンスヘッダーを有します。 |
| その URL における `Accept: text/markdown` | 明示的なメディアタイプに品質があり、`text/html` より低優先ではなく Markdown 表現形式となります。 |
| 拡張子を`.md` を追加した ページ URL | ブラウザの言語設定に依存しない、明示的な Markdown 表現形式。 |
| `/index.md` | トップページの Markdown 概要。 |
| `/docs.md`, `/blog.md`, `/features.md` | 公開コンテンツの Markdown インデックス。 |
| `/changelog.md` | 一つの Markdown ドキュメントにまとめられた公開された変更ログエントリ。 |
| `/terms.md`, `/privacy.md`, `/cookies.md` | 最新公開された法的文書。日付のある法的 URL も`.md` をサポートしています。 |

単なる`*/*` は Markdown に登録できません。HTML レスポンスと Markdown レスポンスは`Vary: Accept` を共有するため、キャッシュは表現を混在させません。

個別のドキュメント、ブログ、機能、および法的コンテンツは、レンダリングされた HTML の変換ではなく、作成された Markdown を使用します。インデックスページは公開された在庫から生成され、トップページには厳選された Markdown 概要があります。インタラクティブな REST 参照は、ブラウザ専用 API ウィジェットを組み込むのではなく、読者を OpenAPI 仕様へ誘導します。

## 言語設定

英語はプレフィックスを付けません。翻訳されたマーケティング URL は文字通りのプレフィックスを使用します：`/de`、`/es`、`/fr`、`/ja`、`/ko`、`/pt-br`、および`/zh-hans`。例えば、公開されている`/es/docs/tutorials/getting-started.md` はスペイン語版を表示します。

URL は Markdown コンテンツの言語を選択します。`Accept-Language` は Markdown リクエストをリダイレクトしません。コンテンツ翻訳が存在しない場合は英語ソースにフォールバックします。トップページの概要は現在英語で作成されています。

## ディスカバリー

- `/robots.txt` はスクレイピングをデフォルトで禁止し、有限公開の HTML および Markdown 在庫、ローカライズされたフィード、`/assets/`、`/fonts/`、および`/images/` 下にあるレンダリングアセット、ファビコン、および`/og/marketing/` 下にある公開マーケティングプレビューを許可します。`/og/app/` 下にあるアカウントプレビュー画像は依然禁止されています。これは協力的なクローラーのためのガイダンスであり、認証メカニズムではありません。
- `/sitemap.xml` は規範的な公開 HTML コンテンツでローカルの交替を示します。変更ログフラグメントは独立した URL ではありません。
- `/llms.txt` は Glossia を紹介し、公開ドキュメント、機能ガイド、および最新の執筆（明示的な Markdown リンクを含む）へのリンクを提供します。
- `/llms-full.txt` はトップページの概要と完全なドキュメント在庫を、Markdown を含む一つのテキストドキュメントとしてエクスポートします。

認証、アカウントダッシュボード、API、およびその他のアプリケーション応答は`noindex, nofollow` とマークされます。公開された成功したコンテンツは`index, follow` とマークされ、エラーは非インデックス化されます。発見テキストファイル（`/robots.txt`、`/llms.txt`、および`/llms-full.txt`）は`noindex, follow` を使用します：読者はこれらを取得しリンクに従うことができますが、検索エンジンは正規のページを重複したドキュメントダンプの代わりにインデックスすべきです。

## キャッシュおよびリソース使用

Markdown およびテキスト発見応答には以下が含まれます：

| ヘッダー | 値または意味 |
|---|---|
| `Content-Type` | `text/markdown; charset=utf-8`、または発見テキスト用の`text/plain; charset=utf-8`。 |
| `Cache-Control` | `public, max-age=300, stale-while-revalidate=60`. |
| `ETag` | 表現の引用された SHA-256 ダイジェスト。 |
| `X-Markdown-Tokens` | 文字数を 4 で割って上丸めした概算値；モデル固有のトークナイザー数ではありません。 |

`If-None-Match` は強力なまたは弱い検証者の整合、複数の検証者、および`*` の整合をサポートします。整合は本体なしで`304` を返します。`HEAD` は全体ヘッダレスで表現ヘッダーを返します。

公開 Markdown 在庫はリリースにコンパイルされます。リクエストはコンテンツ翻訳を実行せず、ソースファイルを読み取らず、認証済みアカウントを読み込まず、LiveView をレンダリングしません。これら公開表現にアクセスするために User-Agent の偽装は必要ありません。

## 運用境界

Markdown ネゴシエーションはアカウントまたはプロジェクトダッシュボードへのアクセスを提供しません。既存のアカウント閲覧レート制限および Turnstile チェックは別個の保護手段として存続します。

プロダクションエッジレート制限は`GET` および`HEAD` の両方に適用されます。検証済みクローラーは依然レート制限されます。超過リクエストはブラウザによる確認ではなく、レート制限応答を受けます。読者は速度を落とし、後でリトライすべきです。共有キャッシュと条件付リクエストはクライアントをレート制限から免除しません。

リポジトリ内のクローラーポリシー変更は、アプリケーションおよび関連インフラ構成がデプロイされるまで効力を発揮しません。
