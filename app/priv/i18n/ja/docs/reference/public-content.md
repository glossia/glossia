Glossia は、アカウントおよびプロジェクトのアプリケーション surface とは別に、公開されたウェブサイトコンテンツを公開します。

## 表現形式

| インターフェース | 動作 |
|---|---|
| 公開された HTML URL | ブラウザ向けの表現、正典メタデータ、および Markdown 代替 `Link` レスポンズヘッダーを備える。 |
| その URL における `Accept: text/markdown` | 明示的なメディアタイプが正の品質を持ち、かつ `text/html` より劣っていない場合に Markdown 表現。 |
| `.md` が追加されたページ URL | ブラウザの言語設定に依存しない、明示的な Markdown 表現。 |
| `/index.md` | ホームページの Markdown 概要。 |
| `/docs.md`, `/blog.md`, `/features.md` | 公開済みコンテンツの Markdown インデックス。 |
| `/changelog.md` | 一つの Markdown ドキュメントにまとまった公開済み変更ログエントリ。 |
| `/terms.md`, `/privacy.md`, `/cookies.md` | 最新の公開された法的ドキュメント。日付付きの法的 URL も `.md` に対応します。 |

`*/*` だけでは Markdown にはなりません。HTML レスポンスと Markdown レスポンスは `Vary: Accept` を共有するため、キャッシュは表現を混同しませんが。

個別のドキュメント、ブログ、機能、および法律コンテンツは、レンダリングされた HTML の変換ではなく、作成された Markdown を使用します。インデックスページは公開されたインベントリから生成され、ホームページには厳選された Markdown 概要があります。インタラクティブな REST 参照は、ブラウザ専用 API ウィジェットを埋め込むのではなく、OpenAPI 規格に読者を誘導します。

## ロケール

英語はプレフィックスなしです。翻訳されたマーケティング URL は文字通りのプレフィックスを使用：`/de`, `/es`, `/fr`, `/ja`, `/ko`, `/pt-br`, および `/zh-hans`。例えば、`/es/docs/tutorials/getting-started.md` が公開された際にはスペイン語版を担当します。

URL は Markdown コンテンツの言語を選択します。`Accept-Language` は Markdown リクエストをリダイレクトしません。コンテンツ翻訳が欠落している場合、英語のソースにフォールバックします。ホームページの概要は現在英語で執筆されています。

## 発見

- `/robots.txt` はデフォルトで Crawling を禁止し、有限の公開 HTML および Markdown インベントリ、ローカイズドフィード、`/assets/`, `/fonts/`, および `/images/` 下のレンダリングアセット、ファビコン、`/og/marketing/` 下の公開マーケティングプレビューを有効にします。`/og/app/` 下のアカウントプレビュー画像は引き続き禁止されています。これは協調的な Crawlers へのガイドラインであり、認証メカニズムではありません。
- `/sitemap.xml` はロケール代替を含む正典公開コンテンツをリストします。Markdown 専用ページの Markdown URL お Дерائن。変更ログフラグメントは別の URL ではありません。
- `/llms.txt` は Glossia を紹介し、公開ドキュメント、機能ガイド、および最近の執筆（明確な Markdown リンクを含む）へのリンクを提供します。
- `/llms-full.txt` は、ホームページ概要、ドキュメント、および Markdown 専用比較コンテンツを Markdown を含む単一テキストドキュメントにエクスポートします。

比較コンテンツは Markdown 専用で公開されています。これは HTML ドキュメント、ナビゲーション、検索、およびドキュメントインデックスから除外されますが、エージェントは `/llms.txt` と sitemap を介してそれを発見できます。正典 URL は `.md` で終わります。元の HTML URL も `Accept: text/markdown` に応答しますが、現在はブラウザページをレンダリングしません。

認証、アカウントダッシュボード、API および他のアプリケーションレスポンスは `noindex, nofollow` でマークされています。公開された成功コンテンツは `index, follow` でマークされており、エラーはインデックス対象外です。発見テキストファイル (`/robots.txt`, `/llms.txt`, および `/llms-full.txt`) は `noindex, follow` を使用します：読者はそれらをフェッチしリンクを追跡できますが、検索エンジンは重複ドキュメントダンプではなく正典ページをインデックスするべきです。

## キャッシュとリソース使用

Markdown およびテキスト発見レスポンスには次のものがあります：

| ヘッダー | 値または意味 |
|---|---|
| `Content-Type` | `text/markdown; charset=utf-8` または発見用テキストの場合は `text/plain; charset=utf-8` |
| `Cache-Control` | `public, max-age=300, stale-while-revalidate=60`. |
| `ETag` | 表現の引用 SHA-256 ダイジェスト |
| `X-Markdown-Tokens` | 文字数を 4 で割った概算、丸め上げ；モデル固有のトークナイザー数ではありません。 |

`If-None-Match` は強力または弱いバリデーターとのマッチ、複数のバリデーター、および `*` をサポートします。一致はボディなしで `304` を返します。`HEAD` はボディなしで表現ヘッダーを返します。

公開 Markdown インベントリはリリースにコンパイルされます。リクエストはコンテンツ翻訳、ソースファイルの読み取り、認証済みアカウントの読み込み、または LiveView のレンダリングを実行しません。これらの公開表現にアクセスするにはユーザーエージェントの偽装は不要です。

## 運用境界

Markdown 協議はアカウントまたはプロジェクトダッシュボードへのアクセスを提供しません。既存のアカウント閲覧レートリミットおよび Turnstile チェックは別の保護手段として維持されます。

プロダクションエッジレートリミットは `GET` および `HEAD` 両方にも適用されます。検証済み Crawlers は引き続きレートリミット対象です。超過リクエストはブラウザチャレンジではなくレートリミットレスポンスを受けます。読者は遅速して、後で再試行する必要があります。共有キャッシュおよび条件付きリクエストはクライアントをレートリミットから除外しません。

リポジトリ内の Crawler ポリシー変更は、アプリケーションおよび関連インフラ構成の展開後のみ効力を発します。
