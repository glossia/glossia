Glossia は、アカウントとプロジェクトのアプリケーション UI とは別に、公開されたウェブサイトコンテンツを公開します。

## 表現形式

| インターフェース | 振る舞い |
|---|---|
| 公開済みの HTML URL | 標準メタデータと Markdown 代替`Link`レスポンスヘッダーを含むブラウザ表示形式。 |
| その URL に`Accept: text/markdown` | 明示的なメディアタイプが正の品質を持ち、`text/html` よりも優先度が低い場合に、Markdown 表示形式。 |
| `.md` に付与されたページ URL | €ブラウザの言語設定に依存しない明示的な Markdown 表示形式。 |
| `/index.md` | ホームページの Markdown 概要。 |
| `/docs.md`, `/blog.md`, `/features.md` | 公開コンテンツの Markdown インデックス。 |
| `/changelog.md` | 1 つの Markdown ドキュメントにまとめた公開された変更記録エントリ。 |
| `/terms.md`, `/privacy.md`, `/cookies.md` | 最新の公開された法的ドキュメント。日付付きの法的 URL も`.md` をサポートする。 |

`*/*` だけでは Markdown には切り替わらない。HTML レスポンスと Markdown レスポンスは`Vary: Accept` を共有するため、キャッシュがこれらを混在させない。

個別のドキュメント、ブログ、機能、および法的コンテンツは、描画された HTML の変換ではなく、作成された Markdown を使用しています。インデックスページは公開されたインベントリから生成され、ホームページには厳選された Markdown 概要があります。インタラクティブな REST 参照は、ブラウザ専用 API ウィジェットを埋め込むのではなく、読者を OpenAPI 仕様へ指し示します。

## ロケール

英語は接頭辞なしです。翻訳されたマーケティング URL は文字列プレフィックス`/de`,`/es`,`/fr`,`/ja`,`/ko`,`/pt-br`,`/zh-hans` を使用します。例えば`/es/docs/tutorials/getting-started.md` は公開された場合にスペイン語版を提供します。

URL が Markdown コンテンツの言語を選択します。`Accept-Language` は Markdown リクエストをリダイレクトしません。コンテンツ翻訳がない場合は英語のソースにフォールバックします。ホームページの概要は現在、英語で作成されています。

## ディスカバリー

- `/robots.txt` のデフォルトはクロールを禁止し、有限の公開 HTML と Markdown インベントリ、ローカリゼーションフィード、`/assets/`,`/fonts/`,`/images/` 下のレンダリングアセット、ファビコン、および`/og/marketing/` 下の公開マーケティングプレビューを選択します。`/og/app/` 下のアカウントプレビュー画像は禁止されます。これは協力的なクローラー向けのガイドラインであり、認証メカニズムではありません。
- `/sitemap.xml` は、沟言選択を含め、標準的な公開コンテンツを列挙します。Markdown のみのページの Markdown URL も含まれます。変更記録の断片は独立した URL ではありません。
- `/llms.txt` は Glossia を紹介し、公開ドキュメント、機能ガイド、および最新の執筆作業にリンクします。明示的な Markdown リンクも含まれます。
- `/llms-full.txt` は、ホームページ概要、ドキュメント、および Markdown 唯一の比較コンテンツを、Markdown を含む 1 つのテキストドキュメントとしてエクスポートします。

比較コンテンツは Markdown でのみ公開されます。これは HTML ドキュメント、ナビゲーション、検索、およびドキュメントインデックスから除外されますが、エージェントは`/llms.txt` とサイトマップを通じてそれを見つかり可以找到します。正規の URL は`.md` で終っています。以前は HTML URL も`Accept: text/markdown` に応答しましたが、ブラウザページを表示する機能はもうありません。

認証、アカウントダッシュボード、API、および他のアプリケーションレスポンスは`noindex, nofollow` にマークされています。公開された成功コンテンツは`index, follow` にマークされ、エラーはインデックスされないままです。ディコンバリーテキストファイル(`/robots.txt`,`/llms.txt`,`/llms-full.txt`) は`noindex, follow` を使用します: 読者はそれらを取得し、リンクを追跡できますが、検索エンジンは重複ドキュメントダンプではなく、正規のページを検索にインデックスすべきです。

## キャッシュとリソース使用

Markdown とテキストディカバリーレスポンスは以下を含みます:

| ヘッダー | 値または意味 |
|---|---|
| `Content-Type` | `text/markdown; charset=utf-8`, またはテキストディカバリー用の`text/plain; charset=utf-8` |
| `Cache-Control` | `public, max-age=300, stale-while-revalidate=60`. |
| `ETag` | 表現の引用 SHA-256 ダイジェスト。 |
| `X-Markdown-Tokens` | 文字を 4 で割り、切り上げた概算値; モデル固有のトークナイザー数ではありません。 |

`If-None-Match` は、強弱バリデータ、複数バリデータ、および`*` とのマッチングをサポートします。マッチングは`304` を返し、本体なし出荷します。`HEAD` は表現ヘッダーを返し、本体なしです。

公開された Markdown インベントリはリリースにコンパイルされます。リクエストはコンテンツ翻訳を実行しません、ソースファイルを参照しません、認証されたアカウントをロードしません、または LiveView をレンダリングしません。これらの公開表現にアクセスするために User-Agent の装飾は必要ありません。

## 運用境界

Markdownネゴシエーションはアカウントまたはプロジェクトダッシュボードへのアクセスを提供しません。既存のアカウント閲覧レート制限と Turnstile チェックは別個の保護手段として残ります。

プロダクショングレートエッジのレート制限は`GET` と`HEAD` 両方に適用されます。認証されたクローラーもレート制限を受けます。余剰リクエストはブラウザチャレンジではなくレート制限レスポンスを受けます; 読者は減速して後で再試行する必要があります。共有キャッシュと条件リクエストはクライアントのレート制限は除外しません。

レポジトリ内のクローラーポリシー変更は、アプリケーションおよび関連インフラストラクチャ設定がデプロイされた後に動作します。
