アカウントトークンは、OAuth フロー全体を介さずに API リクエストを認証するための簡単な方法を提供します。スクリプト、CI/CD パイプライン、およびパーソナル自動化にはこれらが最適です。

## トークンの作成

1. Glossia にログインし、アカウントダッシュボードに移動します。
2. サイドバーの **API** セクションを開きます。
3. **アカウントトークン** をクリックし、次に **新しいトークン** をクリックします。
4. トークンに説明性の高い **名** を入力してください（例："CI デプロイ" または "CLI アクセス"）。
5. トークンに必要な **スコープ** を選択します。必要な最小限の権限のみ付与してください。
6. **有効期限**を設定するか、永久に失効しないトークンの場合は空欄にします。
7. **トークンの作成** をクリックします。

作成後、トークンの完全な値は **1 回** 表示されます。すぐにコピーして安全に保管してください。完全な値を再度表示することはできません。

## トークンの使用

HTTP リクエストの `Authorization` ヘッダーにトークンを含めます:

```
Authorization: Bearer glsa_abc123def456...
```

例えば、`curl` を使用して:

```bash
curl -H "Authorization: Bearer glsa_abc123def456..." \
  https://glossia.ai/api/projects
```

アカウントトークンは OAuth トークンと同じ [認証モデル](/docs/reference/apis/authorization) を使用します。トークンのスコープは、実行できる動作の最大セットを定義し、リソースレベルのポリシーはアカウントの権限に基づいて引き続き適用されます。

## トークン形式

すべてのアカウントトークンは `glsa_` プレフィックスに続いてランダムな十六進数文字列から始まります。このプレフィックスは、ログやシークレットスキャンツールで Glossia トークンを識別しやすくします。

## スコープ

アカウントトークンは OAuth トークンと同じスコープをサポートします。完全な一覧については、[スコープ参照](/docs/reference/apis/authorization) をご覧ください。

トークンを作成する際は、使用ケースに必要なスコープのみを選択します。例:

- 読み取り専用のインテグレーションには `project:read` and `voice:read` が必要です。
- プロジェクトを作成する CI パイプラインには `project:read` and `project:write` が必要です。
- 組織メンバーを管理するスクリプトには `members:read` and `members:write` が必要です。

## トークンの管理

### トークンの表示

**アカウントトークン** ページには、名、スコープ、最後使用日、および有効期限を持つアクティブなすべてのトークンが一覧表示されます。かつて使用されたことのないトークンは、"Never"として最後使用列に表示されます。

### トークンの編集

トークンの **名** と **説明** を編集するには、トークンの名をクリックします。スコープと有効期限は作成後に変更できません。異なるスコープが必要であれば、新しいトークンを作成して古いものを無効化してください。

### トークンの無効化

トークンを無効化するには、トークンリストの **無効化**ボタンをクリックするか、トークンの編集ページを開いて危険エリアにある **トークンの無効化** ボタンを使用します。無効化されたトークンはすぐに機能停止し、復元することはできません。

## セキュリティベストプラクティス

- **トークンを安全に保管してください。** 環境変数またはシークレットマネージャーを使用し、ソースコントルにトークンをコミットすることを決して行わないでください。
- **期限付きのトークンを使用してください。** 可能であれば有効期限を設定してください。
- **スコープを最小限にしてください。** トークンが実際に必要な権限のみが付与されるようにしてください。
- **定期的にローテーションを行ってください。** スケジュールに従って新しいトークンを作成し、古いものを無効化してください。
- **利用状況を確認してください。** 定期的に"last used"日を確認し、利用されていないトークンを無効化してください。
- **統合あたり 1 つのトークンを使用してください。** これにより、1 つのトークンを無効化しても他のワークフローは破損しません。

## API 管理

REST API と MCP サーバーを介してアカウントトークンを管理することもできます。

### REST API

| メソッド | エンドポイント | 説明 |
|--------|----------|-------------|
| `GET` | `/api/tokens` | アクティブなトークンの一覧 |
| `POST` | `/api/tokens` | 新しいトークンの作成 |
| `DELETE` | `/api/tokens/:id` | トークンの無効化 |

### MCP

MCP サーバーは `list_tokens`, `create_token`, および`revoke_token` のツールを公開し、REST API を反映します。
