アカウント トークンは、完全な OAuth フローを経ることなく API リクエストを認証する簡単な方法を提供します。スクリプト、CI/CD パイプライン、および個人用自動化に最適です。

## トークンの作成

1. Glossia にサインインし、アカウント ダッシュボードへ移動してください。
2. 開く **API** サイドバーのセクション。
3. クリック **アカウント トークン**その後、 **新しいトークン**.
4. トークンに分かりやすい **名前を** (例： \\"CI デプロイ\\" または \\"CLI アクセス\\" )。
5. 使用する **スコープを選択** トークンに必要なものです。最小限の権限のみ付与してください。
6. 設定 **有効期限** または期限切れしないトークンのため、空白のままにしてください。
7. クリック **トークンを作成**。

作成後、トークンの完全な値が表示されます。 **一度**。すぐにコピーして安全に保管してください。以降、その全値を表示することはできません。

## トークンを使用する場合は

トークンを `Authorization` HTTP リクエストのヘッダーに含めてください:

    Authorization: Bearer glsa_abc123def456...

例えば、 `curl`:

```bash
curl -H "Authorization: Bearer glsa_abc123def456..." \
  https://glossia.ai/api/projects
```

アカウントトークンも同様です。 [認証モデル](/docs/reference/apis/authentication) OAuth トークンの仕組みです。トークンのスコープは、実行可能なアクションの最大セットを定義し、リソースレベルのポリシーは引き続き、アカウントの関係に基づいて適用されます。

## トークン形式

すべてのアカウントトークンは、 `glsa_` プレフィックスにランダムな 16 進文字列が続きます。このプレフィックスにより、ログや機密スキャナーで Glossia トークンを識別しやすくなります。

## スコープ

アカウントトークンは OAuth トークンのスコープと同等です。詳細は [スコープの参照](/docs/reference/apis/authentication) 完全なリストについては。

トークンを作成する際は、利用ケースに必要なスコープのみを選択してください。例えば：

- 読み取り専用統合には `project:read` 、 `voice:read`。
- プロジェクトを作成する CI パイプラインには `project:read` 、 `project:write`。
- 組織メンバーを管理するスクリプトには `members:read` と `members:write`.

## トークンの管理

### トークンの表示

この **アカウント トークンの** ページには、アクティブなすべてのトークンの名前、スコープ、最終使用日、および有効期限がリストされています。一度も使用されていないトークンは、"Never" を最終使用列に表示します。

### トークンの編集

トークン名をクリックして、その **名前** と **説明**。スコープと有効期限は作成後に変更できません。異なるスコープが必要な場合は、新しいトークンを作成し、古いトークンを無効化してください。

### トークンの無効化

トークンを無効化するには、クリック **無効化** トークンのリスト、またはトークンの編集ページを開いて、 **トークンの無効化** ボタン。無効化されたトークンは直ちに機能停止し、復元できません。

## セキュリティベストプラクティス

- **トークンを安全に保管してください。** 環境変数またはシークレットマネージャーを使用してください。トークンをリポジトリにコミットしてはいけません。
- **期限付きトークンを使用してください。** 可能であれば有効期限を設定してください。
- **スコープを最小限にしてください。** トークンに実際に必要な権限のみを付与してください。
- **定期的にローテーションを行ってください。** スケジュールに従って新しいトークンを作成し、古いトークンを無効化してください。
- **利用状況を監視してください。** 「最終使用日」を定期的に確認してください。使用されていないトークンを無効化してください。
- **各統合に 1 つのトークンを割り当ててください。** この方法では、1 つのトークンを取り消しても他のワークフローには影響しません。

## API 管理

REST API および MCP サーバーを通じて、アカウントトークンの管理も可能です。

### REST API

| メソッド | エンドポイント | 説明 |
|--------|----------|-------------|
| `GET` | `/api/tokens` | アクティブなトークンの一覧 |
| `POST` | `/api/tokens` | 新しいトークンを作成 |
| `DELETE` | `/api/tokens/:id` | トークンを無効化 |

### MCP

MCP サーバは機能を提供する `list_tokens`, `create_token`、 `revoke_token` REST API を反映するツール。
