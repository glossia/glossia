アカウントトークンは、完全な OAuth フローを経由せずに API リクエストを認証するための簡単な方法を提供します。スクリプト、CI/CD パイプライン、および個人用の自動化には最適です。

## トークンの作成

1. Glossia にサインインし、アカウントダッシュボードへ移動します。
2. 開く **API** サイドバーにあるセクションを。
3. クリック **アカウントトークン**, 次に **新しいトークン**.
4. トークンに説明を **名前** (例えば、"CI deploy" または "CLI access")。
5. スコープを選択 **スコープ** トークンに必要な権限のみ。最小限の権限のみを付与してください。
6. 設定 **有効期限** または、永久に有効なトークンのために空欄のままにしてください。
7. クリック **トークンの作成**。

作成後、トークンの完全な値が表示されます。 **一度**. すぐにコピーし、安全に保管してください。再度、完全な値を表示することはできません。

## トークンの使用

トークンを `Authorization` HTTP リクエストのヘッダーに含めます:

    Authorization: Bearer glsa_abc123def456...

例えば、 `curl`:

```bash
curl -H "Authorization: Bearer glsa_abc123def456..." \
  https://glossia.ai/api/projects
```

アカウントトークンは同様です。 [認証モデル](/docs/reference/apis/authentication) OAuth トークンとして。トークンのスコープは、実行可能な最大の操作セットを定義し、アカウントの関係に基づいてリソースレベルのポリシーも引き続き適用されます。

## トークン形式

すべてのアカウントトークンは `glsa_` プレフィックスにランダムな 16 進数文字列が続きます。このプレフィックスは、Glossia トークンをログやシークレットスキャナーで識別しやすくします。

## スコープ

アカウントトークンは OAuth トークンと同じスコープをサポートします。 をご覧ください [スコープ参照](/docs/reference/apis/authentication) 完全リストについては。

トークンを作成する際は、使用ケースに必要なスコープのみを選択してください。例：

- 読み取り専用の統合には、 `project:read` と `voice:read`.
- プロジェクトを作成する CI パイプラインには、 `project:read` と `project:write`.
- 組織メンバーを管理するスクリプトは必要 `members:read` と `members:write`。

## トークンの管理

### トークンの表示

The **アカウントトークン** システムのアカウントトークンページには、すべての有効なトークンの名前、スコープ、最後に使用した日付、および有効期限が表示されます。 вашей トークンの最終使用プロセスに表示されることは “N/A”です。

### トークンの編集

トークンの名前をクリックしてその **名前** と **説明**. スコープと有効期限は作成後に変更できません。異なるスコープが必要な場合は、新しいトークンを作成し、古いトークンを撤回してください。

### トークンの撤回

トークンを撤回するには、クリック **リボーク** トークンリストまたはトークンの編集ページを開き、こちらの **トークンのリボーク** 危険領域のボタン。リボークされたトークンは直ちに機能停止し、復元できません。

## セキュリティのベストプラクティス

- **トークンを安全に保管してください。** 環境変数またはシークレットマネージャーを使用してください。トークンは決してソース管理にコミットしないでください。
- **短命なトークンを使用してください。** 可能な限り有効期限を設定する。
- **スコープを最小化する。** トークンに必要な権限のみ付与する。
- **定期的にローテーションを行う。** スケジュールに応じて新しいトークンを作成し、古いものを無効化する。
- **利用状況を確認する。** 定期的に「最後に使用された」日付を確認し、使用されていないトークンを無効化する。
- **各統合に 1 つのトークンを使用する。** このように、1 つのトークンを無効化しても、他のワークフローには影響しません。

## API 管理

REST API および MCP サーバーを通じて、アカウントトークンを管理することもできます。

### REST API

| メソッド | エンドポイント | 説明 |
|--------|----------|-------------|
| `GET` | `/api/tokens` | アクティブなトークンの一覧 |
| `POST` | `/api/tokens` | 新しいトークンの作成 |
| `DELETE` | `/api/tokens/:id` | トークンの無効化 |

### MCP

MCP サーバーは公開する `list_tokens`, `create_token`、および `revoke_token` REST API を反映するツール。
