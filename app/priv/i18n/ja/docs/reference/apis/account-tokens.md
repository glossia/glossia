アカウントトークンは、フルの OAuth フローを経由せずに API リクエストを認証するシンプルな方法を提供します。スクリプト、CI/CD パイプライン、および個人用自動化には最適です。

## トークンの作成

1. Glossia にサインインし、アカウントダッシュボードに移動します。
2. サイドバーから **API** セクションを開きます。
3. **アカウントトークン**、次に **トークン作成** をクリックします。
4. トークンに記述性の **名前**（例えば、「CI deploy」または「CLI access」）を設定します。
5. トークンに必要な **スコープ** を選択します。必要な最小限の権限のみ付与してください。
6. **有効期限** を設定するか、永続的なトークンの場合は空欄とします。
7. **トークン作成** をクリックします。

作成後、トークンの完全な値が **once** 表示されます。すぐにコピーし、安全に保存してください。その後、完全な値を二度と見ることができません。

## トークンの使用

HTTP リクエストの `Authorization` ヘッダーにトークンを含めます：

```
Authorization: Bearer glsa_abc123def456...
```

例として、`curl` を使用します：

```bash
curl -H "Authorization: Bearer glsa_abc123def456..." \
  https://glossia.ai/api/projects
```

アカウントトークンは OAuth トークンと同じ [認証モデル](/docs/reference/apis/authorization) を準拠しています。トークンのスコープは実行できるアクションの最大セットを定義し、リソースレベルのポリシーもアカウントの関係を基に引き続き適用されます。

## トークンの形式

すべてのアカウントトークンは、ランダムな 16 進文字列が続く `glsa_` プレフィクスから始まります。このプレフィクスは、ログや機密スキャナー内で Glossia トークンを識別しやすくします。

## スコープ

アカウントトークンは OAuth トークンの同じスコープをサポートします。完全なリストについては [スコープ参照](/docs/reference/apis/authorization) を参照してください。

トークンの作成時に、使用ケースに必要であるスコープのみを選択してください。例えば：

- 読み取り専用統合には、`project:read` と `voice:read` が必要です。
- プロジェクトを作成する CI パイプラインには、`project:read` と `project:write` が必要です。
- 組織メンバーを管理するスクリプトには、`members:read` と `members:write` が必要です。

## トークンの管理

### トークンの閲覧

**アカウントトークン** ページには、名前、スコープ、最終使用日時、期限を示したすべてのアクティブなトークンがリストされます。使用されていないトークンは、最終使用列に "Never" を示します。

### トークンの編集

トークンの名前をクリックして、その **名前** と **説明** を編集します。作成後にスコープや期限を変更することはできません。異なるスコープが必要であれば、新しいトークンを作成し、古い方を無効にします。

### トークンの無効化

トークンを無効化するには、トークンリストで **無効化** をクリックするか、トークンの編集ページを開き、危険ゾーンの **トークン無効化** ボタンを使用します。無効化されたトークンは即座に機能停止し、復元できません。

## セキュリティのベストプラクティス

- **トークンを安全に保管してください。** 環境変数またはシークレットマネージャーを使用してトークンを管理してください。ソースコントロールにコミットすることは決してしないでください。
- **有効期限が短いトークンを使用してください。** 可能であれば、有効期限を設定します。
- **スコープを最小化します。** トークンに必要な権限のみ付与してください。
- **定期的に更新します。** スケジュールに基づいて新しいトークンを作成し、古いトークンを無効にします。
- **使用状況を確認します。** 「最終使用」日時を定期的に確認してください。使用されていないトークンを無効にします。
- **1 つの統合に 1 つのトークンを使用してください。** この方法により、1 つのトークンを無効にしても他のワークフローは影響しません。

## API 管理

REST API と MCP サーバーを介して、アカウントトークンを管理することもできます。

### REST API

| メソッド | エンドポイント | 説明 |
|--------|----------|-------------|
| `GET` | `/api/tokens` | アクティブなトークンの一覧 |
| `POST` | `/api/tokens` | トークンの新規作成 |
| `DELETE` | `/api/tokens/:id` | トークンの無効化 |

### MCP

MCP サーバーは REST API と同等の `list_tokens`、`create_token`、および `revoke_token` ツールを公開しています。
