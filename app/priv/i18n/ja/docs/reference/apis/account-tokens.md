アカウントトークンは、完全な OAuth フローを介さずに API リクエストを認証する簡単な方法です。スクリプト、CI/CD パイプライン、および個人の自動化に最適です。

## トークンの作成

1. Glossia にログインし、アカウントダッシュボードへ移動します。
2. を開く **API** サイドバーのセクション。
3. クリック **アカウントトークン**次に **新しいトークン**。
4. トークンに分かりやすい **名前** （ 例えば、「CI deploy」 または「CLI access」）。
5. 次の **スコープ** トークンに必要なものです。必要な最小限の権限のみ付与してください。
6. 有効期限を **有効期限** または、永続的なトークンのため、空白のままにしてください。
7. クリック **トークン作成**。

作成後、トークンの完全な値が表示されます。 **一度**. 直ちにコピーし、安全に保存してください。以降、完全な値は表示されません。

## トークンの使用

トークンを `Authorization` ヘッダーのあなたの HTTP リクエスト：

    Authorization: Bearer glsa_abc123def456...

例えば、 `curl`:

```bash
curl -H "Authorization: Bearer glsa_abc123def456..." \
  https://glossia.ai/api/projects
```

アカウント トークンは同様です [認証モデル](/docs/reference/apis/authentication) OAuth トークンとして動作します。トークンのスコープは実行可能なアクションの最大セットを定義し、アカウントの関係性に基づいてリソースレベルのポリシーも引き続き適用されます。

## トークン形式

すべてのアカウントトークンは `glsa_` プレフィックスに続くランダムな 16 進文字列で始まります。このプレフィックスは、ログおよびシークレットスキャナー内で Glossia トークンを識別しやすくします。

## スコープ

アカウントトークンは OAuth トークンの同じスコープをサポートしています。の [スコープ リファレンス](/docs/reference/apis/authentication) 完全一覧については。

トークン作成時に、必要なスコープのみを選択してください。例えば：

- 読み取り専用統合には `project:read` 、 `voice:read`。
- プロジェクト作成用 CI パイプラインには `project:read` 、 `project:write`。
- 組織メンバーを管理するスクリプトには `members:read` および `members:write`.

## トークンの管理

### トークンの表示

の **アカウント トークン** ページには、アクティブなトークンの名称、スコープ、最終使用日、有効期限がすべてリストされます。未使用のトークンは最終使用列に "Never" を表示します。

### トークンの編集

トークンの名前をクリックしてその **名前** および **説明**を編集できます。作成後ではスコープと有効期限を変更できません。異なるスコープが必要な場合は、新しいトークンを作成し、古いものを取り消してください。

### トークンの取り消し

トークンを取り消すには、 **撤回** トークンリストで、またはトークンの編集ページを開いて「 **トークンを撤回** 」のボタンを使用します。撤回されたトークンは即座に機能停止し、復元できません。

## セキュリティのベストプラクティス

- **トークンを安全に保管してください。** 環境変数またはシークレットマネージャーを使用してください。ソース管理にトークンをコミットしないでください。
- **短期有効なトークンを使用してください。** 可能な限り、有効期限を設定してください。
- **スコープを最小限に抑えてください。** トークンが実際に必要な権限のみを付与してください。
- **定期的にローテーションを行ってください。** 定期的なスケジュールで新しいトークンを作成し、古いものを無効化してください。
- **使用状況を監視してください。** 定期的に「最後に使用された」日付を確認し、使用されていないトークンを無効化してください。
- **各連携には 1 トークンのみを使用してください。** このように、一つのトークンを無効化しても、他のワークフローには影響しません。

## API 管理

REST API および MCP サーバーを通じて、アカウントのトークンを管理することもできます。

### REST API

| メソッド | エンドポイント | 説明 |
|--------|----------|-------------|
| `GET` | `/api/tokens` | アクティブなトークンの一覧 |
| `POST` | `/api/tokens` | 新しいトークンを作成 |
| `DELETE` | `/api/tokens/:id` | トークンを無効化 |

### MCP

MCP サーバーは公開します `list_tokens`, `create_token`、および `revoke_token` REST API を反映するツール。
