アカウントトークンは、完全な OAuth フローを経ることなく API リクエストを認証する簡単な方法です。スクリプト、CI/CD パイプライン、および個人の自動化に最適です。

## トークンの作成

1. Glossia にサインインし、アカウントダッシュボードに移動します。
2. 「 **API** 」サイドバーのセクションを開きます。
3. クリック **アカウントトークン**，次に **新しいトークン**.
4. トークンに記述的な **名前** (例：「CI deploy」または「CLI access」）。
5. スコープを **選択** トークンに必要なものです。必要な最小限の権限のみ付与してください。
6. 設定を **有効期限** または、永続トークンの場合は空白のままにしてください。
7. クリック **トークンを作成**.

作成後、トークンの完全な値が表示されます。 **一度**。すぐにコピーし、安全に保存してください。その後、完全な値を確認することはできません。

## トークンの使用

トークンを `Authorization` HTTP リクエストのヘッダーに：

    Authorization: Bearer glsa_abc123def456...

例えば、使用 `curl`:

```bash
curl -H "Authorization: Bearer glsa_abc123def456..." \
  https://glossia.ai/api/projects
```

アカウントトークンも同様です [認可モデル](/docs/reference/apis/authorization) OAuth トークンとして。トークンのスコープは、そのトークンが実行できる最大アクションのセットを定義し、リソースレベルのポリシーは依然としてアカウントの関連に基づいて適用されます。

## トークン形式

すべてのアカウントトークンは次の `glsa_` プレフィックスに続いてランダムな 16 進数文字列が続きます。このプレフィックスは、ログや機密スキャンツールで Glossia トークンを容易に識別できるようにしています。

## スコープ

アカウントトークンは OAuth トークンと同じスコープをサポートしています。ご参照の [スコープ参照](/docs/reference/apis/authorization) 完全なリストについては。

トークンを作成する際は、利用ケースに必要なスコープのみを選択してください。例えば：

- 読み取り専用の連携には、 `project:read` と `voice:read`。
- プロジェクトを作成する CI パイプラインには、 `project:read` と `project:write`。
- 組織メンバーを管理するスクリプトには、 `members:read` 、 `members:write`。

## トークンの管理

### トークンの表示

、 **アカウント トークン** ページでは、すべてのアクティブなトークンの名称、スコープ、最後の使用日、有効期限一覧が表示されます。未使用のトークンは、最後の使用日列に「未使用」と表示されます。

### トークンの編集

トークンの名前をクリックして、それらの **名前** と **説明**。スコープと有効期限は作成後に変更できません。異なるスコープが必要であれば、新しいトークンを作成し、古いトークンをリボークしてください。

### トークンのリボーク

トークンをリボークするには、クリックしてください **無効化** トークン リストから、またはトークンの編集ページを開き、以下の **トークンの無効化** 危険ゾーンにあるボタン。無効化されたトークンは直ちに機能しなくなり、復元できません。

## セキュリティ ベストプラクティス

- **トークンを安全に保管してください。** 環境変数またはシークレットマネージャーを使用してください。トークンをソース コントロールにコミットしないでください。
- **短命なトークンを使用してください。** 可能であれば、有効期限を設定してください。
- **スコープを最小限にしてください。** トークンに実際に必要な権限のみ付与してください。
- **定期的なローテーションを行ってください。** スケジュールに基づき、新しいトークンを作成し、古いトークンを無効化してください。
- **使用状況を確認してください。** 定期的に「最終使用日」を確認してください。使用されていないトークンは無効化してください。
- **各インテグレーションに 1 つのトークンを使用してください。** この方法では、1 つのトークンを無効にしても、他のワークフローには影響しません。

## API 管理

REST API および MCP サーバー経由でも、アカウントトークンを管理できます。

### REST API

| 方法 | エンドポイント | 説明 |
|--------|----------|-------------|
| `GET` | `/api/tokens` | アクティブなトークンの一覧 |
| `POST` | `/api/tokens` | 新しいトークンを作成 |
| `DELETE` | `/api/tokens/:id` | トークンを無効化 |

### MCP

MCP サーバーは公開します `list_tokens`, `create_token`、そして `revoke_token` REST API をミラーリングするツール。
