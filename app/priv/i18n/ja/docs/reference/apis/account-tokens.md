アカウントトークンは、完全な OAuth フローを経ることなく API リクエストを認証するためのシンプルな方法です。スクリプト、CI/CD パイプライン、および個人の自動化には最適です。

## トークンの作成

1. Glossia にサインインして、アカウントダッシュボードに移動します。
2. サイドバーから **API** セクションを開きます。
3. **アカウント トークン** をクリックし、続いて **新しいトークン** をクリックします。
4. トークンに説明的な **名前** を付けてください（例えば、「CI deploy」または「CLI access」）。
5. トークンに必要な **スコープ** を選択してください。必要な最小限の権限のみを付与します。
6. **有効期限日** を設定するか、有効期限のないトークンの場合は空のままにします。
7. **トークンの作成** をクリックします。

作成後、完全なトークン値は **1 回** だけ表示されます。直ちにコピーし、安全に保存してください。その後、完全な値を表示することはできません。

## トークンの使用

HTTP リクエストの `Authorization` ヘッダーにトークンを追加してください:

```
Authorization: Bearer glsa_abc123def456...
```

例えば、`curl` を使用する場合:

```bash
curl -H "Authorization: Bearer glsa_abc123def456..." \
  https://glossia.ai/api/projects
```

アカウントトークンは OAuth トークンと同じ [認証モデル](/docs/reference/apis/authorization) に従います。トークンのスコープは、実行できるアクションの最大セットを定義し、リソースレベルのポリシーはアカウントの関係に基づいて引き続き適用されます。

## トークン形式

すべてのアカウントトークンには `glsa_` プレフィックスが含まれ、その後にランダムな 16 進文字列が続きます。このプレフィックスは、ログやシークレットスキャナーで Glossia トークンを特定しやすくします。

## スコープ

アカウントトークンは OAuth トークンのと同じスコープをサポートします。完全なリストについては [スコープ リファレンス](/docs/reference/apis/authorization) を参照してください。

トークンを作成する際は、使用するケースに必要なスコープのみを選択してください。例えば:

- 読取専用統合には `project:read` と `voice:read` が必要です。
- プロジェクトを作成する CI パイプラインには `project:read` と `project:write` が必要です。
- 組織メンバーを管理するスクリプトには `members:read` と `members:write` が必要です。

## トークンの管理

### トークンの表示

**アカウント トークン** ページには、アクティブなすべてのトークンの一覧が表示されます。名前、スコープ、最終使用日、および有効期限が含まれます。使用されたことのないトークンについては、最終使用日列に「Never」と表示されます。

### トークンの編集

トークンの名前をクリックして、その **名前** と **説明** を編集します。作成後、スコープと有効期限を変更することはできません。異なるスコープが必要なのは場合は、新しいトークンを作成し、古いトークンを破棄してください。

### トークンの破棄

トークンを破棄するには、**破棄** をクリックするか、トークンの編集ページを開き、危険ゾーン内の **トークンの破棄** ボタンを使用してください。破棄されたトークンは即座に停止し、復元できません。

## セキュリティベストプラクティス

- **セキュリティ対策としてトークンを安全に保管してください。** 環境変数またはシークレットマネージャーを使用してください。トークンをソース管理に決してコミットしないでください。
- **短命なトークンを使用してください。** 可能な限り有効期限を設定してください。
- **スコープを最小限にしてください。** トークンが実際に必要な権限のみを付与してください。
- **定期的にローテーションしてください。** スケジュールに基づいて新しいトークンを作成し、古いトークンを破棄してください。
- **使用状況を監視してください。** 「最終使用日」を定期的に確認し、もう使用されていないトークンを破棄してください。
- **各統合に 1 つのトークンを使用してください。** これにより、1 つのトークンを破棄しても他のワークフローに影響されません。

## API 管理

REST API および MCP サーバーを介してアカウントトークンの管理も可能です。

### REST API

| メソッド | エンドポイント | 説明 |
|--------|----------|-------------|
| `GET` | `/api/tokens` | アクティブ トークンの一覧 |
| `POST` | `/api/tokens` | 新しいトークンの作成 |
| `DELETE` | `/api/tokens/:id` | トークンの破棄 |

### MCP

MCP サーバーは、`list_tokens`, `create_token`, および `revoke_token` のツールを REST API と対応する形で公開しています。
