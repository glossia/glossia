アカウントトークンは、完全な OAuth フローを介さずに API リクエストを認証するための簡単な方法を提供します。スクリプト、CI/CD パイプライン、および個人用自動化には最適です。

## トークンの作成

1. Glossia にサインインし、アカウントダッシュボードに移動してください。
2. 開く **API** のセクションをサイドバーから開きます。
3. クリック **アカウントトークン**次に **新しいトークン**。
4. トークンに説明しやすい **名前** （例：\\"CI deploy\\" または \\"CLI access\\"）
5. 次の **スコープ** トークンに必要なのみです。最小限の権限のみ付与してください。
6. 設定 **有効期限** 永続的なトークンの場合は空白のままにしてください。
7. クリック **トークンを作成**。

作成後、トークンの完全な値が表示されます。 **一度**すぐにコピーし、安全に保管してください。完全な値を確認することは二度とできません。

## トークンの使用

トークンをヘッダーに `Authorization` HTTP リクエストのヘッダー：

    Authorization: Bearer glsa_abc123def456...

例えば、 `curl`:

```bash
curl -H "Authorization: Bearer glsa_abc123def456..." \
  https://glossia.ai/api/projects
```

アカウントトークンは同様です [認可モデル](/docs/reference/apis/authentication) OAuth トークンとして。トークンのスコープは実行可能なアクションの最大セットを定義し、リソースレベルのポリシーはアカウントの関係を基に引き続き適用されます。

## トークン形式

すべてのアカウントトークンは `glsa_` プレフィックスに続くランダムな 16 進文字列で始まります。このプレフィックスにより、ログやシークレットスキャナー内で Glossia トークンを識別しやすくなります。

## スコープ

アカウントトークンは OAuth トークンと同じスコープをサポートします。 を [スコープの参照](/docs/reference/apis/authentication) 完全なリストをご覧ください。

トークンを作成する際は、その用途に必要なスコープのみを選択してください。例えば:

- 読み取り専用の統合には `project:read` また `voice:read`。
- プロジェクトを作成する CI パイプラインには `project:read` また `project:write`。
- 組織メンバーを管理するスクリプトには `members:read` および `members:write`.

## トークンの管理

### トークンの表示

その **アカウント トークン** ページはすべてのアクティブなトークンの名前、スコープ、最終使用日、および有効期限をリストします。未使用のトークンについては、最終使用日列に \\"Never\\" と表示されます。

### トークンの編集

トークンの名前をクリックして、その **名前** と **説明**。スコープと有効期限は作成後に変更できません。異なるスコープが必要な場合は、新しいトークンを作成し、旧トークンを取り消してください。

### トークンの取り消し

トークンを取り消すには、クリック **撤回** トークンリスト上で行うか、トークンの編集ページを開いて **トークンの撤回** の危険域にあるボタンです。撤回されたトークンは直ちに無効化され、復元できません。

## セキュリティのベストプラクティス

- **トークンを安全に保管してください** 環境変数またはシークレットマネージャーを使用してください。トークンをバージョン管理システムにコミットしないでください。
- **短期間有効なトークンを使用してください。** 可能であれば有効期限を設定してください。
- **スコープを最小限にしてください。** トークンに実際に必要な権限のみ付与してください。
- **定期的にローテーションを行ってください。** スケジュールに従って、新しいトークンを作成し、古いものを無効化してください。
- **使用状況を監視してください。** 定期的に「最後使用日」を確認し、使用されていないトークンを無効化してください。
- **各連携に 1 つのトークンを使用してください。** このように、1 つのトークンを無効にしても他のワークフローには影響しません。

## API 管理

REST API と MCP サーバーを通じて、アカウントトークンの管理も可能です。

### REST API

| メソッド | エンドポイント | 説明 |
|--------|----------|-------------|
| `GET` | `/api/tokens` | 有効なトークン一覧 |
| `POST` | `/api/tokens` | 新しいトークンを作成 |
| `DELETE` | `/api/tokens/:id` | トークンを無効化 |

### MCP

MCP サーバーは公開します `list_tokens`、 `create_token`、および `revoke_token` REST API を反映するツール。
