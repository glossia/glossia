**Glossia を選択したいときは、言語自動化をソフトウェア配送の他の部分のように機能させたいとき:** ソース管理された指示、ご自身のモデルトークン、リポジトリネイティブなチェック、そしてレビューのためのプルリクエスト。

[Weblate](https://weblate.org/) はオープンソースのローカライズシステムです。Web 翻訳インターフェース、バージョン管理との統合、そしてセルフホスティングオプションを備えています。公開コードと Git 統合が Glossia に限定されているわけではありません。Glossia を選ぶ理由は、リポジトリ中心の配送、モデル駆動の変換、人間とエージェントの両方にとって再利用可能な言語文脈の組み合わせにあるのです。

## Glossia を選ぶ理由

| 優先事項 | Glossia の利点 |
|---|---|
| 製品のワークフロー内でレビューを実行 | リポジトリの変更およびプルリクエストを通じて、実際のソース管理された出力をレビューします。 |
| 高速に動いているソースリポジトリに合わせる | 変更検出とバッチ公開により、変更されていない入力を繰り返し翻訳することなく、継続的なローカライズループをサポートします。 |
| ご自身のモデルトークンを導入 | アカウントスコープのプロバイダー認証情報でサポートされたモデルを設定し、リポジトリ管理のハンドルで選択します。 |
| ネイティブ検証の再利用 | 現実的なターゲットパスにある候補に対して、リポジトリ固有の検証コマンドを実行します。 |
| 翻訳を超えた文脈の再利用 | 共有された声と用語は、MCP と REST インターフェースを通じて、新しいコンテンツとエージェント統合をガイダンスします。 |

## リポジトリをレビューの領域として維持

Glossia はすでに Git を使用しておいて何を shipments にするかを決定するチーム向けに設計されています。ローカライズ設定はコンテンツの横にあり、提案された出力は製品の変更と同じプロセスを通じてレビューされます。

Weblate もバージョン管理システムと統合されます。ブラウザベースの翻訳インターフェースが、コントリビューターコミュニティのニーズに最適かもしれません。Glossia の強調点は異なります：別の編集インターフェースをチームの作業の中心にするのではなく、リポジトリのレビュー境界を維持し、言語自動化をそこに導入することです。

## ご自身のトークンを導入し、モデルの選択を明確にする

Glossia はプロバイダーの API トークンで設定されたサポートされたモデルを使用します。リポジトリ設定は安定したモデルハンドルを参照し、機密情報の残りはアカウント設定にあります。コンテンツスコープまたはターゲットロケールによって異なる構成されたモデルを選択し、すべてのリポジトリを変更せずに認証情報をローテーションできます。

これにより、チームはコンテンツを作成するモデルを明示的に選ぶことができます。これは、どのトークンやモデルがサポートされているか、あるいは生成によって人工のレビューが必要なくなることを保証するものではありません。[モデルプロバイダーを設定する](/docs/how-to/configure-a-model-provider) を参照してください。

## 納品の変更を定義するチェックを再利用

Glossia に組み込まれている構造的チェックは品質境界の一部に過ぎません。Through `L10N.md`, リポジトリのネイティブ検証スクリプト、パ Seoul、コンパイラー、またはドキュメントチェックを行い、相応の実体ターゲットパスで実行できます。

これは、翻訳コンテンツが単なる文字列だけでなく、アプリケーション固有の形式、Markdown コンポーネント、構造化されたメタデータ、プロジェクトが既に検証方法を知っている制約を含む場合に役立ちます。検証と回復は、パイプラインが発生する実際のファイルに接続され続けます。

実行環境は依然として検証器の依存関係が必要であり、構造的検証は言語的な正確性を確立しません。詳細は [L10N.md](/docs/reference/l10n-md) および [翻訳回復](./translation-recovery) をご覧ください。

## 公開ソースは、基準であって完全な比較ではありません

Glossia のコアは [Apache-2.0](https://github.com/glossia/glossia/blob/main/LICENSE-APACHE) に基づき、その条件の下で商用利用、変更、配布、セルフホスティング、競合するホスト型サービスの提供が可能です。`ee/` のコードには別の [Enterprise ライセンス](https://github.com/glossia/glossia/blob/main/ee/LICENSE.md) が適用され、本番環境での利用には書面による商用契約が必要です。このオープンコアモデルは、Weblate の GPL ベースのライセンスとは異なります。

制限のないオープンソースライセンスと確立された Web 翻訳インターフェースが主要な基準であれば、Weblate は考慮に値します。目標が **ご自身のモデル認証情報、既存のレポジトリチェック、ソフトウェア配送に続く言語作業** である場合、Glossia はそれらの選択肢を言語 OS にまとめます。

この比較は、Weblate が自動化、検証機能、またはプロバイダー統合を欠いていると主張するものではなく、自動的な移行や機能パラリティを保証するものではありません。現在の機能については [Weblate のドキュメント](https://docs.weblate.org/) をご参照ください。
