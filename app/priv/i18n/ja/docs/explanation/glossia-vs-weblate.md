**言語自動化をソフトウェア配信の他の部分のように機能させたい場合は Glossia を選ぶとよい** ソース管理された指示、ご自身のモデルトークン、リポジトリ固有のチェック、およびレビュー用のプルリクエスト。

[Weblate](https://weblate.org/) は、ウェブ翻訳インターフェース、バージョン管理との統合、およびセルフホスティング機能を持つオープンソースローカライゼーションシステムです。公開されたコードと Git ログの統合は Glossia 向けのものでありません。Glossia を選ぶ理由は、リポジトリ中心组められたデフォル、モデルを駆動する変換、および人間とエージェントの両者にとって再利用可能な言語コンテキストの組み合わせです。

## Glossia を何故選ぶのか

| 優先事項 | Glossia の利点 |
|---|---|
| 製品ワークフロー内でのレビュー維持 | リポジトリの変更およびプルリクエストを通じて、実際のソース管理された产出を確認します。 |
| 高速に変化するソースリポジトリの追従 | 変更検知とバッチ公開により、変更していない入力を反復して翻訳する必要なく、継続的なローカライゼーションループをサポートします。 |
| 独自のモデルトークンの提供 | アカウントスコープの提供資格情報でサポートされているモデルを設定し、リポジトリ固有のハンドルでそれらを選択します。 |
| ネイティブ検証の再利用 | 候補をその実際のターゲットパスで対するリポジトリ固有の検証コマンドを実行します。 |
| 翻訳を超えた文脈の再利用 | 共有されたトーンと用語は、MCP と REST インターフェイスを通じて新しいコンテンツとエージェント統合を導きます。 |

## リポジトリをレビューの領域として維持

既に Git を使用して出荷準備完了を決定しているチーム向けに、Glossia は設計されています。ローカライゼーションの構成はコンテンツの隣にあり、提案された出力は製品と同じプロセスでレビュー可能です。

Weblate もバージョン管理と統合しています。ブラウザベースの翻訳インターフェースは、コントリビュータコミュニティの必要なものかもしれません。Glossia の重点は異なっています：リポジトリのレビュー境界線を維持し、言語自動化をもたらすこと、つまりチームの作業の中心になる別の編集インターフェースにするのではなく、

## 独自のトークンの持参とモデル選択の明示化

Glossia は、提供 API トークンで設定されたサポートモデルを使用します。リポジトリの設定は安定したモデルハンドルを指し、機密情報はアカウント設定に残ります。コンテンツスコープまたはターゲットロケールによって異なる構成されたモデルを選択し、すべてのリポジトリを変更せずに認証情報を轮换できます。

これにより、コンテンツを作成するモデルを選択する明示的な場所がチームに与えられます。これは、あらゆるトークンまたはモデルがサポートされている、あるいは生成が人的レビューの必要性を排除したと保証していないことに注意してください。参照：[モデルプロバイダーの設定](/docs/how-to/configure-a-model-provider)。

## デリバラブルな変更を定義するチェックの再利用

Glossia に内蔵されている構造的チェックは、品質の境界の一部分のみです。`L10N.md` を通じて、その実在のターゲットパスでの候補に対して、リポジトリ固有のネイティブ検証スクリプト、パーサー、コンパイラ、またはドキュメントチェックを実行できます。

翻訳されたコンテンツが単なる文字列を超èleる場合に便利です：アプリケーション固有の形式、Markdown コンポーネント、構造化されたメタデータ、およびプロジェクトがすでに検証する方法の制約。検証と回復は、パイプラインが公開する実際のファイルと常に接続されます。

実行環境はまだ、検証者の依存関係を必要とし、構造的検証は言語的な精度を確定しません。参照：[L10N.md](/docs/reference/l10n-md) および [翻訳回復](./translation-recovery)。

## 公開ソースは基準であり、比較全体ではない

Glossia のコアは [Apache-2.0](https://github.com/glossia/glossia/blob/main/LICENSE-APACHE) に基づき、その条件の下で商用利用、変更、配布、セルフホスティング、競合するホスト型サービスの提供が可能です。`ee/` のコードには別の [Enterprise ライセンス](https://github.com/glossia/glossia/blob/main/ee/LICENSE.md) が適用され、本番環境での利用には書面による商用契約が必要です。このオープンコアモデルは、Weblate の GPL ベースのライセンスとは異なります。

無制限のオープンソースライセンスと確立されたウェブ翻訳インターフェースが主要な基準であれば、Weblate は考慮に値します。目的が **独自のモデル認証情報、既存リポジトリチェック、ソフトウェア配送に従う言語劳作** の場合、Glossia はそれを言語 OS としてそれらの選択をまとめることができます。

この比較は、Weblate が自動化、検証機能、またはプロバイダー統合の欠如を主張していないことを意味し、自動移行や機能のパラリティーを保証するものではありません。現在の機能を参照：[Weblate のドキュメンテーション](https://docs.weblate.org/)。
