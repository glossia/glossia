**言語自動化をソフトウェア配信の他の部分のように機能させたいときは Glossia を選びましょう:** ソース管理された指示、独自モデルトークン、リポジトリ純粋なチェック、およびレビュー用のプルリクエスト。

[Weblate](https://weblate.org/) はオープンソースのローカライズシステムであり、ウェブ翻訳インターフェース、バージョン管理統合、およびセルフホスティングオプションを備えています。公開コードと Git 統合は Glossia 独占ではありません。Glossia を選ぶ理由は、リポジトリ中心での配信、モデル駆動変換、および人間とエージェント用の再利用可能な言語コンテキストの組み合わせにあります。

## Glossia を選ぶ理由

| 優先事項 | Glossia の利点 |
|---|---|
| プロダクトワークフロー内にレビューを保つ | リポジトリの変更やプルリクエストを通じて、実際のソース管理された出力をレビューします。 |
| 急速に変動するリポジトリへの適合 | 変更検知とバッチ公開は、変更のない入力への繰り返し翻訳なしで継続的なローカライズループをサポートします。 |
| 独自のモデルトークンを適用 | アカウントレベルのプロバイダー認証情報を使ってサポートモデルを設定し、リポジトリ管理されたハンドルでそれらを選択します。 |
| ネイティブ検証の再利用 | 本物のターゲットパスにある候補に対して、リポジトリ固有の検証コマンドを実行します。 |
| 翻訳を超えたコンテキストの再利用 | 共有の言語と用語は、MCP および REST インターフェースを通じて新コンテンツとエージェント統合を導きます。 |

## リポジトリをレビューの表面として維持

Glossia は Git を既に使用して配送するには何が準備できているかを決定するチーム向けに設計されています。ローカライズ構成はコンテンツの横にあり、提案された出力はプロダクト変更と同じプロセスでレビューできます。

Weblate もバージョン管理システムと統合しています。そのブラウザベースの翻訳インターフェースはコントリビュータコミュニティがまさに必要としているものかもしれません。Glossia の焦点は異なります：もう一つの編集インターフェースをワークの中心にしないこと、リポジトリレビュー境界を守り、言語自動化を導入することです。

## 独自のトークンを適用し、モデルの選択を明確にする

Glossia はプロバイダー API トークンで構成されたサポートモデルを使用します。リポジトリ構成は安定したモデルハンドルを指し、機密情報はアカウント設定に含まれます。コンテンツの範囲やターゲットローカルの違いに応じて構成されたモデルを選択し、すべてのリポジトリを変更せずに認証情報をローテーションできます。

それにより、そのコンテンツを書き込むモデルを選択するチームの明らかな場所が生まれます。どのトークンやモデルがサポートされているか、生成が人間のレビューを排除するかは約束されていません。[モデルプロバイダーの設定](/docs/how-to/configure-a-model-provider) をご覧ください。

## 交付可能な変更を定義するチェックの再利用

Glossia の組み込み構造的チェックは品質境界の一部しかありません。`L10N.md` を通じて、リポジトリ固有の検証スクリプト、パーサー、コンパイラ、またはドキュメントチェックを、実際にターゲットパスにある候補に対して実行できます。

単純な文字列を超えた翻訳コンテンツ：アプリケーション固有の形式、Markdown コンポーネント、構造化されたメタデータ、プロジェクトがすでに検証をどのように行うかを知っている制約。検証と回復はパイプラインが公開する実際のファイルに接続されます。

実行環境は引き続き検証器の依存関係を必要とし、構造的検証は言語的な正確性を確立しません。[L10N.md](/docs/reference/l10n-md) および [翻訳回復](./translation-recovery) をご参照ください。

## 公開ソースは比較全体の基盤ではありません

Glossia の中心部分は公開されており、[Apache-2.0](https://github.com/glossia/glossia/blob/main/LICENSE-APACHE)の下で検査、修正、配布、そしてセルフホストが可能です。これは競合するホストサービスも認可します。`ee/`のエンタープライズコードには、商用用の実質的契約を要件とする独立した[ライセンス](https://github.com/glossia/glossia/blob/main/ee/LICENSE.md)が存在します。このオープンコアモデルは Weblate の GPL ベースライセンスとは異なります。

GPL ベースのライセンスと確立されたウェブ翻訳インターフェースがあなたの主基準なら、Weblate は検討に値します。**独自のモデル認証情報、既存リポジトリチェック、ソフトウェア配信に従う言語作業** の場合、Glossia はこれらの選択を言語 OS で統合します。

この比較は Weblate が自動化、検証機能、またはプロバイダー統合を欠いていることを主張しておらず、自動移行や機能の同等性を約束しません。[Weblate のドキュメント](https://docs.weblate.org/) で現在の機能をご覧ください。
