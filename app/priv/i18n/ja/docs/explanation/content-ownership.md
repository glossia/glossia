企業は、すでに生成されたコンテンツや、そのコンテンツを公開する能力を失うことなく、言語ツールを変更できるようにあるべきです。

## 所有権は、単なるエクスポートボタン以上のものです。

翻訳ファイルのエクスポートは有用ですが、ポータビリティには作業を継続するために必要なレビュー履歴、言語ガイダンス、用語、構成も含まれます。それらが単一の専用ワークスペースにのみ存在する場合、企業は結果を保持しながら、それを生み出したプロセスを失う可能性があります。

Glossia のリポジトリ・ワークフローは公開ソースと翻訳ファイルを Git に保持します。プルリクエストの履歴はリポジトリに残り、ファイルベースの構成はブラウザの編集セッションに依存せず、変換を記述します。

## 言語決定は再利用可能であるべきです。

ボイスと用語集のガイダンスは組織の意図を捉えます。Glossia はその文脈を人間や統合、MCP を通じてのエージェントを含む、に利用可能にします。これは以前翻訳されたセグメントを検索する再利用とは異なる種類の再利用です：メモリに一致する文が存在しなくても、新しいコンテンツを導くことができます。

それは、セグメントベースの翻訳メモリーが廃棄に等しいわけではありません。チームには保持したい価値のあるレビュー済み翻訳や専門ワークフローがあるかもしれません。Glossia の立場は、そのようなリソースは企業のデリバリー・プロセスを補完するものとしており、それを支配する必須の専用権限となるものではない、です。

## 公開ソースは役立ちますが、魔法の脱出計画ではありません。

実装を検証・変更できることは、チームがコンテンツがどのように処理されているかを理解するのを助けます。すべての運用依存関係が消えるわけではありません。デプロイ済みの Glossia インスタンスには、依然としてデータベース、関連ワークフロー用のモデルプロバイダアクセス、認証情報、およびインフラストラクチャが必要です。ダッシュボード管理の言語コンテキストについても、チームがシステムを変更する場合には明確な移行計画が必要です。

現在の O'Saasy ライセンスは、競合するホスティングサービス制限します。公開ソースの提供は、無制限なオープンソースライセンスとは異なり、および代替サービスがあらゆるビジネスモデルの下で運用され得ることを保証するものではありません。リポジトリの[ライセンス](https://github.com/glossia/glossia/blob/main/LICENSE.md)を参照してください。

## 有用なポータビリティテスト

言語サービスが利用できない場合、チームが依然として既存の翻訳コンテンツを検証、レビュー、公開できるかどうかを確認してください。リポジトリ所有の出力において、公開は最新のファイルを回復させるために単に専用エディタを再度開くことを必要としません。

次に、言語ガイダンス、認証情報、および自動化が別のシステムにどのように移行するかを確認してください。これらは別々の質問であり、限定なしの\"ロックインなし\"を約束するよりも、それらを開示しておく方が有益です。
