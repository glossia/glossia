**多言語コンテンツの発行権限を維持すべき場合は Glossia を選ぶべきです。** 文字列、ドキュメント、設定、およびそれらのチェックは既にアプリケーションとともに進化しています。Glossia は言語の変更をその進化に付随させ、チームにホスティングされたエディタを出版権限にすることを求めるのではなく、その進化を維持します。

[Lokalise](https://lokalise.com/) は、協働的なローカライズ、翻訳管理、および開発者向け統合を提供します。Glossia の提案はより具体的です：リポジトリのワークフローを維持し、独自のモデル認証情報を導入し、既存のチェックを再利用し、作業を実行するシステムを確認しましょう。

## ## Glossia を選択する理由

| 優先事項 | Glossia の利点 |
|---|---|
| ソフトウェア配送速度との整合 | ソース変更が翻訳作業を駆動し、提案された出力はリポジトリレビューワークフローを通じて帰還します。 |
| 実装を自ら所有する | パブリックソースは処理を検証可能にし、ライセンス条項下で修正およびセルフホスティングをサポートします。 |
| 独自のモデルトークンを使用する | アカウントスコープのプロバイダー認証情報は、シークレットを Git に格納せずにサポートされたモデルを選択することを可能にします。 |
| 真のアプリケーション内容を確認する | リポジトリスクリプトは、アプリケーションがその存在を期待する場所で候補を確認できます。 |
| 明確なレビュー境界を維持する | プルリクエストは、製品レビューに使用される同じツール内で言語の変更を可視化します。 |

## 言語の変更を製品の変更に関連付け続ける

新しい UI メッセージやドキュメントセクションは孤立した翻訳タスクではありません。それは製品改訂の一部に属し、用語を使用し、その構造と相合して機能しなければなりません。

Glossia はリポジトリ所有 `L10N.md` 設定を読み取り、内容とコンテキストの変化を使用して陳腐な翻訳を特定し、レビュー用の更新を提案します。レビュアーは実際のファイルと差分を確認し、公開パイプラインはあなたのものであります。

Lokalise にも自動化と Git インテグレーションがあります。Glossia の故意は意図されたレコードシステムです：あなたのリポジトリは公開されたコンテンツとその配信ルールを所有し、Glossia は言語コンテキストと変換メカニズムを提供します。

## ハードワイヤリングされた 1 つのモデル選択の代わりに、独自のトークンを導入する

Glossia は、独自のプロバイダー API トークンを使用してサポートされたモデルを設定できます。リポジトリは安定したモデルハンドルを使用するため、認証情報のローテーションやそのハンドルの背後のモデルの更新には、すべてのプロジェクトを変更する必要はありません。

ネスト設定とローカル GUID では、特定のエリアまたは言語のために別の設定されたモデルを選択できます。これは明示的な選択であり、自動プロバイダーフェイルオーバーの保証ではありません。[アカウントモデル](./account-models) を参照。

## 既にあなたのアプリケーションを理解している検証を再利用する

あなたのリポジトリは、無効な文字列、破損したファイル、壊れたコンポーネント属性、またはドキュメントビルド失敗を検出する方法を既に知っているかもしれません。Glossia は設定された検証コマンドを通じてその知識を呼び出すことができます。

候補はチェックのために一時的に実際の出力パスに配置されます。以前の状態は各検証試行後に復元され、承認された候補はその後書き込まれます。却下の出力は、テキストが一見適切だと見なされるだけでなく、設定された回復予算を通じて処理されます。

構造化とリポジトリのチェックは、すべての文が正しいことを証明するものではありません。それらは人間の言語レビューを補完し、そのレビューを配信可能の変更に変化します。[L10N.md](/docs/reference/l10n-md) および [翻訳の回復](./translation-recovery) を参照。

## パブリックソースとリポジトリ所有の出力

Glossia の実装は、[O'Saasy](https://github.com/glossia/glossia/blob/main/LICENSE.md) の下で検査、修正、およびセルフホスティングが可能です。そのライセンスは競合するホスティングサービスを制限しており、制限のないオープンソースライセンスではありません。

日々の配信においてより重要なのは、翻訳された出力が Git に残るということです。すでに所有する既存のファイルを公開するため、別の製品での編集セッションを取得する必要はありません。

中央集権的なブラウザ編集とローカライズ調整を望むチームには Lokalise も適しています。**リポジトリ所有権、独自のモデルトークン、既存の製品チェック** が維持したいワークフローである場合、Glossia が選択となります。

システムを変更する前に、代表的な変更をテストしてください。このページは、自動移行や機能同等性を約束し、Lokalise が自動化やすべてのプロバイダーオプションに欠けていることを主張しません。現在の機能については、[Lokalise のドキュメント](https://docs.lokalise.com/) を参照。
