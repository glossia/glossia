**言語作業を製品の配送システムに追従させたい場合、代わりに並列の翻訳管理プロセスを構築するのではなく、Glossia を選ぶとしましょう。** コンテンツを Git に保ち、ご自身の認証情報を使用してサポートされているモデルを選択し、リポジトリがすでに信頼するチェックを使用して結果を検証してください。

[Phrase](https://phrase.com/) は、ソフトウェアローカライゼーションとマネージド翻訳の異なるニーズに対応するローカライゼーションスイート（ Phrase Strings および Phrase TMS など）を提供しています。 Glossia は集中的アプローチを採用し、ソフトウェアチームに既存のリビューおよびデリバリーループに適合する言語 OS を提供します。

## Glossia を選ぶ理由

| 優先事項 | Glossia の優位性 |
|---|---|
| ソフトウェアと共に言語変更を配送 | リポジトリの変更はローカリゼーションを推進し、出力はレビュー可能な変更として戻されます。 |
| 処理を検証し管理する | 公開のソースはアプリケーションとデプロイメントの実装を公開し、ライセンス条件の下で修改とセルフホスティングを許可します。 |
| 独自のトークンを提供する | 独自のサポートされたモデルプロバイダーの認証情報を設定し、リポジトリ構成内のアカウントハンドルを通じてモデルを選択します。 |
| 検証パイプラインを再利用する | 翻訳候補に対してリポジトリネイティブのチェックを実行し、言語的承認を「ファイルがビルドされること」の証明とするのではなくします。 |
| 永続的な所有権を維持する | 公開されたファイル、設定、およびプルリクエストの履歴はリポジトリに残ります。 |

## ローカリゼーションを継続配送の一部に

Glossia の変更検知は、変わらない入力に対して翻訳作業を繰り返すことを避けます。リポジトリワークフローは、プロジェクトごとに 1 つのオープンな翻訳プルリクエストを保ち、バッチで進捗を発表するので、高速なソースリポジトリは小さな変更ごとに新しい翻訳プロセスを必要としません。

目的は無視されたプロダクションへの競争ではありません。チームがすでに使用しているパイプラインを通じて、言語作業を継続的にレビュー可能で配送可能にすることです。

Phrase も API、統合、そして自動化を提供しています。Glossia が強調する利点はアーキテクチャの整合性です：リポジトリはコンテンツ権威と配送境界として残るため、単に別のワークスペースの結果を同期する場所としてだけでなく存在します。

## モデルと認証情報の選択を自身のコントロール下に保持する

Glossia はサポートされたモデルのためにプロバイダーの API トークンをそのまま受入れます。認証情報はアカウント設定に残ります。リポジトリは安定したハンドルを選択します。チームは、リポジトリの指示を書き換えずにトークンをローテーションしたり、ハンドル背後のモデルを変更したりできます。

異なるコンテンツスコープとターゲット言語は構成されたモデルを異なるものに使用できます。オプションの決定モデルは完全な翻訳を評価し、修正を請求できますが、人間は言語的判断の責任を留まります。[Account models](./account-models) を参照して現在の動作と制限を確認してください。

## リポジトリはすでに有効なコンテンツの意味を知っています

翻訳管理システムのテキストの観点は、必ずしもアプリケーションのファイルの観点ではない場合があります。リポジトリには独自のパーサー、コンパイラ、コンポーネントルール、ドキュメントビルド、プレースホルダーチェックがある可能性があります。

Glossia は `L10N.md` 検証コマンドを通じてそれらのチェックを再利用できます。それは候補を時的に実際のターゲットパスに書き込み、必要なチェックがパスするまでのみ受理します。コマンドとその依存関係は実行環境に利用可能である必要があります。

これにより、チームは既存の品質境界を拡張し、翻訳ワークスペースの内部だけで「有効」の定義のみを維持するのではなくできます。[L10N.md](/docs/reference/l10n-md) を参照してください。

## 公開実装、ブラックボックスではありません

Glossia のアプリケーション、CLI、SDK、およびデプロイメントソースは公開されています。コアは [Apache-2.0](https://github.com/glossia/glossia/blob/main/LICENSE-APACHE) ライセンスの下でオープンソースであり、修改、配布、セルフホスティング、および競合するホスティングサービスを許可します。`ee/` 下のエンタープライズコードには [ライセンス](https://github.com/glossia/glossia/blob/main/ee/LICENSE.md) に別の書面の商業契約が必要となります。

より包括的なローカリゼーションスイートは専門的な翻訳作業や複雑な調整に意味を持つ場合があります。**ソフトウェアのデプロイ速度を独自のトークンとリポジトリチェックに合わせる** ことが優先事項であれば、Glossia はそのワークフローを直接的に保つように設計されています。

確立された翻訳プログラムの移行も、メモリ、用語、および履歴に関する計画が必要です。本ページは自動 Fletcher インポートやスイート完全同等性を約束しないか、Phrase がすべての同等的統合を欠いていると主張するわけではありません。特定のプロダクトの現在の機能については [Phrase のドキュメント](https://support.phrase.com/) を参照してください。
