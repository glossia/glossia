翻訳メモリは通常、以前に翻訳されたソース - ターゲットセグメントを記録します。一致する、または類似するソースセグメントは、以前の実績を再利用できます。このことは反復的な材料の保持ならびに査収済みの翻訳の保持にとって価値があります。

Glossia の言語メモリは別のニーズに対応します：かつてその文に現れたことがなくても、組織の調子に合い、一貫性があるように書かれるための原則です。

## 出力の記憶 versus 意図の記憶

査収済の翻訳は、「これまでどのように翻訳しましたか」と答えます。音声ガイダンスと用語集は、以下の質問に答えます：

- どの製品用語を無変換のまま残すべきですか？
- どの用語を一貫して使用すべきか？
- この対象読者に適するトーンは何ですか？
- 新規資料を起草する際、エージェントがどの言語的な判断を尊重すべきですか？

これらの入力は、ローカライズとソース言語でのコンテンツ作成を支援します。これらはマッチするターゲットセグメントの取得に限定されません。

## 補完的なツール

翻訳メモリと言語ガイダンスは、重複 Though distinct ですが別々の問題を解決します。チームは両方の恩恵を受けられます。Glossia は、モデル生成テキストがすべての査収済セグメントを置き換えることができることを約束するわけでも、プロンプトが言語的な正確さを保証するとは約束していないものです。

重要なアーキテクチャ的選択は、独自のメモリを企業の言語の唯一の権威に置くことを行わないことです。リポジトリ管理コンテンツ、再利用可能な文脈、バージョン履歴、レビューはすべて、チームが理解し維持できるプロセスに寄与します。

## コンテキストは依然としてレビューが必要です

ガイダンスは不完全、あるいは矛盾したものである可能性があります。用語は製品によって異なる意味を持つ場合があります。人間は結果が正確かつ適切かどうかを決定する責任を維持します。検証は構造的な不具合を検出できますが、すべての文が正しいことを証明することはできません。

より広範なモデルについては [Glossia の理由](./why-glossia) を、デリバリーとの関係については [継続的ローカライズ](./continuous-localization) をご参照ください。
