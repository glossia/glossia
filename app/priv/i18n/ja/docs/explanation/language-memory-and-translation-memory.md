翻訳メモリは通常、以前翻訳されたソースターゲットのセグメントを記録します。一致するまたは類似のソースセグメントは以前の仕事を引き継ぐことができます。これは反復する素材やレビュー済み翻訳の保持にとって貴重なものです。

Glossia の言語メモリは別のニーズに応えます：かつて一度も出現したことがない文であっても、新しい文章が組織に似ているように聞こえるような原理です。

## 翻訳された結果を記憶 versus 意図を記憶

レビュー済み翻訳は『これ、以前どのように翻訳したのですか？』と答えます。「声のガイダンス」と「用語表」は 次の問いに答えます:

- どの製品用語は変更せずにそのまま残すべきですか？
- どの用語を統一して使用するべきですか？
- どのトーンがこの対象層に適していますか？
- 新しい素材を作成する際に、エージェントが尊重すべき言語判断はどれですか？

これらの入力はローカライズやソース言語でのコンテンツ作成に役立ちます。これらは一致したターゲットセグメントの取得に限定されません。

## 補完ツール

翻訳メモリと言語ガイダンスは重複するが明確に異なる問題を解決します。両方を活用することでチームが恩恵を受ける可能性があります。Glossia は、モデル生成のテキストがすべてのレビュー済みセグメントを代替できるとは約束せず、プロンプトが言語的正確かさを保証するとも述べていません。

重要なアーキテクチャ上の選択は、機密メモリを会社の言語における唯一の権威にすることではありません。リポジトリ所有コンテンツ、再利用可能なコンテキスト、バージョン履歴、そしてレビューはすべて、チームが理解して維持できるプロセスに貢献します。

## コンテキストもまだレビューが必要です

ガイダンスも不完全または矛盾する可能性があります。用語は製品によって異なる意味を持つ場合があります。人間は結果の正確性と適切性を判断する責任を負い続けています。検証は構造的な不具合を検出できますが、すべての文が正しいことを証明することはできません。
