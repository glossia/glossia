翻訳メモリは通常、以前に翻訳された源−目標セグメントを記録します。一致する、あるいは類似した源セグメントは以前の作業を再利用でき、反復する素材やレビュー済み訳文の保存に価値があります。

Glossia の言語記憶は別のニーズを満たします：かつて一度も出現したことがない文であっても、組織らしい文脈に聞こえるようにする原則です。

## 結果の保持 versus 意図の保持

レビュー済みの翻訳文は、「以前どのように翻訳しましたか」という問いに答えます。ボイスガイダンスと用語集は、以下の問いに答えます:

- どの製品用語は変更せずに残すべきですか？
- どの用語を一貫して使用すべきですか？
- どのトーンがこの読者層に適していますか？
- エージェントが新素材を作成する際、尊重すべき言語上の決断は何ですか？

これらの入力は、ローカライゼーションおよび源言語でのコンテンツ作成に役立ちます。それらは一致する目標セグメントの取得だけには限定されません。

## 補完ツール

翻訳メモリと言語ガイダンスは、重なりつつも別の問題を解決します。チームは双方から利益を得られる可能性があります。Glossia は、モデル生成テキストがすべてのレビュー済みセグメントを置き換えること、またはプロンプトが言語的正確性を保証することを約束しません。

重要なアーキテクチャの選択は、企業言語の唯一の権威としてプロプライエトリアルな記憶を作ることではありません。リポジトリ所有コンテンツ、再利用可能なコンテキスト、バージョン履歴、そしてレビューはすべて、チームが理解し維持できるプロセスに貢献します。

## コンテキストもレビューが必要です

ガイダンスは不完全または矛盾する可能性があります。用語は製品によって異なる意味を持つ場合があります。人間は結果の正確性と適切さを決定する責任に留まります。バリデーションは構造的な_FAILURE_を捉えることができますが、すべての文が正しいことを証明することはできません。
