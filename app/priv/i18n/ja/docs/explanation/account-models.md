Glossia はリポジトリの指示をモデルプロバイダーの認証情報から分離します。リポジトリは翻訳対象を記述し、アカウントはどの [大規模言語モデル](https://en.wikipedia.org/wiki/Large_language_model) が作業を行います。

## モデルがアカウントに属している理由

チームは、同じプロバイダー関係を持つ複数のリポジトリを翻訳することがよくあります。アカウントスコープのモデルにより、管理者はすべてのリポジトリを編集せずに、一度でプロバイダーキーを再発行したり、基盤モデルを切り替えたりできます。

この境界はまた、認証情報をソース管理から除外します。リポジトリには、次のような可読なハンドル `translation-default`, プロバイダーキーではありません。

## ハンドルは安定した意図を提供します。

The `model` field in `L10N.md` refers to an account model handle:

```yaml
model: translation-default
```

The handle expresses the repository's intent. An administrator can later update which provider model that handle selects while the repository configuration stays stable.

## 複数のモデルの使用

Glossia は各ドキュメント翻訳に 1 つの構成されたモデルを使用します。複数のモデルを追加しても、アンサンブル、フォールバックチェーン、または自動的な品質ティアは作成されません。リポジトリの著者は、安定したハンドル（このようなものなど）を通じて目的を選択します `translation-default`再構築済みのドキュメントは以前検証に失敗しました。マークダウンテキストリテラル回復は、一致する長さの JSON 文字列配列を返す必要があります。 `long-form`整合済みのドキュメントは以前検証に失敗しました。Markdown テキストリテラルの復元は、長さが一致する JSON 文字列配列を返す必要があります。 `japanese-specialist`.

選択はドキュメントとターゲットのローカルのコンテキスト階層に従います：

1. 最も近い `L10N/<locale>.md` 宣言するファイル `model` がそのローカルに優先されます。
2. さもなければ、最も近い `L10N.md` 宣言するファイル `model` がそのディレクトリに優先されます。
3. 親 `L10N.md` より近いファイルがモデルを宣言していない場合、設定は継承されます。
4. 適用可能なコンテキストファイルがハンドルを宣言していない場合、Glossia はアカウントのデフォルトを使用します。

明示的に設定されたハンドルが存在する必要があります。Glossia はアカウントのデフォルトに静かに切り替えるのではなく、不明なハンドルに対してエラーを報告します。

## デフォルト選択

プロジェクトのセットアップは、リポジトリが独自のものを有する前にモデルを必要とする `L10N.md`。したがって、Glossia はアカウントのデフォルトを選択します。アカウントに追加された最初のモデルがデフォルトとなり、管理者は設定ページから別のモデルをデフォルトに設定できます。

リポジトリが持っている場合 `L10N.md`，明示的なハンドルを使用することで、レビューヤーが選択が明確になります。省略すると、 `model` リポジトリをアカウントのデフォルトのままで保ちます。

## 人のレビューの境界線

モデル出力は提案された作業であり、自動マージではありません。セットアップおよび翻訳の活動は Glossia で引き続き表示され、リポジトリの変更はレビューのためにプルリクエストを通じて公開されます。これにより、チームが既にコードに対して使用している品質と所有権の境界線が維持されます。
