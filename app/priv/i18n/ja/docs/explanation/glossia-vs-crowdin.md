**Glossia をローカリゼーション作業がソフトウェア配信のペースに合わせて動く必要がある場合に選択してください。** あなたのリポジトリは既に、変更をレビュー、検証、および出荷する方法を定義しています。Glossia は言語作業をそのループに持ち込み、別の翻訳ワークスペースをプロセスの中心とすることはしません。

[Crowdin](https://crowdin.com/) は共同翻訳管理、レビューワークフロー、翻訳メモリ、およびリポジトリ統合を提供します。Glossia のソフトウェアチームへの利点は、リポジトリ所有コンテンツ、検証可能なソース、独自のモデル認証情報、実際のプロジェクトを理解する検証の組み合わせです。

## Glossia を選択する理由

| あなたの優先事項 | Glossia の利点 |
|---|---|
| 継続的な出荷 | 翻訳実行はソース変更を追跡し、レビュー可能なリポジトリ更新を返します。コンテンツは独自の無関係なリリースプロセスこそ必要ありません。 |
| 実装の制御を維持する | 公開アプリケーション、CLI、および展開コードはライセンス条項の範囲で検証、修正、および自己ホストできます。 |
| 自らのトークンを提供招生する | 自らのプロバイダー API トークンを使用してサポートされたモデルを構成します。リポジトリファイルは安定したモデルハンドルを参照し、機密ではありません。 |
| 信頼するチェックを再利用する | 受け入れる前に実行先の実ターゲットパスで候補に対してリポジトリ検証コマンドを実行します。 |
| コンテンツを保持する | ソースファイル、翻訳出力、構成、およびプルリクエスト履歴はリポジトリ内に保持されます。 |

## コミットに追いつくローカリゼーション

バージョン管理された `L10N.md` 指示から始まり、Glossia は変更必要があるコンテンツを検知します。変更されていない入力内容は再度翻訳する必要はありません。プロジェクトは 1 つの公開 translated プルリクエストを保持し、バッチで進捗を公開することで、不要なプルリクエストと繰り返される CI 実行を削減できます。

結果は、あなたのチームがすでに配信する同様の小規模でレビュー可能な変化を中心に設計された言語ワークフローです。継続男女不限を意味しません：レビュワーはまた何をも安全にマージできるかを判断します。

Crowdin もまた Git 統合と自動機能をサポートします。Glossia を選択する理由は Crowdin がリポジトリに接続できないからではなく、リポジトリ配信が Glossia のワークフローの基礎であり、単なる統合境界にすぎないことです。

## あなたのトークン、あなたのモデル選択

プロバイダートークンを回転させたり、翻訳ワークフローの背後にあるモデルを変更したりするために、リポジトリ構成を再構築する必要はありません。Glossia は認証情報をアカウント設定に保存し、リポジトリに対して安定したハンドルを公開します。異なるコンテンツ領域またはターゲットローカリゼーションは異なる構成モデルを選択できます。

これによりあなたのチームは、サポートされるプロバイダー関係と使用するモデル選択を管理できます。[モデルプロバイダーの構成](/docs/how-to/configure-a-model-provider)を参照してください。

## 出力を製品の一部として検証する

翻訳が読みやすくても、ドキュメントビルト、コンポーネント、プレースホルダー、またはアプリケーション解析子を壊す可能性があります。Glossia はエディターのテキスト評価で止まるのではなく、リポジトリチェックを再利用できるようにしまします。

你的リポジトリにドキュメント検証スクリプトを提供している場合、直接参照します：

```yaml
validation:
  - ./scripts/validate-docs.sh
  - --strict
```

検証機は実際のターゲットパスで候補を受け取り、失敗すると非ゼロステータスを返し、設定されたリトライ予算内で実行します。その依存関係は検証環境で利用可能である必要があります。[L10N.md](/docs/reference/l10n-md) で契約を参照してください。

## リポジトリを放棄せずに公開ソース

Glossia のプラン、認証情報処理、Markdown 保存、および検証結果の方法を検証できます。既存の翻訳ファイルは言語サービスが利用不可であっても、リポジトリのパイプラインで公開可能です。

Glossia は[O'Saasy ライセンス](https://github.com/glossia/glossia/blob/main/LICENSE.md)の下でソースアベイラブルであり、自己ホストを可能にしていますが競合するホストサービスは制限しています。これは制限なしのオープンソースライセンスではありません。

Crowdin はコントリビューター協調と専用翻訳エディターを中心とするプログラムにはまだ適しています。**Git 所有コンテンツ、既存の検証、配信に従うローカリゼーション**を優先するソフトウェアチームには、Glossia はそのタスクのために設計されています。

この比較は Crowdin が自動化やすべてのプロバイダー統合形式を欠いていることを主張するものでもなく、また Glossia が自動的にメモリと履歴を移行するものでもありません。現在の機能を参照するには[Crowdin のドキュメント](https://support.crowdin.com/)を参照してください。
