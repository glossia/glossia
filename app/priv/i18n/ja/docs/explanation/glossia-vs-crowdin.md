**Glossia を選択、ローカライズをソフトウェアデリバリーの速度に合わせて進める必要がある場合です。** リポジトリは変更のレビュー、検証、配布方法をすでに定義しています。Glossia は言語作業をそのループ内に導入し、別の翻訳ワークスペースをプロセスの中心にすることはありません。

[Crowdin](https://crowdin.com/) は共同翻訳管理、レビューワークフロー、翻訳メモリ、リポジトリ統合を提供します。ソフトウェアチームにとって Glossia の利点は、リポジトリ管理コンテンツ、検証可能なソース、独自モデル認証、実際のプロジェクトを理解する検証の組み合わせです。

## なぜ Glossia を選択するのか

| あなたの優先事項 | Glossia の利点 |
|---|---|
| 継続的な配布 | 翻訳実行はソース変更を受注し、レビュー可能なリポジトリ更新を返します。コンテンツには関連しない独立したリリースプロセスが必要です。 |
| 実装の管理を保つ | 公開アプリケーション、CLI、デプロイコードはライセンス条項の下で検証、変更、セルフホスティングできます。 |
| 自前のトークンを所持 | 独自プロバイダー API トークンで対応モデルを設定。リポジトリファイルは安定したモデルハンドルを参照し、機密を参照しません。 |
| 信頼するチェックを再利用 | 受け入れる前に、候補を実際のターゲットパスに対してリポジトリ検証コマンドを実行します。 |
| コンテンツをあなた自身のものとして保つ | ソースファイル、翻訳出力、設定、プルリクエスト履歴がリポジトリに残ります。 |

## コミットに追随するローカライズ

Glossia はバージョン管理された `L10N.md` 指示から動作し、更新が必要なコンテンツを検出します。変更のしない入力は再度翻訳する必要はありません。プロジェクトは有効な翻訳プルリクエストを 1 つに維持し、バッチで進捗を発表し、不必要なプルリクエストと繰り返しの CI 実行を削減します。

結果は、チームがすでに配布している詳細な小規模なレビュー可能な変更を元にした言語ワークフローです。継続的は非レビューを意味しません：レビュアーまだ安全にマージできるものを決定します。

Crowdin も Git インテグレーションと自動化をサポートします。Glossia を選択する理由には、Crowdin がリポジトリに接続できないという事実は含まれていません。それはリポジトリデリバリーが Glossia のワークフローの基盤であり、単なる統合境界ではありません。

## あなたのトークン、あなたのモデル選択

プロバイダートークンを回転させたり、翻訳ワークフローの背後にあるモデルを変更したりするためにリポジトリ設定を再構築する必要はありません。Glossia は認証情報をアカウント設定に保存し、安定したハンドルをリポジトリに公開します。異なるコンテンツエリアまたはターゲットローカルは異なる構成モデルを選択できます。

この PV をチームには、サポートされているプロバイダー関係と使用するモデル選択の制御を与えます。[モデルプロバイダーを設定する](/docs/how-to/configure-a-model-provider) を参照してください。

## 出力を製品の一部として検証

翻訳は十分に読めるであっても、ドキュメントビルド、コンポーネント、プレースホルダー、またはアプリケーションパーサーを壊す可能性があります。Glossia はエディタによるテキスト評価だけで終わるのではなく、リポジトリチェックを再利用することを可能にします。

リポジトリがすでにドキュメント検証スクリプトを提供している場合、これを直接参照します：

```yaml
validation:
  - ./scripts/validate-docs.sh
  - --strict
```

検証子は、実際のターゲットパスで候補を受け取り、失敗時にゼロ以外を返します。その依存関係は検証環境で利用可能でなければなりません。詳細は[L10N.md](/docs/reference/l10n-md)で契約を確認してください。

## リポジトリを奪われない公開ソース

Glossia のプランがどのように動作するか、認証を管理し、Markdown を保存し、結果を検証する方法を検証できます。言語サービスが利用できない場合でも、既存の翻訳ファイルはリポジトリのパイプラインを通じて公開可能です。

Glossia はオープンコアです：[Apache-2.0](https://github.com/glossia/glossia/blob/main/LICENSE-APACHE) がコアをカバーし、セルフホスティングと競合ホストサービスを実装することを許可します。`ee/` 下にソース配信エンタープライズコードは独立した[ライセンス](https://github.com/glossia/glossia/blob/main/ee/LICENSE.md)があり、商用プロダクション契約を必要とします。

Crowdin はコントリビューター協調と専用翻訳エディタを中核とするプログラムにはまだ適切かもしれません。ソフトウェアチームの優先事項が**Git 管理コンテンツ、既存検証、配送を追うローカライズ**である場合、Glossia はその仕事のために設計されています。

この比較は、Crowdin が自動化やあらゆる形式のプロバイダー統合を欠いていることを主張しても、Glossia が自動的にメモリと履歴を移行することを意味するわけではありません。現在の機能については[Crowdin のドキュメント](https://support.crowdin.com/)を参照してください。
