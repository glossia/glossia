ソフトウェアのデリバリー速度に合わせてロケライズを進める必要がある場合は、**Glossia を選ぶべきです。** リポジトリはすでに定義されているように、変更をレビューし、検証し、送る方法を定義しています。別の翻訳ワークスペースをプロセスの中心にするのではなく、Glossia はそのループに言語作業をもたらします。

[Crowdin](https://crowdin.com/) は協力翻訳の管理、レビューワークフロー、翻訳メモリー、およびリポジトリ統合を提供します。ソフトウェアチームにとっての Glossia の利点は、リポジトリ固有のコンテンツ、検査可能なソース、独自のモデル認証情報、および実際のプロジェクトを理解する検証の組み合わせです。

## なぜ Glossia を選ぶ

| あなたの優先事項 | Glossia の利点 |
|---|---|
| 継続的なリリース | 翻訳の実行はソースの変更を受け、レビュー可能なリポジトリの更新を返します。コンテンツには独自の無関係のリリースプロセスを必要としません。 |
| 実装の管理を維持する | 公開アプリケーション、CLI、およびデプロイメントコードは、ライセンス条項に基づいて検査、変更、およびセルフホストできます。 |
| 独自のトークンを導入する | サポートされたモデルは、独自のプロバイダー API トークンで構成します。リポジトリファイルは、秘密鍵ではなく、安定したモデルハンドルを参照します。 |
| 信頼できるチェックを再利用する | 受け入れる前に、実際のターゲットパスに対して候補をリポジトリ検証コマンドで走査します。 |
| コンテンツを自らの所有物として維持する | ソースファイル、翻訳された出力、設定、およびプルリクエストの履歴はあなたのリポジトリに残ります。 |

## コミットalarignment に追いつくロケライズ

Glossia はバージョン化された `L10N.md` 指示に基づいて動作し、更新が必要なコンテンツを検出します。不変の入力は再度翻訳する必要はありません。プロジェクトは 1 つのオープンな翻訳プルリクエストを保持し、バッチ形式で進捗を発行し、ソースが変化するにつれ不要なプルリクエストや繰り返しの CI 実行を削減します。

その結果は、すでにあなたのチームが提供している、同一の小さなレビュー可能な変更を基に設計された言語ワークフローです。継続的とは「レビューされていない」を意味しません：審査者はまだ何が安全にマージできるか決定します。

Crowdin も Git 統合と自動化をサポートしています。Glossia を選ぶ理由は、Crowdin がリポジトリに接続できないためではなく、リポジトリデリバリーが Glossia のワークフローの基礎であり、単なる統合境界の要素ではないためです。

## あなたのトークン、あなたのモデル選択

プロバイダートークンを回転させるか、翻訳ワークフローの背後にあるモデルを変更するためにリポジトリ構成を再構築する必要はありません。Glossia は認証情報アカウント設定に保存し、リポジトリに対して制御可能なハンドルを公開します。異なるコンテンツ領域やターゲットロケールは異なる設定されたモデルを選択できます。

モデルプロバイダーを設定するには\<u\>(参照ください)\</u\>。[モデルプロバイダーの設定](/docs/how-to/configure-a-model-provider)。

## 製品の一部としての出力を検証

翻訳は読みやすいが、依然としてドキュメントビルド、コンポーネント、プレースホルダー、またはアプリケーションパーサーを壊す可能性があります。Glossia は、テキストのエディタ評価に留まるのではなく、リポジトリチェックを再利用することを許可します。

あなたのリポジトリにすでにドキュメント検証スクリプトがある場合、直接参照します：

```yaml
validation:
  - ./scripts/validate-docs.sh
  - --strict
```

検証機は候補を実際のターゲットパスで受信し、失敗時に非ゼロステータスを返し、設定されたリトライ予算内ですべてを実行します。依存関係は検証環境で利用可能である必要があります。契約については [L10N.md](/docs/reference/l10n-md) を参照。

## リポジトリを譲渡しない公開ソース

あなたは Glossia のプランがどのように動作し、認証情報を管理し、Markdown を保持し、結果を検証するのかがわかる。言語サービスが利用不可であっても、既存の翻訳ファイルはリポジトリのパイプラインを通じて公開可能です。

Glossia は [O'Saasy ライセンス](https://github.com/glossia/glossia/blob/main/LICENSE.md) の下でソース利用可能です。これはセルフホストを許可しますが、競合するホスト済みサービスには制限を課します。それは制限のないオープンソースライセンスではありません。

Crowdin はコントリビューター調整と専門の翻訳エディターに焦点を当てたプログラムにはまだ適切です。優先事項が **Git 固有のコンテンツ、既存の検証、およびデリバリーに従うロケライズ** のソフトウェアチームには、Glossia はそのタスクのために設計されています。

この比較は、Crowdin が自動化やプロバイダー統合のあらゆる形態を欠乏していることを主張するものでもなく、Glossia が自動的にメモリーと履歴を移行するものでもない。現在の機能については [Crowdin のドキュメント](https://support.crowdin.com/) を参照してください。
