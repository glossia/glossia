**ソフトデリバリー速度でローカライズを進める必要がある際は Glossia を選んでください。** あなたのリポジトリはすでに変更のレビュー、検証、そしてリリース方法を定義しています。Glossia は言語作業をそのループに加え、別々の翻訳ワークスペースをプロセス中心にしないようにします。

[Crowdin](https://crowdin.com/) は協力的な翻訳管理、レビューワークフロー、翻訳メモリ、リポジトリ統合を提供します。ソフトウェアチームにとって Glossia の利点は、リポジトリ所有のコンテンツ、検索可能なソース、独自のモデルクレデンシャル、そして実際のプロジェクトを理解する検証の組み合わせです。

## Glossia を選ぶ理由

| 優先事項 | Glossia のメリット |
|---|---|
| 継続的にリリースする | 翻訳ジョブはソースの変更に合わせて実行され、レビュー可能なリポジトリ更新を返します。コンテンツは自ら独立してリリースプロセスを必要としません。 |
| 実装の制御を維持する | パブリックアプリケーション、CLI、デプロイメントコードはライセンス条項下で検査、修正、セルフホスト可能である。 |
| 独自のトークンを採用する | 対応するモデルを独自の提供元 API トークンで設定します。リポジトリファイルは機密情報ではなく、安定したモデルハンドルを参照します。 |
| 信頼するチェックを再利用 | 受け入れる前に、実際のターゲットパスで候補に対してリポジトリ検証コマンドを実行します。 |
| コンテンツを自らのものとして維持 | ソースファイル、翻訳出力、設定、プルリクエスト履歴はあなたのリポジトリ内に残ります。 |

## コミットに追従するローカライズ

Glossia はバージョン管理された `L10N.md` 指示から動作し、どのコンテンツを更新すべきかを検出します。変更されていない入力は再度翻訳する必要はありません。プロジェクトは 1 つの開いた翻訳プルリクエストを保持し、進捗をバッチ単位で公開することで、ソースが進化する間に不要なプルリクエストや繰り返しの CI 実行を減らします。

その結果、チームがすでに提供している小さなレビュー可能な変更を中心に設計された言語ワークフローが生まれます。継続的とはレビュー済みではないことを意味しません：レビュアーはまだマージに安全なものを決定します。

Crowdin も Git 統合と自動化をサポートします。Glossia を選ぶ理由は、Crowdin がリポジトリに接続できないためではなく、リポジトリのデリバリーが Glossia ワークフローの基礎であり、単なる統合境界ではないからです。

## あなたのトークン、モデルの選択

提供者トークンの回転や翻訳ワークフローの背後のモデル変更のためにリポジトリ構成を再構築する必要はありません。Glossia はクレデンシャルをアカウント設定に保存し、リポジトリに安定したハンドルを公開します。異なるコンテンツエリアやターゲットリーが異なる構成モデルを選択できます。

これによりチームはサポートされる提供者関係と使用されるモデル選択の制御権を得るようになります。 [モデルプロバイダーを設定する](/docs/how-to/configure-a-model-provider) を参照してください。

## 製品の検証の一部として出力を検証する

翻訳は読みやすくてもドキュメントビルドやコンポーネント、プレースホルダー、アプリケーションパーサーを壊す可能性があります。Glossia は編集者のテキスト評価で終わらず、リポジトリチェックを再利用できます。

あなたのリポジトリが既にドキュメント検証スクリプトを提供している場合は、それを直接使用します：

```yaml
validation:
  - ./scripts/validate-docs.sh
  - --strict
```

検証器は実際のターゲットパスで候補を受け取り、失敗時には非ゼロステータスを返し、設定されたリトライ予算内で実行します。依存関係は検証環境で利用可能です。 [L10N.md](/docs/reference/l10n-md) で契約を参照してください。

## リポジトリを明け渡さずに公開ソース

Glossia のプランの動作やクレデンシャル処理、Markdown の保持、結果の検証方法を調べることができます。言語サービスが利用不可であっても、既存の翻訳ファイルはリポジトリパイプラインを通じて公開可能です。

Glossia はオープンコアモデルを採用しています。コアは [Apache-2.0](https://github.com/glossia/glossia/blob/main/LICENSE-APACHE) に基づき、その条件の下で商用利用、変更、配布、セルフホスティング、競合するホスト型サービスの提供が可能です。`ee/` のコードは閲覧できますが、オープンソースではありません。別の [Enterprise ライセンス](https://github.com/glossia/glossia/blob/main/ee/LICENSE.md) が適用され、本番環境での利用には書面による商用契約が必要です。

Crowdin はコントリビューター連携や専属翻訳エディターを中核とするプログラムに対して依然として適切です。ソフトウェアチームの優先事項が **Git で管理されるコンテンツ、既存の検証、およびデリバリーに従うローカライズ** である場合、Glossia はそのためのタスクに設計されています。

この比較は Crowdin が自動化や提供者統合のあらゆる形態を欠いていると主張しておらず、Glossia が自動的にメモリと履歴を移行すると断言しているわけではありません。 [Crowdin のドキュメント](https://support.crowdin.com/) 参照して現在の機能を理解してください。
