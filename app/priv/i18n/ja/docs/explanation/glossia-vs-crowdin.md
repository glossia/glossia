**ソフトウェアの配送速度に合わせてローカライズを進める必要がある場合は Glossia を選びましょう。** リポジトリは既に、変更のレビュー方法、検証方法、および配信方法を定義しており、Glossia は言語作業をそのループに取り込み、独立した翻訳ワークスペースをプロセスの中心に配置する代わりにします。

[Crowdin](https://crowdin.com/) は、共同てん翻訳管理、レビューワークフロー、翻訳メモリ、およびリポジトリ統合を提供します。ソフトウェアチームに対する Glossia の利点は、リポジトリ所有コンテンツ、検証可能なソース、ご自身のモデル認証情報、および実際のプロジェクトを理解する検証の組み合わせにあります。

## Glossia の選択理由

| 優先事項 | Glossia の利点 |
|---|---|
| 継続的なリリース | 翻訳実行はソースの変更をフォローし、レビュー可能なリポジトリアップデートを返します。コンテンツには、関連しない独立したリリースプロセスが必要ではありません。 |
| 実装の管理を維持する | 公開アプリケーション、CLI、およびデプロイメントコードは、ライセンスの項に基づいて検証、変更、および自己ホスティング可能です。 |
| ご自身でトークンを準備する | サポートされているモデルを、ご自身のプロバイダ API トークンで構成しましょう。リポジトリファイルは秘密情報ではなく、安定したモデルハンドルを参照します。 |
| 信頼できるチェックを再利用する | 受け入れる前に、実際のターゲットパスに対して候補を検証するコマンドを実行してください。 |
| コンテンツを所有する | ソースファイル、翻訳出力、構成、およびプルリクエスト履歴は、リポジトリ内に残ります。 |

## コミットに合わせて進化続けるローカライズ

Glossia はバージョン管理された `L10N.md` 指示に基づいて動作し、更新が必要なコンテンツを検出します。変更されていない入力は再度翻訳する必要はありません。プロジェクトは 1 つの open translation pull request を維持し、バッチ形式で進捗を発表し、ソースが進化に従って不要なプルリクエストと繰り返される CI 実行を削減します。

その結果は、あなたのチームがすでにリリースしている小さなレビュー可能な変更の周りに設計された言語ワークフローです。継続的であるとはレビューされていないことを意味しません：レビューヤーは依然として、マージに安全なものを決定します。

Crowdin も Git 統合および自動化をサポートしています。Glossia を選択する理由は、Crowdin がリポジトリに接続できないからではありません。リポジトリの配送は Glossia のワークフローの基礎であり、単なる統合境界ではないからです。

## あなたのトークン、チェント選択

プロバイダトークンのローテーションや翻訳ワークフローの背後にあるモデルの変更のためにリポジトリ構成を再構築する必要はありません。Glossia は認証情報をアカウント設定に保存し、安定したハンドルをリポジトリに公開します。異なるコンテンツ領域またはターゲットロケールは、異なる構成されたモデルを選択できます。

これにより、チームはサポートされているプロバイダ関係と使用するモデルの選択肢を制御できるようになります。[モデルプロバイダを設定する](/docs/how-to/configure-a-model-provider) を参照してください。

## 製品の一部として出力を検証する

翻訳が正しく読みやすかったとしても、ドキュメントビルド、コンポーネント、プレースホルダー、またはアプリケーションパーサーを壊す可能性があります。Glossia は、テキストのエディタの評価で止まるのではなく、リポジトリチェックを再利用することを可能にします。

リポジトリに既にドキュメント検証スクリプトを提供されている場合は、直接参照してください:

```yaml
validation:
  - ./scripts/validate-docs.sh
  - --strict
```

検証器は候補を実際のターゲットパスで受け取り、失敗時にゼロ以外のステータスを返し、設定された再試行予算内で実行されます。その依存関係は検証環境に利用可能である必要があります。契約については[L10N.md](/docs/reference/l10n-md) を参照してください。

## リポジトリを失うことなく公開ソース

Glossia のプランの動作方法、認証情報の処理、Markdown の保持、および結果の検証手法を調査できます。言語サービスが利用できなくても、既存の翻訳ファイルはリポジトリのパイプラインを通じて公開可能です。

Glossia は[O'Saasy license](https://github.com/glossia/glossia/blob/main/LICENSE.md) 元でソース利用可能であり、セルフホスティングを許可しますが、競合するホスティングサービスは制限されています。これは制限のないオープンソースライセンスではありません。

Crowdin は、コントリビュータの協働と専用翻訳エディターにフォーカスするプログラムにも依然として適切です。**Git 所有コンテンツ、既存の検証、デリバリに追従するローカライズ** を優先するソフトウェアチームの場合、Glossia はそのタスクのために設計されています。

この比較は、Crowdin が自動化やプロバイダ統合の全形態を欠いていることを主張するものではなく、Glossia が自動的にメモリや履歴を移行することを主張するものでもありません。現在の機能については[Crowdin のドキュメント](https://support.crowdin.com/) を参照してください。
