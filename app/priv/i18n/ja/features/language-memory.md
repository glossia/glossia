## 言語メモリとは何ですか？

言語メモリは、組織間のコミュニケーション方法などを Glossia のエージェントに伝える蓄積されたコンテキストです。時間とともに作成し、洗練させる 2 つの中核基本要素で構成されています：

**声** コンテンツのトーンや響きを定義します。トーン、形式、ターゲットオーディエンス、そして自由書ガイドラインはすべてここにあります。アカウントのベース「声」を設定し、個別のローカルの特定のフィールドを上書きできるので、日本語のコピーはよりフォーマルになり、英語は会話し合い調のままであるように設定できます。

**用語** 用語の意味とローカライズ方法を定義します。各エントリには定義とそのローカルの翻訳が含まれています。エージェントがソースコンテンツで "workspace" に遭遇した際、用語集はそれをローカライズするか、音訳するか、そのまま残すか、そしてそれぞれのターゲット言語でどの単語を使用すべきかを指示します。

声と用語は、エージェントのすべての実行で参照されるコンテキスト層を構成します。この層への投資が多ければ多いほど、出力に必要なレビューは少なくなります。

## 不変バージョン管理

言語メモリは追記専用です。ボイスや用語を更新する場合、Glossia は旧バージョンを上書きせず、新しいバージョンを作成します。各バージョンは、作成者、作成時刻、および変化内容について説明するオプションの変更メモを記録します。

つまり、常に完全な監査証跡があります。バージョン 3 とバージョン 7 を比較することで、四半期を跨いでトーンがどのように変化してきたかを理解できます。最近の変更で不整合が発生した場合、以前のバージョンにロールバックして進められます。

バージョン管理は協力をより安全にします。複数のチームメンバーは各変更が個別且つ追跡可能であるため、衝突を気にせずボイスの変更を提案できます。

## ロケール対応の解決

エージェントが特定のロケールのワークフローを実行すると、Glossia はそのコンテキストの言語メモリを解決します。まず基本ボイス設定から始まり、その後、ロケール固有の上書きを適用します。用語についても同様で、ターゲットロケールにローカライズされた用語を持つエントリのみが含まれます。

この解決工程により、エージェントは常に最も関連性の高いコンテキストで作業できます。言語ごとに別の設定を維持する必要はありません。デフォルトを一度定義し、必要な場所で上書きし、解決システムに残りを任せてください。

## どこでもご利用ください

言語メモリはローカリゼーション用に設計されましたが、テキストを生成する場所ではどこでも有用です。コンテキストはそれを介してアクセス可能であるため [REST API](/features/rest-api) と [MCP サーバー](/features/mcp-server)、ローカライゼーションの範囲を超えたワークフローにも統合できます：

**マーケティングおよび SNS コンテンツ** -- 組織のトーンをコンテンツエージェントに適用し、ソーシャルメディア投稿、メールキャンペーン、ランディングページのコピーを生成します。用語管理によりブランド用語の一貫性を保ち、トーン設定によりブランドに合わせたトーンを確保します。

**ドキュメント** -- ドキュメントパイプラインに言語知識を投入し、技術ライティングがコンテンツの他の部分と同じスタイルルールに従うようにします。用語エントリにより、ドキュメント、ヘルプ記事、製品内コピーで一貫性のズレを防ぎます。

**コードレビュー** -- あなたの「声」と「用語」を基準に、プルリクエストの文章（エラーメッセージ、UI ラベル、オンボーディングテキスト）をレビューするエージェントを構築します。出荷前に不整合を指摘してください。

**カスタムエージェント** -- どの MCP 互換クライアントでも言語メモリを読み書きできます。コーディングアシスタントに "新しい製品名で用語を更新" または "ドイツ語の言語環境におけるプロフェッショナルな声のトーン設定" と指示し、あなたの意図を正しい API 呼び出しに変換します。

## 段階的な洗練

言語メモリは使用により向上します。レビュー担当者がエージェントの出力を修正するたびに、その修正は次のバージョンの声または用語に反映されます。時間の経過とともに、初案と最終出力のギャップは縮まり、レビュー工程はより速くなります。

これが Glossia の中心にあるフィードバックループです：生成、レビュー、コンテキストの洗練、再度生成。エージェントは単に指示に従うだけではありません。彼らは、サイクルごとに向上するコンテキストを活用します。
