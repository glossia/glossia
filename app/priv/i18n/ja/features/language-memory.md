## 言語メモリとは何ですか？

言語メモリは、Glossia のエージェントが貴社の組織のコミュニケーション方法を理解するための蓄積されたコンテキストです。時間とともに作成し、洗練させられる 2 つの中核的な要素によって構成されています：

**ボイス** コンテンツがどのような響きを持つべきかを定義します。トーン、フォーマルネス、ターゲットオーディエンス、自由形式のガイドラインなど、すべてここにあり、アカウント全体でベースのボイスを設定でき、個々のロケールで特定のフィールドをオーバーライドすることで、日本語のコンテンツはよりフォーマルになり、英語は対話的なままにができます。

**用語** 用語の意味と翻訳方法を定義します。各エントリには定義と局所別の翻訳が含まれています。エージェントがソースコンテンツで "workspace" に遭遇した際、用語は翻訳、音訳、またはそのままにするかを判断し、各ターゲット言語で使用する単語を正確に指示します。

ボイスと用語は、エージェントが各実行で参照するコンテキスト層を形成します。この層への投資が増えるほど、出力のレビュー作業は減ります。

## 不変バージョン管理

言語メモリは追加専用です。ボイス設定や用語を更新すると、Glossia は古いものを上書きするのではなく新しいバージョンを作成します。各バージョンには、作成者、作成日時、および変化内容を説明するオプションの変更注釈が記録されています。

これにより常に完全な監査証跡が確保されます。バージョン 3 とバージョン 7 を比較することで、四半期間のトーン変化を理解できます。最近の変更で不整合が生じた場合は、以前のバージョンにロールバックして作業を継続してください。

バージョニングもコラボレーションをより安全にします。複数のチームメンバーがボイス設定の変更を提案しても、競合を心配する必要はありません。これは各変更が個別かつ追跡可能なイベントとなるためです。

## ロケール対応解決

特定のロケール向けにワークフローを実行すると、エージェントはコンテキストの言語メモリを解決します。基本のボイス設定に基づき、ロケール固有のオーバーライドを適用します。用語についても同様で、ターゲットロケール向けにローカライズされた用語があるエントリのみが含まれます。

この解決ステップにより、エージェントは常に最も関連性の高いコンテキストで作業します。言語ごとに異なる設定を維持する必要はありません。一度デフォルトを設定し、必要な場所でオーバーライドを行い、残りは解決システムに委ねてください。

## どこでも活用

言語メモリはローカライゼーション用に設計されましたが、テキストを作成するどの場面ででも役立ちます。コンテキストは以下を通じて [REST API](/features/rest-api) と [MCP サーバー](/features/mcp-server), ローカリゼーションを越えたワークフローに統合できます:

**マーケティングおよび SNS コンテンツ** -- 組織の声をコンテンツエージェントに適用し、SNS 投稿、メールキャンペーン、ランディングページの原稿を作成します。用語はブランド用語の一貫性を維持し、声設定はブランドのトーンと一致します。

**ドキュメント** -- 言語メモリをドキュメントパイプラインに投入し、テクニカルライティングが他のコンテンツと同じスタイル規則に従うようにします。用語一覧はドキュメント、ヘルプ記事、製品内コピー全体にわたる不統一を防ぎます。

**コードレビュー** -- あなたのトーンと用語に照らして、プルリクエストのテキスト（エラーメッセージ、UI ラベル、オンボーディングテキスト）をレビューするエージェントを作成します。公開前に不整合を指摘します。

**カスタムエージェント** -- 任意の MCP 互換クライアントは言語メモリを読み書きできます。コーディングアシスタントに&#10;"新製品名で用語を更新"または&#10;"ドイツ語ローカルでトーンをプロフェッショナルにする"と指示し、あなたの意図を適切な API 呼び出しに変換します。

## 段階的な洗練

言語メモリは使用によって向上します。レビュアーがエージェントの出力を修正するたびに、その修正はあなたの次回のトーンまたは用語バージョンに反映されます。時間とともに、最初のドラフトと最終出力の差は縮まり、レビュー工程もより速くなります。

これが、Glossia の中核にあるフィードバックループです：生成、レビュー、文脈の洗練、再生成。エージェントは単に指示に従うだけではありません。それらは、サイクルごとに改善されていく文脈を基に作業します。
