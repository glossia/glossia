## 言語メモリとは何ですか？

言語メモリは、組織のコミュニケーション方法を Glossia のエージェントに伝えるための蓄積された文脈です。これは、時間の経過とともに作成し、洗練させる 2 つの基本的な要素で構成されています：

**声** コンテンツがどのような響きを持つべきかを定義します。トーン、フォーマルさ、対象読者、自由記述のガイドラインはすべてここに入ります。アカウントのベースの声を設定し、特定のローカルのフィールドを上書きすることで、日本語のコピーはよりフォーマルになり、英語のコピーは会話調のままにできます。

**用語集** 用語の意味とそのローカライズ方法を定義します。各項目には定義とローカル翻訳が含まれます。エージェントがソースコンテンツ内で "workspace" に遭遇した際、用語集はローカライズするか、音訳するか、原文のままにするかを指示し、ターゲット言語ごとに使用すべき正確な用語を指定します。

声と用語集は、エージェントの各実行時に参照する文脈層を形成します。この層への投資が増えるほど、出力を確認する必要がある量が減ります。

## 不変バージョン管理

言語メモリは追加専用です。声や用語を更新すると、Glossia は古いものの上書きではなく新しいバージョンを作成します。各バージョンには作成者、日時、および何が変化したかを示すオプションの変更メモが記録されます。

これにより常に完全な監査証跡が保たれます。バージョン 3 と 7 を比較して、四半期の中でトーンがどのように変化したかを理解できます。最近の変更で不整合が生じた場合、以前のバージョンに戻って作業を続けます。

バージョン管理により共同作業も安全になります。複数のチームメンバーは競合を気にせず声の変更を提案でき、各変更は個別で追跡可能なイベントだからです。

## ローケール対応解決

エージェントが特定のローケールのワークフローを実行すると、Glossia は该文脈の言語メモリを解決します。まずベースの声設定から始め、その後ローケール固有のオーバーライドを適用します。用語についても同様で、ターゲットローケール向けのローカライズされた用語を持つ項目のみが含まれます。

この解決ステップにより、エージェントは常に最も関連性の高い文脈で作業できます。言語ごとに個別の設定を維持する必要はありません。デフォルトを一度定義し、必要な場所でただオーバーライドし、残りを解決システムに任せてください。

## どこでも使用

言語メモリはローカライゼーションのために設計されましたが、テキストを作成するあらゆる場所で役立ちます。コンテキストはこの通りアクセス可能です [REST API](/features/rest-api) と [MCP サーバー](/features/mcp-server), ローカライゼーションを超えたワークフローにも統合できます：

**マーケティングとソーシャルコンテンツ** -- 組織のトーンをコンテンツエージェントに反映させ、ソーシャルメディア投稿、メールキャンペーン、またはランディングページのコピーを生成します。用語集はブランド用語の一貫性を保ち、トーン設定はブランドのトーンに合わせます。

**ドキュメント** -- 言語メモリをドキュメントパイプラインに投入し、テクニカルライティングがコンテンツ全体のスタイルルールに従うようにします。用語集エントリはドキュメント、ヘルプ記事、および製品内コピー間のズレを防ぎます。

**コードレビュー** -- あなたのトーンと用語に準拠して、プルリクエストのテキスト（エラーメッセージ、UI ラベル、オンボーディングテキスト）をレビューするエージェントを構築します。公開前に不整合を指摘します。

**カスタムエージェント** -- どの MCP 互換クライアントも言語メモリを読み書きできます。コーディングアシスタントに "新しい製品名で用語を更新する"、または "ドイツ語向けにトーンをプロフェッショナルに設定する" と指示すると、あなたの意図を正しい API コールに変換します。

## 段階的洗練

言語メモリは使用により改善します。レビュー者がエージェントの出力を修正するごとに、その修正案はあなたのトーンや用語の次のバージョンに反映されます。時間経過とともに、ファーストドラフトと最終出力の間のギャップは狭まり、レビューステップも速くなります。

これが Glossia の核となるフィードバックループです：生成、レビュー、コンテキストの改善、再度生成。エージェントは単に指示に従うだけではありません。彼らは、サイクルごとに向上するコンテキストを基に作業を行います。
