## 言語メモリとは何ですか？

言語 memoria は、Glossia のエージェントが貴社の組織がどのようにコミュニケーションを行うかを示す蓄積されたコンテキストのことです。時間をかけて作成し、洗練させていく 2 つの核心要素から構成されています：

**ボイス** コンテンツがどのようなトーンになるべきかを定義します。トーン、フォーマル感、対象読者、およびフリーフォームガイドラインはすべてここに格納されています。アカウント全体用のベースのボイスを設定し、特定のローケルごとにフィールドを上書きすることで、日本語のテキストをよりフォーマルにしつつ、英語は会話調のままであるようにできます。

**用語** 用語の意味とそれをどうローカライズすべきかを定義します。各エントリには定義と各ローケルごとの翻訳が含まれています。エージェントがソースコンテンツに "workspace" に遭遇した場合、用語定義はこれをローカライズ、音写、あるいはそのままにするかどうか、および各ターゲット言語で正確にどの単語を使用すべきかを指示します。

ボイスと用語は、エージェントが各実行時に参照するコンテキスト層を形成します。この層への投資を深化させるほど、出力に必要なレビュー量は少なくなります。

## 不変のバージョン管理

言語メモリは追記専用です。ボイスや用語を更新すると、Glossia は以前のものを上書きするのではなく、新しいバージョンを作成します。各バージョンには、作成者、作成日時、および進化の内容を説明するオプションの変更ノートが記録されます。

これにより常に完全な監査証跡があります。バージョン 3 をバージョン 7 と比較して、トーンが四半期を通じてどのように変化していたかを理解できます。最近の変更が不整合を引き起こした場合は、以前のバージョンにロールバックして進めてください。

バージョニングはコラボレーションをより安全にします。各変更が独立した追跡可能なイベントであるため、複数のチームメンバーは、不整合を気にすることなくボイスの変更を提案できます。

## ロケール対応の解決

エージェントが特定のロケール向けのワークフローを実行する際、Glossia はそのコンテキストにおける言語メモリを解決します。まずベースボイス設定から始まり、その後、ロケール固有の上書き設定を適用します。用語についても同様で、ターゲットロケールのローカライズ済み用語を持つエントリのみが含まれます。

この解決ステップにより、エージェントは常に最も関連性の高いコンテキストで作業します。各言語ごとに別の設定を維持する必要はありません。デフォルト設定を一度定義し、必要な場所に上書きし、残りは解決システムが処理します。

## どこでも使える

言語メモリはローカライズのために設計されましたが、テキストを作成するあらゆる場所で役立ちます。コンテキストが…を通じてアクセスできるため [REST API](/features/rest-api) 、および [MCP サーバー](/features/mcp-server)、ローカライズ作業以外のワークフローに統合できます：

**マーケティングおよびソーシャルコンテンツ** -- 組織のトーンをコンテンツエージェントに設定し、ソーシャルメディア投稿、メールキャンペーン、またはランディングページのコピーを作成します。用語はブランド用語の整合性を保ち、トーン設定はブランドのトーンに合わせます。

**ドキュメント** -- 言語メモリをドキュメントパイプラインに供給し、技術ライティングも他のコンテンツと同様のスタイルルールに従います。用語エントリはドキュメント、ヘルプ記事、および製品内コピーにおけるズレを防ぎます。

**コードレビュー** -- ボイスと用語集を基準に、プルリクエストコピー（エラーメッセージ、UI ラベル、オンボーディングテキスト）をレビューするエージェントを構築します。出荷前に不整合を指摘します。

**カスタムエージェント** -- いずれの MCP 互換クライアントも言語メモリの読み書きが可能です。コーディングアシスタントに「新しい製品名で用語を更新する」または「ドイツ語のロケール向けにプロフェッショナルなボイストーン設定する」と指示すれば、意図を適切な API 呼び出しに変換します。

## 段階的な洗練

言語メモリは使用頻度に応じて改善します。レビュヤーがエージェントの出力を修正するたびに、その修正は次のバージョンのボイスまたは用語集に反映されます。時間が経つにつれ、ファーストドラフトと最終出力のギャップは縮まり、レビューステップもより速くなります。

これが Glossia の中核にあるフィードバックループです：生成、レビュー、コンテキストの洗練、再度生成。エージェントは単に指示に従うだけではありません。彼らは、各サイクルでより良くなるコンテキストを用いて作業します。
