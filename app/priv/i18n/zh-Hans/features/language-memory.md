## 什么是语言记忆？

语言记忆是累积的上下文，它告诉 Glossia 的智能体您的组织如何交流。它由两项核心要素构成，您随时间创建并不断完善这些要素：

**语言风格** 它定义了内容应呈现的声音。语调、正式程度、目标受众以及开放式指南均在此定义。您可以为账户设置基础语言风格，然后针对各个区域覆盖特定字段，这样您的日语内容可以更加正式，而英语内容保持轻松自然的对话风格。

**术语** 它定义了术语的含义及其应如何进行本地化。每个条目都包含定义和各个区域的译本。当智能体在您源内容中遇到“工作区”时，术语会指示它是进行本地化、音译还是保持原样，并在每个目标语言中使用哪个确切单词。

语言风格和术语共同构成一个上下文层，智能体在每次运行时都会查阅它。在该层面上的投入越多，您对其输出所需的审查就越少。

## 不可变版本控制

语言记忆仅支持追加写入。当您更新语音或术语时，Glossia 会创建新版本而不是覆盖旧版本。每个版本都记录了创建者、时间以及一条可选的变更说明，解释发生了哪些演变。

这意味着您始终拥有完整的审计记录。您可以将第 3 版与第 7 版进行比较，以便了解您的语气在一个季度内是如何变化的。如果最近的更改引入了不一致之处，请回滚到之前的版本并继续操作。

版本控制也让协作更加安全。多名团队成员可以在不担心冲突的情况下提出语音变更，因为每次变更都是一个独立且可追踪的事件。

## 区域感知解析

当智能体为特定区域运行工作流时，Glossia 会解析该上下文的语言记忆。它首先基于您的基础语音设置，然后应用任何区域特定的覆盖设置。术语处理同样如此：仅包含针对目标区域具有本地化术语的条目。

此解析步骤意味着智能体始终使用最相关的上下文。您无需为每种语言维护单独的配置。仅需一次性定义默认值，在所需的地方进行覆盖，其余交由解析系统处理。

## 随处使用

语言记忆是为本地化而设计的，但在任何您需要生成文本的地方也同样有用。因为上下文可通过该 [REST API](/features/rest-api) 和 [MCP 服务器](/features/mcp-server), 您可以将其集成到超出本地化的工作流中：

**营销和社会内容** -- 将您组织的“声音”融入内容代理，用于起草社交媒体帖子、电子邮件活动或落地页文案。“术语”可确保品牌术语一致，“声音”设置则确保语调与您的品牌相符。

**文档** -- 将语言记忆输入文档流水线，使技术写作遵循与其余内容相同的风格规范。“术语”条目可防止在文档、帮助文章及产品内文案中产生风格偏差。

**代码审查** -- 构建一个代理，审查拉取请求文案（错误消息、UI 标签、引导文本），并对照您的语气和术语。在发布前标记不一致之处。

**自定义代理** -- 任何兼容 MCP 的客户端均可读取和写入语言记忆。告诉您的编程助手 "使用新产品名称更新术语" 或 "将德语区域的语气基调设置为专业"，它会将您的意图转换为正确的 API 调用。

## 渐进式完善

语言记忆随使用而提升。每当审查员修正代理的输出，该修正就会反馈到语气或术语的下一个版本中。随着时间的推移，初稿与最终输出之间的差距缩小，审查步骤也随之变得更快。

这是 Glossia 核心的反馈循环：生成、审查、优化上下文，再生成。智能体不仅仅是遵循指令。它们在每次循环中，都处理着持续优化的上下文。
