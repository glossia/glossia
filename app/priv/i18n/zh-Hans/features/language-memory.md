## 什么是语言记忆？

语言记忆是向 Glossia 的代理传达您的组织沟通方式的累积上下文。它由您随着时间创建和精简的两个核心要素组成：

**语气** 它定义内容应该有的风格。语气、正式程度、目标受众和自由格式准则都包含在此。您可以为账户设置基础语气，然后覆盖各区域特定字段，使您的日语内容更正式，而英语内容保持对话风格。

**术语** 它定义术语的含义及其本地化方式。每个条目包含定义和区域翻译。当代理在您的源内容中遇到 "workspace" 时，术语会指示其进行本地化、音译还是保留原样，以及在每种目标语言中使用的确切词汇。

语气和术语共同构成了代理每次运行时都会查询的上下文层。您在此层上的投入越多，您的输出所需审核就越少。

## 不可变版本控制

语言记忆是追加式的。当您更新语音或术语时，Glossia 将创建一个新版本而非覆盖旧版本。每个版本都会记录创建者、时间，以及可选的变更说明，解释其演进内容。

这意味着您始终拥有完整的审计日志。您可以比较第 3 版和第 7 版，以了解您的语调在季度内发生了何种变化。如果最近的变化引入了不一致，请回滚到先前的版本并继续操作。

版本控制也能使协作更安全。多位团队成员可以提出语音变更而无需担心冲突，因为每次变更都是离散的、可追踪的事件。

## 区域感知解析

当智能体为特定区域运行工作流时，Glossia 会解析该上下文的语言记忆。它首先应用您的基础语音设置，然后叠加任何特定区域的覆盖规则。术语也是一样：仅包含目标区域有本地化术语的条目。

这个解析步骤意味着智能体始终使用最相关的上下文。您无需为每种语言维护单独配置。一次定义默认值，在需要时覆盖，然后将其余部分交由解析系统处理。

## 随处使用

语言记忆专为本地化设计，但它在任何您生成文本的地方都很有用。因为上下文可通过... [REST API](/features/rest-api) 以及 [MCP 服务器](/features/mcp-server), 您可以将其整合到本地化之外的工作流中：

**营销与社交内容** -- 将组织的风格注入内容代理，由其起草社交媒体帖子、电子邮件活动或落地页文案。术语保持品牌术语一致，声音设置确保语调与您的品牌相符。

**文档** -- 将语言记忆输入文档流程，使技术写作遵循与其余内容相同的风格规则。术语条目防止在文档、帮助文章和产品内文案中产生偏差。

**代码审查** -- 构建一个代理来审查拉取请求文案（错误消息、UI 标签、引导文本）是否符合您的声音和术语规范，在发布前标记出不一致之处。

**自定义代理** -- 任何兼容 MCP 的客户端都可以读取和写入语言记忆。您可以指示您的编码助手"用新产品名称更新术语"或"为德语区域设置专业声音基调"，它会将您的意图转换为正确的 API 调用。

## 渐进式优化

语言记忆随使用而不断改善。每次审查者更正代理的输出时，这些修正都会反馈到您的声音或术语规范的下一版本中。随着时间的推移，初稿与最终输出之间的差距逐渐缩小，审查步骤变得更快。

这就是 Glossia 核心的反馈循环：生成、审查、优化上下文、再次生成。智能体不仅仅遵循指令。它们在与每一轮都更加完善的上下文中工作。
