## 什么是语言记忆？

语言记忆是累积的上下文，告诉 Glossia 智能体您组织的沟通方式。它由两个核心基本要素组成，您会随时间创建并不断完善它们：

**语音** 定义了内容应有的声音。语调、正式程度、目标受众和非结构化指南均在此处。您可以为账户设置基础语音，随后为各个区域覆盖特定字段，因此您的日语内容可以更加正式，而英语保持对话风格。

**术语** 定义了术语的含义及应如何本地化。每个条目包含定义和按区域划分的翻译。当智能体在您的源内容中遇到"workspace"时，术语会告知它是否翻译、音译或原样保留，以及每种目标语言应使用的确切词汇。

语音和术语共同构成智能体每次运行都会查阅的上下文层。在此层投入越多，输出所需的复核就越少。

## 不可变版本控制

语言记忆仅支持追加写入。当您更新风格或术语时，Glossia 会创建新版本而不是覆盖旧版本。每个版本都记录了创建者、时间，以及可选的变更备注，解释其演变内容。

这意味着您始终拥有完整的审计记录。您可以比较版本 3 与版本 7，以了解您的风格如何在季度内发生转变。如果最近的变更引入了不一致，回滚到之前的版本并继续。

版本控制也提升了协作的安全性。多名团队成员可以提议风格变更而无需担心冲突，因为每个变更都是一个独立且可追溯的事件。

## 区域感知解析

当代理为特定区域运行工作流时，Glossia 会为该上下文化解语言记忆。它从您的基础风格设置开始，然后应用任何特定于区域的覆盖。术语同理：仅包含对目标区域有本地化术语的条目。

此解析步骤意味着代理始终处理最相关的上下文。您无需为每种语言维护单独配置。只需定义一次默认值，在需要时覆盖，让解析系统处理其余部分。

## 随处使用

语言记忆专为本地化设计，但它在任何需要生成文本的地方都有用。因为上下文可通过该 [REST API](/features/rest-api) 以及 [MCP 服务器](/features/mcp-server), 你可以将其集成到本地化以外的其他工作流程中：

**营销与社媒内容** -- 将组织的品牌语调引入用于草拟社交媒体帖子、邮件营销活动或着陆页文案的内容智能体中。术语保持品牌术语一致，语调设置确保基调与您的品牌相符。

**文档** -- 将语言记忆注入文档流水线，使技术写作遵循其余内容的统一风格规则。术语条目防止文档、帮助文章和产品内文案出现风格偏差。

**代码评审** -- 创建一个代理，审核拉取请求文案（错误消息、UI 标签、入职文本）是否符合您的声调和术语，并在发布前标记不一致之处。

**自定义代理** -- 任何支持 MCP 的客户端都可以读写语言记忆。请要求您的编程助手"用新产品名称更新术语"或"将德语区域的声调设为专业"，它会将其意图转化为正确的 API 调用。

## 渐进式优化

语言记忆随使用而不断提升。每次审核员修正代理的输出时，该修正都会反馈到您的声调或术语的下一个版本中。随着时间的推移，初稿与最终产出之间的差距逐渐缩小，审查步骤也会变得更加快速。

这正是 Glossia 的核心反馈循环：生成、审查、优化上下文、再次生成。智能体不仅仅遵循指令。它们所依赖的上下文每轮都会不断优化。
