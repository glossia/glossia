## 什么是语言记忆？

语言记忆是累积的上下文，它告诉 Glossia 的代理您的组织如何沟通。它由您随时间创建和完善的两个核心原语组成：

**声音** 定义内容应如何发声。语气、正式程度、目标受众以及自由式指南均在此设定。您可以为账户设置基础声音，然后为各个区域覆盖特定字段，因此您的日语内容可以更加正式，而英语内容则保持自然的对话风格。

**术语** 定义术语的含义及其本地化方式。每个条目包含定义和各区域的翻译。当代理在您的源内容中遇到 "workspace" 时，术语指示其是进行本地化、音译还是保留原样，并说明在每个目标语言中应使用的确切词汇。

声音和术语共同构成一个上下文层，代理在每次运行中都会据此查阅。您在此层投入越多，输出所需的审核就越少。

## 不可变版本控制

语言记忆是仅追加式的。当您更新语音或术语时，Glossia 会创建一个新版本而非覆盖旧版本。每个版本都记录创建者、创建时间以及一个可选的变更说明（解释其演变内容）。

这意味着您始终拥有完整的审计轨迹。您可以对比版本 3 与版本 7，以了解您的语气在一个季度内是如何变化的。如果最近的变更引入了不一致之处，请回滚到之前的版本并继续。

版本管理也让协作更安全。多名团队成员可以提议语音变更而无需担心冲突，因为每个变更都是一个独立的、可追溯的事件。

## 区域感知解析

当代理针对特定区域运行工作流时，Glossia 会解析该上下文的语言记忆。它首先基于您的基础语音设置，随后应用任何针对该区域的特定覆盖项。术语的处理相同：仅包含针对目标区域具有本地化术语的条目。

这一解析步骤意味着代理始终处理最相关的上下文。您无需为每种语言维护单独的配置文件。只需定义一次默认值，在需要时覆盖，并让解析系统处理其余部分。

## 随处使用

语言记忆是为本地化设计的，但它在您需要生成文本的地方同样适用。因为上下文可通过该 [REST API](/features/rest-api) 以及 [MCP 服务器](/features/mcp-server)，您可以将其集成到本地化以外的更多工作流中：

**营销与社媒内容** -- 引入您组织的语气至内容代理，以便该代理撰写社交媒体帖子、电子邮件营销活动或落地页文案。术语保持品牌术语一致，语气设置确保语调与您的品牌相符。

**文档** -- 将语言记忆输入文档流水线，使技术写作遵循与其余内容相同的风格规范。术语条目防止在文档、帮助文章及产品内文案中出现风格漂移。

**代码审查** -- 构建一个代理，审查拉取请求文案（错误消息、UI 标签、引导文本），对照您的语气和术语。在正式发布前标记不一致之处。

**自定义代理** -- 任何兼容 MCP 的客户端均可读写语言记忆。要求您的编程助手“根据新产品名更新术语”或“将德语区域的语气设定为专业”，它会将您的意图转化为正确的 API 调用。

## 渐进式优化

语言记忆随使用而增强。每次审查员更正代理的输出时，该更正会反馈至您的语气或术语的下一个版本。随着时间的推移，初稿与最终输出之间的差距缩小，审查步骤也变得更快捷。

这便是 Glossia 核心的反馈循环：生成、审查、优化上下文，再生成。智能体并非仅仅遵循指令。它们处理在每一次循环中不断优化的上下文。
