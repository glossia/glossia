## 什么是语言记忆？

语言记忆是累积的上下文，它告诉 Glossia 的代理您的组织如何进行交流。它由两个核心基础构成，您可以创建并随时间不断优化它们：

**声音** 声音定义了内容应有的风格。语调、正式程度、目标受众以及自由格式指南均在此处存储。您可以为账户设置基础声音，然后为各个区域覆盖特定字段，以便您的日语内容可以更加正式，而英语内容保持轻松的对话风格。

**术语表** 它定义了术语的含义及其本地化方式。每个条目都包含定义和针对各区域的翻译。当代理在源内容中遇到“workspace”时，术语表会告诉它是应进行本地化、音译还是保持原样，以及在每种目标语言中应使用的确切单词。

声音和术语表共同构成一个代理在每次运行时会咨询的上下文层。投入在这一层的资源越多，输出内容所需的审查就越少。

## 不可变版本化

语言记忆是仅追加的。当更新语音或术语表时，Glossia 会创建新版本而非覆盖旧版本。每个版本都记录了创建者、创建时间，以及可选的变更说明，解释发生了何种演变。

这意味着您始终拥有完整的审计记录。您可以将第 3 版与第 7 版进行比较，以了解您的语调在季度内如何变化。如果最近的变化引入了不一致，请回滚到之前的版本并继续。

版本控制也增强了协作的安全性。团队成员可以提交流音更新建议而无需担心冲突，因为每次更改都是一个独立且可追溯的事件。

## 区域感知解析

当智能体为特定区域运行工作流时，Glossia 会为该上下文解析语言记忆。它首先应用您的基础语音设置，然后叠加任何特定区域的覆盖设置。术语表同理：仅包含针对目标区域具有本地化术语的条目。

该解析步骤确保智能体始终使用最相关的上下文。您无需按语言维护不同的配置。一次性定义默认值，仅在必要时覆盖，其余部分由解析系统处理即可。

## 随处使用

语言记忆专为本地化而设计，但它在您生成任何文本的地方都很有用。因为上下文可通过 [REST API](/features/rest-api) 和 [MCP 服务器](/features/mcp-server), 您可以将其集成到本地化之外的工作流程中：

**营销与社交媒体内容** -- 将组织的品牌声音引入内容代理，该代理可起草社交媒体帖子、电子邮件营销活动或着陆页文案。术语表保持品牌术语的一致性，语调设置确保语气与品牌相符。

**文档** -- 将语言记忆注入文档流程，使技术写作遵循与其他内容相同的风格规则。术语表条目防止文档、帮助文章及产品内文案出现术语偏离。

**代码审查** -- 构建一个代理来审查拉取请求中的文案（错误消息、UI 标签、引导文本），并将其与您的语调及词汇表进行对照。在发布前标记出不一致之处。

**自定义代理** -- 任何兼容 MCP 的客户端都可以读写语言记忆。指示您的编程助手"使用新产品名称更新词汇表"或"为德语区域设置语调为专业"，它会将您的意图转换为正确的 API 调用。

## 渐进式完善

语言记忆通过不断使用而提升。每当审查员修正代理的输出时，修正内容便会反馈到下一版本的语调或词汇表中。随着时间的推移，初稿与最终输出之间的差距逐渐缩小，审查步骤也变得更加高效。

这就是 Glossia 核心的反馈循环：生成、审查、优化上下文并再次生成。代理不仅仅是遵循指令。它们工作在随着每个周期而不断改进的上下文中。
