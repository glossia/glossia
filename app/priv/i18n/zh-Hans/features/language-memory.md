## 什么是语言记忆？

语言记忆是累积的上下文，它告诉 Glossia 的智能体贵组织的沟通方式。它由两个核心基础构成，您会随时间创建并加以完善：

**语域**定义了内容应呈现的听感。语气、正式程度、目标受众和开放式指南均在此。您可以为账户设置基础语域，然后为各个地区覆盖特定字段，因此您的日语文案可以更加正式，而英语保持轻松的对话风格。

**术语表**定义了术语的含义及其应如何处理。每个条目都包含定义和特定地区的翻译。当智能体在源代码中遇到“工作区”时，术语表会指示它是进行本地化、音译还是保持原样，以及在每种目标语言中应使用哪个确切单词。

语域和术语表共同构成智能体每次运行时都会查阅的上下文层。您在此层投入越多，输出所需审查就越少。

## 不可变版本管理

语言记忆是追加式的。当您更新语域或术语表时，Glossia 会创建新版本而不是覆盖旧版本。每个版本都记录了创建人、时间及用于解释变化的可选说明。

这意味着您始终拥有完整的审计记录。您可以对比第 3 版与第 7 版，了解语气在季度间的变化。如果最近的变化引入了不一致之处，请回滚到之前的版本并继续操作。

版本管理也让协作更加安全。多名团队成员可以提议语域修改而无需担心冲突，因为每次更改都是一个离散的、可追溯的事件。

## 地区感知解析

当智能体为特定地区运行工作流时，Glossia 会解析该上下文的语言记忆。它从您的基础语域设置开始，然后在顶层应用任何特定地区的覆盖设置。术语表的处理也是如此：仅包含针对目标地区有翻译条目的项。

这个解析步骤意味着智能体始终在最具相关性的上下文中工作。您无需为每种语言维护单独的配置文件。只需定义默认设置一次，在需要的地方进行覆盖，剩下的交由解析系统处理。

## 随处应用

语言记忆专为本地化而设计，但在任何生成文本的地方都很有用。由于该上下文可通过 [REST API](/features/rest-api) 和 [MCP 服务器](/features/mcp-server) 访问，您可以将其集成到本地化范畴之外的工作流中：

**营销及社交媒体内容** -- 将贵组织的语域导入用于起草社交媒体帖子、电子邮件活动或着陆页文案的内容智能体中。术语表保持品牌术语的一致性，语域设置确保语气符合品牌。

**文档** -- 将语言记忆输入文档流程，使技术写作遵循除了您的内容之外的统一风格规则。术语表条目防止了文档、帮助文章和内置文案中的风格漂移。

**代码审查** -- 构建一个智能体来审查拉取请求文案（错误消息、UI 标签、入门引导文本），并将其与您的语域和术语表进行比对。在发布前标记不一致之处。

**自定义智能体** -- 任何兼容 MCP 的客户端都可以读写语言记忆。向您的编程助手发出“更新术语表以包含新产品名称”或“将德语地区的语域语调设置为专业”等操作，它会将其意图翻译成正确的 API 调用。

## 渐进式优化

语言记忆会随着使用而改进。每次审阅者纠正智能体的输出时，该纠正都会反馈到您的语域或术语表的下一个版本中。随着时间的推移，首稿与最终输出之间的差距会缩小，审查步骤也会变得更加快速。

这就是 Glossia 的核心反馈循环：生成、审查、优化上下文，再次生成。智能体不仅遵循指令。它们在每一轮循环中都会变得越来越好的上下文中工作。
