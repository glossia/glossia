## 什么是语言记忆？

语言记忆是累积的上下文，它告诉 Glossia 的代理你的组织如何沟通。它由两个核心原语组成，由您随着时间的推移创建和完善：

**声音** 定义内容应呈现的方式。语气、正式程度、目标受众以及自由形式指导都包含在这里。您可以为您的账户设置基础声音，然后覆写各个区域的特定字段，这样您的日语文案可以更加正式，而您的英语保持口语化。

**术语表** 定义了术语的含义以及如何本地化它们。每个条目都包含定义和各区域翻译。当代理在您的源内容中遇到 "workspace" 时，术语表会告知它是进行本地化、音译还是保持不变，以及在每种目标语言中确切使用哪个单词。

声音和术语表共同形成一个上下文层，代理在每次运行时都会咨询该层。您对这一层投入得越多，输出所需的审阅就越少。

## 不可变版本控制

语言记忆是仅追加的。当您更新声音或术语表时，Glossia 会创建一个新版本而不是覆盖旧版本。每个版本都会记录创建者、时间以及一个可选的变更说明，解释发生了什么演变。

这意味着您始终拥有完整的审计日志。您可以将第 3 版本与第 7 版本进行比较，以了解您的语气在一季度内如何发生变化。如果最近的变更引入了不一致性，请回退到以前的版本并继续。

版本控制也使协作更安全。多个团队成员可以提出声音变更而无需担心冲突，因为每个变更都是一个独立的、可追踪的事件。

## 区域感知解析

当代理为特定区域运行工作流时，Glossia 会为该上下文解析语言记忆。它从您的基础声音设置开始，然后在上面应用任何特定区域的重写项。术语表也是如此：仅包含针对目标区域具有本地化术语的条目。

这个解析步骤意味着代理始终使用最相关的上下文。您无需为每种语言维护单独的配置。定义一次默认值，在需要的位置进行重写，让解析系统处理其余部分。

## 随处使用

语言记忆是为本地化设计的，但它在任何生成文本的地方都有用。因为上下文可通过 [REST API](/features/rest-api) 和 [MCP 服务器](/features/mcp-server) 访问，您可以将其集成到超越本地化的工作流中：

**营销及社交内容** -- 将组织的声音提取到内容代理中，使其起草社交媒体帖子、电子邮件宣传活动或落地页文案。术语表保持品牌术语一致，声音设置确保语气与您的品牌匹配。

**文档** -- 将语言记忆输入文档流水线，使技术写作遵循与您其余内容相同的样式规则。术语表条目防止在文档、帮助文章和产品内文案之间产生漂移。

**代码审查** -- 构建一个代理来审查拉取请求文案（错误消息、UI 标签、引导文本），并将其与您的声音和术语表进行核对。在发布前标记不一致之处。

**自定义代理** -- 任何符合 MCP 标准的客户端都可以读写语言记忆。要求您的编程助手“使用新产品名称更新术语表”或“为德语区域设置专业语气”，它会将您的意图转换为正确的 API 调用。

## 渐进式优化

语言记忆会随着使用而改进。每当审阅者纠正代理的输出时，该纠正措施都会反馈到您的声音或术语表的下一个版本中。随着时间的推移，初稿和最终输出之间的差距缩小，审阅步骤也会更快。

这是 Glossia 核心的反馈循环：生成、审阅、优化上下文、再次生成。代理不仅遵循指令。它们工作在每个循环都更好的上下文中。
