## 什么是语言记忆？

语言记忆是积累形成的上下文，用于告知 Glossia 的智能体您的组织如何进行沟通。它由两项核心要素构成，您可以持续创建并完善这些要素：

**语言风格**定义内容应呈现的表达方式。语气、正式程度、目标受众和自由格式的指南均在此处设置。您可以为账户设定基础语言风格，然后针对各个区域设置覆盖特定字段。例如，日语文案可以更加正式，而英语文案仍保持自然亲切。

**术语**定义词语的含义及其本地化方式。每个条目都包含定义和各区域设置对应的译文。当智能体在源内容中遇到“workspace”时，术语会指明应将其本地化、音译还是保留原文，并明确指定每种目标语言应使用的词语。

语言风格与术语共同构成智能体每次运行时都会参考的上下文层。您在这一层投入得越多，输出内容所需的审核就越少。

## 不可变版本控制

语言记忆仅允许追加。当您更新语言风格或术语时，Glossia 会创建新版本，而不是覆盖旧版本。每个版本都会记录创建者、创建时间，以及用于说明变更内容的可选变更备注。

这意味着您始终拥有完整的审计记录。您可以比较版本 3 和版本 7，了解一个季度内语气发生了怎样的变化。如果近期变更造成了不一致，可以回滚到先前版本并继续工作。

版本控制还能提高协作安全性。多名团队成员可以提出语言风格变更，无需担心冲突，因为每项变更都是独立且可追溯的事件。

## 感知区域设置的解析

当智能体针对特定区域设置运行工作流时，Glossia 会解析适用于该上下文的语言记忆。它首先采用基础语言风格设置，然后应用所有针对该区域设置的覆盖项。术语也采用同样的处理方式：仅包含已提供目标区域设置本地化词语的条目。

这一解析步骤确保智能体始终使用最相关的上下文。您无需为每种语言维护单独的配置。只需定义一次默认设置，在必要时进行覆盖，其余工作交由解析系统处理。

## 在各处使用

语言记忆专为本地化而设计，但同样适用于任何文本生产场景。由于可以通过 [REST API](/features/rest-api) 和 [MCP 服务器](/features/mcp-server)访问这些上下文，您可以将其集成到本地化之外的工作流中：

**营销和社交内容**：将组织的语言风格提供给内容智能体，用于起草社交媒体帖子、电子邮件营销活动或落地页文案。术语可确保品牌用语保持一致，语言风格设置则确保语气符合您的品牌。

**文档**：将语言记忆接入文档工作流，使技术写作遵循与其他内容相同的风格规则。术语条目可避免文档、帮助文章和产品内文案之间出现表达偏差。

**代码审查**：构建一个智能体，依据您的语言风格和术语审查拉取请求中的文案，例如错误消息、用户界面标签和引导文本。在发布之前标记不一致之处。

**自定义智能体**：任何兼容 MCP 的客户端都可以读取和写入语言记忆。您可以要求编程助手“使用新产品名称更新术语”或“将德语区域设置的语言风格语气设为专业”，它会将您的意图转换为正确的 API 调用。

## 渐进式完善

语言记忆会随着使用持续改进。每当审核者修正智能体的输出时，该修正都会反馈到下一版本的语言风格或术语中。随着时间推移，初稿与最终输出之间的差距会逐渐缩小，审核过程也会更加高效。

这是 Glossia 的核心反馈循环：生成、审核、优化上下文、再次生成。智能体并非只是遵循指令，而是基于每一轮都持续完善的上下文开展工作。
