## 什么是语言记忆？

语言记忆是累积的上下文，它告诉 Glossia 的代理您的组织如何沟通。它由两个核心基元组成，您随时间创建并不断加以完善：

**语调** 定义了内容应有的声音。语气、正式程度、目标受众和自由形式指导原则均在此处。您可以为账户设置基础语调，然后为各个区域覆盖特定字段，使您的日语内容更加正式，而英语内容保持对话风格。

**术语** 定义了术语的含义及其本地化方式。每个条目包含定义和区域特定的翻译。当代理在您的源内容中遇到 "workspace" 时，术语指示它是否进行本地化、音译或保持原样，以及每种目标语言中应使用的确切单词。

语调与术语共同构成了代理每次运行都会参考的上下文层。在此层投入越多，输出所需的审查就越少。

## 不可变版本

语言记忆采用追加写入模式。当你更新语音或术语时，Glossia 会创建新版本而不是覆盖旧版本。每个版本都会记录创建者、时间，以及可选的变更说明，解释其演变过程。

这意味着你始终拥有完整的审计记录。你可以对比版本 3 和版本 7，了解一个季度内你的语调发生了怎样的变化。如果近期的更改引入了不一致，请回退到之前的版本并继续操作。

版本管理也让协作更加安全可靠。多名团队成员可以提出语音更改而不必担心冲突，因为每次更改都是一个独立、可追踪的事件。

## 本地化感知解析

当代理为特定本地化运行工作流时，Glossia 会针对该上下文解析语言记忆。它从你的基础语音设置开始，然后应用任何针对该本地的覆盖设置。术语同理：只有包含目标本地化术语的条目才会被纳入。

此解析步骤意味着代理始终使用最相关的上下文。你不需要为每种语言维护单独的配置文件。一次性定义默认值，在需要的地方覆盖，其余部分交由解析系统处理。

## 随处使用

语言记忆专为本地化而设计，但它也适用于你生成任何文本的地方。因为上下文可通过 [REST API](/features/rest-api) 和 [MCP 服务器](/features/mcp-server),你可以将其集成到超越本地化的工作流中：

**市场营销与社交媒体内容** -- 将贵组织的品牌声音引入内容代理，用于起草社交媒体帖子、电子邮件营销活动或着陆页文案。术语确保品牌用词保持一致，声音设置保证语调符合您的品牌。

**文档** -- 将语言记忆注入文档流程，使技术写作遵循与其他内容相同的风格规则。术语条目可防止在文档、帮助文章和产品内文案中出现风格漂移。

**代码审查** -- 构建一个代理以审查拉取请求的文案（错误消息、UI 标签、引导文本），对照您的语调和术语。在上线前标记出不一致之处。

**自定义代理** -- 任何 MCP 兼容客户端均可读写语言记忆。您可以指令编程助理 "使用新产品名称更新术语" 或 "将德语区域的语调设定为专业"，从而将其意图转化为正确的 API 调用。

## 渐进式优化

语言记忆随使用而提升。每当审核员纠正代理的输出，该纠正都会反馈到语调或术语的下一版本。随着时间的推移，初稿与最终输出之间的差距逐渐缩小，审查步骤也会更快。

这是 Glossia 核心的反馈循环：生成、审查、优化上下文、再次生成。智能体不仅仅是遵循指令。它们基于随每次循环而不断完善的上下文工作。
