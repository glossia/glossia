## 什么是语言记忆？

语言记忆是累积的上下文，它告诉 Glossia 的智能体您的组织如何沟通。它由两个核心原语组成，您可以在这些原语之上随时间创建和不断细化：

**语音风格** 定义了内容应该如何表达。语调、正式程度、目标受众以及自由格式指南均在此处。您可以为账户设置基础语音风格，然后针对各个区域覆盖特定字段，这样您的日语内容可以更加正式，而英语保持口语化。

**术语表** 定义了术语的含义及其本地化方式。每个条目包含定义和针对各个区域的翻译。当智能体在您的源内容中遇到 "workspace" 时，术语表会告诉它是应该本地化音译，还是原样保留，并且在每种目标语言中应使用的确切词语是哪一个。

语音风格和术语表共同构成了智能体每次运行时都会查询的上下文层。您在此层上的投入越多，您的输出所需的审核就越少。

## 不可变版本管理

语言记忆是仅追加的。当您更新语音风格或术语表时，Glossia 会创建新版本而不是覆盖旧版本。每个版本都记录了创建者、创建时间以及解释演进过程的可选变更说明。

这意味着您始终拥有完整的审计日志。您可以比较第 3 版和第 7 版，以了解语调在一个季度内如何转变。如果最近的变更引入了不一致性，请回退到之前的版本并继续进行。

版本管理也让协作更安全。多名团队成员可以提议语音风格的变更而不必担心冲突，因为每次变更都是一个离散、可追溯的事件。

## 区域感知解析

当智能体为特定区域运行工作流时，Glossia 会解析该上下文的语言记忆。它首先从您的基础语音风格设置开始，然后应用任何区域特定的覆盖。术语表的操作也是如此：仅包含针对目标区域包含本地化术语的条目。

该解析步骤意味着智能体始终使用最相关的上下文。您无需为每种语言维护单独的配置文件。一次性定义您的默认值，在关键位置覆盖，然后由解析系统处理其余部分。

## 处处可用

语言记忆是为本地化设计的，但它在任何生成文本的地方都有用。因为上下文可通过 [REST API](/features/rest-api) 和 [MCP 服务器](/features/mcp-server) 访问，您可以将其集成到除本地化之外的其他工作流中：

**营销和社交媒体内容** -- 将组织的语音风格提取至内容代理中，该代理负责起草社交媒体帖子、电子邮件活动或落地页文案。术语表保持品牌术语的一致性，语音风格设置确保语调与您的品牌相符。

**文档** -- 将语言记忆输入文档流水线，使技术写作遵循与您的其他内容相同的样式规则。术语表条目防止在文档、帮助文章和内部文案中出现风格漂移。

**代码审查** -- 构建一个代理来审查 pull 请求副本（错误消息、UI 标签、引导文本），对照您的语音风格和术语表。在发布前标记不一致之处。

**自定义代理** -- 任何兼容 MCP 的客户端都可以读取和写入语言记忆。让您的编码助手“用新产品名称更新术语表”或“将德语区域的语音语调设置为专业”，它将把您的意图转换为正确的 API 调用。

## 渐进式优化

语言记忆随使用而不断改进。每当审核员修正智能体的输出时，该修正都会反馈到您的语音风格或术语表的下一版本中。随着时间的推移，初稿和最终输出之间的差距会缩小，审核步骤也会变得更快。

这就是 Glossia 核心机制中的反馈循环：生成、审核、优化上下文、再次生成。智能体不仅仅是遵循指令。它们使用随每个循环而不断优化的上下文工作。
