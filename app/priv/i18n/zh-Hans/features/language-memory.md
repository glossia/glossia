## 什么是语言记忆？

语言记忆是累积的上下文，告诉 Glossia 的代理如何传达您组织的沟通方式。它由两个核心要素组成，您随着时间的推移创建并不断完善：

**风格** 定义了内容应呈现的风格。语气、正式程度、目标受众以及自由式准则均在此处体现。您可以为账户设置基础风格，然后为各个本地化区域覆盖特定字段，因此可以让日语内容更加正式，而英语内容保持对话式风格。

**术语** 定义术语的含义及其本地化方式。每个条目包含定义以及针对不同区域的翻译。当代理在源内容中遇到 "workspace" 时，术语会指示代理进行本地化、音译还是保留原文，并明确在每个目标语言中应使用哪个词汇。

风格 和 术语 共同构成一个上下文层，代理每次运行都会查阅这一层。您对这一层投入越多，输出所需的人工审查就越少。

## 不可变版本控制

语言记忆仅支持追加写入。当你更新语气或术语时，Glossia 会创建新版本而不是覆盖旧版本。每个版本都会记录创建者、创建时间，以及可选的变更说明，解释发生了哪些演变。

这意味着你永远拥有完整的审计记录。你可以对比版本 3 和版本 7 来了解你的语气在季度内是如何变化的。如果最近的变更引入了不一致，回滚到之前的版本然后继续。

版本化也让协作更安全。多个团队成员可以在不担心冲突的情况下提议语气变更，因为每次变更都是独立且可追踪的事件。

## 区域感知解析

当代理为特定区域运行工作流程时，Glossia 会解析该上下文的语言记忆。它从你的基础语气设置开始，然后应用任何特定区域的覆盖。术语同理：只有包含目标区域本地化术语的条目才会被包含。

这个解析步骤意味着代理始终使用最相关的上下文。你无需为每种语言维护单独的配置。只需定义一次默认值，在关键地方进行覆盖，其余交由解析系统处理。

## 随处使用

语言记忆专为本地化设计，但你在任何生成文本的地方都能用到。因为该上下文可通过 [REST API](/features/rest-api) 以及 [MCP 服务器](/features/mcp-server)，您可以将其集成到本地化工作流之外的其他工作流中：

**营销与社交内容** -- 将您组织的品牌声音注入能生成社交媒体帖子、电子邮件营销活动或落地页文案的内容代理中。术语表确保品牌术语一致，声音设置则确保语调符合您的品牌。

**文档** -- 将语言记忆导入文档流程，使技术写作遵循与其余内容相同的风格规则。术语条目防止在文档、帮助文章和产品文案中发生风格漂移。

**代码审查** -- 构建一个代理来审查合并请求内容（错误消息、UI 标签、引导文本）以符合您的风格与术语。在发布前标记出不一致之处。

**自定义代理** -- 任何兼容 MCP 的客户端均可读写语言记忆。要求您的编程助手"使用新产品名称更新术语"或"将德语区域的风格基调设置为专业"，它将您的意图转化为正确的 API 调用。

## 渐进式优化

\-- 语言记忆随使用而增强。每次审查员修正代理输出，修正内容都会反馈到您的下一版本风格或术语中。随着时间的推移，初稿与最终输出之间的差距缩小，审查步骤也变得更加快速。

这是 Glossia 的核心反馈循环：生成、审查、优化上下文、再次生成。智能体不仅仅遵循指令。它们利用每一次循环中不断优化的上下文工作。
