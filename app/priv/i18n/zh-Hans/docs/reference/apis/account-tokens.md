账户令牌提供了一种无需经过完整 OAuth 流程即可对 API 请求进行认证的简单方式。它们非常适合脚本、CI/CD 流水线以及个人自动化。

## 创建令牌

1. 登录 Glossia 并导航至您的账户仪表板。
2. 打开 **API** 侧边栏中的部分。
3. 点击 **账户令牌**, 然后 **新建令牌**,
4. 为令牌提供一个描述性的 **名称** ,(例如，"CI 部署"或"CLI 访问")。
5. 选择 **授权范围** 令牌所需的权限。仅授予所需的最低权限。
6. 设置一个 **过期日期** 或留空以创建永不过期的令牌。
7. 点击 **创建令牌**。

创建后，将显示完整的令牌值 **一次**。请立即复制并安全存储该令牌。您将无法再次查看完整值。

## 使用令牌

将令牌包含在 `Authorization` 您的 HTTP 请求头中：

    Authorization: Bearer glsa_abc123def456...

例如，使用 `curl`:

```bash
curl -H "Authorization: Bearer glsa_abc123def456..." \
  https://glossia.ai/api/projects
```

账户令牌遵循相同 [授权模型](/docs/reference/apis/authentication) 作为 OAuth 令牌。令牌的作用域定义了它能够执行的最大操作集，且资源级别策略仍基于您的账户关系适用。

## 令牌格式

所有账户令牌均以 `glsa_` 前缀后跟一个随机十六进制字符串。该前缀便于在日志和密钥扫描器中识别 Glossia 令牌。

## 作用域

账户令牌支持与 OAuth 令牌相同的作用域。查看 [作用域参考](/docs/reference/apis/authentication) 完整列表。

创建令牌时，仅选择您用例所需的权限范围。例如：

- 只读集成需要 `project:read` 和 `voice:read`。
- 创建项目的 CI 流水线需要 `project:read` 和 `project:write`。
- 管理组织成员的脚本需要 `members:read` 和 `members:write`。

## 管理令牌

### 查看令牌

该 **账户令牌** 页面列出所有有效令牌，包括其名称、作用域、最后使用时间以及过期时间。从未使用过的令牌在“最后使用”列中显示“未使用”。

### 编辑令牌

点击令牌名称以编辑其 **名称** 和 **描述**。创建后无法修改作用域和过期时间。如果需要使用不同作用域，请创建新令牌并撤销旧令牌。

### 撤销令牌

要撤销令牌，请点击 **撤销** 在令牌列表或打开令牌的编辑页面，并使用的 **撤销令牌** 位于危险区域的按钮。已撤销的令牌会立即停止工作且无法恢复。

## 安全最佳实践

- **安全存储令牌。** 使用环境变量或密钥管理器。切勿将令牌提交到源代码控制。
- **使用短时有效的令牌。** 尽可能设置过期日期。
- **最小化作用域。** 仅授予令牌实际所需的权限。
- **定期轮换。** 按计划创建新令牌并撤销旧令牌。
- **监控使用情况。** 定期查看"最后使用"日期。撤销不再使用的令牌。
- **每个集成仅使用一个令牌。** 这样，撤销一个令牌不会影响其他工作流。

## API 管理

您还可以通过 REST API 和 MCP 服务器管理账户令牌。

### REST API

| 方法 | 端点 | 描述 |
|--------|----------|-------------|
| `GET` | `/api/tokens` | 活动令牌列表 |
| `POST` | `/api/tokens` | 创建新令牌 |
| `DELETE` | `/api/tokens/:id` | 撤销令牌 |

### MCP

MCP 服务器提供 `list_tokens`, `create_token`, 并 `revoke_token` 能镜像 REST API 的工具。
