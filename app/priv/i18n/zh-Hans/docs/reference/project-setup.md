---
项目设置会准备一个供 Glossia 使用的已连接仓库。它在用户选择仓库并至少选择一种目标语言后在 **新项目** 流程。

## 先决条件

- 账户中至少配置了一个模型。
- Glossia GitHub App 可以访问所选仓库。
- 用户可以在该账户中创建项目。
- 至少选择了一种目标语言。

## 状态

| 状态 | 含义 | 可用操作 |
|---|---|---|
| **等待中** | 项目已获接受，正在等待开始。| 查看进展，或离开页面稍后返回。|
| **运行中** | Glossia 正在检查并更新仓库。 | 关注实时动态。 |
| **已完成** | 本地化基线已准备并发布以供审核。 | 打开、审核并合并拉取请求。 |

项目为暂定，而设置处于 **待定** 或 **运行中**. 如果设置无法正常完成或无法发布有效更改，Glossia 将清理设置环境并删除临时项目。仓库随后可在 **新建项目** 流程中，以便可以再次尝试设置。

## 可见进度

设置卡片在新项目流程及项目概览中仍然可用。它包括：

- 一个状态徽章和进度条。
- 当前状态的简短说明。
- 最近的仓库准备、审查、文件变更、核对和完成活动。
- 设置无法完成时，会显示清晰的失败信息。

临时项目存在期间会存储进度。终端失败会同时丢弃项目和其可见的设置进度。

## 完成结果

成功的连接设置会针对存储库的默认分支创建一个专用分支和拉取请求。该拉取请求包含生成的本地化基线，包括 `L10N.md` 上下文以及加载本地化内容所需的最小实际更改。

设置不发布仅包含标头的目标目录。当本地化框架要求在翻译前生成目标目录时，目录包含提取的来源消息条目且翻译值为空。如果目前尚未需要目标目录，设置会将其保留用于首次翻译运行。

Glossia 不会合并拉取请求。存储库维护者会通过其正常的 GitHub 流程审查并合并它。

当此拉取请求处于打开状态时，项目概览显示设置通知。拉取请求合并后，通知被移除。如果拉取请求未合并即被关闭，概览会说明必须重新打开它，设置才能被视为已完成。
