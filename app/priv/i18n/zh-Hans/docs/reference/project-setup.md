%{title: "项目设置", summary: "仓库设置的状态、进度信息以及结果。", category: "reference", order: 2}
---
项目设置会为 Glossia 准备一个已连接的仓库。它始于用户在 **新建项目** 流程中选择仓库并至少选择一个目标语言之后。

## 先决条件

- 账户至少配置了一个模型。
- Glossia GitHub App 能够访问所选仓库。
- 用户可以在账户中创建项目。
- 已至少选择一个目标语言。

## 状态

| 状态 | 含义 | 可用操作 |
|---|---|---|
| **等待中** | 项目已接受，等待开始。 | 查看进度或离开页面稍后返回。 |
| **运行中** | Glossia 正在检查并更新仓库。 | 查看实时活动。 |
| **已完成** | 本地化基线已准备就绪并发布用于审查。 | 打开、审查并合并拉取请求。 |

当设置处于 **等待中** 或 **运行中** 时，项目处于临时状态。如果设置无法完成或发布可用变更，Glossia 会清理设置环境并删除临时项目。随后仓库将变得可用于 **新建项目** 流程，以便重新尝试设置。

## 可见进度

设置卡片在新项目流程和项目概览中保持可用。它包括：

- 状态徽章和进度条。
- 当前状态的简短说明。
- 最近的仓库准备、审查、文件变更、检查和完成活动。
- 设置无法完成时的清晰错误消息。

临时项目存在期间会存储进度。最终失败会同时丢弃项目和其可见设置进度。

## 完成结果

成功的连接设置会创建一个专用分支和针对仓库默认分支的拉取请求。拉取请求包含生成的本地化基线，包括 `GLOSSIA.md` 上下文和加载本地化内容所需的最小实用变更。

设置不会发布仅包含标头的目标目录。当本地化框架要求在翻译前提供目标目录时，目录将包含包含空翻译值的提取源消息条目。如果当前尚未要求目标目录，设置会将其保留以供首次翻译运行使用。

Glossia 不会合并拉取请求。仓库维护者将通过其正常的 GitHub 流程审查并合并它。

当此拉取请求处于打开状态时，项目概览会显示设置通知。拉取请求合并后，该通知将被移除。如果拉取请求在未合并的情况下被关闭，概览将说明在设置被视为完成之前必须重新打开它。
