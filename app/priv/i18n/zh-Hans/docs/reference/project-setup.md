项目设置会为 Glossia 准备一个已连接的仓库。它始于用户选择一个仓库和至少一个目标语言，在 **新建项目** 流程。

## 前置条件

- 该账户中已至少配置一个模型。
- Glossia GitHub App 可访问所选仓库。
- 用户可在该账户中创建项目。
- 已选择至少一个目标语言。

## 状态

| 状态 | 含义 | 可用操作 |
|---|---|---|
| **待处理** | 项目已接受并等待开始。 | 跟踪进度或离开页面稍后返回。 |
| **进行中** | Glossia 正在检查和更新仓库。| 查看实时活动。 |
| **完成** | 本地化基线已准备并发布以供审查。| 打开、审查并合并拉取请求。 |

项目处于暂定状态，而设置 **待处理** 或 **运行中**。如果设置无法完成或发布可用的更改，Glossia 将清理设置环境并删除临时项目。随后仓库将变为可用，位于 **新建项目** 流程，以便可以再次尝试设置。

## 可见进度

设置卡片在新建项目流程中和项目概览中仍然可用。它包含：

- 一个状态徽章和进度条。
- 当前状态的简短说明。
- 最近的仓库准备、审查、文件变更、检查及完成活动。
- 当设置无法完成时，将显示清晰的失败消息。

进度在临时项目存在期间得以保存。致命失败会同时丢弃项目和其可见的设置进度。

## 已完成结果

成功的连接设置会创建一个专用分支，并向仓库的默认分支创建拉取请求。该拉取请求包含生成的本地化基线，包括 `L10N.md` 上下文以及加载本地化内容所需的最小实用变更。

设置不会发布仅含头部的目标目录。当本地化框架要求在翻译前提供目标目录时，目录中包含提取的源消息条目，翻译值留空。如果此时尚不需要目标目录，设置会将其保留以供首次翻译运行。

Glossia 不会合并该拉取请求。仓库维护者将通过其正常的 GitHub 流程进行审核和合并。

在项目概览中，只要此拉取请求处于开放状态，就会显示设置通知。该通知会在拉取请求合并后被移除。如果拉取请求在未合并的情况下被关闭，概览将说明必须在设置被视为完成前重新打开拉取请求。
