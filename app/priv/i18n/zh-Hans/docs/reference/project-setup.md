项目设置会为 Glossia 准备已连接的仓库。用户在**新建项目**流程中选择仓库和至少一种目标语言后，设置即会开始。

## 前提条件

- 账户中至少配置了一个模型。
- Glossia GitHub App 可以访问所选仓库。
- 用户有权在账户中创建项目。
- 至少选择了一种目标语言。

## 状态

| 状态 | 含义 | 可执行操作 |
|---|---|---|
| **待处理** | 项目已被接受，正在等待开始。 | 跟踪进度，或离开页面后稍后返回。 |
| **运行中** | Glossia 正在检查并更新仓库。 | 跟踪实时活动。 |
| **已完成** | 本地化基线已准备就绪并发布以供审核。 | 打开、审核并合并拉取请求。 |

设置处于**待处理**或**运行中**状态时，项目为临时项目。如果设置无法完成或无法发布可用的更改，Glossia 会清理设置环境并删除该临时项目。之后，该仓库会重新出现在**新建项目**流程中，以便再次尝试设置。

## 可见进度

设置卡片会持续显示在新建项目流程和项目概览中，其中包括：

- 状态徽章和进度条。
- 当前状态的简要说明。
- 最近的仓库准备、检查、文件更改、校验和完成活动。
- 设置无法完成时显示的明确失败消息。

只要临时项目仍然存在，进度就会被保留。发生最终失败时，项目及其可见设置进度都会被丢弃。

## 完成结果

成功完成连接设置后，系统会创建专用分支，并针对仓库的默认分支创建拉取请求。该拉取请求包含生成的本地化基线，包括 `GLOSSIA.md` 上下文，以及加载本地化内容所需的最少实际更改。

设置不会发布仅包含标头的目标目录文件。如果本地化框架要求在翻译前创建目标目录文件，这些目录文件会包含从源内容提取的消息条目，并将翻译值留空。如果暂时不需要目标目录文件，设置会将其留待首次翻译运行时创建。

Glossia 不会合并拉取请求。仓库维护者需通过其常规 GitHub 流程审核并合并该拉取请求。

当此拉取请求处于打开状态时，项目概览会显示设置通知。拉取请求合并后，该通知会被移除。如果拉取请求未经合并便被关闭，概览会说明必须重新打开该拉取请求，设置才能被视为完成。
