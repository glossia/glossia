---

项目设置会让 Glossia 准备一个连接的存储库。在用户于 **新项目** 流中选择存储库后，他们将选择两种设置模式之一。

## 设置模式

| 模式 | Glossia 会做什么 | 何时选择 |
|---|---|---|
| **自动化设置** | 检查存储库，并使用针对所选目标语言生成的 `L10N.md` 配置创建拉取请求。 | 仓库尚未进行本地化配置。 |
| **手动配置** | 立即创建项目。它不会检查仓库、修改或打开拉取请求。 | 存储库已存在一个 `L10N.md` 文件，或者由维护者编写。 |

下方描述的状态、进度信息和拉取请求仅适用于自动化设置。

## 手动配置

手动配置的项目没有设置状态。创建后可立即使用，不会因设置失败而被删除。

Glossia 会在下一次向存储库的默认分支推送时启动翻译运行。该运行会翻译存储库的 [`L10N.md`](/docs/reference/l10n-md) 文件中声明的每个目标，因为在 **新项目** 流程中没有选择目标语言。

在第一次翻译运行之前，项目概览会显示一个通知，说明 Glossia 正在等待一个包含 `L10N.md` 文件的推送。

## 前置条件

- 账户至少配置了一个模型。
- Glossia GitHub App 可以访问所选仓库。
- 用户可以在账户中创建项目。
- 对于自动化设置，至少需要选择一个目标语言。

## 状态

| 状态 | 含义 | 可用操作 |
|---|---|---|
| **待处理** | 项目已被接受并等待开始。 | 跟踪进度或离开页面稍后返回。 |
| **运行中** | Glossia 正在检查和更新仓库。 | 跟踪实时状态。 |
| **已完成** | 本地化基线已准备并向待审核。 | 打开、审核并合并拉取请求。 |

设置处于 **待处理** 或 **运行中** 时，项目处于临时状态。如果设置无法完成或发布可用更改，Glossia 将清理设置环境并删除临时项目。然后该存储库将在 **新项目** 流程中可用，以便再次尝试设置。

## 可见进度

设置卡片在新项目流程和项目概览中保持可用，包括：

- 状态徽章和进度条。
- 当前状态的简要说明。
- 仓库准备、检查、文件变更、检查和完成活动的最新记录。
- 当设置无法完成时，会显示清晰的失败消息。

只要临时项目存在，进度就会保存。如果出现终止失败，项目和其可见的设置进度都会被丢弃。

## 完成结果

成功的连接设置会针对存储库的默认分支创建专用分支和拉取请求。拉取请求包含生成的本地化基线，包括 `L10N.md` 上下文以及加载本地化内容所需的最小实际更改。

设置不会发布仅包含头部的目标目录。当本地化框架在翻译前需要目标目录时，这些目录将包含带有空翻译值的提取源消息项。如果尚未需要目标目录，设置会将其保留以供第一次翻译运行使用。

Glossia 不会合并拉取请求。仓库维护者会通过他们正常的 GitHub 流程审核和合并它。

当此拉取请求打开时，项目概览会显示设置通知。拉取请求合并后，通知将被移除。如果拉取请求在未被合并的情况下被关闭，概览会解释必须在设置被视为完成之前重新打开它。
