---
项目设置会为 Glossia 准备一个已连接的仓库。它在用户选择一个仓库和至少一个目标语言后开始，在 **新项目** 流程。

## 先决条件

- 账户需至少配置一个模型。
- Glossia GitHub 应用可访问所选仓库。
- 用户可以在账户中创建项目。
- 至少已选择一个目标语言。

## 状态

| State | Meaning | Available action |
|---|---|---|
| **Pending** | 项目已接受，正在等待开始。| 查看进度或离开页面稍后返回。|
| **Running** | Glossia 正在检查和更新仓库。 | 关注实时活动。 |
| **已完成** | 本地化基线已准备并发布以供审核。 | 打开、审核并合并拉取请求。 |

项目为临时状态，设置状态为 **待处理** 或 **运行中**。如果设置无法完成或无法发布可用的更改，Glossia 将清理设置环境并删除临时项目。随后该仓库将在 **新项目** 流程，以便可以再次尝试设置。

## 可见进度

设置卡片在新项目流程和项目概览中仍可用。包括：

- 状态徽章及进度条。
- 当前状态的简短说明。
- 最近的仓库准备、检查、文件变更、校验及完成活动。
- 当设置无法完成时，会显示清晰的失败消息。

临时项目存在期间会保存进度。无法恢复的错误将同时丢弃项目和其可见的设置进度。

## 完成结果

成功的连接设置会创建专用分支，并针对仓库的默认分支发起拉取请求。该拉取请求包含生成的本地化基线，包括 `L10N.md` 上下文以及加载本地化内容所需的最小实用变更。

设置不会发布仅包含头部信息的翻译目录。当本地化框架要求在翻译前生成翻译目录时，这些目录会包含提取的源消息条目，但翻译值为空。如果当前尚不需要生成翻译目录，设置会保留它们，以供首次翻译时处理。

Glossia 不会合并拉取请求。仓库维护者将通过其常规的 GitHub 流程进行审查和合并。

在拉取请求保持开启期间，项目概览会显示设置通知。拉取请求合并后该通知会被隐藏。如果拉取请求在未合并的情况下关闭，概览将说明需要重新打开请求，设置才能被视为完成。
