项目设置会为您准备 Glossia 所连接的仓库。用户在 **新建项目** 流程中选择仓库后，需要选择两种设置模式之一。

## 设置模式

| 模式 | Glossia 将做什么 | 何时选择它 |
|---|---|---|
| **自动设置** | 检查仓库并打开包含生成的 `L10N.md` 配置的拉取请求。 | 该仓库还没有设置本地化。 |
| **手动配置** | 立即创建项目。它不会检查仓库、对其进行更改或打开拉取请求。 | 该仓库已有 `L10N.md` 文件，或者维护者将编写它。 |

以下描述的状态、进度信息和拉取请求仅适用于自动设置。

## 手动配置

手动配置的项目没有设置状态。创建后即可使用，且不会被失败的设置操作丢弃。

Glossia 在下一次推送到仓库的默认分支时启动翻译运行。该运行会将翻译译入仓库中 [`L10N.md`](/docs/reference/l10n-md) 文件中声明的每个目标语言，因为在 **新建项目** 流程中没有选择目标语言。

直到首次翻译运行前，项目概览会显示通知，说明 Glossia 正在等待包含 `L10N.md` 文件的推送。

## 前提条件

- 账户已有至少一个配置好的模型。
- Glossia GitHub App 可以访问选定的仓库。
- 用户可以在账户中创建项目。
- 对于自动设置，已选择至少一个目标语言。

## 状态

| State | 含义 | 可用操作 |
|---|---|---|
| **待处理** | 项目已接受，正在等待开始。 | 关注进度或离开页面稍后返回。 |
| **运行中** | Glossia 正在检查和更新仓库。 | 关注实时活动。 |
| **已完成** | 本地化基线已准备就绪并对外发布以供审查。 | 打开、审查并合并拉取请求。 |

在 **待处理** 或 **运行中** 时，项目为临时性质。如果设置无法完成或未发布可用变更，Glossia 将清理设置环境并删除临时项目。随后，该仓库将在 **新建项目** 流程中可用，以便再次尝试设置。

## 可见进度

设置卡片在新增项目流程和项目概览中依然可用，包括：

- 一个状态徽章和进度条。
- 当前状态的简短说明。
- 近期的仓库准备、检查、文件变更、检查和完成活动。
- 当设置无法完成时，会显示一条清晰的失败消息。

只要临时项目存在，进度就会被存储。如果发生致命失败，项目及其可见的设置进度将被丢弃。

## 完成结果

成功的关联设置会创建一个专用分支和一个针对仓库默认分支的拉取请求。该拉取请求包含生成的本地化基线，包括 `L10N.md` 上下文以及加载本地化内容所需的最小实际变更。

设置不会发布仅包含目标表头的清单。当本地化框架在翻译前需要目标清单时，这些清单包含带有空翻译值的提取源消息条目。如果此时尚不需要目标清单，设置会将其留给首次翻译运行。

Glossia 不会合并拉取请求。仓库维护者通过其正常的 GitHub 流程审查并合并它。

当拉取请求处于打开状态时，项目概览会显示设置通知。拉取请求合并后，通知会被移除。如果拉取请求在未合并的情况下被关闭，概览会说明必须在拉取请求重新打开之前，设置才能被视为已完成。
