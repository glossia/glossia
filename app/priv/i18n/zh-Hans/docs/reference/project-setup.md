---
项目设置会为 Glossia 准备一个已连接的仓库。它在用户选择仓库并至少选择一个目标语言之后在 **新项目** 流程。

## 先决条件

- 该账户已配置至少一个模型。
- Glossia GitHub 应用可以访问所选仓库。
- 用户可以在该账户中创建项目。
- 至少一个目标语言已选定。

## 状态

| 状态 | 含义 | 可用操作 |
|---|---|---|
| **等待中** | 项目已接受，等待开始。 | 追踪进度或离开页面稍后返回。 |
| **进行中** | Glossia 正在检查并更新仓库。 | 查看实时活动。 |
| **完成** | 本地化基线已准备并发布以供审核。 | 打开、审核并合并拉取请求。 |

项目处于暂定状态，而设置处于 **待定** 或 **运行中**. 如果设置无法完成或无法发布可用的更改，Glossia 将清理设置环境并删除临时项目。然后仓库就可以在 **新建项目** 流程即可再次尝试设置。

## 进度可视

设置卡片在新建项目流程和项目概览中依然可用。其中包括：

- 一个状态徽章和进度条。
- 当前状态的简短说明。
- 最近的仓库准备、检查、文件变更、复核和完成活动。
- 设置无法完成时，会显示清晰的失败信息。

在临时项目存在期间会保存进度。若遇到终结性失败，项目及其可见的设置进度均会被删除。

## 已完成

成功关联的设置会创建一个专用分支，并向仓库的主分支提交合并请求。该合并请求包含生成的本地化基线，包括 `L10N.md` 上下文内容以及加载本地化内容所需的最小变更。

设置不会发布仅含头部的目标目录。当本地化框架要求在翻译前提供目标目录时，目录包含提取的源消息条目，译文值为空。若尚未要求目标目录，设置会将其保留以待首次翻译运行。

Glossia 不会合并此合并请求。仓库维护者通过其常规 GitHub 流程进行审核和合并。

当该合并请求处于打开状态时，项目概述会显示设置通知。合并请求合并后，该通知会被移除。如果合并请求在未合并的情况下被关闭，概述中将说明必须重新打开后才可视为设置完成。
