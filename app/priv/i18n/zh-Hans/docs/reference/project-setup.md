---
Glossia 项目设置会为 Glossia 准备一个连接的仓库。它始于用户选择仓库和至少一个目标语言后，在 **新建项目** 流程。

## 前提条件

- 账户中至少配置了一个模型。
- Glossia GitHub 应用可以访问选定的仓库。
- 用户可以在账户中创建项目。
- 至少已选择一个目标语言。

## 状态

| 状态 | 说明 | 可用操作 |
|---|---|---|
| **等待中** | 项目已接受，正在等待开始。 | 查看进度或离开页面稍后返回。 |
| **运行中** | Glossia 正在检查并更新仓库。 | 跟踪实时活动。 |
| **已完成** | 本地化基线已准备并发布以供审查。 | 打开、审查并合并该请求。 |

项目为临时状态，当设置是 **等待中** 或 **运行中**. 如果设置无法完成或发布有效更改，Glossia 将清理设置环境并删除临时项目。随后，仓库将可用于 **新项目** 流程，以便再次尝试设置。

## 可见进度

设置卡片在新项目流程中以及项目概览上保持可用。内容包括：

- 状态徽章和进度条。
- 当前状态的简要说明。
- 最近的仓库准备、审查、文件变更、检查和完成活动。
- 当设置无法完成时，将显示清晰的失败消息。

临时项目存在期间会保存进度。最终失败会同时丢弃该项目及其可见的设置进度。

## 已完成结果

成功连接设置将创建一个专用分支，并向存储库的默认分支创建拉取请求。该拉取请求包含了生成的本地化基线，包括 `L10N.md` 上下文，以及加载本地化内容所需的最小实用变更。

设置不会发布仅含头部文件的目标目录。当本地化框架要求在翻译前提供目标目录时，这些目录包含带有空翻译值的提取源消息条目。若目标目录尚未需要，设置会将其保留以供首次翻译运行。

Glossia 不会合并拉取请求。存储库维护者将通过其正常的 GitHub 流程进行审查并合并。

项目概览会在该拉取请求处于打开状态时显示设置通知。拉取请求合并后，通知会被移除。如果拉取请求在未合并的情况下被关闭，概览会说明在设置被判定为完成之前必须重新打开它。
