项目设置会为 Glossia 准备一个已连接的仓库。当用户在 **新项目** 流程中，他们将从两种设置模式中选择一种。

## 设置模式

| 模式 | Glossia 做什么 | 何时选择它 |
|---|---|---|
| **自动化设置** | 检查仓库并为选定的目标语言创建包含已生成的 `L10N.md` 配置及相关拉取请求。 | 仓库目前尚未包含本地化配置。 |
| **手动配置** | 立即创建项目。它不会检查仓库、修改它或创建拉取请求。 | 仓库已经有一个 `L10N.md` 文件，或者由维护者编写。 |

下方所述的状态、进度信息和拉取请求仅适用于自动设置。

## 手动配置

手动配置的项目没有设置状态。它在创建后即可使用，且永远不会因设置失败而被丢弃。

Glossia 会在推送到仓库的默认分支后的下次推送中启动翻译任务。该任务会将内容翻译到已声明的每个目标所在的仓库的 [`L10N.md`](/docs/reference/l10n-md) 文件，因为未选择目标语言在 **新项目** 流程。

在第一次翻译任务之前，项目概览会显示一条通知，说明 Glossia 正在等待包含一个的推送 `L10N.md` 文件。

## 前置条件

- 该账户至少配置了一个模型。
- Glossia GitHub App 可访问所选仓库。
- 该用户可以在该账户中创建项目。
- 为了自动设置，至少需要选择一个目标语言。

## 状态

| 状态 | 含义 | 可用操作 |
|---|---|---|
| **待处理** | 项目已接受，等待开始。 | 查看进度或离开页面稍后返回。 |
| **运行中** | Glossia 正在检查和更新仓库。 | 关注实时活动。 |
| **已完成** | 本地化基线已准备并发布以供审查。 | 打开、审查并合并拉取请求。 |

项目是临时的，当设置 **等待中** 或 **运行中**. 如果设置无法完成或发布可用变更，Glossia 会清理设置环境并删除临时项目。仓库随后可在 **新建项目** 流程中可再次尝试设置。

## 可见进度

设置卡片在新项目流程及项目概览中依然可用。其内容包括：

- 状态徽章与进度条。
- 当前状态的简要说明。
- 最近的仓库准备、审查、文件变更、检查及完成活动。
- 设置无法完成时显示清晰的失败消息。

进度在暂存项目存续期间被存储。最终失败将同时丢弃项目及其可见的设置进度。

## 完成结果

成功的连接设置会创建专用分支，并向仓库的默认分支发起拉取请求。该拉取请求包含生成的本地化基线，包括 `L10N.md` 上下文以及加载本地化内容所需的最小实际变更。

设置不会发布仅包含头部信息的目标目录。当本地化框架在翻译前需要目标目录时，这些目录包含带有空翻译值的提取源消息条目。如果当前尚不需要目标目录，设置会将其保留以供首次翻译运行使用。

Glossia 不会合并拉取请求。存储库维护者将通过其正常的 GitHub 流程进行审核和合并。

只要此拉取请求处于开启状态，项目概述就会显示设置通知。拉取请求合并后，通知将被移除。如果拉取请求在未合并的情况下被关闭，概述将说明在设置被视为完成之前必须重新开启。
