---

项目设置是为 Glossia 准备的一个已连接仓库。用户在 **新建项目** 流程选择一个仓库后，会从两种设置模式中选择一种。

## 设置模式

| 模式 | Glossia 执行的操作 | 何时选择它 |
|---|---|---|
| **自动设置** | 检查仓库并生成针对选定目标语言的 `L10N.md` 配置，同时发起拉取请求。 | 该仓库尚未进行本地化配置。 |
| **手动配置** | 立即创建项目。该模式不会检查、更改仓库或提交拉取请求。 | 该仓库已包含 `L10N.md` 文件，或者维护人员将编写该文件。 |

下文所述的仓库状态、进度信息和拉取请求仅适用于自动设置。

## 手动配置

手动配置的项目没有设置状态。创建后即可使用，且不会因设置失败而被丢弃。

Glossia 在下一次推送到仓库默认分支时启动翻译运行。该运行将内容翻译至在仓库的 [`L10N.md`](/docs/reference/l10n-md) 文件中声明的所有目标，因为在 **新建项目** 流程中未选定任何目标语言。

在第一次翻译运行之前，项目概览将显示一则通知，说明 Glossia 正在等待包含 `L10N.md` 文件的推送。

## 先决条件

- 账户中至少配置了一个模型。
- Glossia GitHub App 能够访问选定的仓库。
- 用户可以在账户中创建项目。
- 对于自动设置，已选定至少一个目标语言。

## 状态

| 状态 | 含义 | 可用操作 |
|---|---|---|
| **等待中** | 项目已获准，正在等待启动。 | 查看进度或离开页面稍后返回。 |
| **运行中** | Glossia 正在检查和更新仓库。 | 查看实时活动。 |
| **已完成** | 本地化基线已准备完毕并发布供审查。 | 打开、审查并合并拉取请求。 |

当设置处于 **等待中** 或 **运行中** 时，项目为临时项目。如果设置无法完成或发布可用更改，Glossia 将清理设置环境并删除临时项目。随后仓库将在 **新建项目** 流程中可用，以便再次尝试设置。

## 可见进度

设置卡在“新建项目”流程中和项目概览中仍然可用。内容包括：

- 一个状态徽章和一个进度条。
- 当前状态的简要说明。
- 最近的仓库准备、检查、文件变更、校验及完成活动。
- 设置无法完成时显示的清晰失败消息。

在临时项目存在期间，进度会被保存。致命失败会同时丢弃项目及其可见的设置进度。

## 已完成结果

成功的连接设置会创建专用分支，并向仓库的默认分支发起拉取请求。该拉取请求包含生成的本地化基线，包括 `L10N.md` 上下文以及加载本地化内容所需的最小可行更改。

设置不会发布仅包含头部信息的目标目录。当本地化框架在翻译之前需要目标目录时，这些目录将包含具有空翻译值的提取源消息条目。如果尚未需要目标目录，设置会将其保留给第一次翻译运行。

Glossia 不会合并该拉取请求。仓库维护人员将通过其正常的 GitHub 流程审查并合并它。

在拉取请求保持打开状态时，项目概览将显示设置通知。拉取请求合并后，该通知将被移除。如果拉取请求在未合并的情况下被关闭，概览将解释必须重新打开后，设置才能被视为已完成。
