---
项目设置会为 Glossia 准备一个已连接的仓库。它始于用户选定一个仓库和至少一个目标语言之后，在 **新项目** 流程。

## 先决条件

- 账户中至少配置了一个模型。
- Glossia GitHub 应用可以访问选定的仓库。
- 用户可以在账户中创建项目。
- 至少选定了一个目标语言。

## 状态

| 状态 | 说明 | 可用操作 |
|---|---|---|
| **等待中** | 项目已接受，等待开始。| 查看进度，或离开页面稍后返回。|
| **运行中** | Glossia 正在检查和更新存储库。 | 查看实时活动。 |
| **已完成** | 本地化基线已准备并发布以供审查。 | 打开、审查并合并拉取请求。 |

项目是临时的，只要设置 **待定** 或 **运行中**. 如果设置无法完成或未发布可用的更改，Glossia 将清理设置环境并删除临时项目。仓库随后可在 **新项目** 流程以便可尝试重复搭建。

## 可见进度

设置卡片保留在新项目流程和项目概览中。它包括：

- 一个状态徽章和进度条。
- 当前状态的简短说明。
- 最近的仓库准备、审查、文件变更、检查及完成活动。
- 配置无法完成时会显示清晰的失败信息。

进度在临时项目存续期间会被保存。致命失败会同时丢弃项目和其可见的配置进度。

## 完成结果

成功的关联配置会创建一个专用分支以及针对仓库默认分支的合并请求。该合并请求包含生成的本地化基线，包括 `L10N.md` 上下文以及加载本地化内容所需的最小可行变更。

配置不会发布仅包含头部的目标目录。当本地化框架要求在翻译前提供目标目录时，目录内包含提取的源消息条目，且翻译值为空。当目标目录尚未需要时，配置会保留它们以供首次翻译运行使用。

Glossia 不会合并该合并请求。仓库维护者会按照常规的 GitHub 流程对其进行审查和合并。

在项目概览中，只要该合并请求处于开启状态，便会显示配置通知。合并请求合并后，通知将被移除。如果合并请求在未合并的情况下被关闭，概览会说明必须先重新开启，才能视配置为已完成。
