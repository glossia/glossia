---
项目设置会为 Glossia 准备一个已连接的存储库。它始于用户选择一个存储库和至少一个目标语言之后，在 **新项目** 流程。

## 前置条件

- 账户需配置至少一个模型。
- Glossia GitHub 应用可访问所选存储库。
- 用户可在账户中创建项目。
- 至少已选择了一个目标语言。

## 状态

| 状态 | 含义 | 可用操作 |
|---|---|---|
| **等待中** | 项目已获受理，正在等待开始。 | 查看进度，或离开页面稍后返回。 |
| **运行中** | Glossia 正在检查并更新仓库。 | 关注实时活动。 |
| **已完成** | 本地化基线已准备并发布以供审查。 | 打开、审查并合并拉取请求。 |

项目处于临时状态，而设置处于 **待定** 或 **运行中**. 如果设置无法完成或发布可用更改，Glossia 将清理设置环境并删除临时项目。随后仓库将可在 **新项目** 流程，以便可以重新尝试设置。

## 可见进度

设置卡片在新项目流程中及项目概览中始终可用。包括：

- 一个状态徽章和进度条。
- 当前状态的简要说明。
- 最近的仓库准备、审查、文件变更、检查及完成活动。
- 当设置无法完成时，将显示明确的失败消息。

进度会在暂定项目存在期间存储。最终失败会同时丢弃项目和其可见的设置进度。

## 完成结果

成功的连接设置会创建专用分支和针对存储库默认分支的拉取请求。拉取请求包含生成的本地化基准，包括 `L10N.md` 上下文以及加载本地化内容所需的最小实用变更。

设置不会发布仅头部文件的目标目录。当本地化框架要求在翻译前需要目标目录时，这些目录包含提取的源消息条目及空翻译值。当目标目录尚不需要时，设置会保留它们以供首次翻译运行。

Glossia 不会合并拉取请求。仓库维护者通过其正常的 GitHub 流程进行审查和合并。

项目概览会在该拉取请求开放时显示设置通知。拉取请求合并后，通知将被移除。如果拉取请求在未合并的情况下被关闭，概览将说明必须重新打开后，设置才能被视为已完成。
