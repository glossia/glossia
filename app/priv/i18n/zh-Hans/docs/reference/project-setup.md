%{title: "项目设置", summary: "仓库设置的状态、进度信息以及结果。", category: "参考", order: 2}
---
项目设置会为 Glossia 准备一个已连接的存储库。它在用户选择存储库并至少选择一种目标语言后的 **新建项目** 流程。

## 先决条件

- 账户至少已配置一个模型。
- Glossia GitHub App 可访问所选存储库。
- 用户可在账户中创建项目。
- 至少选择了一种目标语言。

## 状态

| 状态 | 含义 | 可用操作 |
|---|---|---|
| **待处理** | 项目已接受，正在等待开始。 | 跟踪进度或离开页面稍后返回。 |
| **运行中** | Glossia 正在检查并更新仓库。| 跟踪实时活动。|
| **已完成** | 本地化基线已准备并发布以供审查。| 打开、审查并合并拉取请求。|

项目处于暂定状态，而设置阶段处于 **待处理** 或 **运行中**. 如果设置无法完成或发布可用的更改，Glossia 将清理设置环境并删除临时项目。随后仓库将在 **新项目** 流程以便可以重新尝试设置。

## 可见进度

设置卡片在新项目流程和项目概览中始终可用。它包括：

- 一个状态徽章和进度条。
- 当前状态的简短说明。
- 最近的仓库准备、检查、文件变更、复核及完成活动。
- 当设置无法完成时，显示清晰的失败消息。

临时项目存在期间会保留进度。若发生彻底失败，项目和其可见的设置进度将被丢弃。

## 完成结果

成功的关联设置会创建一个专用分支，并向仓库的默认分支发起一个拉取请求。该拉取请求包含生成的本地化基线，包括 `L10N.md` 上下文以及加载本地化内容所需的最小改动。

设置不会发布仅包含头部的目标目录。当本地化框架要求在翻译前生成目标目录时，这些目录包含提取的来源消息条目，但翻译值为空。当目标目录尚不需要时，设置会保留它们以供首次翻译运行使用。

Glossia 不会合并拉取请求。仓库维护者将通过其正常的 GitHub 流程审查并合并它。

当此拉取请求处于打开状态时，项目概览会显示设置通知。拉取请求合并后，该通知会被移除。如果拉取请求在未合并的情况下被关闭，概览将说明必须重新打开它，才能将设置视为已完成。
