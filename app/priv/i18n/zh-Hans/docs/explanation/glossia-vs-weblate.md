**当您希望语言自动化像您的软件交付的其他部分一样运作时选择 Glossia：** 源代码控制的指令、您自己的模型令牌、存储库原生的检查以及用于审查的拉取请求。

[Weblate](https://weblate.org/) 是一个开源本地化系统，具有网页翻译界面、版本控制集成和自我托管选项。公共代码和 Git 集成并不专属于 Glossia。选择 Glossia 的原因在于其结合的中心存储库交付、模型驱动转换以及为人和智能体提供的可复用语言上下文。

## 为何选择 Glossia

| 您的优先事项 | Glossia 的优势 |
|---|---|
| 将审查保留在产品工作流中 | 通过存储库更改和拉取请求审查实际的源代码控制输出。 |
| 匹配快速移动的源存储库 | 更改检测和批量发布支持持续的本地化循环，而无需重复翻译未更改的输入。 |
| 带来您自己的模型令牌 | 使用范围限于账户的提供商凭据配置支持的模型，并使用存储库拥有的句柄进行选择。 |
| 复用原生验证 | 在实时目标路径上对候选项运行存储库自身的验证命令。 |
| 在翻译之外复用上下文 | 共享的声音和术语可以通过 MCP 和 REST 接口指导新内容和代理集成。 |

## 将存储库保持为审查界面

Glossia 专为已经使用 Git 来决定哪些内容准备就绪的团队设计。其本地化配置存放在内容旁边，建议的产出可以通过与产品变更相同的过程进行审查。

Weblate 同样也集成了版本控制。其基于浏览器的翻译界面可能正是贡献者社区所需要的。Glossia 的重点不同：保持存储库审查边界并将语言自动化带入其中，而不是让另一个编辑界面成为团队工作的中心。

## 带来您的令牌并使模型选择明确

Glossia 使用经过您的提供商 API 令牌配置的受支持模型。存储库配置指的是稳定模型句柄；密钥保留在账户设置中。您可以根据内容范围或目标区域选择不同的配置模型，而无需更改每个存储库的凭据。

这使得您的团队有一个明确的选择用于书写其内容的模型的地方。它并不承诺任何令牌或模型得到支持，或承诺生成消除了对人眼审查的需要。请见 [配置模型提供商](/docs/how-to/configure-a-model-provider)。

## 复用定义可交付变更的检查

Glossia 内置的结构化检查仅是质量边界的一部分。通过 `L10N.md`, 它可以在候选的实时目标路径上运行存储库的原生验证脚本、解析器、编译器或文档检查。

这很有用当翻译内容不仅包含纯字符串：特定于应用程序的格式、Markdown 组件、结构化元数据以及项目已知的如何验证的约束。验证和恢复保持连接到您的管道将要发布的实际文件。

执行环境仍然需要验证程序的依赖项，结构化验证并不建立语言准确性。请见 [L10N.md](/docs/reference/l10n-md) 和 [翻译恢复](./translation-recovery)。

## 公开源码是基准，而非整个比较

Glossia 的核心是公开的，可在 [Apache-2.0](https://github.com/glossia/glossia/blob/main/LICENSE-APACHE) 许可下进行检查、修改、分发和自我托管，这允许了竞争的托管服务。在 `ee/` 下的企业代码拥有单独的 [许可](https://github.com/glossia/glossia/blob/main/ee/LICENSE.md)，生产使用需书面商业协议。这种开放核心模型与 Weblate 基于 GPL 的授权不同。

如果基于 GPL 的授权和成熟的网页翻译界面是您的主要标准，Weblate 值得考虑。如果您的目标是 **您自己的模型凭据、现有的存储库检查以及遵循软件交付的语言工作**，Glossia 将这些选择合并到一个语言操作系统中。

此比较不声称 Weblate 缺乏自动化、验证功能或提供商集成，也不承诺自动迁移或功能奇平。请见 [Weblate 的文档](https://docs.weblate.org/) 了解当前能力。
