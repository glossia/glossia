Glossia 将仓库指令与模型提供商凭证分离。仓库描述需要翻译的内容，而账户决定选择哪个 [大语言模型](https://en.wikipedia.org/wiki/Large_language_model) 执行工作。

## 为什么模型属于账户

团队通常会翻译具有相同提供商关系的多个仓库。账户范围模型允许管理员一次性轮换提供商密钥或切换底层模型，而无需修改每个仓库。

此边界也能将凭据排除在源码控制之外。仓库中包含一个可读句柄，例如 `translation-default`，而非提供商密钥。

## 句柄提供稳定的意图。

该 `model` 字段在 `L10N.md` 指代一个账户模型句柄：

```yaml
model: translation-default
```

该句柄表达了仓库的意图。管理员可以在之后更新该句柄选定的提供商模型，同时保持仓库配置的稳定性。

## 多个模型的使用方式

Glossia 为每个文档翻译使用一个配置的模型。添加多个模型不会创建模型集成、回退链或自动质量等级。仓库作者通过稳定的句柄（例如）来选择其用途。 `translation-default`此前重新组合的文档验证失败：Markdown 文本字面量恢复必须返回长度匹配的 JSON 字符串数组 `long-form`，或 `japanese-specialist`.

选择遵循文档和目标语言的上下文层级结构：

1. 最接近 `L10N/<locale>.md` 声明该文件的 `model` 对其上下文优先级最高。
2. 否则，对于该同级目录， `L10N.md` 声明该文件的 `model` 优先级最高。
3. Parent `L10N.md` 设置会在更近的文件未声明模型时被继承。
4. 当没有适用的上下文文件声明句柄时，Glossia 会使用账户默认值。

明确配置的句柄必须存在。Glossia 会对未知句柄报告错误，而不是静默地切换到账户默认值。

## 默认选择

项目设置需要在仓库拥有其自身之前需要一个模型 `L10N.md`. Glossia 因此选择账户默认值。添加到账户的第一个模型将变为默认模型，管理员可以在其设置页面将另一个模型设为默认。

一旦仓库拥有 `L10N.md`, 使用显式句柄可使审查员清楚其选择。省略 `model` 保持仓库处于账户默认设置。

## 人工审查边界

模型输出为提议的工作，而非自动合并。设置和翻译活动保留在 Glossia 中可见，而仓库更改将通过拉取请求发布供团队审查。这保留了团队已使用的相同质量和所有权边界。
