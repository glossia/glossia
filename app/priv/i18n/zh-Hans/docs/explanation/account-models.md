Glossia 将存储库指令与模型提供商凭据分离。存储库描述需要翻译的内容，而账户决定哪些 [大型语言模型](https://en.wikipedia.org/wiki/Large_language_model) 执行工作。

## 为什么模型属于账户

团队通常需要翻译多个具有相同提供商关系的存储库。账户范围内的模型可以让管理员在不修改每个存储库的情况下旋转提供商密钥或切换底层模型一次。

这个边界也将凭据保留在源代码控制之外。存储库包含一个可读句柄，例如 `translation-default`"，不是提供商密钥。"

## 句柄提供稳定的意图

该 `model` 字段在 `L10N.md` 指的是账户模型句柄：

```yaml
model: translation-default
```

该句柄表达了仓库的意图。管理员稍后可更新该句柄所选的提供商模型，同时保持仓库配置稳定。

## 如何使用多个模型

Glossia 为每个文档翻译使用一个配置的模型。添加多个模型不会创建集成、备用链或自动质量等级。存储库作者通过稳定的句柄（例如）来选择其用途 `translation-default`此前重新组装的文档验证失败：Markdown 文本字面量恢复必须返回长度一致的 JSON 字符串数组 `long-form`重组后的文档先前验证失败：Markdown 文本字面量恢复必须返回长度匹配的 JSON 字符串数组 `japanese-specialist`.

选择遵循文档与目标语言的上下文层级：

1. 最近的 `L10N/<locale>.md` 声明该文件的 `model` 在该语言层级优先生效。
2. 否则，最近的 `L10N.md` 声明该文件的 `model` 在该目录层级优先生效。
3. 父级 `L10N.md` 当更近的文件未声明模型时，设置将被继承。
4. 当没有适用的上下文文件声明句柄时，Glossia 会使用账户默认值。

必须明确配置一个存在的句柄。对于未知句柄，Glossia 会报告错误，而不是静默切换到账户默认值。

## 默认选择

项目设置需在仓库拥有自己的模型之前先配置一个模型 `L10N.md`. Glossia 因此选择账户默认值。账户中添加的第一个模型将成为默认值，管理员可从其设置页面将另一模型设为默认值。

一旦仓库拥有 `L10N.md`, 使用显式句柄能让评审者清楚其选择。省略 `model` 会保持仓库使用账户默认配置。

## 人工审核边界

模型输出是提议的工作，而非自动合并。设置和翻译活动在 Glossia 中保持可见，而仓库变更将通过拉取请求发布以供团队评审。这保留了团队已用于代码的相同质量和所有权边界。
