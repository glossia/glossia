**在希望语言工作遵循产品的交付系统，不止构建围绕它并行的翻译管理流程时，请选择 Glossia。** 将内容保留在 Git 中，使用自己的凭据选择支持模型，并根据您的存储库已信任的检查验证结果。

[Phrase](https://phrase.com/) 提供本地化套件，包括满足软件本地化及托管翻译不同需求的 Phrase Strings 和 Phrase TMS。Glossia 采取专注的方法：为软件团队提供适配其现有审核和交付循环的语言操作系统。

## 为什么选择 Glossia

| 您的优先级 | Glossia 的优势 |
|---|---|
| 随软件交付语言变更 | 存储库变更驱动本地化，输出返回为可审核的变更。 |
| 检查并掌控处理 | 公开源暴露了应用程序和部署实现，在许可条款下允许修改和自托管。 |
| 自带凭证 | 配置您自己的支持模型提供方凭证；通过存储库配置中的账户句柄选择模型。 |
| 复用验证流水线 | 对翻译候选对象运行存储库原生检查，而不是将语言批准视为文件构建的证明。 |
| 保持持久所有权 | 已发布文件、配置和拉取请求历史记录保留在存储库中。 |

## 将本地化纳入持续交付

Glossia 的变更检测避免了对未变输入重复翻译。其存储库工作流程每项目只保持一个开放的翻译拉取请求，并批量发布进度，因此快速变更的源存储库无需为每个小变更启动新的翻译流程。

目标不是未经审核的冲刺上线。是让语言工作持续可审核，并通过您的团队现有管道交付。

Phrase 也提供 API、集成和自动化。Glossia 强调的优势是架构对齐：存储库继续作为内容权威和交付边界，而不仅仅是同步另一工作区结果的地点。

## 将模型选择和凭证掌握在自己手中

Glossia 接受您自己的支持模型提供方 API Token。凭证保留在账户设置中；存储库选择稳定的句柄。团队可以轮换 Token 或更改句柄后面的模型，而无需重写其存储库说明。

不同的内容范围和目标语言可使用不同的配置模型。可选决策模型可以评估完整翻译并请求修正，而人类继续负责语言判断。查看 [账户模型](./account-models) 了解当前行为和限制。

## 您的存储库已了解有效内容的含义

翻译管理系统对字符串的看法不一定等同于应用程序对文件的看法。存储库可能有自己的解析器、编译器、组件规则、文档构建和占位符检查。

Glossia 可通过 `L10N.md` 验证命令复用这些检查。它将候选项暂时写入其真实目标路径进行验证，并在通过所需检查后才接受它。命令及其依赖必须位于执行环境中。

这使团队能够扩展现有的质量边界，而不是仅在翻译工作区内维护“有效”的单独定义。查看 [L10N.md](/docs/reference/l10n-md)。

## 公开实现，非黑盒

Glossia 的应用程序、CLI、SDK 和部署源是公开的。您可以检查内容处理方式，并在 [O'Saasy license](https://github.com/glossia/glossia/blob/main/LICENSE.md) 下修改或自托管实现。该许可证限制竞争对手的托管服务，并非不受限制的开源代码许可证。

更广泛的翻译套件适合专业翻译运营和复杂协调。如果您的优先级是 **用自有凭证和存储库检查匹配软件交付速度**，Glossia 旨在保持该工作流直接。

迁移现有的翻译程序仍需计划其翻译记忆、术语和历史。此页面不承诺自动 Phrase 导入器或完整套件的同等性，或断言 Phrase 缺乏所有等效集成。查阅 [Phrase 的文档](https://support.phrase.com/) 以了解特定产品的当前能力。
