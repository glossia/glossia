词汇表是一组精心整理的关键术语，您的翻译每次都必须以相同的方式呈现。“提交”在版本控制意义上保持不变。 `commit` 在西班牙语中，变为 `提交` 在简体中文中，以及 `コミット` 在日语中。每种语言只需一个决定，并在所有地方强制执行。

## 词汇表可存在的两个位置

Glossia 会在两个位置查找词汇表条目，并在翻译时合并它们：

- **您的仓库**，在您已用于翻译设置的文件中。 `L10N.md` 声明了术语，且每种语言的 `L10N/<locale>.md` 声明了它们的翻译。这是开发者权威的术语表：更改通过合并请求流转，每种语言的审查员拥有自己的文件，嵌套文件可为仓库的特定部分细化。
- **您的 Glossia 账户**, 由托管仪表板管理。这是语言专家权威的术语表：评审员和本地化贡献者可在不修改代码的情况下添加或细化条目，通过仪表板、 [REST API](/docs/reference/apis), 或 [MCP 服务器](/docs/reference/mcp). 它适用于账户翻译的每个仓库。

两者都有用，且互不替代。

## 何时使用哪一个

在...中定义术语 **你的 Glossia 账户** 当：

- **它适用于多个仓库。** 产品名称、品牌术语和公司词汇只需定义一次，即可在任何地方使用。
- **做出该决策的人员不在仓库工作。** 语言学家、评审员和外部贡献者，即使仓库是闭源或他们无写入权限，也能完善术语表。
- **你想在不修改代码的情况下修复术语。** 更正后的翻译将在下次运行中生效，无需对代码库发起拉取请求。
- **更改需要经过审查并保留历史记录。** 每次编辑都会创建一个新的版本并附带变更说明，贡献者可以将更改作为建议供他人批准，且较早版本依然可用。
- **其他工具也需要它。** 代理和集成可通过 REST API 和 MCP 服务器读取术语表，例如用于编写已使用已批准术语的新内容。

在...中定义术语 **你的仓库** 何时：

- **它属于这个代码库。** 特定于单一项目的术语，例如表示版本控制操作的“提交”，会紧邻使用它的代码。
- **它应与源文本同步变更。** 该术语及其引入它的文案位于同一合并请求中，并一起接受审查。
- **只有仓库的一部分需要它。** 一个嵌套 `L10N.md` 或者 `L10N/<locale>.md` 可以为某个目录添加或覆盖条目，例如营销页面。
- **它必须覆盖账户词汇表。** 对于相同的术语，仓库条目优先于账户条目，针对它所翻译的语言。

## 它们的组合方式

对于每个文件和目标语言，Glossia 将这两个词汇表解析为一个有效集合：

1. 首先使用目标语言的账户词汇表条目。
2. 覆盖该语言的仓库条目：来自该文件的 `L10N.md` 包含其翻译的链 `L10N/<locale>.md` 链。当存储库条目与账户条目具有相同的源术语时，存储库条目优先。
3. 如果存储库术语没有某种语言的翻译，该语言的账户条目仍然适用，存储库不会阻止其未进行翻译的语言。

合并发生 **每个目标语言**, 而非按条目。对“提交”的西班牙语翻译在 `L10N/es.md` 替换了账户的“提交”西班牙语条目，但不会更改同一术语的日语条目。审核人员可以看到哪些账户条目被替换：翻译会话摘要显示覆盖的数量，且每个文件的锁文件在 `glossary.shadowed`。

## 当术语表更改时，文件会重新翻译

当你编辑术语表条目时，Glossia 只会重翻译其 *有效术语表已更改的*. 如果文件的源文本没有包含编辑后的术语，其译文保持原样。如果文件使用了该术语，下一轮翻译时段将包含更新后的指令。

同一原则同样适用于反向：仅添加由部分文件使用的术语并不会强制进行全面重运行。

## 术语表不是什么

- 并非机器翻译词典。Glossia 模型会读取周围上下文，若句意需要，可对术语进行差异化处理。术语表仅是指南，而非替换。
- 并非完整的风格指南。风格、语气、正式程度和受众存在于你的账户风格配置及 `L10N.md`. 术语表仅针对单个术语及其批准的译文。
- 并非静默。每个已应用的术语均已记录在文件的锁文件中，以便审核者可以精确地追溯哪些术语表条目已应用到模型中。
