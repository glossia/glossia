术语表是一组精心策划的术语，您的翻译必须每次都呈现一致。版本控制中的"Commit"仍保持 `commit` 在西班牙语中，变为 `提交` 在简体中文中，以及 `コミット` 在日语中。每个语言一个决定，在所有地方强制执行。

## 术语表可以存在的两个位置

Glossia 在两个地方查找术语表条目，并在翻译时合并它们：

- **您的仓库**", 在您已用于翻译设置的文件中。 `L10N.md` 声明术语，而每种语言的 `L10N/<locale>.md` 声明了它们的翻译。这是开发者权威术语表：更改通过拉取请求进行，每种语言的审阅人员拥有自己的文件，嵌套文件可以针对仓库的某一部分对其进行完善。
- **服务器**, 存储在你的账户中。这是翻译权威术语表：审阅人员和本地化贡献者在无需接触代码的情况下，即可通过仪表板， [REST API](/docs/reference/apis), 或 [MCP 服务器](/docs/reference/mcp). 它适用于该账户翻译的所有仓库。

两个地方都有用，且互不替代。

## 何时使用哪个

定义术语于 **服务器** 何时：

- **它适用于多个仓库。** 产品名称、品牌术语和公司词汇只需定义一次，并在所有地方使用。
- **做出该决策的人员不在仓库内工作。** 语言学家、审核员和外部贡献者即使在仓库闭源或没有写入权限时，也能对术语表进行完善。
- **你想在不修改代码的情况下修正术语。** 更正后的翻译将在下一次运行时生效，无需对代码库发起拉取请求。
- **更改需要审查并保留历史记录。** 每次编辑都会生成带变更说明的新版本，贡献者可以将更改作为建议提案供他人审核，且早期版本依然保留。
- **其他工具需要它。** 代理和集成可以通过 REST API 和 MCP 服务器读取术语表，例如创建已采用批准术语的新内容。

在...中定义术语。 **您的仓库** 何时：

- **它归属于此代码库。** 含义特定于单一项目的术语，例如表示版本控制操作的"commit"，应紧邻使用它的代码。
- **它应随源文本一同变更。** 该术语及其引入它的文案位于同一拉取请求中，并一同进行审核。
- **仅仓库的一部分需要它。** 一个嵌套的 `L10N.md` 或 `L10N/<locale>.md` 可以为一个目录添加或覆盖条目，例如营销页面。
- **它必须覆盖服务器。** 对于同一术语，仓库条目优于服务器条目，针对其翻译的语言。

## 它们如何组合

对于每个文件和目标语言，Glossia 将这两个术语表合并为一个有效集合：

1. 首先使用目标语言的服务器术语表条目。
2. 叠加该语言的仓库条目：来自文件的术语 `L10N.md` 具有其翻译的链 `L10N/<locale>.md` 链。当仓库条目与服务器条目具有相同的源术语时，仓库条目优先。
3. 如果仓库术语没有某种语言的翻译，该语言的服务器条目仍然适用。仓库永远不会阻止其未翻译的语言。

合并发生 **每个目标语言**, 不是每个条目。"commit" 的西班牙语翻译位于 `L10N/es.md` 替换了服务器端的 "commit" 西班牙语条目，但不会触碰同一个术语的服务器端日语条目。审核人员可以看到哪些服务器条目被替换：翻译会话摘要显示有多少被覆盖，每个文件的锁文件在下方列出它们 `glossary.shadowed`．

## 术语表变更时，文件将重新翻译

当您编辑词汇表条目时，Glossia 仅会重新翻译那些文件所属 *有效词汇表已变更的*". 如果文件的源文本不包含编辑术语的匹配项，其翻译将保持不变。如果文件使用了该术语，其下一次翻译流程将包含更新后的说明。"

同一原则也适用于反向情形：仅为部分文件添加一个术语并不会强制进行完整重新运行。

## 词汇表不是什么

- 并非机器翻译词典。Glossia 的模型会读取周围上下文，并在句子要求时以不同方式呈现术语。词汇表仅提供指引，而非替换。
- 并非整个风格指南。语音、语气、正式程度以及受众均存在于您的账户风格配置以及 `L10N.md`". 词汇表仅针对各个术语及其已批准的翻译。"
- 并非静默。每个应用的术语都记录在文件的锁文件中，以便审查者可以追溯确切哪些术语表条目已达到模型。
