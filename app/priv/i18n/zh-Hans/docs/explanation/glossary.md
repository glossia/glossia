词库（术语表）是您翻译必须始终一致呈现的精心收集的一组术语。版本控制意义上的“提交”在西班牙语中保持 `commit`，在简体中文中变为 `提交`，在日语中变为 `コミット`。每个语言一个决定，到处强制执行。

## 词库可以存在的两个位置

词库在两个位置查找术语表条目，并在翻译时合并它们：

- **您的仓库**，在您已用于翻译设置的文件中。 `L10N.md` 声明术语，每种语言的 `L10N/<locale>.md` 声明其翻译。这是开发者权威的词库：更改通过拉取请求进行，每种语言的审查者自有自己的文件，嵌套文件可以更细地针对仓库部分进行完善。
- **您的 Glossia 账户**，通过托管仪表板管理。这是语言学家权威的词库：审查者和本地化贡献者可以通过仪表板、 [REST API](/docs/reference/apis) 或 [MCP 服务器](/docs/reference/mcp) 在不触及代码的情况下添加或完善条目。它适用于该账户翻译的每个仓库。

这两个位置都有用，且互不取代。

## 何时使用哪个

在以下情况在 **您的 Glossia 账户** 中定义术语：

- **它适用于多个仓库。** 产品名称、品牌术语和公司词汇定义一次，并随处使用。
- **做出决定的人员不在仓库内工作。** 语言学家、审查者和外部贡献者即使在仓库是封闭源代码或他们没有写入访问权限的情况下也可以完善术语表。
- **您想在不改变代码的情况下修复术语。** 更正后的翻译在下一次运行时生效，无需针对代码库创建拉取请求。
- **更改需要审查和历史记录。** 每次编辑都会创建一个带有更改说明的新版本，贡献者可以将更改作为建议供某人批准，之前的版本仍保留可用。
- **其他工具需要它。** 代理和集成可以通过 REST API 和 MCP 服务器读取术语表，例如写入已经使用批准术语的新内容。

在 **您的仓库** 中定义术语时：

- **它属于该代码库。** 含义针对特定项目的术语，如版本控制操作的“提交”，就位于使用它的代码旁边。
- **它应与源文本一起更改。** 术语及其引入它的合并内容落在同一个拉取请求中，并共同审查。
- **只有仓库的一部分需要它。** 一个嵌套的 `L10N.md` 或 `L10N/<locale>.md` 可以为一个目录（例如营销页面）添加或覆盖条目。
- **它必须覆盖账户词库。** 对于其翻译的语言，仓库条目在具有相同术语的账户条目之上获胜。

## 它们的组合方式

对于每个文件和目标语言，词库将两个术语表解析为一个有效的集合：

1. 从目标语言的账户术语表条目开始。
2. 覆盖该语言的仓库条目：来自文件 `L10N.md` 链中有其 `L10N/<locale>.md` 链中翻译的术语。当仓库条目与账户条目具有相同的源术语时，仓库条目获胜。
3. 如果某个仓库术语没有针对特定语言的翻译，该语言的账户条目仍然适用。仓库不会阻止它未翻译的语言。

合并是针对 **每个目标语言** 进行的，而不是针对每个条目。 `L10N/es.md` 中“提交”的西班牙语翻译会替换账户的“提交”西班牙语条目，但不会触及账户中针对同一术语的日语条目。审查者可以看到哪些账户条目被替换：翻译会话摘要显示被覆盖的数量，每个文件的锁文件将它们列在 `glossary.shadowed` 下。

## 术语表变更时，文件重新翻译

当您编辑术语表条目时，词库只会重新翻译那些 *生效的术语表已更改* 的文件。如果文件的源文本不包含编辑术语的匹配项，其翻译保持原样。如果文件使用了该术语，其下一次翻译过程将包含更新的说明。

同样的原则也适用于反向操作：仅在部分文件中使用的术语添加不会强制进行完整重新运行。

## 术语表不是什么

- 不是机器翻译词典。词库的模型会读取上下文，如果句子需要，它可以以不同方式呈现术语。术语表是指导，不是替换。
- 不是完整的样式指南。声音、语调、正式程度和受众存在于您账户的 Voice 配置和 `L10N.md` 中。术语表仅用于各个术语及其批准的翻译。
- 不是静默的。每个应用的术语都会记录在文件的锁文件中，使审查者能够追踪确切地有哪些术语表条目进入了模型。
