术语表是一套经过精心编排的术语，您的翻译必须每次都一致地呈现。版本控制意义上的“Commit”在西班牙语中保持 `commit`，变为 `提交` 简体中文，以及 `コミット` 日语。每种语言一个决策，强制执行。

## 词汇表可以存放的两个位置

Glossia 从两个地点查找词汇表条目并在翻译时合并它们：

- **您的仓库** 位于您已用于翻译设置的文件中。`L10N.md` 声明术语，而每种语言的 `L10N/<locale>.md` 声明它们的翻译。这是由开发者权威的术语表：变更通过拉取请求传播，每种语言的审查员拥有自己的文件，嵌套的文件可以针对仓库的某个部分对其进行细化。
- **您的 Glossia 账户** 通过托管仪表板进行管理。这是由语言本地化人员权威的术语表：审查员和本地化贡献者在不触碰代码的情况下通过仪表盘、[REST API](/docs/reference/apis) 或 [MCP 服务器](/docs/reference/mcp) 添加或细化条目。它适用于账户翻译的每个仓库。

两个地方都很实用，互相不能替代。

## 何时使用哪一个

在**您的 Glossia 账户**中定义术语，当：

- **它适用于多个仓库。** 产品名称、品牌术语和公司用语只需定义一次即可随处使用。
- **决策者不在该仓库工作。** 语言专家、审查者和外部贡献者即使仓库是私有源代码或未获得写访问权限，也可以完善词汇表。
- **您想无需代码变更来修正术语。** 修正后的翻译在下一次运行即生效，无需对代码库创建拉取请求。
- **变更需要审查和历史记录。** 每次编辑都会创建一个带变更说明的新版本，贡献者可以将变更作为建议供某人批准，早期版本也会保留可用。
- **其他工具需要它。** 代理程序和集成可以通过 REST API 和 MCP 服务器读取词汇表，例如撰写已使用批准术语的新内容。

在**您的仓库**中定义术语，当：

- **它属于这个代码库。** 对单个项目意义特定、例如在版本控制中表示"commit"这个版本控制操作的术语，位于使用该术语的代码旁边。
- **它应该与源文本一起变更。** 术语和引入它的文案会进入同一个拉取请求并一起审查。
- **只有仓库的一部分需要它。** 嵌套的`L10N.md`或`L10N/<locale>.md`可以为单个目录添加或覆盖条目，例如营销页面。
- **它必须覆盖账户词汇表。** 对于它翻译的语言，仓库条目力账户条目对于同一术语。

## 它们如何合并

对于每个文件和目标语言，Glossia 会解决两个词汇表组合成一个有效集：

1. 从目标语言的账户词汇表条目开始。
2. 叠加该语言的仓库条目：文件`L10N.md`链中具有其`L10N/<locale>.md`链翻译的术语。当仓库条目与账户条目具有相同源术语时，仓库条目胜出。
3. 如果仓库术语对某语言没有翻译，该语言的账户条目仍然适用。仓库不会阻止它未翻译的任何语言。

合并发生在 **每个目标语言**，而非每个条目。在 `L10N/es.md` 中“commit”的西班牙语翻译替换了账户中“commit”的西班牙语条目，但不会影响账户中该术语的日语条目。审查员可以看到哪些账户条目被替换：翻译会话摘要显示有多少被覆盖，而每个文件的锁文件将它们列在 `glossary.shadowed` 下。

## 当词汇表变更时，文件会重新翻译

当您编辑词汇表条目时，Glossia 只会重新翻译*有效词汇表变更*的文件。如果文件的源文本不包含已编辑术语的任何匹配项，其翻译将保持不变。如果文件使用该术语，下一次翻译流程将包含更新后的指令。

同一原则也适用于反向情况：仅部分文件使用的术语不会强制完全重新运行。

## 词汇表不是什么

- 不是机器翻译词典。Glossia 的模型会读取周围上下文，可以根据句子需求以不同方式呈现术语。词汇表是指导而非替换。
- 不是完整的风格指南。Voice、语调、正式程度和受众都存在于您的账户 Voice 配置和`L10N.md`中。词汇表仅针对单个术语及其获批翻译。
- 不是沉默的。每个应用的术语都会记录在文件的锁文件中，审查者可以精确追踪哪些词汇表条目进入了模型。
