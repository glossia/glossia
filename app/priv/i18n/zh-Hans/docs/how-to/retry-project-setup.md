%{title: "重试项目设置", summary: "设置失败后恢复项目。", category: "指南", section: "translation", order: 4}
---

当自动设置失败时，Glossia 会丢弃临时项目以便再次选择仓库。设置流程中可能会出现失败通知，但失败的项目及其进度记录不会被保留。

## 1. 阅读失败信息

离开设置流程前，请先阅读失败通知。常见原因包括：

- 账户未配置模型。
- 缺少提供者密钥或密钥已失效。
- Glossia GitHub App 无法访问该仓库。
- 无法准备或检查仓库。

## 2. 修复前置条件

针对模型问题，打开 **设置 → 模型**。针对仓库访问问题，在 GitHub 上更新 Glossia GitHub App 安装并授予其访问仓库的权限。

## 3. 再次开始设置

打开 **项目 → 新建项目**，选择仓库，选择 **自动设置**，并再次选择目标语言。跟随新的设置尝试直到其完成。

如果失败的项目仍然可见并提供 **重试设置**，该操作将启动新的尝试。不要依赖其保持可用：失败的项目会在清理期间被移除。

## 4. 复核完成情况

设置完成后，在 GitHub 上复核由此产生的拉取请求。有关生命周期和清理行为，请参阅 [项目设置](/docs/reference/project-setup)。
