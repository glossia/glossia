在修复导致项目设置失败的问题后，使用 **重试设置**。

## 1. 查看失败原因

打开项目概览。设置进度卡片会显示失败信息和最新的设置活动。

常见原因包括：

- 账户未配置模型。
- 提供商密钥缺失或已失效。
- Glossia GitHub App 无法访问该仓库。
- 无法准备或检查仓库。

## 2. 修复先决条件

对于模型问题，请打开 **设置** 和 **模型**。对于仓库访问问题，请在 GitHub 中更新 Glossia GitHub App 安装，并授予其访问该仓库的权限。

## 3. 重试

返回项目概览并选择 **重试设置**。

卡片状态会恢复为 **待处理**，然后变为 **运行中**，并随着工作的推进显示新的活动。仅当项目处于 **失败** 状态时，才能执行重试，以防止两个设置尝试同时运行。

## 4. 检查完成结果

当状态变为 **已完成** 时，请在 GitHub 中检查生成的拉取请求。如果再次失败，请使用卡片中的新活动而不是上一次尝试的信息来确定下一步操作。
