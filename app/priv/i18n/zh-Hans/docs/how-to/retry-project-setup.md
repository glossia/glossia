%{title: "重试项目设置", summary: "在设置报告失败后恢复项目。", category: "教程", section: "translation", order: 4}
---

当自动设置失败时，Glossia 会丢弃临时项目以便重新选择存储库。设置流程中可能会出现失败通知，但失败的项目及其进度历史不会保留。

## 1. 阅读故障

在离开设置流程之前，阅读故障通知。常见原因包括：

- 账户未配置模型。
- 提供者密钥丢失或已失效。
- Glossia GitHub 应用无法访问存储库。
- 存储库无法准备或检查。

## 2. 修复前置条件

对于模型问题，打开 **设置→模型**。对于存储库访问问题，更新 GitHub 上的 Glossia GitHub 应用安装，并授予其访问存储库的权限。

## 3. 再次开始设置

打开 **项目→新项目**，选择存储库，选择 **自动设置**，并再次选择目标语言。继续新的设置尝试直至完成。

如果失败的项目仍然可见并提供 **重试设置**，该操作将启动新的尝试。不要依赖它持续可用：失败的临时项目会在清理期间被移除。

## 4. 查看完成情况

设置完成后，在 GitHub 中查看生成的拉取请求。有关生命周期和清理行为，请见 [项目设置](/docs/reference/project-setup)。
