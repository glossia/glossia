%{title: "重试项目设置", summary: "设置失败后恢复项目。", category: "教程", section: "translation", order: 4}
---

当自动设置失败时，Glossia 会删除临时项目，以便可以重新选择仓库。设置流程中可能会出现失败通知，但失败的项目及其进度历史记录不会被保留。

## 1. 阅读失败信息

在离开设置流程之前阅读失败通知。常见原因包括：

- 该账户未配置模型。
- 提供商密钥丢失或已无效。
- Glossia GitHub 应用无法访问仓库。
- 无法准备或检查仓库。

## 2. 修复先决条件

对于模型问题，打开 **设置 → 模型**。对于仓库访问问题，更新 GitHub 上的 Glossia GitHub 应用安装，并授予其对仓库的访问权限。

## 3. 重新开始设置

打开 **项目 → 新建项目**，选择仓库，选择 **自动设置**，并再次选择目标语言。跟随新的设置尝试，直到其完成。

如果失败的项目仍然可见并提供 **重试设置** 选项，该操作将启动新的尝试。不要依赖它保持可用：失败的临时项目会在清理期间被移除。

## 4. 检查完成状态

设置完成后，审查 GitHub 中的结果拉取请求。有关生命周期和清理行为，请参阅 [项目设置](/docs/reference/project-setup)。
