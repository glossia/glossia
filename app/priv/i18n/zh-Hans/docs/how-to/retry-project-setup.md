%{title: "重试项目设置", summary: "项目设置失败后恢复项目。", category: "教程", section: "translation", order: 4}
---
当自动化设置失败时，Glossia 会丢弃临时项目以便再次选择存储库。设置流程中可能会出现失败通知，但失败的项目及其进度历史不会被保留。

## 1\. 阅读失败

在离开设置流程前请阅读失败通知。常见原因包括：

- 账户未配置模型。
- 提供者密钥缺失或已失效。
- Glossia GitHub App 无法访问存储库。
- 存储库无法准备或检查。

## 2\. 修复前置条件

若遇到模型问题，打开 **设置 → 模型**. 若遇到仓库访问问题，请在 GitHub 中更新 Glossia GitHub 应用安装，并授予其对仓库的访问权限。

## 3\. 重新开始设置

打开 **项目 → 新建项目**，选择仓库，选择 **自动化设置**,并再次选择目标语言。请继续跟进新的设置尝试直到它完成。

如果失败的项目仍然可见并提供 **重试设置**,该操作将启动另一次尝试。不要依赖其保持可用：失败的临时项目将在清理过程中被移除。

## 4\. 审查完成

当设置完成时，请审查 GitHub 中生成的拉取请求。参见 [项目设置](/docs/reference/project-setup) 有关生命周期和清理行为。
