---
本教程将 GitHub 仓库连接到 Glossia，选择首个目标语言，并为您团队准备本地化基线以供审阅。

## 开始之前

您需要：

- 一个您可以管理设置和项目的 Glossia 账户。
- 一个您可以授予 Glossia GitHub App 读取和更新权限的 GitHub 仓库。
- 一个用于支持的提供商密钥 [大型语言模型](https://en.wikipedia.org/wiki/Large_language_model).

## 1\. 配置账户模型

打开 **设置**，然后 **模型**，并选择 **新建模型**.

1. 给模型指定一个简短句柄，例如 `translation-default`.
2. 打开模型选择器并输入提供商或模型名称的一部分以过滤列表。
3. 选择您希望 Glossia 使用的模型。
4. 输入提供商密钥并保存模型。

句柄使仓库无需将提供商凭据置于源代码控制中即可引用此账户模型。另见 [配置模型提供商](/docs/how-to/configure-a-model-provider) 获取更多详细信息。

## 2\. 开始一个项目

返回 **项目** 并选择 **新项目**。

如果 Glossia 请求仓库访问权限，请跟随链接前往 GitHub 并授予 Glossia GitHub App 对该仓库的访问权限。返回 Glossia 后，重新打开 **新项目** 如有必要。

## 3\. 选择仓库

选择您想要本地化的仓库。Glossia 仅列出通过当前账户的 GitHub App 安装可用的仓库。

继续到语言步骤。

## 4\. 选择目标语言

选择一种或多种需要从仓库源内容生成的语言，然后开始设置。

## 5\. 跟踪设置进度

在 Glossia 准备项目时，请保持设置页面打开。进度卡片会显示当前状态和最近的活动，包括仓库准备、文件检查、变更、校验及完成。

您可以离开页面并返回项目概览，不会丢失设置状态。如果设置失败，同一张卡片会说明需要关注的事项并提供 **重试设置**.

## 6\. 检查结果

当设置完成时，打开项目概览并查看为仓库创建的合并请求。建议的基线通常包括：

- 一个根 `L10N.md` 包含源语言、源路径和目标语言的文件。
- 加载本地化文件所需的最小应用程序或内容变更。
- 任何已在仓库中可用的轻量级验证。

通过您常规的 GitHub 工作流审核并合并拉取请求。未来的翻译运行将使用合并后的 `L10N.md` 上下文。

项目概览在设置拉取请求合并前保持可见。如果该请求在未合并的情况下被关闭，请从设置通知中的链接重新打开它。
