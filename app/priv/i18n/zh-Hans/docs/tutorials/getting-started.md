本教程将 GitHub 仓库连接到 Glossia，选择其首个目标语言，并为您的团队准备本地化基线以供审查。

## 开始之前

您需要：

- 一个可以管理设置和项目的 Glossia 账户。
- 一个您可以授予 Glossia GitHub App 读取和更新权限的 GitHub 仓库。
- 一个受支持的提供商密钥 [大型语言模型](https://en.wikipedia.org/wiki/Large_language_model)。

## 1\. 配置账户模型

打开 **设置**，然后 **模型**，并选择 **新建模型**。

1. Glossia 模型需要一个简短的&#10; 别名&#10;，例如 `translation-default`.
2. 打开模型选择器，输入提供商或模型名称的一部分以过滤列表。
3. 选择您希望 Glossia 使用的模型。
4. 输入提供商密钥并保存模型。

别名允许存储库引用此账户模型，而无需将提供商凭据放入源代码管理。见 [配置模型提供商](/docs/how-to/configure-a-model-provider) 以获取更多信息。

## 2\. 启动项目

返回 **项目** 并选择 **新建项目**.

如果 Glossia 请求仓库访问权限，请按照链接前往 GitHub 并授予 Glossia GitHub 应用对该仓库的访问权限。返回 Glossia 后，重新打开 **新建项目** 如必要。

## 3\. 选择一个仓库

选择您想要本地化的仓库。Glossia 仅列出当前账户通过 GitHub App 安装可用的仓库。

进入语言设置步骤。

## 4\. 选择目标语言

选择您希望从仓库源内容生成的一种或多种语言，然后开始设置。

## 5\. 跟踪设置进度

在 Glossia 准备项目时，请保持设置页面打开。进度卡片将显示当前状态和近期活动，包括仓库准备、文件检查、变更、检查及完成。

您可以离开页面并返回项目概览而不会丢失设置状态。如果设置失败，相同的卡片会解释需要注意的内容并提供 **重试设置**,(

## 6\. 查看结果

设置完成后，打开项目概览并查看为仓库创建的拉取请求。建议基线通常包括：

- 一个根 `L10N.md` 包含源语言、源路径和目标语言的文件。
- 加载本地化文件所需的最小应用程序或内容更改。
- 仓库中任何此前已可用的轻量级验证。

通过您正常的 GitHub 工作流程审查并合并拉取请求。未来的翻译运行将使用合并后的 `L10N.md` 上下文。

项目概述会将设置拉取请求保持可见，直到其被合并。如果它在未被合并的情况下被关闭，请从设置通知中的链接重新打开它。
