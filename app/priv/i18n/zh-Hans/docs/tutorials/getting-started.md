---

本教程将 GitHub 仓库连接到 Glossia，选择其第一批目标语言，并为您团队准备本地化基线以供审查。

## 开始之前

您需要：

- 一个可管理设置和项目的 Glossia 账户。
- 一个可授予 Glossia GitHub App 读取和更新权限的 GitHub 仓库。
- 一个受支持的 [大型语言模型](https://en.wikipedia.org/wiki/Large_language_model) 的提供商密钥。

## 1. 配置账户模型

打开 **设置**，然后点击 **模型**，接着选择 **新建模型**。

1. 为模型设定一个简短代号，例如 `translation-default`。
2. 打开模型选择器并输入提供商或模型名称的一部分以过滤列表。
3. 选择您希望 Glossia 使用的模型。
4. 输入提供商密钥并保存模型。

使用此代号，仓库可以在源代码控制中不放置提供商凭证的情况下引用此账户模型。有关更多详情，请参阅 [配置模型提供商](/docs/how-to/configure-a-model-provider)。

## 2. 启动项目

返回 **项目** 并选择 **新建项目**。

如果 Glossia 请求仓库访问权限，请跟随链接访问 GitHub 并授予 Glossia GitHub App 对该仓库的访问权限。返回 Glossia 后，如需要，重新打开 **新建项目**。

## 3. 选择仓库

选择您希望本地化的仓库。Glossia 仅列出通过当前账户的 GitHub App 安装可用的仓库。

## 4. 选择项目设置方式

选择 **自动设置** 以让 Glossia 检查仓库并在拉取请求中提出本地化配置。本教程将按此路径进行。

如果仓库已有一个 `L10N.md` 文件，或者您偏好自己编写，则选择 **手动配置**。Glossia 会立即创建项目，您可以跳过剩余步骤。请查看 [项目设置](/docs/reference/project-setup) 以了解各模式的功能。

## 5. 选择目标语言

选择应从仓库源内容生成的一种或多种语言，然后开始设置。

## 6. 跟踪设置进度

在 Glossia 准备项目时，保持设置页面处于打开状态。进度卡片显示当前状态和近期活动，包括仓库准备、文件检查、变更、检查和完成。

您可以离开页面并返回项目概览而不丢失设置状态。如果设置失败，请读取失败通知。Glossia 将弃用临时项目；请修正先决条件并通过 **新建项目** 重新开始。详见 [重试项目设置](/docs/how-to/retry-project-setup)。

## 7. 审查结果

设置完成后，打开项目概览并审查为仓库创建的拉取请求。提议的基线通常包括：

- 一个包含源语言、源路径和目标语言的根 `L10N.md` 文件。
- 加载本地化文件所需的最小应用程序或内容变更。
- 任何仓库中原本可用的轻量级验证。

通过您的常规 GitHub 工作流程审查并合并拉取请求。未来的翻译运行将使用合并后的 `L10N.md` 上下文。

项目概览会保持设置拉取请求可见，直到被合并。如果被关闭且未合并，请从设置通知中的链接重新打开它。
