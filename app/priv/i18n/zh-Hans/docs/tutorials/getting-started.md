---
本教程演示如何将 GitHub 仓库连接到 Glossia，选择首批目标语言，并为您的团队准备本地化基线供审查。

## 开始之前

您需要：

- 一个可以管理设置和项目的 Glossia 账户。
- 一个已授予 Glossia GitHub App 读取和更新权限的 GitHub 仓库。
- 一个受支持的提供程序密钥 [大语言模型](https://en.wikipedia.org/wiki/Large_language_model).

## 1\. 配置账户模型

打开 **设置**，然后 **模型**，并选择 **新模型**。

1. 给模型指定一个简短标识，例如 `translation-default`.
2. 打开模型选择器，输入提供商或模型名称的一部分以筛选列表。
3. 选择您希望 Glossia 使用的模型。
4. 输入提供商密钥并保存模型。

该标识允许仓库引用此账户模型，而无需将提供商凭据放入版本控制。参见 [配置模型提供商](/docs/how-to/configure-a-model-provider) 以获取更多详情。

## 2\. 开始项目

返回 **项目** 并选择 **新建项目**.

如果 Glossia 提示需要仓库访问，请点击链接进入 GitHub 并授予 Glossia GitHub 应用对仓库的访问权限。返回 Glossia 后，重新打开 **新建项目** 如有需要。

## 3\. 选择一个仓库

选择您要本地化的仓库。Glossia 仅列出通过当前账户的 GitHub App 安装可用的仓库。

## 4\. 选择项目设置方式

选择 **自动化设置** 以便让 Glossia 检查仓库，并在拉取请求中提出本地化配置建议。本教程将遵循此路径。

如果仓库已经有一个 `L10N.md` 文件，或者您更倾向于自行编写，请选择 **手动配置** 反之。Glossia 会立即创建项目，您可以跳过剩余步骤。查看 [项目设置](/docs/reference/project-setup) 以了解每种模式的功能。

## 5\. 选择目标语言

请选择一个或多个需从仓库源内容生成的语言，然后开始设置。

## 6\. 跟踪设置进度

在 Glossia 准备项目期间，请保持设置页面开启。进度卡显示当前状态和近期活动，包括仓库准备、文件检查、变更、检查及完成。

您可以离开页面并返回项目概览而不会丢失设置状态。如果设置失败，请查看失败通知。Glossia 会丢弃临时项目；请修复先决条件，并通过以下方式重新尝试： **新项目**. 查看 [重试项目设置](/docs/how-to/retry-project-setup).

## 7\. 查看结果

设置完成后，请打开项目概览并审查为仓库创建的拉取请求。建议的基线通常包括：

- 根 `L10N.md` 包含源语言、源路径和目标语言的文件。
- 加载本地化文件所需的最小应用程序或内容变更。
- 仓库中已有的任何轻量级验证。

通过您常规的 GitHub 工作流审查并合并拉取请求。未来的翻译运行将使用已合并的 `L10N.md` 上下文。

项目概览在合并前保持设置拉取请求可见。如果未合并即关闭，请从设置通知中的链接重新打开它。
