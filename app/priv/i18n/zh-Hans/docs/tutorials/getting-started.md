本教程将 GitHub 仓库连接到 Glossia，选择首批目标语言，并为团队准备可供审核的本地化基准。

## 开始之前

您需要：

- 一个可管理设置和项目的 Glossia 账户。
- 一个您可以授权 Glossia GitHub 应用读取和更新的 GitHub 仓库。
- 受支持的[大语言模型](https://en.wikipedia.org/wiki/Large_language_model)的提供商密钥。

## 1. 配置账户模型

打开**设置**，然后打开**模型**，并选择**新建模型**。

1. 为模型指定一个简短标识，例如 `translation-default`。
2. 打开模型选择器，输入部分提供商名称或模型名称以筛选列表。
3. 选择您希望 Glossia 使用的模型。
4. 输入提供商密钥并保存模型。

通过此标识，仓库可以引用该账户模型，而无需将提供商凭据放入源代码管理系统。有关更多详细信息，请参阅[配置模型提供商](/docs/how-to/configure-a-model-provider)。

## 2. 创建项目

返回**项目**并选择**新建项目**。

如果 Glossia 请求仓库访问权限，请点击链接前往 GitHub，并授权 Glossia GitHub 应用访问该仓库。返回 Glossia 后，如有必要，请重新打开**新建项目**。

## 3. 选择仓库

选择要本地化的仓库。Glossia 仅列出当前账户安装的 GitHub 应用有权访问的仓库。

继续进入语言选择步骤。

## 4. 选择目标语言

选择一种或多种需要根据仓库源内容生成的语言，然后开始设置。

## 5. 查看设置进度

Glossia 准备项目时，请保持设置页面打开。进度卡片会显示当前状态和近期活动，包括仓库准备、文件检查、变更、校验和完成情况。

您可以离开此页面并返回项目概览，设置状态不会丢失。如果设置失败，同一卡片会说明需要处理的问题，并提供**重试设置**操作。

## 6. 审核结果

设置完成后，打开项目概览，并审核为该仓库创建的拉取请求。建议的基准通常包括：

- 一个位于根目录的 `GLOSSIA.md` 文件，其中包含源语言、源路径和目标语言。
- 加载本地化文件所需的最少应用程序或内容变更。
- 仓库中已有的任何轻量级验证。

通过团队常用的 GitHub 工作流程审核并合并该拉取请求。后续翻译运行将使用合并后的 `GLOSSIA.md` 上下文。

在设置拉取请求合并之前，项目概览会持续显示该请求。如果该请求未经合并即被关闭，请通过设置通知中的链接重新打开。
