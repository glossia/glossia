%{title: "入门", summary: "连接仓库并准备首次本地化设置。", category: "教程", order: 1}
---
本教程将 GitHub 仓库连接到 Glossia，选择其首个目标语言，并准备一个本地化基线供您团队审查。

## 开始之前

您需要：

- 一个您可以在其中管理设置和项目的 Glossia 账户。
- 您可以授予 Glossia GitHub App 读取和更新权限的 GitHub 仓库。
- 一个受支持的 [大语言模型](https://en.wikipedia.org/wiki/Large_language_model) 的提供商密钥。

## 1\. 配置账户模型

打开 **设置**，然后 **模型**，并选择 **新建模型**。

1. 为该模型指定一个简短句柄，例如 `translation-default`。
2. 打开模型选择器，并输入提供商或模型名称的一部分以过滤列表。
3. 选择您希望 Glossia 使用的模型。
4. 输入提供商密钥并保存模型。

句柄允许仓库在不将提供商凭据放入源代码控制的情况下引用此账户模型。有关更多详细信息，请查看 [配置模型提供商](/docs/how-to/configure-a-model-provider)。

## 2\. 开始项目

返回 **项目** 并选择 **新建项目**。

如果 Glossia 请求访问仓库，请跟随链接前往 GitHub 并授予 Glossia GitHub App 对该仓库的访问权限。返回 Glossia 后，如有必要，请重新打开 **新建项目**。

## 3\. 选择仓库

选择您想要本地化的仓库。Glossia 仅列出通过当前账户的 GitHub App 安装可用的仓库。

继续语言步骤。

## 4\. 选择目标语言

选择一个或多个应从仓库源内容生成的语言，然后开始设置。

## 5\. 跟踪设置进度

在 Glossia 准备项目时保持设置页面处于打开状态。进度卡片显示当前状态和最近的动态，包括仓库准备、文件检查、更改、检查和完成。

您可以离开页面并返回项目概述，而不会丢失设置状态。如果设置失败，同一张卡片会解释需要关注的内容并提供 **重试设置**。

## 6\. 审查结果

设置完成后，打开项目概述并审查为仓库创建的拉取请求。建议的基线通常包括：

- 包含源语言、源路径和目标语言的主 `GLOSSIA.md` 文件。
- 加载本地化文件所需的最小应用程序或内容更改。
- 仓库中已有的任何轻量级验证。

通过您正常的 GitHub 工作流程审查和合并拉取请求。未来的翻译运行将使用已合并的 `GLOSSIA.md` 上下文。

项目概述在合并不前保持设置拉取请求可见。如果未合并即关闭，请从设置通知中的链接重新打开它。
