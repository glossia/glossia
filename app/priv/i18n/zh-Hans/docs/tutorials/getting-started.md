%{title: "快速开始", summary: "连接仓库并准备首个本地化设置。", category: "教程", order: 1}
---
本教程将 GitHub 仓库连接到 Glossia，选择其第一个目标语言，并为您的团队准备本地化基线以供审查。

## 开始之前

您需要：

- 一个可以管理设置和项目的 Glossia 账户。
- 一个您可以授予 Glossia GitHub 应用读取和更新权限的 GitHub 仓库。
- 一个用于受支持的提供商密钥 [大型语言模型](https://en.wikipedia.org/wiki/Large_language_model)。

## 1\. 配置账户模型

打开 **设置**，然后 **模型**，并选择 **新建模型**.

1. 为模型指定简短句柄，例如 `translation-default`.
2. 打开模型选择器并输入提供商或模型名称的一部分以筛选列表。
3. 选择您希望 Glossia 使用的模型。
4. 输入提供商密钥并保存模型。

句柄使仓库能够在无需将提供商凭证置于源代码控制中即可引用此账户模型。参阅 [配置模型提供商](/docs/how-to/configure-a-model-provider) 更多详细信息。

## 2\. 开始一个项目

返回 **项目** 并选择 **新建项目**.

如果 Glossia 请求仓库访问权限，请按照链接前往 GitHub 并授权 Glossia GitHub App 访问该仓库。返回 Glossia 后，重新打开 **新建项目** 如有需要。

## 3\. 选择仓库

选择您想要本地化的仓库。Glossia 仅列出通过当前账户的 GitHub App 安装可用的仓库。

继续到语言步骤。

## 4\. 选择目标语言

选择一种或多种需从仓库的源内容生成的语言，然后开始设置。

## 5\. 查看设置进度

Glossia 准备项目时请保持设置页面打开。进度卡片显示当前状态和最近活动，包括仓库准备、文件审查、变更、检查及完成。

您可以离开页面并返回到项目概览而不会丢失设置状态。如果设置失败，同一卡片将说明需要注意的内容，并提供 **重试设置**。

## 6\. 查看结果

当设置完成后，打开项目概览并查看为仓库创建的拉取请求。建议基线通常包括：

- 一个根 `L10N.md` 包含源语言、源路径和目标语言的文件。
- 加载本地化文件所需的最小应用程序或内容更改。
- 任何已在仓库中可用的轻量级验证。

通过您常规的 GitHub 工作流程审查并合并该拉取请求。未来的翻译运行将使用合并后的 `L10N.md` 上下文。

项目概览在设置拉取请求合并前保持可见。如果它未经合并即被关闭，请从设置通知中的链接将其重新打开。
