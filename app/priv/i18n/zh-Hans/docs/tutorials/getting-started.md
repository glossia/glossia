---
本教程将 GitHub 仓库连接到 Glossia，选择其首目标语言，并为您的团队准备本地化基线以供审阅。

## 开始之前

您需要：

- 一个您可以管理设置和项目的 Glossia 账户。
- 一个您可以授予 Glossia GitHub App 读取和更新权限的 GitHub 仓库。
- 一个用于受支持的提供商密钥 [大语言模型](https://en.wikipedia.org/wiki/Large_language_model).

## 1\. 配置账户模型

打开 **设置**，然后 **模型**，并选择 **新建模型**。

1. 为模型指定一个简短标识，例如 `translation-default`。
2. 打开模型选择器，输入部分提供商或模型名称以筛选列表。
3. 选择您希望 Glossia 使用的模型。
4. 输入提供商密钥并保存模型。

该标识使仓库能够引用此账户模型，而无需将提供商凭据放入源码控制中。参见 [配置模型提供商](/docs/how-to/configure-a-model-provider) 了解更多详情。

## 2\. 开始一个项目

返回至 **项目** 并选择 **新建项目**.

如果 Glossia 提示需要仓库访问权限，请点击链接前往 GitHub 并授予 Glossia GitHub App 对仓库的访问权限。返回 Glossia 后，重新打开 **新建项目** 如有必要。

## 3\. 选择仓库

选择您要本地化的仓库。Glossia 仅列出当前账户的 GitHub App 安装中可用的仓库。

转到语言步骤。

## 4\. 选择目标语言

选择一个或多个应从仓库源内容生成的语言，然后开始设置。

## 5\. 跟踪设置进度

Glossia 准备项目时请保持设置页面打开。进度卡显示当前状态和近期活动，包括仓库准备、文件审查、变更、检查和完成。

您可以离开页面并返回项目概览，而不会丢失设置状态。如果设置失败，同一卡片会说明需要注意的事项并提供 **重试设置**.

## 6\. 查看结果

设置完成后，打开项目概览并查看为该仓库创建的拉取请求。建议的基线通常包括：

- 一个根 `L10N.md` 包含源语言、源路径和目标语言的文件。
- 加载本地化文件所需的最小应用或内容变更。
- 任何已在仓库中可用的轻量级验证。

通过您正常的 GitHub 工作流审查并合并拉取请求。未来的翻译运行使用合并的 `L10N.md` 上下文。

项目概述会保持设置拉取请求可见，直到它被合并。如果它未合并即被关闭，请从设置通知中的链接重新打开它。
