%{title: "快速开始", summary: "连接仓库并准备首次本地化配置。", category: "教程", order: 1}
---

本教程将 GitHub 仓库连接到 Glossia，选择首个目标语言，并为您的团队准备本地化基准以供审核。

## 开始之前

您需要：

- 一个可以管理设置和项目的 Glossia 账户。
- 一个 GitHub 仓库，您可以授予 Glossia GitHub App 读取和更新权限。
- 一个受支持的 [大语言模型](https://en.wikipedia.org/wiki/Large_language_model) 的提供者密钥。

## 1. 配置账户模型

打开 **设置**，然后 **模型**，并选择 **新建模型**。

1. 给模型一个简短的标识，例如 `translation-default`。
2. 打开模型选择器并键入提供者或模型名称的一部分以过滤列表。
3. 选择您希望 Glossia 使用的模型。
4. 输入提供者密钥并保存模型。

该标识允许仓库引用此账户模型，而无需将提供者凭据放在源代码控制中。有关更多详细信息，请参阅 [配置模型提供者](/docs/how-to/configure-a-model-provider)。

## 2. 启动项目

返回到 **项目** 并选择 **新建项目**。

如果 Glossia 请求仓库访问权限，请按照链接进入 GitHub 并授予 Glossia GitHub App 对该仓库的访问权限。返回 Glossia 后，如有必要，请重新打开 **新建项目**。

## 3. 选择仓库

选择您要本地化的仓库。Glossia 仅显示通过当前账户的 GitHub App 安装可用的仓库。

## 4. 选择如何设置项目

选择 **自动设置** 以让 Glossia 检查仓库并在合并请求中提出本地化配置。本教程遵循此路径。

如果仓库中已有 `L10N.md` 文件，或者您更喜欢自己编写它，请选择 **手动配置** 代替。Glossia 会立即创建项目，您可以跳过剩余步骤。有关各模式的功能，请参阅 [项目设置](/docs/reference/project-setup)。

## 5. 选择目标语言

选择一个或多个应源自仓库源内容生成的语言，然后开始设置。

## 6. 查看设置进度

在 Glossia 准备项目时保持设置页面打开。进度卡片显示当前状态和最近活动，包括仓库准备、文件检查、更改、检查和完成。

您可以离开页面并返回到项目总览而不会丢失设置状态。如果设置失败，请读取失败通知。Glossia 会丢弃临时项目，修复先决条件，并通过 **新建项目** 重新开始。请参阅 [重试项目设置](/docs/how-to/retry-project-setup)。

## 7. 审核结果

设置完成后，打开项目总览并审核为仓库创建的合并请求。建议的基准通常包括：

- 一个根 `L10N.md` 文件，包含源语言、源路径和目标语言。
- 加载定位文件所需的最小应用程序或内容更改。
- 仓库中已可用的任何轻量级验证。

通过您的正常 GitHub 工作流审核和合并合并请求。未来的翻译运行将使用已合并的 `L10N.md` 上下文。

项目总览在合并之前保持设置合并请求可见。如果它未合并即被关闭，请从设置通知中的链接重新打开它。
